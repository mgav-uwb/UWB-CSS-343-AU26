Edit Distance

Data Structures & Algorithms. Algorithm (dynamic programming).
Edit (Levenshtein) distance: the min-of-three recurrence over prefix pairs, the worked table for kitten \(\to\) sitting (distance \(3\)), the traceback that reads off the edit script, complete code, the metric property, weighted costs and sequence alignment, and the side-by-side comparison with the longest common subsequence. The method itself is the Dynamic Programming Method handout. With a demo and exercises.

The DP recipe is the Dynamic Programming Method handout; the two-dimensional prefix-pair table it built for the longest common subsequence here acquires a min-of-three transition. Edit distance is the table behind every spell-checker, and its \(\Theta(mn)\) is truly polynomial, a sharp contrast with knapsack’s pseudo-polynomial bound.

1. Edit distance

Definition (edit distance) The edit distance (also Levenshtein distance) between strings \(A\) (length \(m\)) and \(B\) (length \(n\)) is the fewest single-character edits (insert, delete, or replace) that transform \(A\) into \(B\).

The classic instance: kitten \(\to\) sitting takes three edits: replace k\(\to\)s, replace e\(\to\)i, insert g. Edit distance is the engine behind spell-checkers (nearest dictionary word to a typo), “did you mean…?” fuzzy search, record linkage, and, with weighted operations, DNA and protein alignment. Like LCS (the Longest Common Subsequence handout), the brute force over all edit sequences is exponential; the DP is \(\Theta(mn)\), and truly polynomial (the 0/1 Knapsack handout’s pseudo-polynomial contrast).

Definition (edit-distance table) Let \(D[i][j]\) be the edit distance between the first \(i\) characters of \(A\) and the first \(j\) characters of \(B\). If the last characters match, no edit is spent on them; otherwise pay \(1\) for the cheapest of the three operations: \[ D[i][j] = \begin{cases} D[i-1][j-1] & \text{if } A[i{-}1] = B[j{-}1] \text{ (match, free)}\\[4pt] 1 + \min\bigl(D[i-1][j],\; D[i][j-1],\; D[i-1][j-1]\bigr) & \text{otherwise,} \end{cases} \] where the three candidates are delete \(A[i{-}1]\) (up), insert \(B[j{-}1]\) (left), and replace \(A[i{-}1] \to B[j{-}1]\) (diagonal). Base cases: \(D[i][0] = i\) (turn a length-\(i\) prefix into the empty string by \(i\) deletions) and \(D[0][j] = j\) (build a length-\(j\) prefix by \(j\) insertions). The answer is \(D[m][n]\).

The state is again a pair of prefixes (the same 2-D shape as LCS), but the transition reads three neighbors and takes a min. Two cells worked by hand make the fill mechanical:

Example (two worked cells) \(D[1][1]\), turning "k" into "s": 
  'k' != 's'  →  1 + min( D[0][1] = 1,     // delete 'k', then insert 's'
                           D[1][0] = 1,     // insert 's', then delete 'k'
                           D[0][0] = 0 )    // replace k → s
              =  1 + 0  =  1                (one replace)
The delete and insert routes each cost \(2\) in total (the neighbor already holds one edit); the single replace wins. Next, \(D[2][1]\), turning "ki" into "s": 'i' \(\ne\) 's', so \(1 + \min(D[1][1], D[2][0], D[1][0]) = 1 + \min(1, 2, 1) = 2\): for instance replace k\(\to\)s then delete i. All four behaviours are visible in these fourteen cells:

  • Delete wins alone at \(D[5][2]\), \(D[5][3]\), \(D[5][4]\), \(D[6][2]\), \(D[6][3]\), \(D[6][4]\). These are cells deep into a row whose remaining source characters have no counterpart left in the target prefix, so dropping a character of \(A\) is cheapest.
  • Replace wins alone at \(D[5][5]\): up and left both hold \(2\) while the diagonal holds \(1\), so \(1 + \min(2,2,1) = 2\). This is the e\(\to\)i replace of the final script.
  • Insert wins alone at \(D[6][7]\): the left neighbour \(D[6][6] = 2\) beats up \(4\) and diagonal \(3\), giving \(1 + 2 = 3\). This is the appended g, and it is the answer cell.
  • The free match at \(D[6][6]\): n equals n, so the value is copied straight from the diagonal, \(2\), with no \(+1\). Had the characters differed, the mismatch formula would have charged \(1 + \min(3,3,2) = 3\) instead. That saved unit is exactly what the traceback later reports as a match.

The tie rows show the other structural fact: several neighbours can explain one cell, so several optimal scripts exist. They are ties in value only, and the traceback takes whichever it tests first. 

// Edit (Levenshtein) distance. D[i][j] = fewest edits turning the first i
// characters of a into the first j characters of b. Theta(mn) time and space.
int editDistance(const string& a, const string& b, vector<vector<int>>& D) {
    int m = a.size(), n = b.size();
    D.assign(m + 1, vector<int>(n + 1, 0));
    for (int i = 0; i <= m; i++) D[i][0] = i;         // base: delete all of a
    for (int j = 0; j <= n; j++) D[0][j] = j;         // base: insert all of b
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            if (a[i-1] == b[j-1])
                D[i][j] = D[i-1][j-1];                // match: free diagonal
            else
                D[i][j] = 1 + min({D[i-1][j],         // delete a[i-1]
                                   D[i][j-1],         // insert b[j-1]
                                   D[i-1][j-1]});     // replace a[i-1]->b[j-1]
    return D[m][n];
}

// Traceback: read the edit script off the table, bottom-right to origin. Each
// step asks which neighbor produced this cell's value. O(m + n).
vector<string> editScript(const string& a, const string& b,
                          const vector<vector<int>>& D) {
    vector<string> ops;
    int i = a.size(), j = b.size();
    while (i > 0 || j > 0) {
        if (i > 0 && j > 0 && a[i-1] == b[j-1] && D[i][j] == D[i-1][j-1]) {
            ops.push_back(string("match ") + a[i-1]);            // free
            i--; j--;
        } else if (i > 0 && j > 0 && D[i][j] == D[i-1][j-1] + 1) {
            ops.push_back(string("replace ") + a[i-1] + "->" + b[j-1]);
            i--; j--;
        } else if (i > 0 && D[i][j] == D[i-1][j] + 1) {
            ops.push_back(string("delete ") + a[i-1]);
            i--;
        } else {
            ops.push_back(string("insert ") + b[j-1]);
            j--;
        }
    }
    reverse(ops.begin(), ops.end());                  // forward order
    return ops;
}
// Edit (Levenshtein) distance. D[i][j] = fewest edits turning the first i
// characters of a into the first j characters of b. Theta(mn) time and space.
static int editDistance(String a, String b, int[][] D) {
    int m = a.length(), n = b.length();
    for (int i = 0; i <= m; i++) D[i][0] = i;     // base: delete all of a
    for (int j = 0; j <= n; j++) D[0][j] = j;     // base: insert all of b
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            if (a.charAt(i-1) == b.charAt(j-1))
                D[i][j] = D[i-1][j-1];            // match: free diagonal
            else
                D[i][j] = 1 + Math.min(D[i-1][j],           // delete
                              Math.min(D[i][j-1],           // insert
                                       D[i-1][j-1]));       // replace
    return D[m][n];
}

# Edit (Levenshtein) distance. D[i][j] = fewest edits turning the first i
# characters of a into the first j characters of b. Theta(mn) time and space.
def edit_distance(a, b):
    m, n = len(a), len(b)
    D = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): D[i][0] = i            # base: delete all of a
    for j in range(n + 1): D[0][j] = j            # base: insert all of b
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                D[i][j] = D[i - 1][j - 1]         # match: free diagonal
            else:
                D[i][j] = 1 + min(D[i - 1][j],    # delete a[i-1]
                                  D[i][j - 1],    # insert b[j-1]
                                  D[i - 1][j - 1])  # replace a[i-1]->b[j-1]
    return D                                      # D[m][n] is the distance

# Traceback: read the edit script off the table, bottom-right to origin. Each
# step asks which neighbor produced this cell's value. O(m + n).
def edit_script(a, b, D):
    ops, i, j = [], len(a), len(b)
    while i > 0 or j > 0:
        if i > 0 and j > 0 and a[i-1] == b[j-1] and D[i][j] == D[i-1][j-1]:
            ops.append("match " + a[i - 1])       # free
            i, j = i - 1, j - 1
        elif i > 0 and j > 0 and D[i][j] == D[i-1][j-1] + 1:
            ops.append("replace " + a[i - 1] + "->" + b[j - 1])
            i, j = i - 1, j - 1
        elif i > 0 and D[i][j] == D[i-1][j] + 1:
            ops.append("delete " + a[i - 1])
            i -= 1
        else:
            ops.append("insert " + b[j - 1])
            j -= 1
    return ops[::-1]                              # forward order
// Edit (Levenshtein) distance. d[i][j] = fewest edits turning the first i
// characters of a into the first j characters of b. Theta(mn) time and space.
fn edit_distance(a: &[u8], b: &[u8]) -> Vec<Vec<usize>> {
    let (m, n) = (a.len(), b.len());
    let mut d = vec![vec![0usize; n + 1]; m + 1];
    for i in 0..=m { d[i][0] = i; }                   // base: delete all of a
    for j in 0..=n { d[0][j] = j; }                   // base: insert all of b
    for i in 1..=m {
        for j in 1..=n {
            d[i][j] = if a[i - 1] == b[j - 1] {
                d[i - 1][j - 1]                       // match: free diagonal
            } else {
                1 + d[i - 1][j]                       // delete a[i-1]
                    .min(d[i][j - 1])                 // insert b[j-1]
                    .min(d[i - 1][j - 1])             // replace a[i-1]->b[j-1]
            };
        }
    }
    d                                                 // d[m][n] is the distance
}

// Traceback: read the edit script off the table, bottom-right to origin.
// Each step asks which neighbor produced this cell's value. O(m + n).
fn edit_script(a: &[u8], b: &[u8], d: &[Vec<usize>]) -> Vec<String> {
    let mut ops = Vec::new();
    let (mut i, mut j) = (a.len(), b.len());
    while i > 0 || j > 0 {
        if i > 0 && j > 0 && a[i - 1] == b[j - 1] && d[i][j] == d[i - 1][j - 1] {
            ops.push(format!("match {}", a[i - 1] as char));     // free
            i -= 1; j -= 1;
        } else if i > 0 && j > 0 && d[i][j] == d[i - 1][j - 1] + 1 {
            ops.push(format!("replace {}->{}", a[i - 1] as char, b[j - 1] as char));
            i -= 1; j -= 1;
        } else if i > 0 && d[i][j] == d[i - 1][j] + 1 {
            ops.push(format!("delete {}", a[i - 1] as char));
            i -= 1;
        } else {
            ops.push(format!("insert {}", b[j - 1] as char));
            j -= 1;
        }
    }
    ops.reverse();                                    // forward order
    ops
}

Structurally this is LCS’s double loop with the max-of-two swapped for a min-of-three and the base-case edges filled with \(i\) and \(j\) instead of zeros. The traceback, as always, turns the number into the answer users actually want.

How the traceback works
  1. Start at the bottom-right cell \(D[M][N]\), which holds the final distance.
  2. Look back at the three cells that could have produced it: the diagonal \((i{-}1, j{-}1)\), up \((i{-}1, j)\), and left \((i, j{-}1)\).
  3. Step to the one that accounts for this cell’s value under the recurrence: on a mismatch, a neighbour with \(D[i][j] = 1 + D[\text{neighbour}]\); on a match, the diagonal, taken at cost 0. The rule is not “step to the smallest neighbour” but “step to the one the recurrence used”: on a match the free diagonal is always available, since adjacent cells differ by at most 1.
  4. Stop at \((0,0)\), then reverse the collected moves: they were gathered backwards, and reversing is what turns “how I got here” into “what to do”.

Each move names an operation: a diagonal on matching characters is a free match, a diagonal on differing characters a replace, an up-step a delete from \(A\), a left-step an insert from \(B\). Where two neighbours both explain a cell there are several optimal scripts and any one is correct: ab \(\to\) ba has distance 2 by three distinct routes.

For kitten \(\to\) sitting the optimal script is unique: 

  k → s   replace
  i → i   match        t → t   match        t → t   match
  e → i   replace
  n → n   match
  ε → g   insert
  →  2 replaces + 1 insert  =  3 edits  =  D[6][7]  ✓

This script, not the count, is what a spell-checker’s suggestion ranking, a diff hunk, or a genome aligner outputs.

Edit distance is a metric With unit costs, edit distance satisfies the metric axioms: \(d(A,A) = 0\), symmetry \(d(A,B) = d(B,A)\) (every edit has an inverse of equal cost), and the triangle inequality \(d(A,C) \le d(A,B) + d(B,C)\) (concatenating two edit scripts transforms \(A\) to \(C\), so the shortest script can only be shorter). Strings therefore live in a genuine metric space, which unlocks metric algorithms and data structures: nearest-neighbor search, clustering, and BK-tree (Burkhard–Keller tree) indexes that answer “every dictionary word within \(2\) edits of this typo” without a linear scan. Not every similarity score is a metric; this one is, and the triangle inequality is precisely what the indexes prune with.

LCS and edit distance, side by side

The two 2-D string DPs are close cousins: same prefix-pair state, same three-neighbor reads, opposite objective:

LCSedit distance
goalmaximize common lengthminimize edits
matchdiagonal \(+\,1\)diagonal, free
mismatch\(\max(\text{up}, \text{left})\)\(1 + \min(\text{up}, \text{left}, \text{diag})\)
base caseszeros\(D[i][0]=i\), \(D[0][j]=j\)
cost\(\Theta(mn)\)\(\Theta(mn)\)

They are also numerically linked. If only insert and delete were allowed (no replace), the optimal strategy would be to keep exactly an LCS and edit everything else: \(m + n - 2\cdot\mathrm{LCS}\) edits. Allowing replace can only help (one replace does the work of a delete\(+\)insert pair), so \[ \max(m, n) - \mathrm{LCS} \;\le\; \text{edit distance} \;\le\; m + n - 2\cdot\mathrm{LCS}. \] On kitten/sitting: the LCS is ittn, length \(4\) (check it in the LCS demo), giving bounds \(7 - 4 = 3 \le 3 \le 6 + 7 - 8 = 5\); the lower bound is tight here because the optimal script uses replaces wherever possible. If you can fill one of these tables, you can fill the other; they are the “same” problem viewed as a max versus a min.

Weighting the edits Nothing in the DP assumes each operation costs \(1\). Replace the constants with per-operation costs (say replace \(= 2\), insert \(=\) delete \(= 1\), to model a typo as cheaper than an omission), or even a per-character-pair cost matrix, and the recurrence, fill order, and traceback are unchanged. That one-line generalization is biological sequence alignment: the Needleman–Wunsch algorithm is weighted edit distance with a substitution matrix that charges likely mutations less. Same table, different constants, Nobel-grade reach.

The bound of §1 confirms it: the LCS is ace, length \(3\), so the distance is at least \(\max(5,3) - 3 = 2\).
