Longest Common Subsequence

The Unix diff program, written by James Hunt and Douglas McIlroy in 1976, compares two files by finding a longest common subsequence of their lines. J. W. Hunt and M. D. McIlroy, “An Algorithm for Differential File Comparison,” Bell Labs CSTR 41, 1976

Dynamic programming solves a problem by trying every choice and caching the overlapping subproblems; the method, its two implementations, and its five-step recipe are the Dynamic Programming Method handout. The longest common subsequence runs the recipe in two dimensions: the subproblem is a pair of string prefixes, and the table it fills is the one behind every diff you have ever run.

1. Longest common subsequence

LCS is the most deployed DP you will meet this term.

Definition (subsequence, LCS) A subsequence of a string keeps the characters’ relative order but may skip any of them: ACT is a subsequence of AGCAT. The longest common subsequence (LCS) of two strings \(A\) and \(B\) is a longest string that is a subsequence of both. For \(A = \texttt{AGCAT}\), \(B = \texttt{GAC}\): the LCS has length \(2\): AC (or GC, or GA; length is unique, the string need not be).
Subsequence ≠ substring A substring is contiguous (GCA in AGCAT); a subsequence may leave gaps (ACT is not a substring of AGCAT, but is a subsequence). LCS is about subsequences, which is precisely why it tolerates insertions: in a file comparison, lines added in the middle should not break the match around them. Longest common substring is a different problem, also solvable by DP, with a different recurrence.

Brute force (enumerate all \(2^m\) subsequences of \(A\) and test each against \(B\)) is exponential. The DP subproblem is the LCS of two prefixes:

Proposition (LCS recurrence) Let \(L[i][j]\) be the LCS length of the first \(i\) characters of \(A\) and the first \(j\) of \(B\). Then \(L[i][0] = L[0][j] = 0\), and for \(i, j \ge 1\): \[ L[i][j] = \begin{cases} L[i-1][j-1] + 1 & \text{if } A[i{-}1] = B[j{-}1] \quad\text{(match: extend the diagonal)}\\[2pt] \max\bigl(L[i-1][j],\; L[i][j-1]\bigr) & \text{otherwise} \quad\text{(drop one last character)} \end{cases} \]
Why the recurrence is correct. Look at the last characters of the two prefixes. If they match, some LCS of the prefixes ends with that character: an LCS that ends elsewhere can be exchanged, match for match, into one that uses it without getting shorter. Pairing the two last characters therefore costs nothing, and what remains is an LCS of both shorter prefixes: the diagonal cell, plus one. If they mismatch, no common subsequence ends with both of them, so at least one of the two last characters is not in the LCS; drop one, \(A\)’s (the cell above) or \(B\)’s (the cell to the left), and take the better. Every case reduces to a strictly smaller prefix pair, and the empty prefix is the base case: optimal substructure. Overlap is massive (the same prefix pair is reachable along exponentially many drop orders), and caching leaves just \((m{+}1)(n{+}1)\) subproblems at \(O(1)\) each: \(\Theta(mn)\). ∎

The four outcomes, one instance each:
  • match, diagonal \(+\,1\): row C, column C takes \(1 + 1 = 2\), the only cell in the table that reaches \(2\) by a match;
  • mismatch, up wins: row T, column A takes \(\max(2, 1) = 2\) from above, because dropping A’s T keeps a longer match than dropping B’s A;
  • mismatch, left wins: row A (first), column C takes \(\max(0, 1) = 1\) from the left;
  • mismatch, tie: row G, column A takes \(\max(1, 1) = 1\), and either neighbor gives the same value, which is why a traceback may break the tie either way and still be right.
Base cases are the whole of row \(0\) and column \(0\): an empty prefix shares nothing with anything, so those cells are \(0\) without consulting the recurrence at all. Every non-base cell above reads only cells already written, which is what makes row-by-row a legal fill order. 
// LCS table: L[i][j] = LCS length of A's first i chars and B's first j.
// Fill row by row -- up, left, and diagonal are ready when a cell needs them.
// Theta(mn) time and space.
int lcsLength(const string& A, const string& B, vector<vector<int>>& L) {
    int m = A.size(), n = B.size();
    L.assign(m + 1, vector<int>(n + 1, 0)); // row 0 / col 0 = 0: empty prefix
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            if (A[i - 1] == B[j - 1])
                L[i][j] = L[i - 1][j - 1] + 1;             // match: diagonal + 1
            else
                L[i][j] = max(L[i - 1][j], L[i][j - 1]);   // drop one: up / left
    return L[m][n];                         // bottom-right = the answer
}

// Traceback: walk from L[m][n] toward L[0][0]. The matched characters,
// reversed, spell one LCS. O(m + n) steps -- needs the whole table.
string lcsString(const string& A, const string& B,
                 const vector<vector<int>>& L) {
    string out;
    int i = A.size(), j = B.size();
    while (i > 0 && j > 0) {
        if (A[i - 1] == B[j - 1]) {         // match: it's in the LCS
            out += A[i - 1]; i--; j--;      // step diagonally
        }
        else if (L[i - 1][j] >= L[i][j - 1]) i--;   // follow the larger
        else j--;                                   //   of up / left
    }
    reverse(out.begin(), out.end());
    return out;                             // AGCAT / GAC -> "AC"
}

static String lcsString(String A, String B, int[][] L) {
    StringBuilder out = new StringBuilder();
    int i = A.length(), j = B.length();
    while (i > 0 && j > 0) {

# Traceback: walk from L[m][n] toward L[0][0]. The matched characters,
# reversed, spell one LCS. O(m + n) steps -- needs the whole table.
def lcs_string(A, B, L):
    out = []
    i, j = len(A), len(B)
    while i > 0 and j > 0:
        if A[i - 1] == B[j - 1]:            # match: it's in the LCS
            out.append(A[i - 1])            # step diagonally
            i, j = i - 1, j - 1
        elif L[i - 1][j] >= L[i][j - 1]:    # follow the larger
            i -= 1                          #   of up / left
        else:
            j -= 1
    return "".join(reversed(out))           # AGCAT / GAC -> "AC"
// LCS table: L[i][j] = LCS length of A's first i chars and B's first j.
// Fill row by row -- up, left, and diagonal are ready when a cell needs them.
// Theta(mn) time and space.
fn lcs_length(a: &[u8], b: &[u8]) -> Vec<Vec<usize>> {
    let (m, n) = (a.len(), b.len());
    let mut l = vec![vec![0usize; n + 1]; m + 1]; // row 0 / col 0 = empty prefix
    for i in 1..=m {
        for j in 1..=n {
            l[i][j] = if a[i - 1] == b[j - 1] {
                l[i - 1][j - 1] + 1                    // match: diagonal + 1
            } else {
                l[i - 1][j].max(l[i][j - 1])           // drop one: up / left
            };
        }
    }
    l                                       // l[m][n] = the answer
}

// Traceback: walk from L[m][n] toward L[0][0]. The matched characters,
// reversed, spell one LCS. O(m + n) steps -- needs the whole table.
fn lcs_string(a: &[u8], b: &[u8], l: &[Vec<usize>]) -> String {
    let mut out = Vec::new();
    let (mut i, mut j) = (a.len(), b.len());
    while i > 0 && j > 0 {
        if a[i - 1] == b[j - 1] {           // match: it's in the LCS
            out.push(a[i - 1]); i -= 1; j -= 1;   // step diagonally
        } else if l[i - 1][j] >= l[i][j - 1] {
            i -= 1;                         // follow the larger of up / left
        } else {
            j -= 1;
        }
    }
    out.reverse();
    String::from_utf8(out).unwrap()         // AGCAT / GAC -> "AC"
}

Walk the traceback on the worked table to see it recover AC: start at \(L[5][3] = 2\). T vs C mismatch, up and left tie at \(2\), follow up; A vs C mismatch, up again; row C vs column C match: emit C, step diagonally; G vs A mismatch, up; row A vs column A match: emit A, step diagonally to row \(0\), stop. Emitted C, A; reversed: AC. Where the traceback breaks a tie differently, it finds a different, equally valid, LCS of the same length. This particular walk happens never to step left: on this instance every mismatch it meets either ties (and the code’s \(\ge\) test sends it up) or has a strictly larger cell above. Exercise 1 below contains the missing branch, a mismatch at \((2,2)\) where up holds \(0\) and left holds \(1\), so the walk moves left; the Traceback & Space-Saving handout treats the walk in general.

A built-in bug detector The LCS table has structure you can check at a glance, and a hand-filled (or coded) table that violates it is wrong somewhere:
  • values never decrease going right or down: a longer prefix can only keep or grow the LCS;
  • adjacent cells differ by at most \(1\): adding one character adds at most one match;
  • the bottom-right cell is a maximum of the whole table.
A value that drops, or jumps by \(2\), pinpoints a recurrence or indexing bug to within a cell; check these invariants on a small example before trusting any LCS code (exercise 2 practices exactly this).

Cost, by the DP cost formula: \((m+1)(n+1)\) cells at \(O(1)\) each, \(\Theta(mn)\) time and space. Since each row depends only on the row above and the current row’s left neighbor, the space can drop to two rows, \(\Theta(\min(m,n))\) with the shorter string as columns, but the two-row version can report only the length: the traceback needs the whole table. Decide up front which your application needs (the DP recipe, step 5).

LCS in the wild The same \(\Theta(mn)\) table powers diff and git diff (LCS of lines: unmatched lines are the insertions and deletions shown), merge tools and plagiarism detectors, and, at industrial scale, DNA and protein sequence alignment, where LCS-style tables measure evolutionary similarity. Its close cousin edit distance, the minimum number of single-character edits between two strings, fills an almost identical table and drives spell-checking; it is treated in the Edit Distance handout.

Interactive The LCS subproblem tree is the recursion this table is an optimization of, and it answers the question the table cannot: why \(\Theta(mn)\) is available at all. A node is a prefix pair \((i,j)\); an edge is the move: ↖ on a match (worth \(+1\), and only ONE child follows), ↑ or ← on a mismatch, which is the two-way branch that makes the tree grow exponentially. Run Naive then Memoized: the same walk in the same order, differing only in the cache. On AGCAT / GAC that is \(27\) nodes against \(19\) visited over \(16\) distinct pairs, and the bound is the point, since there are never more than \((m{+}1)(n{+}1) = 24\) distinct pairs however wildly the tree branches. A pair is a cell of the table. The green chain is the traceback, and its ↖ edges spell AC.

2. Exercises (with solutions)

  1. Fill the complete LCS table for \(A = \texttt{ABCB}\) (rows), \(B = \texttt{BDCB}\) (columns). Give the LCS length and recover one LCS by traceback.
    solution Length \(L[4][4] = 3\). Traceback from the corner: B/B match: emit B, go diagonal to \((3,3)\); C/C match: emit C, diagonal to \((2,2)\), which is row B, column D: mismatch, and up (\(L[1][2] = 0\)) loses to left (\(L[2][1] = 1\)), so go left to \((2,1)\); B/B match: emit B, diagonal to \((1,0)\), column \(0\): stop. Emitted B, C, B; reversed: BCB, which is indeed a subsequence of both strings.
  2. A student fills the LCS table for \(A = \texttt{CAB}\), \(B = \texttt{ACB}\) and gets the table below. Using only the sanity invariants of §1 (no re-derivation), point out two cells that cannot be right, then give the correct table.
    solution Row A, column C holds \(0\) but the cell above it holds \(1\): values may never decrease going down. And the corner holds \(3\) while its up and left neighbors hold \(1\): adjacent cells may differ by at most \(1\). Correct table: LCS length \(2\); the traceback yields CB (or AB; both are common subsequences of length \(2\)).
