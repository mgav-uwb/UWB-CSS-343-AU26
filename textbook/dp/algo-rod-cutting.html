Rod Cutting

Data Structures & Algorithms. Algorithm (dynamic programming).
Rod cutting, the first full optimization DP: a maximization over every first cut, the recurrence and its optimal-substructure proof, the worked \(\Theta(n^2)\) table for the running instance (prices \(1, 5, 8, 9\), optimum \(10\) by cutting \(2 + 2\)), the cut[] record and the traceback that reads the cuts off it, and complete code in four languages. The method itself (memoization, tabulation, and the design recipe) is the Dynamic Programming Method handout. With demos and exercises.

Dynamic programming solves a problem by trying every choice and caching the overlapping subproblems; the method, its two implementations, and its five-step recipe are the Dynamic Programming Method handout. Rod cutting is the recipe’s first optimization problem: no single first cut is provably safe, so every one must be tried, and the subproblems those trials generate overlap.

1. Rod cutting: optimizing over choices

Fibonacci (the Dynamic Programming Method handout) has overlap but nothing to optimize. Rod cutting adds the missing ingredient, a choice at every step, and with it the full shape of an optimization DP.

Problem (rod cutting) Given a rod of integer length \(n\) and a price list where a piece of length \(i\) sells for \(\mathrm{price}[i]\), cut the rod into pieces (zero or more cuts) to maximize the total selling price.
Example (the running instance) Lengths \(1\)–\(4\) priced \(1, 5, 8, 9\), rod length \(n = 4\). Selling the rod whole earns \(9\); cutting \(3 + 1\) earns \(8 + 1 = 9\); but cutting into two length-\(2\) pieces earns \(5 + 5 = 10\): the optimum, and nothing about the raw prices announces it.

A greedy attempt fails, exactly in the Greedy Method handout’s sense of a counterexample. The natural greedy rule (cut the piece with the best price per unit length first) computes the ratios \(1/1 = 1.0\), \(5/2 = 2.5\), \(8/3 \approx 2.67\), \(9/4 = 2.25\), grabs the length-\(3\) piece, and is left with a length-\(1\) remainder: total \(8 + 1 = 9 < 10\). The locally best ratio is not globally best because taking it constrains what is left. Since the best first cut cannot be identified without solving the rest of the rod, every first cut must be tried, and the subproblems those trials generate overlap, which is DP’s cue.

Proposition (rod-cutting recurrence) Let \(\mathrm{best}(\ell)\) be the maximum revenue for a rod of length \(\ell\). Then \(\mathrm{best}(0) = 0\) and, for \(\ell \ge 1\), \[ \mathrm{best}(\ell) \;=\; \max_{1 \le i \le \ell} \bigl(\mathrm{price}[i] + \mathrm{best}(\ell - i)\bigr). \]
Why this is correct (optimal substructure). Any optimal cutting of a length-\(\ell\) rod has some first piece, of some length \(i\); the rest of that solution cuts the remaining \(\ell - i\). If that remainder were cut suboptimally, replacing it with an optimal cutting of length \(\ell - i\) would raise the total, contradicting optimality. So the optimum equals \(\mathrm{price}[i] + \mathrm{best}(\ell - i)\) for its own first piece \(i\), and taking the max over all \(i\) can only find it. The subproblems overlap because \(\mathrm{best}(k)\) is needed along many different first-cut paths; without a cache the recursion is \(\Theta(2^n)\), with one it is \(n\) subproblems at \(O(n)\) each: \(\Theta(n^2)\). ∎

One new concern appears that Fibonacci never raised: the table stores the optimal value, but we usually want the cuts. The fix is two lines: record, at each length, which first cut won the max, then walk the records backwards. Every optimization DP does this. 

// Rod cutting, tabulated: best[len] = max over first cuts i of
// price[i] + best[len-i], recording the winning i in cut[len] for the
// traceback. n subproblems x O(n) choices each = Theta(n^2) time, Theta(n) space.
int rodCut(const vector<int>& price, int n, vector<int>& cut) {
    vector<int> best(n + 1, 0);           // base case: best[0] = 0 (empty rod)
    cut.assign(n + 1, 0);
    for (int len = 1; len <= n; len++) {
        int m = -1;
        for (int i = 1; i <= len; i++)    // try every first cut
            if (price[i] + best[len - i] > m) {
                m = price[i] + best[len - i];
                cut[len] = i;             // remember the choice that won
            }
        best[len] = m;                    // reuses smaller best[] -- the overlap
    }
    return best[n];
}

// Traceback: repeatedly take the recorded first cut until nothing is left.
vector<int> pieces(const vector<int>& cut, int n) {
    vector<int> out;
    while (n > 0) {
        out.push_back(cut[n]);            // the winning first cut at length n
        n -= cut[n];                      // cut it off, continue on the rest
    }
    return out;                           // prices 1,5,8,9 at n=4: {2, 2}
}

def rod_cut(price, n):                    # price[1..n]; price[0] unused

// Rod cutting, tabulated: best[len] = max over first cuts i of
// price[i] + best[len-i], recording the winning i in cut[len] for the
// traceback. n subproblems x O(n) choices each = Theta(n^2) time, Theta(n) space.
fn rod_cut(price: &[i32], n: usize) -> (i32, Vec<usize>) {
    let mut best = vec![0i32; n + 1];     // base case: best[0] = 0 (empty rod)
    let mut cut = vec![0usize; n + 1];
    for len in 1..=n {
        let mut m = -1;
        for i in 1..=len {                // try every first cut
            if price[i] + best[len - i] > m {
                m = price[i] + best[len - i];
                cut[len] = i;             // remember the choice that won
            }
        }
        best[len] = m;                    // reuses smaller best[] -- the overlap
    }
    (best[n], cut)
}

// Traceback: repeatedly take the recorded first cut until nothing is left.
fn pieces(cut: &[usize], mut n: usize) -> Vec<usize> {
    let mut out = Vec::new();
    while n > 0 {
        out.push(cut[n]);                 // the winning first cut at length n
        n -= cut[n];                      // cut it off, continue on the rest
    }
    out                                   // prices 1,5,8,9 at n=4: [2, 2]
}

Notice \(\mathrm{best}[4]\) reuses \(\mathrm{best}[3]\), \(\mathrm{best}[2]\), \(\mathrm{best}[1]\), the very cells \(\mathrm{best}[3]\) also used. That sharing is the overlap; without the table, \(\mathrm{best}[2]\) would be recomputed along every first-cut path, exactly like naive Fibonacci’s \(\mathrm{fib}(2)\). The traceback then reads the cuts off the last column: \(\mathrm{cut}[4] = 2\), so take a length-\(2\) piece, leaving length \(2\); \(\mathrm{cut}[2] = 2\), take another, leaving \(0\). Cuts: \(2 + 2\), value \(10\).

Both branches of the if appear here: two candidates improve the running maximum and rewrite \(\mathrm{cut}[4]\), two do not and leave both alone. The scan at \(len = 3\) adds the third possibility, a candidate that equals the running maximum: \(i = 1\) sets \(m = 1 + 5 = 6\), \(i = 2\) offers \(5 + 1 = 6\), and because the test is strict the tie is rejected and \(\mathrm{cut}[3]\) stays \(1\) until \(i = 3\) wins outright at \(8\).
Example (the two extremes: cut everywhere, cut nowhere) The winning first cut can be any \(i\) from \(1\) to \(len\), and the two endpoints are worth seeing on their own instances. Both are the same code on the same recurrence; only the price list changed.

Traceback, one step: \(\mathrm{cut}[4] = 4\) takes the whole rod and leaves \(0\). Pieces \(\{4\}\), value \(10\), zero cuts. Lengths \(1\)–\(3\) meanwhile record \(\mathrm{cut} = 1\) on a three-way tie, which costs nothing: those cells are never reached by this traceback, and their values are correct in any case.

Ties are fine At length \(3\), the candidates \(1 + 5\) and \(5 + 1\) tie at \(6\) before \(8\) wins outright; in other instances the max itself ties, and then several different cut lists achieve the same optimal value. The DP is unbothered: it returns one optimal solution, whichever choice it recorded first. When an exercise asks for “the” cuts, any optimal set is correct unless a tie-breaking rule is stated; when writing such an exercise, state one.

2. Exercises (with solutions)

  1. Rod cutting with prices \(2, 5, 7, 8\) for lengths \(1\)–\(4\): fill \(\mathrm{best}[1..4]\), showing every candidate, and give an optimal set of cuts.
    solution \(\mathrm{best}[1] = 2 + 0 = 2\). \(\mathrm{best}[2] = \max(2 + 2,\; 5 + 0) = 5\) (whole piece). \(\mathrm{best}[3] = \max(2 + 5,\; 5 + 2,\; 7 + 0) = 7\), a three-way tie, so a \(1{+}2\) split and the whole piece are all optimal. \(\mathrm{best}[4] = \max(2 + 7,\; 5 + 5,\; 7 + 2,\; 8 + 0) = \max(9, 10, 9, 8) = 10\), achieved only by \(5 + 5\): two length-\(2\) pieces, value \(10\). (Note the whole-rod price \(8\) is again not optimal, the same shape as the running instance.)
  2. Extend the running instance with \(\mathrm{price}[5] = 10\) (so prices \(1, 5, 8, 9, 10\)) and a rod of length \(5\). Compute \(\mathrm{best}[5]\), the recorded \(\mathrm{cut}[5]\), and run the traceback.
    solution The smaller cells are unchanged: \(\mathrm{best}[0..4] = 0, 1, 5, 8, 10\). Candidates for length \(5\): \(1 + \mathrm{best}[4] = 11\); \(5 + \mathrm{best}[3] = 13\); \(8 + \mathrm{best}[2] = 13\); \(9 + \mathrm{best}[1] = 10\); \(10 + \mathrm{best}[0] = 10\). So \(\mathrm{best}[5] = 13\). Both \(i = 2\) and \(i = 3\) achieve it; the code as written keeps the first winner, \(\mathrm{cut}[5] = 2\). Traceback: take \(2\) (remainder \(3\)), then \(\mathrm{cut}[3] = 3\), take \(3\) (remainder \(0\)): pieces \(\{2, 3\}\), value \(5 + 8 = 13\). The tie is harmless: \(i = 3\) first leads to the same \(\{3, 2\}\) multiset.
