Matrix-Chain Multiplication

Data Structures & Algorithms. Algorithm (dynamic programming).
Matrix-chain multiplication, the canonical interval dynamic program: why associativity fixes the product but not its price, the last-decision derivation of the subproblem (the outermost split \(k\)), the recurrence with its optimal-substructure proof, the \(m\) and \(s\) tables filled diagonal by diagonal for \(p = (5, 4, 6, 2, 7)\) with every candidate’s arithmetic shown, the traceback that rebuilds \(((A_1(A_2A_3))A_4)\), the \(\Theta(n^3)\) time and \(\Theta(n^2)\) space counted rather than asserted, and code in four languages. The method itself is the Dynamic Programming Method handout; the shape is catalogued in DP Patterns. With exercises.

Matrix multiplication is associative: \((AB)C\) and \(A(BC)\) are the same matrix, entry for entry. It is not, however, equally priced: the two orders can differ by a factor of six on three small matrices, and by unbounded factors on longer chains. Choosing the cheapest bracketing is an optimization over a number of candidates that grows exponentially, and it is solved by a dynamic program whose state is a range of the chain. That state shape is called interval dynamic programming (DP), and this problem is its canonical instance.

1. The cost of a parenthesization

Fix the unit of work first. The standard triple-loop algorithm computes each of the \(p \cdot r\) output entries as a dot product of length \(q\), so it performs \(p\,q\,r\) scalar multiplications.

Definition (cost of one multiply) Multiplying a \(p \times q\) matrix by a \(q \times r\) matrix costs \(p\,q\,r\) scalar multiplications and produces a \(p \times r\) matrix. The inner dimensions must agree; the outer dimensions of the result are inherited from the operands.

Now chain them. A chain \(A_1 A_2 \cdots A_n\) is described entirely by one dimension vector \(p = (p_0, p_1, \ldots, p_n)\), with \(A_i\) of shape \(p_{i-1} \times p_i\). Because a bracketing only reorders which products are formed, never which matrices are adjacent, every intermediate result \(A_i \cdots A_j\) has shape \(p_{i-1} \times p_j\) no matter how it was bracketed. That is the fact the whole dynamic program rests on: the shape of a range does not depend on how the range is parenthesized, only its price does.

Example (three matrices, two orders) \(A\ (10{\times}30)\), \(B\ (30{\times}5)\), \(C\ (5{\times}60)\). 
  (AB)C :  AB costs 10·30·5 = 1500, giving 10×5;  (AB)C costs 10·5·60  =  3000
           total  1500 +  3000 =   4,500

  A(BC) :  BC costs 30·5·60 = 9000, giving 30×60; A(BC) costs 10·30·60 = 18000
           total  9000 + 18000 =  27,000      6× worse
Both compute the same \(10 \times 60\) matrix. The difference is that \((AB)C\) squeezes the chain down to \(10 \times 5\) before touching the wide \(C\), while \(A(BC)\) first inflates the middle to \(30 \times 60\) and then pays for that width twice.

With four matrices there are five bracketings, and their prices spread further.

The best order costs \(158\) and the worst \(414\), a factor of \(2.6\) with no matrix larger than \(6 \times 7\). Nothing in the raw dimension list announces the winner: the cheapest bracketing is neither strictly left-to-right nor strictly right-to-left nor the balanced split, and the balanced split is the worst of the five.

Problem (matrix-chain multiplication) Given a dimension vector \(p = (p_0, \ldots, p_n)\) describing a chain \(A_1 \cdots A_n\), find a full parenthesization of the product minimizing the total number of scalar multiplications. The output is the bracketing, not the product: no matrix entries are ever touched.
Why not enumerate The number of full parenthesizations of \(n\) matrices is the Catalan number \(P(n) = C_{n-1} = \frac{1}{n}\binom{2n-2}{n-1}\), because choosing the outermost split at \(k\) and recursing gives \(P(n) = \sum_{k=1}^{n-1} P(k)\,P(n-k)\), the Catalan recurrence, with \(P(1) = 1\). That is \(1, 1, 2, 5, 14, 42, 132, 429, 1430, 4862, 16796\) for \(n = 1, \ldots, 11\), and it grows like \(\Theta(4^n / n^{3/2})\). Enumerating is hopeless past a chain of a couple of dozen; the same recurrence, read as a DP instead of a count, solves the problem in \(\Theta(n^3)\).

2. Finding the subproblem: the outermost split

Do not start by guessing a table. Start from the Dynamic Programming Method handout’s first question: what is the last decision the algorithm makes, and what is left to decide once it is fixed?

A full parenthesization of \(A_1 \cdots A_n\) is a tree, and its root is one multiplication: the final one, which combines the product of some prefix with the product of the matching suffix. So there is an index \(k\), with \(1 \le k < n\), such that the last multiply is \[ (A_1 \cdots A_k) \times (A_{k+1} \cdots A_n). \] Fixing \(k\) is the last decision. Once it is fixed, two independent questions remain: how to bracket \(A_1 \cdots A_k\), and how to bracket \(A_{k+1} \cdots A_n\). Neither can influence the other, because the shape of each side is already determined (\(p_0 \times p_k\) and \(p_k \times p_n\)), so the price of the final multiply, \(p_0\,p_k\,p_n\), is fixed by \(k\) alone.

Those two remaining questions are the same problem on a contiguous range of the chain. That is the subproblem, and it forces the state.

State \(m[i][j]\) = the minimum number of scalar multiplications needed to compute \(A_i A_{i+1} \cdots A_j\), for \(1 \le i \le j \le n\). The answer to the whole problem is \(m[1][n]\).

Note what the state is not. It is not indexed by a prefix length, as in Rod Cutting, and not by a pair of positions in two different inputs, as in Longest Common Subsequence. Both indices point into the same sequence and together name a window of it. A DP whose state is a range, and whose transition chooses where to split that range, is an interval DP.

Proposition (matrix-chain recurrence) With \(A_i\) of shape \(p_{i-1} \times p_i\), \[ m[i][j] \;=\; \begin{cases} 0, & i = j, \\[4pt] \displaystyle\min_{i \le k < j} \bigl(m[i][k] + m[k+1][j] + p_{i-1}\,p_k\,p_j\bigr), & i < j. \end{cases} \]
Why this is correct (optimal substructure). A single matrix requires no multiplication, so \(m[i][i] = 0\). For \(i < j\), consider any optimal parenthesization \(P\) of \(A_i \cdots A_j\) and let \(k\) be its outermost split, so \(P\) consists of a parenthesization \(P_L\) of \(A_i \cdots A_k\), a parenthesization \(P_R\) of \(A_{k+1} \cdots A_j\), and one final multiply. The operands of that final multiply have shapes \(p_{i-1} \times p_k\) and \(p_k \times p_j\) regardless of \(P_L\) and \(P_R\), so its price is exactly \(p_{i-1}\,p_k\,p_j\) and \(\mathrm{cost}(P) = \mathrm{cost}(P_L) + \mathrm{cost}(P_R) + p_{i-1}\,p_k\,p_j\). Now suppose \(P_L\) were not optimal for \(A_i \cdots A_k\). Replacing it by an optimal \(P_L'\) yields a valid parenthesization of \(A_i \cdots A_j\) with the same \(k\) and the same final price, hence strictly smaller total: contradiction. The same argument applies to \(P_R\). So \(\mathrm{cost}(P) = m[i][k] + m[k+1][j] + p_{i-1}\,p_k\,p_j\) for its own \(k\), which is one of the terms the minimum ranges over; the minimum is therefore \(\le m[i][j]\). Conversely each term of the minimum is achievable (glue optimal bracketings of the two halves and multiply), so no term is smaller than \(m[i][j]\). The two inequalities give equality. ∎

Independence of the halves, given \(k\), is the whole content of that proof: swapping in a cheaper bracketing of the left half changes neither the shape of the left operand nor anything the right half does. The subproblems also overlap, the second DP prerequisite: the range \(A_2 A_3\) is needed by the \(k = 1\) candidate of \(A_1 A_2 A_3\), by the \(k = 3\) candidate of \(A_2 A_3 A_4\), and again through both of those inside \(A_1 \cdots A_4\). In general \([i, j]\) is a subproblem of every wider range containing it, which is why a plain recursion revisits it Catalan-many times while the table computes it once.

Fill order \(m[i][j]\) reads \(m[i][k]\) and \(m[k+1][j]\), both of which describe strictly shorter ranges (\(k - i + 1 < j - i + 1\) and \(j - k < j - i + 1\)). So the table must be filled in order of increasing range length \(L = j - i + 1\): all ranges of length \(1\) (the base cases), then \(2\), then \(3\), and so on. On the square \(m\) table these are the diagonals above the main diagonal, filled outward.

3. The algorithm

Three pieces: the \(\Theta(n^2)\)-cell table \(m\), the parallel table \(s\) recording which \(k\) won each cell, and a recursive printer that turns \(s\) into a bracketing. 

// Matrix-chain order. p has n+1 entries; A_i is p[i-1] x p[i], i = 1..n.
// m[i][j] = min scalar multiplications for A_i..A_j; s[i][j] = winning split.
// Theta(n^3) time, Theta(n^2) space.
int matrixChain(const vector<int>& p,
                vector<vector<int>>& m, vector<vector<int>>& s) {
    int n = (int)p.size() - 1;
    m.assign(n + 2, vector<int>(n + 2, 0));   // base case: m[i][i] = 0
    s.assign(n + 2, vector<int>(n + 2, 0));
    for (int L = 2; L <= n; L++)              // range length, shortest first
        for (int i = 1; i + L - 1 <= n; i++) {
            int j = i + L - 1;
            m[i][j] = INT_MAX;
            for (int k = i; k < j; k++) {     // every outermost split
                int c = m[i][k] + m[k + 1][j] + p[i - 1] * p[k] * p[j];
                if (c < m[i][j]) { m[i][j] = c; s[i][j] = k; }
            }
        }
    return m[1][n];
}

// Traceback: s[i][j] names the last multiply of the range, so recurse on both
// halves and wrap. Theta(n) calls, one per node of the parse tree.
string parens(const vector<vector<int>>& s, int i, int j) {
    if (i == j) return "A" + to_string(i);
    int k = s[i][j];
    return "(" + parens(s, i, k) + parens(s, k + 1, j) + ")";
}

# Matrix-chain order. p has n+1 entries; A_i is p[i-1] x p[i], i = 1..n.
# m[i][j] = min scalar multiplications for A_i..A_j; s[i][j] = winning split.
# Theta(n^3) time, Theta(n^2) space.
def matrix_chain(p):
    n = len(p) - 1
    m = [[0] * (n + 2) for _ in range(n + 2)]     # base case: m[i][i] = 0
    s = [[0] * (n + 2) for _ in range(n + 2)]
    for L in range(2, n + 1):                     # range length, shortest first
        for i in range(1, n - L + 2):
            j = i + L - 1
            m[i][j] = float("inf")
            for k in range(i, j):                 # every outermost split
                c = m[i][k] + m[k + 1][j] + p[i - 1] * p[k] * p[j]
                if c < m[i][j]:
                    m[i][j], s[i][j] = c, k
    return m[1][n], m, s

# Traceback: s[i][j] names the last multiply of the range, so recurse on both
# halves and wrap. Theta(n) calls, one per node of the parse tree.
def parens(s, i, j):
    if i == j:
        return "A%d" % i
    k = s[i][j]
    return "(" + parens(s, i, k) + parens(s, k + 1, j) + ")"

// Matrix-chain order. p has n+1 entries; A_i is p[i-1] x p[i], i = 1..n.
// m[i][j] = min scalar multiplications for A_i..A_j; s[i][j] = winning split.
// Theta(n^3) time, Theta(n^2) space.
fn matrix_chain(p: &[usize]) -> (usize, Vec<Vec<usize>>, Vec<Vec<usize>>) {
    let n = p.len() - 1;
    let mut m = vec![vec![0usize; n + 2]; n + 2];   // base case: m[i][i] = 0
    let mut s = vec![vec![0usize; n + 2]; n + 2];
    for len in 2..=n {                              // range length, shortest first
        for i in 1..=(n - len + 1) {
            let j = i + len - 1;
            m[i][j] = usize::MAX;
            for k in i..j {                         // every outermost split
                let c = m[i][k] + m[k + 1][j] + p[i - 1] * p[k] * p[j];
                if c < m[i][j] { m[i][j] = c; s[i][j] = k; }
            }
        }
    }
    (m[1][n], m, s)
}

// Traceback: s[i][j] names the last multiply of the range, so recurse on both
// halves and wrap. Theta(n) calls, one per node of the parse tree.
fn parens(s: &[Vec<usize>], i: usize, j: usize) -> String {
    if i == j { return format!("A{}", i); }
    let k = s[i][j];
    format!("({}{})", parens(s, i, k), parens(s, k + 1, j))
}
// p = [5,4,6,2,7]:  matrix_chain -> 158,  parens(&s,1,4) -> "((A1(A2A3))A4)"

Three index conventions to keep straight The dimension vector is \(0\)-based while the matrices are \(1\)-based; the outer loop variable is the range length, not an endpoint; and the split \(k\) belongs to the left half, so the halves are \([i, k]\) and \([k+1, j]\), never \([i, k-1]\) and \([k, j]\). A quick check on the price \(p_{i-1} p_k p_j\): it uses the rows of \(A_i\), the columns of \(A_k\) (the shared inner dimension), and the columns of \(A_j\).

4. The table, filled diagonal by diagonal

The running instance again: \(p = (5, 4, 6, 2, 7)\), so \(n = 4\) and the matrices are \(A_1\ (5{\times}4)\), \(A_2\ (4{\times}6)\), \(A_3\ (6{\times}2)\), \(A_4\ (2{\times}7)\). Only the upper triangle \(i \le j\) is used.

Ties When two splits achieve the same minimum the code as written keeps the first, because the update is a strict <. Several bracketings then have equal cost and any is correct. Where an exercise asks for “the” parenthesization, either the instance has a unique optimum or a tie-breaking rule is stated. The running instance has no ties: its five bracketings cost \(158, 244, 250, 392, 414\), all distinct.

Only \(s\) is needed for the traceback, and it is the same record-the-winning-choice device used elsewhere in this catalog: the cut[] array of Rod Cutting, the arrow table of Longest Common Subsequence, treated in general in Traceback and Space Saving. One difference matters: those tracebacks are loops walking a single path back through the table, while this one is a recursion that branches, because the solution is a tree rather than a sequence. It visits \(2n - 1\) nodes (\(n\) leaves and \(n-1\) internal splits), so it is \(\Theta(n)\).

6. Cost: \(\Theta(n^3)\) time, \(\Theta(n^2)\) space

Count the innermost operation, one candidate evaluation, which is a constant number of array reads, two additions, two multiplications and a comparison. The loops enumerate every triple \((i, j, k)\) with \(1 \le i \le k < j \le n\). A range of length \(L\) has \(L - 1\) splits, and there are \(n - L + 1\) ranges of length \(L\), so the total is \[ T(n) \;=\; \sum_{L=2}^{n} (n - L + 1)(L - 1) \;=\; \sum_{d=1}^{n-1} (n - d)\,d \;=\; n\!\cdot\!\frac{(n-1)n}{2} - \frac{(n-1)n(2n-1)}{6} \;=\; \frac{n^3 - n}{6}, \] substituting \(d = L - 1\). Equivalently \(T(n) = \binom{n+1}{3}\), the number of ways to choose the triple. Checks: \(T(4) = (64 - 4)/6 = 10\), exactly the ten candidates counted in §4, and \(T(5) = (125-5)/6 = 20\), which is the count for the five-matrix chain of exercise 3.

Since \(\frac{n^3-n}{6}\) is bounded above by \(\frac{n^3}{6}\) and below by \(\frac{n^3}{12}\) for \(n \ge 2\), it is \(\Theta(n^3)\) by the definition in Asymptotic Notation. This is a tight bound, not an upper bound: the loops have no early exit, so every instance of size \(n\) evaluates exactly \((n^3-n)/6\) candidates. The traceback adds \(\Theta(n)\), which disappears into the \(\Theta(n^3)\).

Space: two \((n+1) \times (n+1)\) tables, of which only the upper triangles (\(\binom{n+1}{2}\) cells each) are ever read, so \(\Theta(n^2)\) either way. Unlike Longest Common Subsequence, where the value table can be reduced to two rows, there is no useful row-by-row compression here: the cell \(m[i][j]\) reads \(m[i][k]\) along its own row and \(m[k+1][j]\) down its own column, so an entire triangle is live at once. And \(s\) cannot be dropped without losing the answer, since the bracketing is the deliverable.

Two comparisons Against enumeration: at \(n = 20\) there are \(C_{19} = 1{,}767{,}263{,}190\) parenthesizations, against \((8000-20)/6 = 1330\) candidate evaluations for the DP. Against the work being planned: a single multiply in the chain typically costs far more than \(n^3\) arithmetic for realistic dimensions, so planning the order is cheap relative to executing it, which is why libraries and query planners do it. The recurrence can also be run as a memoized recursion, in the Dynamic Programming Method handout’s top-down style: identical bounds, no need to reason out the diagonal fill order, at the price of \(\Theta(n)\) stack depth. Bottom-up is preferred here because every cell of the triangle is needed anyway, so skipping unreachable subproblems buys nothing.

7. Where this sits

Matrix-chain multiplication is the canonical interval DP: the state is a contiguous range \([i, j]\), the transition minimizes over a split point \(k\) strictly inside it, the fill order is by increasing range length, and the cost is \(\Theta(n^3)\) from \(\Theta(n^2)\) ranges times \(\Theta(n)\) splits. That template, and its place beside the one-dimensional and grid shapes, is DP Patterns: Grid, Interval, Coin Change & LIS; the five-step recipe the derivation in §2 followed (state, transition, base cases, order, answer) is The Dynamic Programming Method.

Reading it against the other dynamic programs in the catalog sharpens what is specific to intervals. Rod Cutting optimizes over a first cut with a one-dimensional state and \(\Theta(n^2)\) work; Longest Common Subsequence, Edit Distance and 0/1 Knapsack use two-dimensional states with a constant number of predecessors per cell, hence \(\Theta(mn)\). Only the interval shape has a variable-size minimum inside the cell, and that inner loop is where the extra factor of \(n\) comes from.

The same template solves the optimal binary search tree problem: given keys with access frequencies, \(m[i][j]\) is the least expected search cost of a binary search tree (BST) over keys \(i..j\) and the split is which key becomes the root, with \(\sum_{k=i}^{j} \mathrm{freq}(k)\) added because installing any root pushes every key of the range one level deeper. That is the reason a height-balanced tree, as in Trees & Binary Search Trees and AVL Trees, is not optimal under skewed access frequencies. Optimal polygon triangulation is another member of the family.

The contrast with The Greedy Method closes the case for DP here. The plausible greedy rule (repeatedly perform the cheapest currently available adjacent multiply) is wrong, with a counterexample in exercise 2, because performing a cheap multiply can leave behind an unfavourable shape. No exchange argument goes through, so every split must be tried.

8. Exercises (with solutions)

  1. Fill both tables completely for \(p = (2, 3, 6, 4, 5)\), showing every candidate on every diagonal, and give the parenthesization and its verified cost.
    solution \(A_1\ (2{\times}3)\), \(A_2\ (3{\times}6)\), \(A_3\ (6{\times}4)\), \(A_4\ (4{\times}5)\).
    \(L = 2\): \(m[1][2] = 2{\cdot}3{\cdot}6 = 36\ (s{=}1)\); \(m[2][3] = 3{\cdot}6{\cdot}4 = 72\ (s{=}2)\); \(m[3][4] = 6{\cdot}4{\cdot}5 = 120\ (s{=}3)\).
    \(L = 3\): \(m[1][3] = \min(k{=}1: 0 + 72 + 2{\cdot}3{\cdot}4 = 96,\; k{=}2: 36 + 0 + 2{\cdot}6{\cdot}4 = 84) = 84\), \(s[1][3] = 2\); \(m[2][4] = \min(k{=}2: 0 + 120 + 3{\cdot}6{\cdot}5 = 210,\; k{=}3: 72 + 0 + 3{\cdot}4{\cdot}5 = 132) = 132\), \(s[2][4] = 3\).
    \(L = 4\): \(m[1][4] = \min(k{=}1: 0 + 132 + 2{\cdot}3{\cdot}5 = 162,\; k{=}2: 36 + 120 + 2{\cdot}6{\cdot}5 = 216,\; k{=}3: 84 + 0 + 2{\cdot}4{\cdot}5 = 124) = 124\), \(s[1][4] = 3\).
    Traceback: \(s[1][4] = 3\) gives \(([1,3])(A_4)\); \(s[1][3] = 2\) gives \(([1,2])(A_3)\); \(s[1][2] = 1\) gives \(A_1A_2\). Result \((((A_1A_2)A_3)A_4)\), the fully left-associated order. Check: \(2{\cdot}3{\cdot}6 + 2{\cdot}6{\cdot}4 + 2{\cdot}4{\cdot}5 = 36 + 48 + 40 = 124\). Note this instance has the small dimension at the left end, so keeping the running product only \(2\) rows tall beats every alternative.
  2. Consider the greedy rule “repeatedly perform the cheapest currently available adjacent multiply.” Run it on \(p = (6, 1, 8, 7, 5)\), then run the DP on the same instance, and state where the greedy argument breaks.
    solution \(A_1\ (6{\times}1)\), \(A_2\ (1{\times}8)\), \(A_3\ (8{\times}7)\), \(A_4\ (7{\times}5)\). Greedy: the three available multiplies cost \(6{\cdot}1{\cdot}8 = 48\), \(1{\cdot}8{\cdot}7 = 56\) and \(8{\cdot}7{\cdot}5 = 280\), so it takes \(A_1A_2\) for \(48\), leaving a \(6 \times 8\) block. Now the choices are \(6{\cdot}8{\cdot}7 = 336\) and \(8{\cdot}7{\cdot}5 = 280\); it takes \(A_3A_4\) for \(280\), leaving \(6{\times}8\) times \(8{\times}5\), which costs \(6{\cdot}8{\cdot}5 = 240\). Greedy total: \(48 + 280 + 240 = 568\).
    DP. \(L = 2\): \(m[1][2] = 48\), \(m[2][3] = 56\), \(m[3][4] = 280\). \(L = 3\): \(m[1][3] = \min(0 + 56 + 6{\cdot}1{\cdot}7 = 98,\; 48 + 0 + 6{\cdot}8{\cdot}7 = 384) = 98\) at \(k = 1\); \(m[2][4] = \min(0 + 280 + 1{\cdot}8{\cdot}5 = 320,\; 56 + 0 + 1{\cdot}7{\cdot}5 = 91) = 91\) at \(k = 3\). \(L = 4\): \(m[1][4] = \min(k{=}1: 0 + 91 + 6{\cdot}1{\cdot}5 = 121,\; k{=}2: 48 + 280 + 6{\cdot}8{\cdot}5 = 568,\; k{=}3: 98 + 0 + 6{\cdot}7{\cdot}5 = 308) = 121\) at \(k = 1\), giving \((A_1((A_2A_3)A_4))\), cost \(1{\cdot}8{\cdot}7 + 1{\cdot}7{\cdot}5 + 6{\cdot}1{\cdot}5 = 56 + 35 + 30 = 121\).
    Greedy is \(568\) against the optimum \(121\), off by a factor of \(4.7\), and note that the greedy answer is precisely the \(k = 2\) candidate the DP rejects. The break: a cheap multiply is not a safe one, because its result shape constrains everything after it. Consuming \(A_1A_2\) destroys the \(1\), the one small inner dimension in the chain, and every later multiply then pays \(6\) or \(8\) where it could have paid \(1\). There is no exchange argument turning an optimal solution into the greedy one, which is the test in The Greedy Method.
  3. Extend the running instance with \(A_5\ (7{\times}3)\), so \(p = (5, 4, 6, 2, 7, 3)\). Which previously computed cells can be reused unchanged? Compute the new cells and the new optimum, and confirm the candidate count against §6.
    solution Every cell \(m[i][j]\) with \(j \le 4\) is unchanged, because the recurrence for a range reads only \(p_{i-1}, \ldots, p_j\) and cells inside that range; appending a matrix cannot affect them. So \(m[1][2] = 120\), \(m[2][3] = 48\), \(m[3][4] = 84\), \(m[1][3] = 88\), \(m[2][4] = 104\), \(m[1][4] = 158\) all carry over. The new cells are those with \(j = 5\).
    \(L = 2\): \(m[4][5] = 2{\cdot}7{\cdot}3 = 42\), \(s = 4\).
    \(L = 3\): \(m[3][5] = \min(k{=}3: 0 + 42 + 6{\cdot}2{\cdot}3 = 78,\; k{=}4: 84 + 0 + 6{\cdot}7{\cdot}3 = 210) = 78\), \(s = 3\).
    \(L = 4\): \(m[2][5] = \min(k{=}2: 0 + 78 + 4{\cdot}6{\cdot}3 = 150,\; k{=}3: 48 + 42 + 4{\cdot}2{\cdot}3 = 114,\; k{=}4: 104 + 0 + 4{\cdot}7{\cdot}3 = 188) = 114\), \(s = 3\).
    \(L = 5\): \(m[1][5] = \min(k{=}1: 0 + 114 + 5{\cdot}4{\cdot}3 = 174,\; k{=}2: 120 + 78 + 5{\cdot}6{\cdot}3 = 288,\; k{=}3: 88 + 42 + 5{\cdot}2{\cdot}3 = 160,\; k{=}4: 158 + 0 + 5{\cdot}7{\cdot}3 = 263) = 160\), \(s[1][5] = 3\).
    Traceback: \(s[1][5] = 3\) splits into \([1,3]\) and \([4,5]\); \(s[1][3] = 1\) gives \((A_1(A_2A_3))\); \(s[4][5] = 4\) gives \((A_4A_5)\). Result \(((A_1(A_2A_3))(A_4A_5))\), cost \(48 + 40 + 42 + 5{\cdot}2{\cdot}3 = 130 + 30 = 160\).
    Count: \(1{+}1{+}1{+}1\) candidates on \(L{=}2\), \(2{+}2{+}2\) on \(L{=}3\), \(3{+}3\) on \(L{=}4\), \(4\) on \(L{=}5\): \(4 + 6 + 6 + 4 = 20 = (5^3 - 5)/6\), as §6 predicts. Note that adding one matrix lowered nothing but raised the total only from \(158\) to \(160\): \(A_5\) is cheap to append because the running product is already \(5 \times 2\).
  4. Change min to max throughout (and initialize to \(-\infty\) instead of \(+\infty\)). Does the resulting algorithm correctly compute the most expensive parenthesization? Prove or refute, then run it on \(p = (5, 4, 6, 2, 7)\) and check the answer against §1.
    solution It is correct. The optimal-substructure proof of §2 never uses the direction of the comparison: it uses only that the total decomposes as \(\mathrm{cost}(P_L) + \mathrm{cost}(P_R) + p_{i-1}p_kp_j\) with the third term fixed by \(k\), and that the two halves are independent given \(k\). Substituting a more expensive bracketing of a half raises the total in the same way, so a worst parenthesization restricts to worst parenthesizations of its halves, and the argument runs verbatim with every inequality reversed. Fill order and cost are unchanged.
    On the running instance: \(L = 2\) is unchanged (single candidates): \(120, 48, 84\). \(L = 3\): \(M[1][3] = \max(88, 180) = 180\) at \(k = 2\); \(M[2][4] = \max(252, 104) = 252\) at \(k = 2\). \(L = 4\): \(M[1][4] = \max(k{=}1: 0 + 252 + 140 = 392,\; k{=}2: 120 + 84 + 210 = 414,\; k{=}3: 180 + 0 + 70 = 250) = 414\) at \(k = 2\), giving \(((A_1A_2)(A_3A_4))\). That is exactly the worst row of the §1 enumeration, and the three candidate totals \(392, 414, 250\) are the three worst bracketings of the five. (Note the \(k=1\) and \(k=3\) candidates changed value from the min run, because they now read the maximizing sub-cells \(M[2][4] = 252\) and \(M[1][3] = 180\).)
  5. The code loops over range length. Suppose someone rewrites it in the obvious row-major order, for i in 1..n: for j in i+1..n:, keeping the same body. Trace what goes wrong on the running instance, and identify the first cell that is computed from stale data. Is there any correct loop order that is not by increasing length?
    solution Row-major visits \(m[1][2], m[1][3], m[1][4], m[2][3], m[2][4], m[3][4]\). The first cell is fine: \(m[1][2] = 120\). The second, \(m[1][3]\), needs \(m[2][3]\), which has not been computed and still holds its initial \(0\). Its \(k = 1\) candidate is therefore evaluated as \(0 + 0 + 40 = 40\) instead of \(0 + 48 + 40 = 88\), so \(m[1][3]\) is set to \(\min(40, 180) = 40\): wrong, and wrong in the dangerous direction, since a spuriously small value will not be corrected later and propagates. \(m[1][4]\) then reads both the stale \(m[1][3] = 40\) and the still-uncomputed \(m[2][4] = 0\) and reports \(\min(0+0+140,\;120+0+210,\;40+0+70) = 110\), below the true optimum \(158\), which is impossible for a genuine parenthesization.
    Yes, other correct orders exist. The only requirement is that every cell be computed after all strictly shorter ranges it reads, so any linear extension of that dependency order works. Two practical ones: iterate \(i\) from \(n\) down to \(1\) and, inside, \(j\) from \(i+1\) up to \(n\) (each cell then reads \(m[i][k]\) already done on the current row and \(m[k+1][j]\) from a row with a larger index, already finished); or run the memoized top-down recursion, which discovers a valid order by itself. The length-indexed loop is preferred because the reason it is correct is visible in the loop bounds.
