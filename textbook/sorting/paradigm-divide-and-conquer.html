Divide-and-Conquer

In 1960 Andrey Kolmogorov conjectured that multiplying two n-digit numbers takes on the order of n² operations. Within a week, Anatoly Karatsuba, a student in his seminar, found a divide-and-conquer method using about n1.585. A. A. Karatsuba, “The Complexity of Computations,” Proc. Steklov Institute of Mathematics 211, 1995

You sorted in CSS 342; the frame here is divide-and-conquer: split a problem into smaller subproblems, solve them recursively, and combine the answers. The master theorem reads the cost of such an algorithm straight off its recurrence, no unrolling required. Mergesort and quicksort are the two famous sorts you get by putting the work in the combine step versus the divide step; their handouts lean on this one for their recurrence solutions.

1. The paradigm and the master theorem

Definition (divide-and-conquer) A divide-and-conquer algorithm solves a problem in three steps, applied recursively: divide it into smaller subproblems, conquer each by recursing, and combine the sub-answers into the full answer. A base case (a subproblem small enough to solve directly) stops the recursion.

You have already met the paradigm: binary search halves a sorted array (\(T(n) = T(n/2) + O(1)\)), and mergesort splits and merges. The base case is easy to overlook and fatal to omit (a size-\(0\)-or-\(1\) array is already sorted, an empty search range means the key is absent), and forgetting it means infinite recursion. The cost of a divide-and-conquer algorithm obeys a recurrence \[ T(n) = a\,T(n/b) + f(n), \] where \(a\) is the number of subproblems, \(b\) the factor by which each shrinks, and \(f(n)\) the cost of dividing and combining. Mergesort’s is \(T(n) = 2\,T(n/2) + \Theta(n)\).

The master theorem

Theorem (master theorem) For \(T(n) = a\,T(n/b) + f(n)\) with \(a \ge 1\), \(b > 1\), compare \(f(n)\) with \(n^{\log_b a}\):
  1. if \(f(n) = O(n^{\log_b a - \varepsilon})\) for some \(\varepsilon > 0\) (leaf work dominates), then \(T(n) = \Theta(n^{\log_b a})\);
  2. if \(f(n) = \Theta(n^{\log_b a})\) (the two tie), then \(T(n) = \Theta(n^{\log_b a}\log n)\);
  3. if \(f(n) = \Omega(n^{\log_b a + \varepsilon})\) and a regularity condition holds (combine work dominates), then \(T(n) = \Theta(f(n))\).
Why the three cases (a recursion-tree sketch). Sum the tree level by level. The root costs \(f(n)\); level \(i\) has \(a^i\) subproblems of size \(n/b^i\), costing \(a^i f(n/b^i)\); the bottom level has \(a^{\log_b n} = n^{\log_b a}\) leaves, each \(\Theta(1)\). The total is the geometric-like series \(\sum_i a^i f(n/b^i)\), and, like any geometric series, it is dominated by its largest term: the root if the terms shrink (case 3, cost \(\Theta(f(n))\)), the leaves if they grow (case 1, cost \(\Theta(n^{\log_b a})\)), and if every term is equal, one level’s cost times the \(\Theta(\log n)\) depth (case 2). The three cases are the three behaviors of that series. ∎

The critical exponent is \(\log_b a\) (the leaf count), and the whole method is: compute it, compare to \(f(n)\), pick the case.

Example (reading recurrences) 
  mergesort:      2T(n/2) + Θ(n)   n^(log₂2) = n = f  → case 2  ⇒ Θ(n log n)
  binary search:   T(n/2) + Θ(1)   n^(log₂1) = 1 = f  → case 2  ⇒ Θ(log n)
  case 1 example: 4T(n/2) + Θ(n)   n^(log₂4) = n² > n  → case 1  ⇒ Θ(n²)
  Karatsuba mult: 3T(n/2) + Θ(n)   n^(log₂3) ≈ n^1.58 > n  → Θ(n^1.58)
  case 3 example: 2T(n/2) + Θ(n²)  n^(log₂2) = n < n²  → case 3  ⇒ Θ(n²)
Karatsuba multiplication does three half-size multiplies instead of four, and its \(n^{1.58}\) beats grade-school \(n^2\): a divide-and-conquer win read straight off the recurrence.
Example (each case worked in full) The table above reads the case off at a glance; here is each comparison spelled out once, hypotheses and all.
  • Case 1, \(T(n) = 4T(n/2) + \Theta(n)\): \(a = 4\), \(b = 2\), so \(n^{\log_b a} = n^{\log_2 4} = n^2\). Is \(f(n) = n\) polynomially smaller? Yes: \(n = O(n^{2-\varepsilon})\) with \(\varepsilon = 1\). Leaf work dominates: \(T(n) = \Theta(n^2)\). (The recursion tree agrees: level \(i\) costs \(4^i \cdot n/2^i = 2^i n\), a series that doubles every level, so the bottom level’s \(n^2\) dominates.)
  • Case 2, \(T(n) = 2T(n/2) + \Theta(n)\) (mergesort): \(n^{\log_2 2} = n = f(n)\) exactly, so every one of the \(\log_2 n\) levels costs \(\Theta(n)\) and \(T(n) = \Theta(n\log n)\).
  • Case 3, \(T(n) = 2T(n/2) + \Theta(n^2)\): \(n^{\log_2 2} = n\), and \(f(n) = n^2 = \Omega(n^{1+\varepsilon})\) with \(\varepsilon = 1\), polynomially larger. Case 3 also demands the regularity condition \(a f(n/b) \le c f(n)\) for some \(c < 1\): here \(2 (n/2)^2 = n^2/2 = \tfrac12 f(n)\), so \(c = \tfrac12\) works, and \(T(n) = \Theta(f(n)) = \Theta(n^2)\). (The condition guarantees the level costs really do shrink geometrically below the root; ordinary polynomial \(f\) always satisfies it.)
  • No case applies, \(T(n) = 2T(n/2) + n\log n\): \(n^{\log_2 2} = n\), and \(n \log n\) is bigger than \(n\), but not polynomially bigger: \(n\log n \ne \Omega(n^{1+\varepsilon})\) for any \(\varepsilon > 0\), since \(\log n\) grows slower than every \(n^{\varepsilon}\). Case 3’s hypothesis fails (and cases 1 and 2 plainly do not fit), so the theorem is silent. The recursion tree still answers: level \(i\) costs \(n(\log n - i)\), and summing \(i = 0 \ldots \log n\) gives \(\Theta(n\log^2 n)\).

Read the columns. The first doubles every level, so its total \(8128\) is under twice the \(4096 = n^2\) of the highlighted bottom level: case 1, \(\Theta(n^{\log_b a})\). The second is flat at \(64 = n\), so its total is \(n\) times the number of levels, \(64 \cdot 7 = 448\): case 2, \(\Theta(n\log n)\). The third halves every level, so its total is under twice the highlighted root \(4096 = f(n)\): case 3, \(\Theta(f(n))\). The fourth shrinks too, but only by a subtracted constant rather than a constant factor (\(384, 320, 256, \ldots\), an arithmetic series, not a geometric one), and that is exactly why case 3 does not apply to it: its total \(1344\) is \(\Theta(\log n)\) times the root, not \(\Theta(1)\) times it. In closed form that column is \(\sum_{i=0}^{\log_2 n} n(\log_2 n - i) = \tfrac{n\log_2 n(\log_2 n + 1)}{2}\), which at \(n = 64\) is \(64 \cdot 6 \cdot 7 / 2 = 1344\).

Balance is everything The savings depend on balanced splits. Even splits give \(\log n\) levels and \(\Theta(n\log n)\); a skewed split into sizes \(1\) and \(n-1\) gives \(n\) levels and \(\Theta(n^2)\). And the combine must be cheap: halving a quadratic pass and recursing on that alone still sums to \(\Theta(n^2)\), because a top-heavy geometric series is dominated by its root. The \(n\log n\) sweet spot needs both balanced splits and a linear combine: exactly \(2T(n/2) + \Theta(n)\). This is the difference between mergesort (always splits at the midpoint) and quicksort (splits at a pivot).

Divide-and-conquer reaches far beyond sorting: binary search (\(O(\log n)\)), Karatsuba and Strassen’s matrix multiplication (\(7T(n/2)+\Theta(n^2) = \Theta(n^{2.81})\)), the closest-pair-of-points algorithm (\(\Theta(n\log n)\)), and the FFT are all recurrences the master theorem reads at a glance. The two great sorts, mergesort and quicksort, are its most famous instances; each has its own handout.

When the master theorem does not apply The master theorem covers \(a\,T(n/b) + f(n)\), but real recurrences wander outside that form, and Cormen et al. give three tools for the rest. The substitution method: guess the answer and prove it by induction (the honest way to verify a bound the tree method suggested). The recursion-tree method: draw the tree, sum each level, and add up the geometric series; that is exactly the sketch behind the three cases, and the way to handle a gap case like \(T(n) = 2T(n/2) + n\log n\) (which is \(\Theta(n\log^2 n)\), a factor the basic theorem cannot name). And the Akra–Bazzi method, a heavier generalization that handles unequal subproblem sizes: \(T(n) = T(n/5) + T(7n/10) + \Theta(n)\), the median-of-medians recurrence of quickselect, whose solution \(\Theta(n)\) no elementary case delivers. The recurrence is still the analysis; the master theorem is just the common special case.
Example (substitution, worked on the gap case) The tree suggested \(\Theta(n\log^2 n)\) for \(T(n) = 2T(n/2) + n\log_2 n\); substitution proves it. Guess \(T(n) \le c\,n\log_2^2 n\), assume it for \(n/2\), and substitute: \[ \begin{aligned} T(n) &\le 2c\tfrac{n}{2}\log_2^2\tfrac{n}{2} + n\log_2 n = c\,n(\log_2 n - 1)^2 + n\log_2 n \\ &= c\,n\log_2^2 n - 2c\,n\log_2 n + c\,n + n\log_2 n \\ &= c\,n\log_2^2 n - \bigl[(2c-1)\,n\log_2 n - c\,n\bigr]. \end{aligned} \] The bracket is the slack, and the guess survives exactly when it is non-negative, that is when \((2c-1)\log_2 n \ge c\). Take \(c = 1\): the requirement becomes \(\log_2 n \ge 1\), i.e. \(n \ge 2\). The base case checks out too, since \(T(1) = 0\) and \(T(2) = 2T(1) + 2 = 2 = 1 \cdot 2 \cdot \log_2^2 2\). So \(T(n) \le n\log_2^2 n\) for every power of two, and the tree’s exact sum \(\tfrac{n\log_2 n(\log_2 n + 1)}{2}\) sits just under it: at \(n = 64\), \(1344\) against \(64 \cdot 36 = 2304\). Tree first for the guess, induction second for the proof.

The method is unforgiving about which guess you make, which is its other lesson. Try to prove \(T(n) = 2T(n/2) + n\) is \(O(n)\) by guessing \(T(n) \le c\,n\): substituting gives \(T(n) \le 2c\tfrac{n}{2} + n = c\,n + n\), which is not \(\le c\,n\) for any \(c\). The induction fails, and it fails for the right reason: the bound is false. A failed substitution is evidence, not a dead end.

2. Exercises (with solutions)

  1. Use the master theorem on \(T(n) = 9T(n/3) + \Theta(n^2)\) and on \(T(n) = T(n/2) + \Theta(n)\).
    solution First: \(\log_3 9 = 2\), so \(n^{\log_b a} = n^2 = f(n)\), case 2, giving \(\Theta(n^2\log n)\). Second: \(\log_2 1 = 0\), so \(n^{\log_b a} = 1\) while \(f(n) = n\) dominates, case 3, giving \(\Theta(n)\). (The second is the recurrence for the one-sided scan in quickselect: one subproblem of half size plus a linear partition, hence linear overall.)
  2. True or false, with justification: “Divide-and-conquer always beats a direct \(\Theta(n^2)\) algorithm.”
    solution False. Splitting helps only when the subproblems are balanced and the combine is cheap. The recurrence \(T(n) = 2T(n/2) + \Theta(n^2)\) (a quadratic combine) is master-theorem case 3 and stays \(\Theta(n^2)\); an unbalanced split \(T(n) = T(n-1) + \Theta(n)\) is also \(\Theta(n^2)\). Only balanced splits with a cheap (e.g. linear) combine reach the \(\Theta(n\log n)\) sweet spot, as mergesort does; splitting alone is not magic.
  3. Classify each of \(T(n) = 3T(n/4) + n\log n\), \(T(n) = 7T(n/2) + \Theta(n^2)\) (Strassen’s matrix multiplication) and \(T(n) = 2T(n/2) + n/\log n\). For any case 3 you claim, check the regularity condition explicitly.
    solution First: \(\log_4 3 \approx 0.79\), so \(n^{\log_b a} \approx n^{0.79}\), and \(f(n) = n\log n\) is polynomially larger (take \(\varepsilon = 0.2\), since \(n\log n = \Omega(n^{0.99})\)). Regularity: \(a f(n/b) = 3\tfrac{n}{4}\log\tfrac{n}{4} \le \tfrac34 n\log n = \tfrac34 f(n)\), so \(c = \tfrac34\) works. Case 3, \(T(n) = \Theta(n\log n)\). Second: \(\log_2 7 \approx 2.807\), so \(n^{\log_b a} \approx n^{2.807}\), against \(f(n) = n^2\), which is polynomially smaller (\(\varepsilon \approx 0.8\)). Case 1, \(T(n) = \Theta(n^{2.807})\), which is what makes Strassen beat the \(\Theta(n^3)\) of the schoolbook \(8T(n/2) + \Theta(n^2)\). Third: \(n^{\log_2 2} = n\) and \(f(n) = n/\log n\) is smaller, but not polynomially smaller: \(n/\log n\) is not \(O(n^{1-\varepsilon})\) for any \(\varepsilon > 0\), because \(n^{\varepsilon}/\log n \to \infty\). No case applies. The recursion tree answers anyway: level \(i\) costs \(2^i \cdot \tfrac{n/2^i}{\log(n/2^i)} = \tfrac{n}{\log n - i}\), and summing \(i = 0 \ldots \log n - 1\) gives \(n\,H_{\log n} = \Theta(n\log\log n)\).
