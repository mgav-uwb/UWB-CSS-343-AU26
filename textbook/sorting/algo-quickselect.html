Quickselect

Hoare published quickselect as “Algorithm 65: Find” in 1961, in the same issue of the journal as quicksort’s “Algorithm 64.” A worst-case linear-time selection algorithm followed in 1973. C. A. R. Hoare, CACM 4(7), 1961; Blum, Floyd, Pratt, Rivest and Tarjan, “Time Bounds for Selection,” 1973

Often you need one order statistic, not the whole sorted order. Quickselect finds the \(k\)-th smallest in linear average time by reusing quicksort’s partition and recursing into only one side. Its recurrence, \(T(n) = T(n/2) + \Theta(n)\) on balanced pivots, solves to \(\Theta(n)\) by master-theorem case 3 (the Divide-and-Conquer handout): one recursive call instead of two is exactly what drops \(n\log n\) to \(n\).

1. Selection: order statistics in linear time

Often you do not need the whole sorted order, only one order statistic: the \(k\)-th smallest element. \(k = 0\) is the minimum, \(k = n-1\) the maximum, \(k = n/2\) the median, \(k = 0.95n\) the 95th percentile. Sorting to extract one of them, at \(\Theta(n\log n)\), is wasteful. Quickselect does it in linear average time by reusing quicksort’s partition but recursing into only one side. 

// Quickselect: the k-th smallest element (0-indexed). Partition, then recurse
// into ONLY the side that contains rank k. Average Theta(n). Reuses partition().
int quickselect(int a[], int lo, int hi, int k) {
    if (lo == hi) return a[lo];           // one element left
    int p = partition(a, lo, hi);         // pivot lands at rank p
    if (k == p)      return a[p];          // found it
    else if (k < p)  return quickselect(a, lo, p - 1, k);   // left side only
    else             return quickselect(a, p + 1, hi, k);   // right side only
}
// Quickselect: the k-th smallest element (0-indexed). Partition, then recurse
// into ONLY the side that contains rank k. Average Theta(n). Reuses partition().
static int quickselect(int[] a, int lo, int hi, int k) {
    if (lo == hi) return a[lo];           // one element left

    if (k == p)      return a[p];          // found it
    else if (k < p)  return quickselect(a, lo, p - 1, k);   // left side only
    else             return quickselect(a, p + 1, hi, k);   // right side only
}
# Quickselect: the k-th smallest element (0-indexed). Partition, then recurse
# into ONLY the side that contains rank k. Average Theta(n). Reuses partition().
def quickselect(a, lo, hi, k):
    if lo == hi:                          # one element left
        return a[lo]
    p = partition(a, lo, hi)              # pivot lands at rank p
    if k == p:
        return a[p]                       # found it
    elif k < p:
        return quickselect(a, lo, p - 1, k)    # recurse into the left side only
    else:
        return quickselect(a, p + 1, hi, k)    # recurse into the right side only
// Quickselect: the k-th smallest element (0-indexed). Partition, then recurse
// into ONLY the side that contains rank k. Average O(n). Reuses partition().
fn quickselect(a: &mut [i32], lo: usize, hi: usize, k: usize) -> i32 {
    if lo == hi { return a[lo]; }         // one element left
    let p = partition(a, lo, hi);         // pivot lands at rank p
    if k == p { a[p] }                    // found it
    else if k < p { quickselect(a, lo, p - 1, k) }   // left side only
    else { quickselect(a, p + 1, hi, k) }            // right side only
}

After partitioning (the Lomuto partition of the Quicksort handout), the pivot sits at some final rank \(p\). If \(p = k\), the pivot is the answer; if \(k < p\), the \(k\)-th smallest is in the left part; otherwise it is in the right part. Only that one side is searched.

Proposition (quickselect cost) Quickselect runs in \(\Theta(n)\) average time (\(\Theta(n^2)\) worst case with unlucky pivots, removed by randomization).
Sketch. Each call partitions in \(\Theta(n)\) and recurses on one side. A random pivot leaves, on average, at most a constant fraction of the elements (at most \(3/4\) of them), so the surviving size shrinks geometrically, and the total work is bounded by a geometric series \(c\,(n + \tfrac34 n + (\tfrac34)^2 n + \cdots) = \Theta(n)\). The worst case, where every pivot peels one element, is \(\Theta(n^2)\), but a random pivot makes that astronomically unlikely; median-of-medians (below) removes it entirely. ∎
Example (find the median) In \([7, 2, 9, 4, 1, 6, 3]\) (\(7\) elements) the median has rank \(3\) (three below, three above). quickselect(3) partitions, follows only the side containing rank \(3\), and returns \(4\) (the sorted order is \(1\ 2\ 3\ 4\ 6\ 7\ 9\)) in about \(n\) comparisons on average, not \(n\log n\). In C++, std::nth_element(v.begin(), v.begin()+3, v.end()) does exactly this.

The comparison of \(k\) against \(p\) has exactly three outcomes, and each is a different fate for the recursion. One query on one array exercises all three.

Example (all three branches, unrolled) Take the same \([7, 2, 9, 4, 1, 6, 3]\) and ask for rank \(k = 4\) (the fifth smallest; the sorted order is \(1\ 2\ 3\ 4\ 6\ 7\ 9\), so the answer should be \(6\)). Each call runs the Lomuto partition on its own range and then compares \(k\) with the pivot’s landing index \(p\). Eleven comparisons in all. Three things are worth reading off this run. The array is left partially sorted, not sorted: \([2, 1, 3, 4, 6, 7, 9]\) still has \(2\) before \(1\), and that is fine, because everything left of index \(4\) is \(\le 6\) and everything right is \(\ge 6\), which is all the question asked. Call 2 shows the branch that costs: a pivot at the extreme of its range discards one element instead of half, the same degenerate partition that makes quicksort quadratic, and a run of them would make quickselect quadratic too. And the recursion is a chain, never a tree: each call spawns at most one child, which is why the cost is \(n + n/2 + n/4 + \cdots\) rather than \(\log n\) levels of \(n\).
Example (the fourth exit: the base case) The three branches above are not the only way a run ends. Ask the same array for \(k = 3\), the median, instead. Calls 1 and 2 go exactly as before (\(p = 2\), recurse right; \(p = 6\), recurse left), but call 3 now finds \(k = 3 < p = 4\) and recurses left on \((3, 3)\): a range of one element. That call takes the lo == hi guard and returns \(a[3] = 4\) without partitioning at all, which is the right answer, since a range of one element can hold only one rank. So a range narrowing to a single element is a fourth exit, and it is why the base case is tested before the partition: partitioning a one-element range would return \(p = lo\) and, if \(k\) somehow disagreed, recurse on an empty range forever.
Guaranteeing \(O(n)\): median-of-medians To kill the quadratic worst case deterministically, choose a provably good pivot: split the array into groups of \(5\), take each group’s median, then recursively take the median of those medians as the pivot. It guarantees at least a \(30\)/\(70\) split, hence worst-case \(O(n)\) selection (the BFPRT algorithm). The constant is large, so randomized quickselect wins in practice; median-of-medians matters when you need a hard guarantee.
Interactive Quickselect demo. Choose a rank \(k\) and watch half the array get discarded at each partition; that one-sided recursion is what makes it \(\Theta(n)\) rather than \(\Theta(n\log n)\). Compare the counters against a full quicksort: selection does a fraction of the work.

2. Exercises (with solutions)

  1. You must report the \(90\)th-percentile latency from \(10^7\) recorded request times. Contrast sorting with selection, and give the running time of the better approach.
    solution Sorting all \(10^7\) values to index the percentile costs \(\Theta(n\log n)\) and produces far more order than needed. Selection answers the single query directly: quickselect for rank \(\lfloor 0.9\,n \rfloor\) runs in \(\Theta(n)\) average time (C++ std::nth_element). For one percentile, selection is the right primitive; only if you need many percentiles at once does a single sort start to pay off.
  2. Run quickselect on \([5, 1, 8, 3, 9, 2, 7]\) for \(k = 5\) with the last-element pivot. Name the branch taken at each call, count the comparisons, and give the answer.
    solution Call 1, range \(0..6\), pivot \(a[6] = 7\): \(5, 1\) go left (\(i = 1\)), \(8\) is skipped, \(3\) goes left (\(i = 2\)), \(9\) is skipped, \(2\) goes left (\(i = 3\)), then the placement swap gives \([5, 1, 3, 2, 7, 8, 9]\) with \(p = 4\). Six comparisons, and \(k = 5 > 4\), so recurse right on \((5, 6)\). Call 2, range \([8, 9]\), pivot \(9\): one comparison, \(p = 6\), and \(k = 5 < 6\), so recurse left on \((5, 5)\). Call 3 hits \(lo = hi\) and returns \(a[5] = 8\) with no work. Seven comparisons in total; the sorted order is \(1\ 2\ 3\ 5\ 7\ 8\ 9\), whose rank-\(5\) element is indeed \(8\).
  3. You call quickselect(a, 0, n-1, 0) (the minimum) with a last-element pivot on the already-sorted array \([1, 2, \dots, n]\). How many comparisons does it make, which branch does it take every time, and what should you have done instead?
    solution The last element is the maximum of every range, so the pivot lands at \(p = hi\) and \(k = 0 < p\) always: the recurse-left branch, every time, discarding exactly one element per call. That is \((n-1) + (n-2) + \cdots + 1 = \binom{n}{2}\) comparisons, so \(\Theta(n^2)\); for \(n = 6\) it is \(15\) comparisons to find the number \(1\). A single linear scan finds the minimum in \(n - 1\) comparisons, and randomizing the pivot restores the \(\Theta(n)\) expectation for general \(k\). The lesson is the same as quicksort’s: with a fixed-position pivot, sorted input is the adversarial input.
