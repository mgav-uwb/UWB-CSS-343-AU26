Suffix Arrays

Udi Manber and Gene Myers introduced suffix arrays in 1990 as a space-efficient alternative to suffix trees. U. Manber and G. Myers, “Suffix Arrays: A New Method for On-Line String Searches,” SODA 1990

The substring searchers (Substring Search: The Problem & Baselines) all preprocess the pattern and then scan the text: the right shape when the text arrives once and the pattern is fixed. Flip the workload: one huge, fixed text (a genome, a corpus, a log archive) and many patterns, arriving later, unknown in advance. Now it pays to preprocess the text. The suffix array is the standard way to do it: sort all \(n\) suffixes of the text once, and every future pattern becomes a binary search.

1. All suffixes, sorted

Definition (suffix, sentinel) For a text \(t\) of length \(n\), the suffix starting at index \(i\) is \(t[i \mathinner{.\,.} n-1]\): the tail of the text from position \(i\) to the end. There are exactly \(n\) of them, one per starting index. By convention the text ends with a sentinel character $ that appears nowhere else and sorts before every real character; it guarantees that no suffix is a prefix of another, so any two suffixes differ at some character position.
Definition (suffix array) The suffix array \(SA\) of \(t\) is the array of the \(n\) starting indices, arranged so that the suffixes they name are in sorted (lexicographic) order: \(SA[r]\) is the starting index of the \(r\)-th smallest suffix. The suffixes themselves are never copied: the structure is \(n\) integers, and every “row” is read off the original text on demand.

Build one fully by hand for \(t = \texttt{banana\$}\) (\(n = 7\)). Step one: list every suffix with its starting index.

So \(SA(\texttt{banana\$}) = [\,6, 5, 3, 1, 0, 4, 2\,]\). Two observations that drive everything below. First, all suffixes beginning with the same string sit in a contiguous run of rows: the three a-suffixes are rows 1–3, the two na-suffixes are rows 5–6; that is just what sorted order means. Second, the array costs \(n\) integers (28 bytes here at 4 bytes each) no matter how long the suffixes are, because it stores indices, never string copies.

The complete operations in code: build (naively, by sorting the indices with suffix comparisons; the real algorithms are the subject of the construction section), search, count, and the LCP scan of the LCP section. 

// Suffix array: build (naive O(n^2 log n) sort), search (binary search for the
// first row whose suffix >= pattern), count (the band of rows starting with
// the pattern), LCP array (adjacent-row scan). Text must end with '$'.
vector<int> suffixArray(const string& t) {
    vector<int> sa(t.size());
    iota(sa.begin(), sa.end(), 0);            // indices 0..n-1
    sort(sa.begin(), sa.end(), [&](int a, int b) {
        return t.compare(a, string::npos, t, b, string::npos) < 0;
    });                                       // compare the two SUFFIXES
    return sa;
}
int search(const string& t, const vector<int>& sa, const string& p) {
    int lo = 0, hi = sa.size();
    while (lo < hi) {                         // invariant: rows < lo are < p
        int mid = (lo + hi) / 2;              //            rows >= hi are >= p
        if (t.compare(sa[mid], string::npos, p) < 0) lo = mid + 1;
        else hi = mid;
    }
    if (lo < (int)sa.size() && t.compare(sa[lo], p.size(), p) == 0)
        return sa[lo];                        // suffix at row lo starts with p
    return -1;                                // no occurrence
}
int count(const string& t, const vector<int>& sa, const string& p) {
    int lo = 0, hi = sa.size();               // lower bound: first row >= p
    while (lo < hi) { int m = (lo + hi) / 2;
        if (t.compare(sa[m], string::npos, p) < 0) lo = m + 1; else hi = m; }
    int lo2 = lo; hi = sa.size();             // upper bound: first row whose
    while (lo2 < hi) { int m = (lo2 + hi) / 2;   // length-m prefix > p
        if (t.compare(sa[m], p.size(), p) <= 0) lo2 = m + 1; else hi = m; }
    return lo2 - lo;                          // width of the band
}
vector<int> lcpArray(const string& t, const vector<int>& sa) {
    vector<int> lcp(sa.size(), 0);            // lcp[r]: rows r-1 and r
    for (size_t r = 1; r < sa.size(); r++) {
        int i = sa[r-1], j = sa[r], k = 0;
        while (t[i+k] == t[j+k]) k++;         // '$' stops the loop
        lcp[r] = k;
    }
    return lcp;
}

}

        while (t.charAt(i+k) == t.charAt(j+k)) k++;   // '$' stops the loop
        lcp[r] = k;

def lcp_array(t, sa):
    lcp = [0] * len(sa)                       # lcp[r]: rows r-1 and r
    for r in range(1, len(sa)):
        i, j, k = sa[r-1], sa[r], 0

// Suffix array: build (naive O(n^2 log n) sort), search (binary search for the
// first row whose suffix >= pattern), count (the band of rows starting with
// the pattern), LCP array (adjacent-row scan). Text must end with '$'.
fn suffix_array(t: &str) -> Vec<usize> {
    let mut sa: Vec<usize> = (0..t.len()).collect();  // indices 0..n-1
    sa.sort_by(|&a, &b| t[a..].cmp(&t[b..]));         // compare the SUFFIXES
    sa
}
fn search(t: &str, sa: &[usize], p: &str) -> i32 {
    let (mut lo, mut hi) = (0, sa.len());
    while lo < hi {                           // invariant: rows < lo are < p
        let mid = (lo + hi) / 2;              //            rows >= hi are >= p
        if &t[sa[mid]..] < p { lo = mid + 1; } else { hi = mid; }
    }
    if lo < sa.len() && t[sa[lo]..].starts_with(p) {
        return sa[lo] as i32;                 // suffix at row lo starts with p
    }
    -1                                        // no occurrence
}
fn count(t: &str, sa: &[usize], p: &str) -> usize {
    let (mut lo, mut hi) = (0, sa.len());     // lower bound: first row >= p
    while lo < hi { let m = (lo + hi) / 2;
        if &t[sa[m]..] < p { lo = m + 1; } else { hi = m; } }
    let (mut lo2, mut hi) = (lo, sa.len());   // upper bound: first row whose
    while lo2 < hi {                          // length-m prefix > p
        let m = (lo2 + hi) / 2;
        let end = (sa[m] + p.len()).min(t.len());
        if &t[sa[m]..end] <= p { lo2 = m + 1; } else { hi = m; }
    }
    lo2 - lo                                  // width of the band
}
fn lcp_array(t: &str, sa: &[usize]) -> Vec<usize> {
    let tb = t.as_bytes();
    let mut lcp = vec![0; sa.len()];          // lcp[r]: rows r-1 and r
    for r in 1..sa.len() {
        let (i, j, mut k) = (sa[r-1], sa[r], 0);
        while tb[i+k] == tb[j+k] { k += 1; }  // '$' stops the loop
        lcp[r] = k;
    }
    lcp
}

2. Substring search as binary search

The key equivalence: a pattern \(p\) occurs in \(t\) at index \(i\) exactly when \(p\) is a prefix of the suffix starting at \(i\). So “find \(p\) in \(t\)” becomes “find a suffix that starts with \(p\)”, and since the suffixes starting with \(p\) form a contiguous band of rows, binary search finds the band. The search above maintains the standard lower-bound invariant: every row below lo holds a suffix \(< p\), every row at or above hi holds a suffix \(\ge p\). When lo meets hi, that row is the first suffix \(\ge p\); the pattern occurs in the text if and only if that suffix starts with \(p\).

Example (hit, traced) Search for \(p = \texttt{ana}\) in \(\texttt{banana\$}\), \(SA = [6,5,3,1,0,4,2]\), rows \(0..6\), so lo = 0, hi = 7. Each step compares the pattern with the suffix at the middle row:

The remaining miss shape: a pattern greater than every suffix (say \(\texttt{z}\)) drives lo all the way to \(n\), and the lo < n guard catches it (exercise 5).

Counting and reporting all occurrences

Because the suffixes starting with \(p\) are one contiguous band, a second binary search (for the first row whose length-\(m\) prefix exceeds \(p\)) finds the band’s end, and the band answers three queries at once: exists (band nonempty), count (band width), report all (read the band’s \(SA\) entries). For \(p = \texttt{ana}\) the band is rows \([2, 4)\): count \(2\), occurrences at text indices \(\{3, 1\}\), and the two occurrences overlap in the text; the suffix array counts overlapping occurrences without any extra care. For \(p = \texttt{a}\) the band is rows \([1, 4)\): count \(3\), indices \(\{5, 3, 1\}\).

Proposition (search cost) Searching for a length-\(m\) pattern in the suffix array of a length-\(n\) text costs \(O(m \log n)\) character comparisons: the binary search runs \(\lceil \log_2 (n+1) \rceil\) rounds, and each round’s suffix-versus-pattern comparison stops at the first mismatch, after at most \(m\) character comparisons (the pattern has only \(m\) characters, and comparing beyond a mismatch is never needed). Reporting all \(occ\) occurrences adds \(O(occ)\) after the two bounding searches.

The \(m\) and \(\log n\) multiply rather than add, which is the price of the array’s simplicity; a refinement that reuses longest-common-prefix information inside the binary search brings search to \(O(m + \log n)\) (Manber and Myers), and a suffix tree achieves \(O(m)\) (aside below). In practice \(m \log n\) is small: a 30-character pattern against a \(n = 10^9\) genome is at most \(30 \times 30 = 900\) character comparisons.

3. The LCP array, and the longest repeated substring

Definition (LCP array) The longest common prefix (LCP) of two strings is the longest string that is a prefix of both. The LCP array of a suffix array stores, for each row \(r \ge 1\), the length of the longest common prefix of the suffixes at rows \(r-1\) and \(r\): \(LCP[r] = \mathrm{lcp}(t[SA[r-1]..],\, t[SA[r]..])\). Adjacent rows only: in sorted order, adjacent suffixes are the similar ones, and (as the theorem below shows) adjacent entries already carry all the repetition structure.

Compute it by hand for \(\texttt{banana\$}\): walk the sorted rows, comparing each suffix with the one above it character by character.

row \(r\)\(SA[r]\)suffixcommon prefix with row above\(LCP[r]\)

31anana$ana3
40banana$(none: a vs b)0
54na$(none: b vs n)0

So \(LCP = [\,\text{–}, 0, 1, 3, 0, 0, 2\,]\). What it buys: the LCP array is the repetition structure of the text, precomputed. The flagship application:

Theorem (longest repeated substring) The length of the longest substring that occurs at least twice in \(t\) equals \(\max_r LCP[r]\), and the maximizing row exhibits it: the substring is the first \(LCP[r]\) characters of the suffix at row \(r\), occurring at text indices \(SA[r-1]\) and \(SA[r]\).
(\(\le\)) Let \(w\), of length \(L\), occur at two distinct indices \(i \ne j\). Then \(w\) is a prefix of both the suffix starting at \(i\) and the suffix starting at \(j\), so both suffixes lie in the contiguous band of rows beginning with \(w\). Any two adjacent rows inside that band share at least the prefix \(w\) (both start with it), so every adjacent pair in the band has LCP \(\ge L\); the band contains at least two rows, hence at least one adjacent pair, hence \(\max_r LCP[r] \ge L\). (\(\ge\)) Conversely, for the maximizing row \(r\), the first \(LCP[r]\) characters of row \(r\)’s suffix occur at both \(SA[r-1]\) and \(SA[r]\): a repeated substring of exactly that length. So the maximum is achieved and no repeat is longer. ∎
Example (longest repeated substring, worked) For \(\texttt{banana\$}\) the maximum LCP entry is \(LCP[3] = 3\), at the adjacent rows \(\texttt{ana\$}\) (row 2, index 3) and \(\texttt{anana\$}\) (row 3, index 1). The longest repeated substring is their common prefix \(\texttt{ana}\), length 3, occurring at text indices 1 and 3: \(\texttt{b\,\underline{ana}na\$}\) and \(\texttt{ban\,\underline{ana}\$}\). The two occurrences overlap; the theorem never needed them disjoint. One linear scan of the LCP array answers a question that looks quadratic.

The same array powers a family of one-scan answers: the number of distinct substrings of \(t\) is \(\binom{n}{2} + n - \sum_r LCP[r]\) (each row contributes its length minus what it shares with the row above; exercise 6 works a small case), and the Manber–Myers search refinement of the search section is LCP information applied inside the binary search. Computing the LCP array by the adjacent-pair scan above costs \(O(n^2)\) in the worst case; Kasai’s algorithm computes it in \(O(n)\) from the text and the suffix array (name-checked here; the trick is that dropping the first character of a suffix decreases its LCP with its neighbor by at most one, so a smart visiting order makes the total work telescope).

4. Construction cost: naive, doubling, linear

Proposition (naive construction cost) Building the suffix array by handing the \(n\) suffix indices to a comparison sort costs \(O(n^2 \log n)\) character comparisons in the worst case: the sort performs \(\Theta(n \log n)\) suffix comparisons (Mergesort’s guarantee, or expected for Quicksort), and one suffix comparison walks character by character until the first mismatch, which can take \(\Theta(n)\) characters: on \(\texttt{aaa}\ldots\texttt{a\$}\), any two suffixes agree until the shorter one runs into the sentinel, so a comparison of two long suffixes costs their full length. On non-repetitive text comparisons stop early and the naive build behaves like \(O(n \log n)\); it is the repetitive texts, exactly the ones suffix arrays are built for, that hit the bound.

Prefix doubling: sort by 1, 2, 4, 8, … characters

The naive build wastes work the same way brute-force substring search does: it re-compares the same characters again and again. The classic fix (Manber and Myers) sorts the suffixes by their first \(k\) characters for \(k = 1, 2, 4, 8, \ldots\), doubling \(k\) each round, and never compares characters after round one. The engine is a rank array: after the round for length \(k\), \(rank_k[i]\) is the sorted position of suffix \(i\)’s length-\(k\) prefix (equal prefixes share a rank). The doubling step is one observation:

Key idea (rank pairs) The first \(2k\) characters of suffix \(i\) are the first \(k\) characters of suffix \(i\) followed by the first \(k\) characters of suffix \(i+k\). So sorting suffixes by length-\(2k\) prefixes is sorting the pairs \(\bigl(rank_k[i],\, rank_k[i+k]\bigr)\): two already-computed integers, compared in \(O(1)\), no characters touched. (When \(i + k \ge n\) there is no second half; use \(-1\), which sorts first, matching the fact that the shorter prefix, ending in the sentinel, sorts first.)
Example (one doubling round, traced) \(t = \texttt{banana\$}\). Round \(k=1\): rank each suffix by its first character, using \(\texttt{\$}=0, \texttt{a}=1, \texttt{b}=2, \texttt{n}=3\): \(rank_1 = [\,2, 1, 3, 1, 3, 1, 0\,]\) (ties everywhere: three suffixes rank 1, two rank 3). The doubling round \(k = 1 \to 2\) forms each suffix’s pair and sorts the pairs:
\(i\)suffixpair \((rank_1[i],\, rank_1[i+1])\)sorted position → \(rank_2[i]\)
0banana$(2, 1)3

Sorted pair order: \((0,-1) < (1,0) < (1,3) = (1,3) < (2,1) < (3,1) = (3,1)\), so \(rank_2 = [\,3, 2, 4, 2, 4, 1, 0\,]\): the suffixes are now sorted by their first two characters, and the surviving ties (\(\texttt{anana\$}\) vs \(\texttt{ana\$}\), both starting \(\texttt{an}\); \(\texttt{nana\$}\) vs \(\texttt{na\$}\), both \(\texttt{na}\)) are exactly the suffix pairs that agree to depth 2. The next round \(k = 2 \to 4\) pairs ranks two apart: \(i=1\!: (2,2)\), \(i=3\!: (2,1)\), \(i=2\!: (4,4)\), \(i=4\!: (4,0)\), and the ties break: \(rank_4 = [\,4, 3, 6, 2, 5, 1, 0\,]\), all seven ranks distinct. Reading the indices in rank order gives \(SA = [\,6, 5, 3, 1, 0, 4, 2\,]\): the same array as the hand sort in the build section, reached without ever comparing characters after round one.
Proposition (doubling cost) Prefix doubling stops when all ranks are distinct, which happens after at most \(\lceil \log_2 n \rceil\) rounds (once \(k \ge n\), prefixes are whole suffixes, and the sentinel makes those distinct). Each round sorts \(n\) integer pairs: \(O(n \log n)\) per round by comparison sort, so \(O(n \log^2 n)\) total; sorting the pairs with radix sort (two stable counting-sort passes on integers in \([-1, n)\), see the counting-sort idea in The Sorting Lower Bound: it does not apply to integer keys) makes each round \(O(n)\) and the build \(O(n \log n)\).

Linear-time construction exists and is what production libraries use: the DC3 / skew algorithm (Kärkkäinen and Sanders, a divide-and-conquer on suffix positions modulo 3) and SA-IS (Nong, Zhang, and Chan, induced sorting), both \(O(n)\). Name-checked only: each is a handout’s worth of machinery, and prefix doubling is the version worth carrying in your head. The practical summary: build once in \(O(n)\) to \(O(n \log n)\), store \(n\) integers, answer every later pattern in \(O(m \log n)\).

Aside (suffix trees) The suffix array’s older sibling is the suffix tree: a compressed trie (Tries & Ternary Search Trees, which compresses one-child chains into edges labeled with substrings) whose keys are all \(n\) suffixes of the text. The sentinel gives it exactly \(n\) leaves; searching costs \(O(m)\), and it supports a wider zoo of queries directly. The two structures carry the same information: the suffix array is the left-to-right order of the tree’s leaves, the LCP array is the depth of the branching node between adjacent leaves, and the pair \((SA, LCP)\) can simulate any suffix-tree traversal (the “enhanced suffix array”). Arrays are the practical form: a suffix tree costs tens of bytes per text character in nodes, pointers, and edge labels, against 4–8 bytes per character for the array, and the array’s binary search touches memory in a cache-friendly pattern where the tree chases pointers. Linear-time suffix-tree construction (Ukkonen’s algorithm) predates linear-time suffix-array construction, but modern practice builds the array and adds LCP when tree power is needed.

5. Where this sits

The suffix array completes a symmetry in the string toolkit. Substring Search: The Problem & Baselines and its fast successors (Knuth–Morris–Pratt, Boyer–Moore) preprocess the pattern in \(O(m)\) and pay \(O(n)\) per search: right when the text streams past once. The suffix array preprocesses the text in \(O(n)\) to \(O(n \log n)\) and pays \(O(m \log n)\) per search: right when the text is fixed and the patterns keep coming. And it is the trie idea pushed to its limit: a trie exploits the character structure of a key set you chose to store; the suffix array (and the suffix tree behind it) applies the same exploit to the set of all suffixes of one string, turning questions about the string’s insides (occurrences, repeats, distinct substrings) into questions about a sorted collection. It is the index behind genome aligners, full-text search in editors and databases, plagiarism and clone detectors, and data-compression transforms that need the sorted rotations of a text.

Band \([10, 12)\), count 2, occurrences at indices \(\{5, 2\}\): \(\texttt{mi\underline{ssi}ssippi}\) and \(\texttt{missi\underline{ssi}ppi}\).
  3. Compute the LCP array of \(\texttt{mississippi\$}\) by hand from the sorted table of exercise 1, and read off the longest repeated substring.
    solution Comparing each row with the one above: \(LCP = [\,\text{–}, 0, 1, 1, 4, 0, 0, 1, 0, 2, 1, 3\,]\) (rows in the order of the table: $|i$ share 0, i$|ippi$ share 1 (i), ippi$|issippi$ share 1, issippi$|ississippi$ share 4 (issi), then 0 at the i/m and m/p borders, pi$|ppi$ share 1, 0 at p/s, sippi$|sissippi$ share 2 (si), sissippi$|ssippi$ share 1, ssippi$|ssissippi$ share 3 (ssi)). The maximum is \(LCP[4] = 4\): longest repeated substring \(\texttt{issi}\), at text indices \(SA[3] = 4\) and \(SA[4] = 1\): \(\texttt{m\underline{issi}ssippi}\) and \(\texttt{miss\underline{issi}ppi}\), overlapping at index 4.
  4. Run prefix doubling on \(t = \texttt{abab\$}\) (\(n = 5\)): compute \(rank_1\), trace the round \(k = 1 \to 2\) (all five rank pairs and the new ranks), state which tie survives, and finish.
    solution With \(\texttt{\$}=0, \texttt{a}=1, \texttt{b}=2\): \(rank_1 = [\,1, 2, 1, 2, 0\,]\). Round \(k = 1 \to 2\), pairs \((rank_1[i], rank_1[i+1])\), with \(-1\) past the end:
    \(i\)suffixpair\(rank_2[i]\)
    0abab$(1, 2)1
    1bab$(2, 1)3
    2ab$(1, 2)1
    3b$(2, 0)2
    4$(0, −1)0
    Sorted: \((0,-1) < (1,2) = (1,2) < (2,0) < (2,1)\), so \(rank_2 = [\,1, 3, 1, 2, 0\,]\). The surviving tie is suffixes 0 and 2, \(\texttt{abab\$}\) and \(\texttt{ab\$}\): both start \(\texttt{ab}\). Round \(k = 2 \to 4\) pairs ranks two apart: \(i=0\!: (1, rank_2[2]) = (1,1)\), \(i=2\!: (1, rank_2[4]) = (1,0)\), and \((1,0) < (1,1)\) breaks the tie (suffix 2’s continuation reaches the sentinel first): \(rank_4 = [\,2, 4, 1, 3, 0\,]\), all distinct. Reading indices in rank order: \(SA = [\,4, 2, 0, 3, 1\,]\), which is the sorted list \(\texttt{\$}, \texttt{ab\$}, \texttt{abab\$}, \texttt{b\$}, \texttt{bab\$}\).
  5. Two searches in \(\texttt{banana\$}\) that miss differently: (a) \(p = \texttt{z}\); (b) in \(\texttt{mississippi\$}\), \(p = \texttt{issa}\). For each, say where the lower bound lands and which check rejects it.
    solution (a) Every suffix starts with $, a, b, or n, all \(< \texttt{z}\), so every comparison says “suffix < pattern” and lo climbs to \(n = 7\) (trace: mid 3 \(\texttt{anana\$}\), mid 5 \(\texttt{na\$}\), mid 6 \(\texttt{nana\$}\), all <). The lo < n guard fails: miss, with no suffix ever tested for a prefix. (b) The lower bound lands at row 3, \(\texttt{issippi\$}\): every earlier row is \(< \texttt{issa}\) (row 2, \(\texttt{ippi\$}\), loses at position 1, p < s) and \(\texttt{issippi\$} > \texttt{issa}\) at position 3 (i > a). The landing row exists but does not start with \(\texttt{issa}\): the startswith check rejects it. These are the only two miss shapes; a hit is exactly “lands in range and starts with the pattern”.
  6. The number of distinct nonempty substrings of \(t\) (sentinel excluded from \(t\)) equals the total length of all suffixes minus \(\sum_r LCP[r]\). Explain why, and evaluate it for \(\texttt{banana}\) using the arrays of the build and LCP sections (drop the sentinel row and its \(LCP\) entry of 0; the sentinel contributes nothing else).
    solution Every substring is a prefix of exactly the suffixes it starts, so counting distinct substrings is counting distinct suffix prefixes. Walk the rows in sorted order: row \(r\)’s suffix has as many prefixes as its length, but its first \(LCP[r]\) prefixes already appeared as prefixes of row \(r-1\)’s suffix (they share exactly that much), and no longer prefix of row \(r\) can have appeared earlier (rows before \(r-1\) share \(\le LCP[r]\) with row \(r\), since the band sharing more is contiguous and would include \(r-1\)). So row \(r\) contributes \(|suffix_r| - LCP[r]\) new prefixes. For \(\texttt{banana}\): suffix lengths sum to \(6+5+4+3+2+1 = 21\); the LCP entries among the six real rows (\(\texttt{a}, \texttt{ana}, \texttt{anana}, \texttt{banana}, \texttt{na}, \texttt{nana}\), same order as the build section’s table minus row 0) are \(0, 1, 3, 0, 0, 2\), summing to 6. Distinct substrings: \(21 - 6 = 15\). Check by hand: \(\texttt{a}, \texttt{an}, \texttt{ana}, \texttt{anan}, \texttt{anana}, \texttt{b}, \texttt{ba}, \texttt{ban}, \texttt{bana}, \texttt{banan}, \texttt{banana}, \texttt{n}, \texttt{na}, \texttt{nan}, \texttt{nana}\): fifteen.
  7. A text of length \(n = 2^{30}\) (about a billion characters) is searched for \(10^6\) different patterns of length \(m \le 50\). Compare the total character-comparison budget of (a) running Knuth–Morris–Pratt per pattern and (b) building a suffix array once (assume the \(O(n \log n)\) doubling build) and binary-searching per pattern. Where is the crossover?
    solution (a) KMP costs \(O(n + m)\) per pattern: about \(10^6 \times 2^{30} \approx 10^{15}\) character comparisons in all; the billion-character scan is paid a million times. (b) The build costs \(O(n \log n) \approx 2^{30} \times 30 \approx 3 \times 10^{10}\) operations, paid once; each search costs \(O(m \log n) \le 50 \times 31 \approx 1550\) character comparisons, so \(10^6\) searches add \(\approx 1.6 \times 10^9\): total \(\approx 3 \times 10^{10}\), about \(30{,}000\) times less than (a). The crossover: the array wins as soon as the number of searches exceeds roughly build cost divided by scan cost, \((n \log n)/n = \log n \approx 30\) searches. Thirty queries against a fixed text already justify indexing it; this is the precompute-to-answer-fast trade, with the roles of pattern and text exchanged relative to Substring Search: The Problem & Baselines.
