Knuth–Morris–Pratt

Donald Knuth found the algorithm by working through a theorem of Stephen Cook about two-way pushdown automata. James Morris had found it independently while writing a text editor, and the three published together in 1977. D. E. Knuth, J. H. Morris and V. R. Pratt, “Fast Pattern Matching in Strings,” SIAM J. Computing 6(2), 1977

Brute-force substring search (Substring Search: The Problem & Baselines) re-examines text characters after every partial match, and pays \(\Theta(nm)\) in the worst case. The Knuth–Morris–Pratt (KMP) algorithm eliminates the re-reading. The key observation: when a mismatch occurs after matching \(j\) characters, those last \(j\) text characters are not unknown: they equal the pattern’s first \(j\) characters, which we know perfectly well. So instead of rewinding the text, slide the pattern forward to the next alignment consistent with what was just matched, and resume. The text pointer \(i\) never decreases; on a mismatch only the pattern pointer \(j\) falls back.

1. The insight, and the failure function

Example (the key insight) 
  text:     A B A B A B C …
  pattern:  A B A B C
                    ↑ mismatch at pattern[4]
We matched ABAB and failed at pattern[4]. Brute force would slide by one and re-read from text[1]. But look at what was matched: AB is a prefix of the pattern that is also a suffix of the matched ABAB. Slide the pattern so that prefix re-aligns under the text’s last two matched characters, resume comparing at pattern[2], and never move \(i\) back. The “how much of my partial match survives” number is what KMP precomputes, for every mismatch position, before ever touching the text.
Definition (failure function) For a pattern \(P\) of length \(m\), the failure function is the array \[ \mathit{fail}[j] = \text{length of the longest }\textit{proper}\text{ prefix of } P[0..j] \text{ that is also a suffix of } P[0..j], \] for \(j = 0, \dots, m-1\), where \(P[0..j]\) means the first \(j+1\) characters (inclusive). “Proper” excludes the whole string, so \(\mathit{fail}[0] = 0\) always. Reading: if my partial match ends at \(P[j]\) and then breaks, \(\mathit{fail}[j]\) matched characters survive. After matching \(j\) characters, a mismatch sends the pattern pointer to \(j = \mathit{fail}[j-1]\), and the text pointer stays put.
Example (failure function, worked) Pattern AABAA:
j01234
P[j]AABAA
fail[j]01012
Walk it: \(\mathit{fail}[1] = 1\) (prefix A = suffix A of AA); \(\mathit{fail}[2] = 0\) (AAB ends in B, no prefix survives); \(\mathit{fail}[3] = 1\) (AABA ends with the prefix A); \(\mathit{fail}[4] = 2\) (AABAA ends with the prefix AA). So a mismatch after matching all of AABAA falls back to \(j = \mathit{fail}[4] = 2\): the AA the text just supplied re-serves as the pattern’s first two characters.
Example (a second table: the exam classic) Pattern ABABAC:
j012345
P[j]ABABAC
fail[j]001230
The ABAB self-overlap grows the entries \(1, 2, 3\) (prefixes A, AB, ABA re-appear as suffixes), and the final C matches no prefix, resetting to \(0\). A mismatch at \(j = 5\) (after matching ABABA) falls back to \(j = \mathit{fail}[4] = 3\): the ABA prefix re-aligns under the text’s last three matched characters. Fill in one of these tables by hand; it is the standard exam question on KMP.

2. Building the table, and the search

The failure function is computed by matching the pattern against itself: a running index \(k\) tracks the current longest prefix-suffix, growing by one when the next character extends it and falling back through the (partially built) table when it does not: the same never-back-up logic, applied to the pattern. The build is \(\Theta(m)\); then the scan reads each text character with the same extend-or-fall-back step. Both loops below are four lines long, and getting the build loop right is the crux of implementing KMP: trace it once on AABAA. 

// Failure function: fail[j] = length of the longest proper prefix of the
// pattern's first j+1 characters that is also a suffix of them. Built by
// matching the pattern against ITSELF: k falls back through the very table
// under construction. Theta(m).
vector<int> failureFn(const string& p) {
    int m = p.size();
    vector<int> fail(m, 0);
    int k = 0;                             // length of the current prefix-suffix
    for (int j = 1; j < m; j++) {
        while (k > 0 && p[j] != p[k]) k = fail[k - 1];  // shrink until it extends
        if (p[j] == p[k]) k++;             // extend the prefix-suffix
        fail[j] = k;
    }
    return fail;
}

// KMP search: the text pointer i NEVER decreases; on a mismatch only the
// pattern pointer j falls back, via the table. Theta(n) scan after the
// Theta(m) build: Theta(n + m) total, guaranteed.
int kmpSearch(const string& t, const string& p) {
    vector<int> fail = failureFn(p);
    int j = 0;                             // characters matched so far
    for (int i = 0; i < (int)t.size(); i++) {
        while (j > 0 && t[i] != p[j]) j = fail[j - 1];  // fall back in the pattern
        if (t[i] == p[j]) j++;             // extend the partial match
        if (j == (int)p.size()) return i - j + 1;       // full match: report start
    }
    return -1;                             // no occurrence
}

// Failure function: fail[j] = length of the longest proper prefix of the
// pattern's first j+1 characters that is also a suffix of them. Built by
// matching the pattern against ITSELF: k falls back through the very table
// under construction. O(m).
fn failure_fn(p: &str) -> Vec<usize> {
    let p = p.as_bytes();
    let mut fail = vec![0usize; p.len()];
    let mut k = 0;                         // length of the current prefix-suffix
    for j in 1..p.len() {
        while k > 0 && p[j] != p[k] { k = fail[k - 1]; }  // shrink until extends
        if p[j] == p[k] { k += 1; }        // extend the prefix-suffix
        fail[j] = k;
    }
    fail
}

// KMP search: the text pointer i NEVER decreases; on a mismatch only the
// pattern pointer j falls back, via the table. O(n) scan after the O(m)
// build: O(n + m) total, guaranteed.
fn kmp_search(t: &str, p: &str) -> i32 {
    let fail = failure_fn(p);
    let (t, p) = (t.as_bytes(), p.as_bytes());
    let mut j = 0;                         // characters matched so far
    for i in 0..t.len() {
        while j > 0 && t[i] != p[j] { j = fail[j - 1]; }  // fall back in pattern
        if t[i] == p[j] { j += 1; }        // extend the partial match
        if j == p.len() { return (i + 1 - j) as i32; }    // full match: start
    }
    -1                                     // no occurrence
}

Between them the two loops have exactly six outcomes, and a correct hand-trace has to produce all six. One step of the build loop (one value of \(j\)) ends in one of four ways:

  1. Extend from \(k = 0\): the while loop does not run, \(P[0] = P[j]\), so \(\mathit{fail}[j] = 1\).
  2. Extend from \(k > 0\): the while loop does not run, \(P[k] = P[j]\), so \(\mathit{fail}[j] = k+1\): the current prefix-suffix grows by one at the cost of one comparison.
  3. Fall back, then extend: \(P[k] \ne P[j]\), so \(k\) walks down the chain \(\mathit{fail}[k-1], \dots\) until some candidate does extend; \(\mathit{fail}[j]\) is that shorter candidate \(+\,1\).
  4. Fall back to \(0\) and die: the chain reaches \(k = 0\) and even \(P[0] \ne P[j]\), so \(\mathit{fail}[j] = 0\): no border of \(P[0..j-1]\) extends.

One step of the search loop (one text character) ends in one of these:

  1. Match: \(t[i] = P[j]\), so \(j\) grows; if it reaches \(m\), report the occurrence at \(i - j + 1\).
  2. Mismatch with \(j > 0\): \(j\) drops to \(\mathit{fail}[j-1]\) and the same \(t[i]\) is tried again, possibly several times down the chain, possibly all the way to \(j = 0\). The text pointer does not move.
  3. Mismatch with \(j = 0\): nothing is matched, so there is nothing to fall back to; the while loop is skipped, the if fails, and \(i\) advances with \(j\) still \(0\). This is the brute-force step, and it is the only mismatch that consumes a text character.

4A1 P[1] = A = A: extend22

Finished table: \(\mathit{fail} = [0, 1, 0, 1, 2, 0]\) (\(\mathit{fail}[0] = 0\) by definition, never computed by the loop). Read the two interesting rows. At \(j = 2\) the running prefix-suffix A cannot survive a B, one fall-back empties it, and the last test proves that even the single character A does not start with B. At \(j = 5\) the chain is longer: the borders of the five matched characters AABAA are \(2, 1, 0\), and C extends none of them, so three tests establish \(\mathit{fail}[5] = 0\) exhaustively. Case 3 (fall back, then extend) does not arise in a pattern this short; it is worked in §3, where AABAAABAAAABAAAB falls from \(k = 6\) to \(2\) to \(1\) and the last candidate accepts. Eight comparisons in total for a six-character pattern, inside the \(2m = 12\) bound proved in §4.

3. Why the fall-back is right: borders

Both loops contain the same suspicious-looking move: on a mismatch, jump to \(\mathit{fail}[k-1]\) and try again. Why is that the right amount to fall back: why not one less, and how do we know nothing in between was skipped that could have worked? Both questions have the same answer, and it is worth naming the object it rests on.

Definition (border) A border of a string is a proper prefix that is also a suffix. In this vocabulary the failure function reads: \(\mathit{fail}[j]\) is the length of the longest border of \(P[0..j]\). One string can have several borders (ABABA has three: ABA, A, and the empty string), and both correctness arguments below come down to enumerating all of them.
Lemma (the fall-back chain visits every border) Let \(S\) be a string whose longest border \(C\) has length \(k\). Then the borders of \(S\) are exactly: \(C\) itself, and the borders of \(C\). Consequently the chain \[ k,\;\; \mathit{fail}[k-1],\;\; \mathit{fail}[\mathit{fail}[k-1]-1],\;\; \dots,\;\; 0 \] lists all border lengths of \(S\), in strictly decreasing order: no length strictly between two consecutive chain values can be a border.
Proof. Two directions. A border of \(C\) is a border of \(S\): a prefix of \(C\) is a prefix of \(S\) (prefix of a prefix), and a suffix of \(C\) is a suffix of \(S\) (suffix of a suffix). Every border of \(S\) shorter than \(C\) is a border of \(C\): let \(B\) be such a border, \(|B| < k\). \(B\) and \(C\) are both prefixes of \(S\), so the shorter is a prefix of the longer: \(B\) is a prefix of \(C\). \(B\) and \(C\) are both suffixes of \(S\), so likewise \(B\) is a suffix of \(C\). Hence \(B\) is a border of \(C\). So below \(C\), the borders of \(S\) and of \(C\) are the same set, and repeating the argument inside \(C\) (whose longest border has length \(\mathit{fail}[k-1]\)) walks down through every border and nothing else. ∎
Example (the chain, checked by hand) Take \(S = \) ABABA, the first five characters of the exam-classic pattern ABABAC, whose table row reads \(\mathit{fail} = [0, 0, 1, 2, 3, 0]\). The chain starts at its longest border, \(\mathit{fail}[4] = 3\): 
  chain:  3  →  fail[2] = 1  →  fail[0] = 0
  ABABA’s borders:   ABA (3)    A (1)    ε (0)
Exactly the three borders, longest first. And the lemma says why length \(2\) is legitimately absent from the chain: a border of length \(2\) would have to be a border of ABA (every shorter border lives inside the longest one), and ABA’s longest border is A, length \(1\), so no border of length \(2\) exists, and skipping from \(3\) to \(1\) skips nothing real.
Proposition (the build loop is correct) In failureFn, the while loop while (k > 0 && p[j] != p[k]) k = fail[k-1] computes \(\mathit{fail}[j]\) exactly.
Proof. What could \(\mathit{fail}[j]\) be? A nonzero border of \(P[0..j]\) ends at \(P[j]\), so it is some border of \(P[0..j-1]\) extended by one character: a border of length \(\ell\) extends precisely when \(P[\ell] = P[j]\), giving a border of length \(\ell + 1\). So the candidates for \(\mathit{fail}[j]\) are: (some border \(\ell\) of \(P[0..j-1]\) with \(P[\ell] = P[j]\)) \(+ 1\), or \(0\) if no border extends. Entering iteration \(j\), the variable \(k\) holds \(\mathit{fail}[j-1]\) (the longest border of \(P[0..j-1]\)), and the while loop walks the chain of the Lemma: it tests the borders of \(P[0..j-1]\) in strictly decreasing order, missing none, and stops at the first one that extends. The first to extend is the longest that extends, so \(\mathit{fail}[j] = k+1\) is the longest border of \(P[0..j]\). (If the chain bottoms out at \(k=0\) and even \(P[0] \ne P[j]\), no border extends and \(\mathit{fail}[j] = 0\).) ∎
Example (one build step, both outcomes) All candidates die. Pattern ABABAC, last step \(j = 5\), where \(k\) enters holding \(\mathit{fail}[4] = 3\): 
  k = 3:  P[3] = B ≠ C   → fall back, k = fail[2] = 1
  k = 1:  P[1] = B ≠ C   → fall back, k = fail[0] = 0
  k = 0:  P[0] = A ≠ C   → no border extends: fail[5] = 0
Three tests, one per border of ABABA: the loop proved no border extends by C, so \(0\) is not a guess but an exhaustive check. A shorter candidate wins. Pattern AABAAABAAAABAAAB, whose finished table is \(\mathit{fail} = [0,1,0,1,2,2,3,4,5,6,2,3,4,5,6,7]\). The interesting step is \(j = 10\): \(k\) enters holding \(\mathit{fail}[9] = 6\), and the borders of the ten matched characters AABAAABAAA are AABAAA (6), AA (2), A (1), \(\epsilon\); lengths \(3, 4, 5\) are not borders, and the chain never touches them: 
  k = 6:  P[6] = B ≠ A   → fall back, k = fail[5] = 2
  k = 2:  P[2] = B ≠ A   → fall back, k = fail[1] = 1
  k = 1:  P[1] = A = A    → extends: fail[10] = k + 1 = 2

  (j = 11, k enters as fail[10] = 2)
  k = 2:  P[2] = B = B    → extends: fail[11] = k + 1 = 3
Drawn as alignments: each candidate \(k\) slides a fresh copy of the pattern so that its first \(k\) characters sit under the last \(k\) already matched, and the cell compared is \(P[k]\) under \(P[j]\): 
  P:        A A B A A A B A A A A B A A A B
                                ↑ j = 10
  k = 6:            A A B A A A B      AABAAA re-aligned; P[6] = B ≠ A  ✗
  k = 2:                    A A B      AA re-aligned; P[2] = B ≠ A  ✗
  k = 1:                      A A      A  re-aligned; P[1] = A = A  ✓
                                  ↑ j = 11
  k = 2:                      A A B    AA (= fail[10]); P[2] = B = B  ✓
TWO fall-backs, and neither runs to \(k = 0\): the border AABAAA refuses to extend, so does AA, and A accepts: \(\mathit{fail}[10] = 2\), reached by visiting exactly the borders \(6 \to 2 \to 1\) and skipping \(5, 4, 3\) on the Lemma’s authority, not on faith. And keeping that \(k\) pays off immediately: \(j = 11\) enters with the AA border in hand, one comparison grows it to AAB, and the next four steps ride the same wave with one comparison each: \(\mathit{fail}[12..15] = 4, 5, 6, 7\). Check the end of it: the pattern indeed ends with AABAAAB, its own first seven characters.
Proposition (the search loop is correct) In kmpSearch, suppose the scan has matched \(j > 0\) characters: the pattern is aligned at text position \(i - j\), and \(t[i]\ne P[j]\). Then any occurrence of \(P\) starting after the current alignment, up to and including \(i\), must begin at \(i - \ell\) for some border length \(\ell\) of \(P[0..j-1]\); the while loop while (j > 0 && t[i] != p[j]) j = fail[j-1] tries exactly those alignments, nearest first, and every alignment it jumps over is impossible.
Proof. Consider a candidate alignment \(s'\) with \(i - j < s' \le i\), and suppose an occurrence starts there. Its first \(i - s'\) characters occupy text positions \(s' .. i-1\), all inside the region the scan already matched, where \(t[i-j..i-1] = P[0..j-1]\). So the occurrence needs \(P[0..i-s'-1]\) (a prefix of the pattern) to equal \(t[s'..i-1]\) (a suffix of the matched region, i.e. a suffix of \(P[0..j-1]\)): the length \(\ell = i - s'\) must be a border of \(P[0..j-1]\). Setting \(j = \mathit{fail}[j-1]\) moves the alignment to \(i - \mathit{fail}[j-1]\) (the candidate given by the longest border, the smallest possible forward slide), and repeating walks the Lemma’s chain: all viable alignments, in left-to-right order. Each is then judged by comparing \(t[i]\) with the new \(P[j]\); on failure the next border is tried. Alignments between two chain stops correspond to lengths that are not borders, so they cannot even agree with the text already read: the loop skips them without a single comparison, on evidence computed from the pattern alone at build time. If the chain reaches \(j = 0\), every alignment up to \(i\) is ruled out and the scan continues by comparing \(t[i]\) with \(P[0]\) (alignment \(i\) itself); alignments beyond \(i\) are untouched and remain available to later iterations. ∎
Example (the skipped alignments, drawn) Pattern AABAAC in text AABAABAAC, the same pair as the full run below. The scan matches AABAA at alignment \(0\), then hits \(t[5] = \)B \(\ne\) C\( = P[5]\): 
  text:      A A B A A B A A C
  align 0:   A A B A A C           ✗ matched AABAA, then C ≠ B at text[5]
  align 1:     A A B A A C         is AABA a border of AABAA? no, skipped
  align 2:       A A B A A C       is AAB a border? no, skipped
  align 3:         A A B A A C     is AA a border? YES: the loop’s first stop
The borders of AABAA are \(2, 1, 0\), so the only alignments worth trying are \(5-2=3\), \(5-1=4\), \(5-0=5\). The loop takes one step, \(j = \mathit{fail}[4] = 2\) (alignment \(3\)), compares \(t[5] = \)B with \(P[2] = \)B (a match), and the scan carries on to find the occurrence at index \(3\). Alignments \(1\) and \(2\) were rejected without reading a single text character: their impossibility was already a fact about the pattern. That is the whole trick of KMP: the table is a precomputed proof about \(P\), spent one mismatch at a time against \(t\).
Example (a shorter border rescues the search) Above, the loop’s first stop already matched. It need not: a stop is only a candidate, judged by comparing \(t[i]\) against the new \(P[j]\), and when it fails the loop falls to the next shorter border, without moving \(i\). Pattern AABAAB (table \(\mathit{fail} = [0,1,0,1,2,3]\)) in text AABAAABAAB. The scan matches AABAA at alignment \(0\), then hits \(t[5] = \)A \(\ne\) B\( = P[5]\), and the matched prefix is again AABAA, borders \(2, 1, 0\): 
  text:      A A B A A A B A A B
  align 0:   A A B A A B           ✗ matched AABAA, then B ≠ A at text[5]
  align 3:         A A B A A B     border AA: P[2] = B vs A  ✗; fall again
  align 4:           A A B A A B   border A:  P[1] = A vs A  ✓; j = 2, scan on
Two stops this time: the longest border’s candidate (alignment \(3\)) fails on the very next character, the loop falls once more to \(j = \mathit{fail}[1] = 1\), and the shorter border’s candidate (alignment \(4\)) accepts \(t[5]\), leaving \(j = 2\). The scan then just keeps going (\(t[6..9] = \) BAAB matches \(P[2..5]\)), and completes the occurrence at index \(4\): exactly the alignment the second fall-back chose. The shorter border was not a consolation prize; it was the real occurrence, and \(i\) never moved backward while the loop found it. (This is the search-side twin of the build example’s \(j = 10\) step above: the same walk down a matched prefix’s borders, longest first, stopping at the first that fits.)

4. Cost, the DFA view, and the demo

Proposition (KMP cost) KMP makes at most \(2n\) character comparisons in the scan, after a \(\Theta(m)\) preprocessing pass: \(\Theta(n + m)\) total, guaranteed, on every input.
Proof. Bound the scan’s comparisons by watching the quantity \(i - j\) (the pattern’s current alignment) and \(i\) itself. Each comparison ends in one of two ways. A match advances \(i\) by one, and \(i\) only ever increases, so at most \(n\) comparisons are matches. A mismatch with \(j > 0\) drops \(j\) to \(\mathit{fail}[j-1] < j\) while \(i\) stays, so the alignment \(i - j\) strictly increases; a mismatch at \(j = 0\) advances \(i\), which also increases \(i - j\). The alignment starts at \(0\), never decreases, and cannot exceed \(n\), so at most \(n\) comparisons are mismatches. Total: at most \(2n\) comparisons, and the text pointer never moved backward. The same argument applied to the build loop (pattern against itself) gives \(2m\). ∎

(Brute force on this same pair tries four alignments and makes \(15\) comparisons: its six extra are all re-examinations of text characters KMP read once.)

That run shows cases 5 and 6 of §2 with a chain of length one. The remaining two, a chain that runs all the way down to \(j = 0\) and a mismatch at \(j = 0\), appear when the text supplies a character the pattern does not contain at all:

Comparisons \(6, 7, 8\) are case 6 three times over: the chain walks the borders \(2 \to 1 \to 0\) of the matched AABAA, each step re-testing the same \(t[5]\) against a shorter alignment, with \(i\) frozen. Those three stops are the alignments \(5-2 = 3\), \(5-1 = 4\), \(5-0 = 5\). When the chain empties, the while loop’s guard \(j > 0\) fails and comparison \(9\) is case 7: the pattern is now aligned at \(i\) itself, nothing is matched, so the mismatch simply consumes the text character and the scan restarts from \(t[6]\). Fifteen comparisons in all, and \(i\) never moved backward, even while four consecutive comparisons happened at \(i = 5\). Note also what did not happen: alignments \(1\) and \(2\) were never tested, because lengths \(4\) and \(3\) are not borders of AABAA; the table ruled them out at build time.
Sedgewick’s DFA view Sedgewick presents the same precomputation as a full deterministic finite automaton (DFA) over the pattern: a 2-D table \(\mathit{dfa}[c][j]\) giving, for every alphabet character \(c\) and pattern state \(j\), the next state directly. The scan then has no fall-back loop at all: one array lookup per text character, \(j = \mathit{dfa}[t[i]][j]\). The build costs \(\Theta(Rm)\) (one entry per character–state pair) instead of \(\Theta(m)\), buying a perfectly branch-free \(\Theta(n)\) scan. It is the identical algorithm with the fall-backs tabulated in advance, and it is this handout’s bridge to Regular Expressions & Automata, where the “pattern” itself generalizes from one string to a whole language and the automaton becomes the star.
First match, all matches The code above returns the first occurrence. Find-and-replace-all, grep -c, and hit-highlighting need every occurrence, and the change is one line: on a full match, instead of returning, record the index, set \(j = \mathit{fail}[m-1]\), and keep scanning. That fall-back (rather than \(j = 0\)) correctly finds overlapping occurrences (the two AAs inside AAA), and since \(i\) still never backs up, reporting all matches is still \(\Theta(n + m)\).
Interactive Substring-search race. The Run menu picks a pairing: BF vs KMP, BF vs Boyer, KMP vs Boyer (Boyer–Moore’s bad-character rule, comparing right-to-left, its right[] table drawn under the pattern). The two chosen searchers run the same text side by side in lockstep, one comparison per tick, every occurrence found and counted. The text is typed straight into the left panel (long prose is fine; A^40B expands), the value box takes only the pattern (spaces allowed, case ignored), and the KMP panel draws fail[] under the pattern. A thin frame outlines the window of text the pattern currently covers, and playback paces itself: it hurries over first-letter misses and slows wherever a partial match is being extended or torn down. The bold filled chip is the comparison in flight (at \(t[i]\) and \(P[j]\) simultaneously), and the tinted run is the current partial match, highlighted in the text and the pattern; on a fall-back it shortens in place while \(i\)’s chip stands still, with the consulted fail[] cell in amber. The counting is deliberately honest: KMP’s panel splits its total into cmp + tbl (character comparisons plus failure-table consultations), because a fall-back is a memory read and a jump, work a compare-only counter would hide. On this handout’s running pair ABABABCABABABCAB / ABABC both find \(2\) matches, at \(32\) total ops against \(18 + 4 = 22\); the adversarial A^40B / A^6B reads \(245\) against \(75 + 35 = 110\) (a \(2.2\times\) win even on honest totals), and KMP freezes, finished, while brute force is still re-scanning. The examples… menu loads both of §3’s drawn diagrams (including AABAAABAAB / AABAAB, the shorter-border rescue), an overlapping-matches case (AA in A^6: five hits, because a full match continues with \(j = \mathit{fail}[m-1]\)), and a DNA run on real data: GATC (the Sau3AI restriction site) in the first \(1150\) bases of the human mitochondrial reference sequence (rCRS, NC_012920), \(3\) cut sites found. On the DNA, brute force beats both clever algorithms: \(1364\) against KMP’s \(1315 + 168 = 1483\) and Boyer–Moore’s \(1000 + 707 = 1707\). A 4-letter alphabet defeats them symmetrically: GATC’s lack of self-overlap (\(\mathit{fail} = [0,0,0,0]\)) means KMP’s table never saves a comparison while every teardown costs a read, and every text character occurs somewhere in GATC, so the bad-character leap never comes (the average shift is barely \(2\)). On the prose the tables turn: Boyer–Moore reads only \(158\) of the \(807\) characters (\(+\,91\) table reads \(= 249\) ops) against brute force’s \(897\): Boyer–Moore’s sublinear claim, live on screen. That is the honest shape of the family: brute force wins small alphabets, Boyer–Moore wins real text, and KMP’s prize is the worst-case guarantee plus the never-back-up property the next paragraph turns into streaming: the one thing Boyer–Moore, re-reading inside every window, cannot offer.

Scaled up, the gap is not academic: on an all-As text with \(n = 10^6\) and \(m = 1000\), brute force makes about \(n \cdot m = 10^9\) comparisons and KMP about \(n + m \approx 10^6\): a thousandfold difference on a megabyte of data. And because the text pointer never retreats, KMP reads its input strictly left to right, once: it runs happily on a stream it cannot rewind (network traffic, a pipe, a file too big to buffer), which no algorithm that backs up or looks ahead can do.

5. Exercises (with solutions)

  1. Compute the failure function of AAAA and of ABCABD.
    solution AAAA: \([0, 1, 2, 3]\); each added A extends the self-overlap by one (the longest proper prefix of \(j+1\) As that is also a suffix is \(j\) As). ABCABD: \([0, 0, 0, 1, 2, 0]\); B and C match no prefix; then A, B rebuild the overlap to \(1, 2\) (AB is both prefix and suffix of ABCAB); the final D fails against \(P[2] = \texttt{C}\), falls back to \(\mathit{fail}[1] = 0\), fails against \(P[0] = \texttt{A}\), and settles at \(0\).
  2. KMP is searching for ABABC (\(\mathit{fail} = [0, 0, 1, 2, 0]\)) in ABABABCABABABCAB. The first four comparisons match ABAB; comparison five finds \(\texttt{text}[4] = \texttt{A} \ne \texttt{C} = P[4]\). What exactly happens next, and why is it safe not to move \(i\)?
    solution The mismatch after \(j = 4\) matched characters sets \(j = \mathit{fail}[3] = 2\) while \(i\) stays at \(4\): the next comparison is text[4] = A against \(P[2] = \texttt{A}\) (a match), and the scan proceeds to find the full match at index \(2\) after \(8\) total comparisons. It is safe because the matched text text[0..3] = ABAB is known: its suffix AB equals the pattern’s prefix AB, so the only alignment worth trying next is the one where that prefix re-uses the last two matched text characters: everything the fall-back skipped provably cannot match. The text characters before \(i = 4\) never need re-reading.
  3. Run the build loop on AABAAA, showing for each \(j\) the value \(k\) holds on entry, the inner-loop tests, and \(\mathit{fail}[j]\). Which step is case 3 of §2 (fall back, then extend), and how does its answer differ from the same step for AABAAC?
    solution
    jP[j]k intestsfail[j]
    1A0P[0] = A = A1
    2B1P[1] = A ≠ B: k = fail[0] = 0; P[0] = A ≠ B0
    3A0P[0] = A = A1
    4A1P[1] = A = A2
    5A2P[2] = B ≠ A: k = fail[1] = 1; P[1] = A = A2
    \(\mathit{fail} = [0,1,0,1,2,2]\). Step \(j = 5\) is case 3: the longest candidate, the border AA of AABAA, does not extend by A (it would need \(P[2] = \texttt{B}\) to be A), the chain falls to the border A, and that one extends, giving \(\mathit{fail}[5] = 1 + 1 = 2\). For AABAAC the same step walks the same chain but nothing extends, so it runs on to \(k = 0\) and yields \(0\): same borders, different last character, opposite endings.
  4. Search for ABABAC (\(\mathit{fail} = [0,0,1,2,3,0]\)) in ABABABABAC. How many comparisons does the scan make, how many of them are mismatches, and at which text positions does \(i\) stand still?
    solution Twelve comparisons, two of them mismatches, both at \(j = 5\) (\(P[5] = \texttt{C}\) against a B), at \(i = 5\) and \(i = 7\). Each sets \(j = \mathit{fail}[4] = 3\) with \(i\) frozen, and the very next comparison, \(t[i] = \texttt{B}\) against \(P[3] = \texttt{B}\), succeeds, so the chain stops at its first stop both times (case 6 with a one-step chain). The match is found at index \(4\) on comparison \(12\). The three characters ABA already matched are reused twice without being re-read: brute force would restart at \(i = 1\) and make \(20\) comparisons over five alignments.
