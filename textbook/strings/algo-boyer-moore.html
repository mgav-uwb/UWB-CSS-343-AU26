Boyer–Moore

Data Structures & Algorithms. Algorithm.
Substring search at practical speed: compare each alignment right to left, and on a mismatch let the mismatched text character decide the jump, skipping up to a whole pattern length for one comparison. The bad-character rule with a worked trace, the good-suffix rule, and the quadratic worst case that the linear-guarantee fixes address. With the race demo, and exercises.

Knuth–Morris–Pratt guarantees linearity; Boyer–Moore goes after raw speed, and on typical text it examines fewer than \(n\) characters (sublinear), which is why it (or a variant) sits inside grep and most editors’ find. The substring-search problem and its brute-force baseline are in Substring Search: The Problem & Baselines. The written treatment here is the idea, the code, and worked traces of every shift the rule can produce; the race demo implements the same bad-character rule, so every claim in this handout can be checked live (pick BF vs Boyer or KMP vs Boyer in its Run menu).

1. Right to left, and the bad-character rule

Two reversals produce the speed. Compare each alignment right to left; then, on a mismatch, use the mismatched text character (the bad character) to decide the jump. If that character does not occur in the pattern at all, no alignment overlapping it can possibly match, so the pattern leaps past it entirely: up to \(m\) positions skipped for one comparison. If it does occur, slide the pattern so its last occurrence lines up under the text character (never sliding backward: the shift is at least 1).

Example (Boyer–Moore, worked) Search for SEARCH (\(m = 6\)) in STRING SEARCH (\(n = 13\)). Cells show the pattern’s placement; only green (compared, matched) and amber (compared, mismatched) cells were actually examined; plain cells were skipped without a look:
text →STRING␣SEARCHcompares

Alignment 0: the rightmost comparison pits pattern[5] = H against text[5] = G, and G occurs nowhere in SEARCH, so the pattern jumps past it: shift by \(6\), one comparison for six positions. Alignment 6: H against text[11] = C; C does occur in the pattern (last occurrence at index \(4\)), so slide until they line up: shift by \(5 - 4 = 1\). Alignment 7: the right-to-left comparison matches all six: found at index \(7\). Total: \(8\) comparisons to search a \(13\)-character text; six of the text’s characters were never examined at all. That is the sublinear effect, and it grows with \(m\): a longer pattern skips further.
The full algorithm: two rules Industrial Boyer–Moore precomputes two shift tables from the pattern and jumps by whichever is larger. The bad-character rule is the one traced above (as a lone heuristic it is the Boyer–Moore–Horspool variant, a popular simplification). The good-suffix rule is KMP’s idea pointed the other way: the alignment just matched a suffix of the pattern before failing, so slide to the next place that suffix (or a prefix of the pattern matching its tail) re-occurs. Combined, they make Boyer–Moore the practical champion on natural text; its plain worst case is \(\Theta(nm)\) (e.g. all-A texts), with known fixes that restore a linear guarantee at some constant-factor cost.

2. The right[] table, and the code

The rule needs one precomputed table. right[c] is the index of the rightmost occurrence of character \(c\) in the pattern, and \(-1\) if \(c\) does not occur: one pass over the pattern, later occurrences overwriting earlier ones. On a mismatch at \(P[j]\) against text character \(c\), the shift is \(j - \mathit{right}[c]\), clamped to at least \(1\) so the pattern never slides backward. For the pattern NEEDLE (used in the trace of the next section):

right[c]0534−1

E occurs three times (indices \(1, 2, 5\)) and the table keeps only the last, \(5\): the rightmost occurrence gives the smallest forward slide that lines the characters up, and any larger slide could jump over a match. The scan itself is the brute-force loop with both reversals installed: compare right to left, and advance by the table’s verdict. 

// Bad-character table: right[c] = index of the RIGHTMOST occurrence of c in
// the pattern, -1 if absent. One pass, later occurrences overwrite: Theta(m + R).
vector<int> rightmost(const string& p) {
    vector<int> right(256, -1);
    for (int j = 0; j < (int)p.size(); j++)
        right[(unsigned char)p[j]] = j;
    return right;
}

// Boyer-Moore, bad-character rule: compare each alignment RIGHT to left; on a
// mismatch at p[j] against text character c, slide so the pattern's rightmost
// c lands under it: shift = j - right[c], clamped to at least 1 (never slide
// backward). Sublinear on typical text; Theta(nm) worst case.
int bmSearch(const string& t, const string& p) {
    int n = t.size(), m = p.size();
    vector<int> right = rightmost(p);
    int skip;
    for (int i = 0; i + m <= n; i += skip) {
        skip = 0;
        for (int j = m - 1; j >= 0; j--)           // right to left
            if (p[j] != t[i + j]) {
                skip = j - right[(unsigned char)t[i + j]];
                if (skip < 1) skip = 1;            // clamp: at least 1
                break;
            }
        if (skip == 0) return i;                   // all m matched: found
    }
    return -1;                                     // no occurrence
}
// Bad-character table: right[c] = index of the RIGHTMOST occurrence of c in
// the pattern, -1 if absent. One pass, later occurrences overwrite: Theta(m + R).
static int[] rightmost(String p) {
    int[] right = new int[256];
    Arrays.fill(right, -1);
    for (int j = 0; j < p.length(); j++)
        right[p.charAt(j)] = j;
    return right;
}

// Boyer-Moore, bad-character rule: compare each alignment RIGHT to left; on a
// mismatch at p[j] against text character c, slide so the pattern's rightmost
// c lands under it: shift = j - right[c], clamped to at least 1 (never slide
// backward). Sublinear on typical text; Theta(nm) worst case.
static int bmSearch(String t, String p) {
    int n = t.length(), m = p.length();
    int[] right = rightmost(p);
    int skip;
    for (int i = 0; i + m <= n; i += skip) {
        skip = 0;
        for (int j = m - 1; j >= 0; j--) {         // right to left
            if (p.charAt(j) != t.charAt(i + j)) {
                skip = Math.max(1, j - right[t.charAt(i + j)]);
                break;                             // clamp: at least 1
            }
        }
        if (skip == 0) return i;                   // all m matched: found
    }
    return -1;                                     // no occurrence
}

def rightmost(p):

# Boyer-Moore, bad-character rule: compare each alignment RIGHT to left; on a
# mismatch at p[j] against text character c, slide so the pattern's rightmost
# c lands under it: shift = j - right[c], clamped to at least 1 (never slide
# backward). Sublinear on typical text; Theta(nm) worst case.
def bm_search(t, p):
    n, m = len(t), len(p)
    right = rightmost(p)
    i = 0
    while i + m <= n:
        skip = 0
        for j in range(m - 1, -1, -1):     # right to left
            if p[j] != t[i + j]:
                skip = max(1, j - right.get(t[i + j], -1))
                break                      # clamp: at least 1
        if skip == 0:
            return i                       # all m matched: found
        i += skip
    return -1                              # no occurrence
// Bad-character table: right[c] = index of the RIGHTMOST occurrence of c in
// the pattern, -1 if absent. One pass, later occurrences overwrite: O(m + R).
fn rightmost(p: &[u8]) -> [i32; 256] {
    let mut right = [-1i32; 256];
    for (j, &c) in p.iter().enumerate() {
        right[c as usize] = j as i32;      // later occurrences overwrite
    }
    right
}

// Boyer-Moore, bad-character rule: compare each alignment RIGHT to left; on a
// mismatch at p[j] against text character c, slide so the pattern's rightmost
// c lands under it: shift = j - right[c], clamped to at least 1 (never slide
// backward). Sublinear on typical text; O(nm) worst case.
fn bm_search(t: &str, p: &str) -> i32 {
    let (t, p) = (t.as_bytes(), p.as_bytes());
    let (n, m) = (t.len() as i32, p.len() as i32);
    let right = rightmost(p);
    let mut i = 0i32;
    while i + m <= n {
        let mut skip = 0i32;
        for j in (0..m).rev() {            // right to left
            if p[j as usize] != t[(i + j) as usize] {
                let c = t[(i + j) as usize] as usize;
                skip = (j - right[c]).max(1);   // clamp: at least 1
                break;
            }
        }
        if skip == 0 { return i; }         // all m matched: found
        i += skip;
    }
    -1                                     // no occurrence
}

Note what the code does not do: nothing remembers the matched suffix of a failed alignment, so unlike Knuth–Morris–Pratt (KMP) the next alignment may re-read text characters this one already compared. The bet is that the jumps more than pay for the re-reads, and on real text they do.

3. A second trace, and every case of the shift

One alignment’s right-to-left scan ends in exactly one of four ways, and a correct hand-trace must handle all four:

  1. Full match: all \(m\) comparisons succeed; report the index.
  2. Mismatch, \(c\) absent (\(\mathit{right}[c] = -1\)): no alignment overlapping \(c\) can match; shift \(j - (-1) = j + 1\), past it entirely.
  3. Mismatch, \(\mathit{right}[c] < j\): slide the rightmost \(c\) under the text’s \(c\); shift \(j - \mathit{right}[c] \ge 1\).
  4. Mismatch, \(\mathit{right}[c] \ge j\): the rightmost \(c\) sits at or to the right of the mismatch, so the formula is zero or negative, a backward slide. The clamp fires: shift \(1\). The rule learned nothing usable; only correctness (never go backward) decides the move.

The §1 trace showed cases 1, 2, and 3 with every mismatch on the first comparison. This trace adds a mismatch after a partial match: NEEDLE (\(m = 6\)) in FINDINAHAYSTACKNEEDLE (\(n = 21\)), with the \(\mathit{right}\) table of §2:

Alignment 15: all six match (case 1): found at index \(15\). Total: \(10\) comparisons for a \(21\)-character text, and eleven text characters never examined.

Example (case 4: the clamp) Search for BAAAA (\(m = 5\), \(\mathit{right}[\texttt{A}] = 4\), \(\mathit{right}[\texttt{B}] = 0\)) in AAAAAAAAAA (\(n = 10\)). Every alignment plays out identically: 
  text:     A A A A A A A A A A
  align 0:  B A A A A            scan right to left: A,A,A,A match,
                                 then P[0] = B vs t[0] = A mismatches
  rule:     j = 0, c = A, right[A] = 4  →  shift 0 - 4 = -4  → CLAMPED to 1
  align 1:  . B A A A A          the same five comparisons, the same clamp
  …         (6 alignments of 5 comparisons each: 30 comparisons, no match)
The mismatched A occurs in the pattern to the right of the mismatch position, so “line up the rightmost A” would slide the pattern backward, and the clamp advances it by \(1\) instead. Every alignment then costs \(m\) comparisons and gains one position: the sublinear engine running at its worst. The next section turns this example into the worst-case bound.

4. Cost: sublinear on top, quadratic on the bottom

Proposition (best case \(\approx n/m\)) If every alignment mismatches on its first comparison against a character absent from the pattern, Boyer–Moore makes about \(n/m\) comparisons in total.
Proof. Such an alignment costs exactly one comparison (case 2 of §3) and shifts by \(j + 1 = m\). The alignments therefore sit \(m\) apart: about \(n/m\) of them, one comparison each. The condition is not exotic: searching English prose for a word with an uncommon final letter meets it at most alignments, which is why the demo’s prose run examines fewer than a fifth of the text’s characters. A longer pattern makes the search cheaper: the opposite of every other algorithm in this unit. ∎
Proposition (worst case \(\Theta(nm)\)) With the bad-character rule alone, there are pattern/text pairs on which Boyer–Moore makes \(\Theta(nm)\) comparisons.
Proof. The clamp example of §3, scaled up: pattern \(\texttt{B}\texttt{A}^{m-1}\), text \(\texttt{A}^n\). Every alignment matches \(m - 1\) A’s right to left, then mismatches \(P[0] = \texttt{B}\) against an A; since \(\mathit{right}[\texttt{A}] = m - 1 > 0\), the shift clamps to \(1\). So each of the \(n - m + 1\) alignments costs \(m\) comparisons: \((n - m + 1)\,m = \Theta(nm)\), brute force’s worst case with extra steps. ∎

Both bounds are real, and the gap between them is the Boyer–Moore trade: typically far under \(n\), with no worst-case guarantee. The good-suffix rule (§1’s aside) does not close the gap by itself; the known fixes that do (Galil’s rule, which remembers the matched suffix across alignments the way KMP remembers its prefix) restore a linear guarantee at a constant-factor cost, and engines that need the guarantee cheaply instead fall back on KMP. On the DNA alphabet the sublinear case collapses for a different reason: with \(R = 4\), every text character occurs in any reasonable pattern, so case 2 never fires and the average shift is small; the demo’s GATC run measures exactly that.

5. Exercises (with solutions)

  1. Boyer–Moore is matching SEARCH right to left, and the very first comparison of an alignment mismatches at \(P[5] = \texttt{H}\). Using the bad-character rule, give the shift when the mismatched text character is (a) X, (b) S, (c) R.
    solution The rule slides the pattern so its last occurrence of the text character lands under it: shift \(= j - \mathit{last}[c]\) with \(\mathit{last}[c] = -1\) for an absent character (taking at least \(1\)). Last occurrences in SEARCH: S:0, E:1, A:2, R:3, C:4, H:5. (a) X is absent: \(5 - (-1) = 6\); leap the whole pattern past it. (b) S: \(5 - 0 = 5\). (c) R: \(5 - 3 = 2\). One comparison can thus discard up to \(m\) alignments: the sublinear engine.
  2. Build the \(\mathit{right}\) table for the pattern ABABAC, then give the shift for each of these mismatches: (a) \(P[5] = \texttt{C}\) against text character B; (b) \(P[5] = \texttt{C}\) against A; (c) \(P[1] = \texttt{B}\) against C. Which case of §3 is each?
    solution Scanning ABABAC left to right and letting later occurrences overwrite: \(\mathit{right}[\texttt{A}] = 4\), \(\mathit{right}[\texttt{B}] = 3\), \(\mathit{right}[\texttt{C}] = 5\), everything else \(-1\). (a) \(5 - 3 = 2\) (case 3). (b) \(5 - 4 = 1\), the smallest useful slide, still case 3. (c) \(\mathit{right}[\texttt{C}] = 5 \ge j = 1\), so the formula gives \(1 - 5 = -4\), a backward slide; the clamp fires and the shift is \(1\) (case 4). The pattern’s only C is to the right of the mismatch, so lining it up would move the pattern the wrong way, and the rule contributes nothing.
