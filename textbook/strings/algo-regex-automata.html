Regular Expressions & Automata

Stephen Kleene defined regular expressions in 1951 to describe what McCulloch-Pitts nerve nets can recognize. Ken Thompson’s 1968 paper compiled them to machine code for the QED text editor. S. C. Kleene, RAND memorandum, 1951; K. Thompson, “Regular Expression Search Algorithm,” CACM 11(6), 1968

The substring-search handout searched a text for one fixed pattern. This handout generalizes the pattern itself: a regular expression describes not one string but a whole set of strings (all binary numerals, all valid phone numbers, all strings ending in B), and the matching question becomes “is this string in the set?” The beautiful result is that every such pattern can be compiled into a machine: a finite automaton that reads the string once and answers yes or no. We build that machine (Thompson’s construction), run it (by tracking a set of states: graph reachability from the DFS handout, reused), and close with Kleene’s theorem, which says the pattern and the machine have exactly the same expressive power. Pattern in, machine out: theory meets practice.

1. Regular expressions and the languages they describe

Definition (regular expression; language) A regular expression (regex) over an alphabet is a pattern built from single characters and four operations: concatenation (AB: an A then a B), or (A|B: an A or a B), closure (A*: zero or more A’s), and grouping ((…)). A regex denotes a language \(L\) (the set of all strings it matches), and a string matches the regex if and only if it is in that language.

You use regexes daily (grep, editor find, input validation), and the four operations generate everything:

regexmatches
ABexactly "AB"
A|B"A" or "B"
A*"", "A", "AA", "AAA", …
(AB)*"", "AB", "ABAB", …

Thinking in terms of the set of accepted strings (not the character-by-character syntax) is what connects regexes to automata, which are membership testers for these sets:

\[ \begin{aligned} L(\texttt{A*B}) &= \{\texttt{B}, \texttt{AB}, \texttt{AAB}, \texttt{AAAB}, \dots\} \quad \text{(any run of A's, then a B)}\\ L(\texttt{(A|B)C}) &= \{\texttt{AC}, \texttt{BC}\}\\ L(\texttt{(0|1)*}) &= \text{every binary string, of any length, including the empty one}\\ L(\texttt{A(B|C)*D}) &= \text{an A, then any mix of B's and C's, then a D} \end{aligned} \]

The reading skill is to decompose at the outermost operator first: break the regex at its top-level | and *, then recurse into the groups. That recursive structure is exactly what the machine construction of §3 will follow.

Example (does it match?) Which of "ABAB", "ABA", and "" does (AB)* match? "ABAB" is two copies of AB: match. "ABA" has a dangling A that no whole number of copies covers: no match. And the empty string matches, because * allows zero copies, the case students forget. Read * as “any number, including none.”
Example (write the regex) Over the alphabet \(\{\texttt{A},\texttt{B}\}\), describe all strings that end in B. Answer: (A|B)*B, anything, then one final B. Check it against boundary strings: "B" matches (the star contributes zero characters), "AB" and "AABB" match; "BA" fails (ends in A) and "" fails (there must be at least the final B). The common wrong answer is A*B: it describes “A’s then a B,” which rejects "BAB" even though that string does end in B. Testing a proposed pattern against the empty string, single characters, and one deliberately tricky case is exactly how you should test real-world regexes too.
Precedence: the #1 source of regex bugs Binding tightest to loosest: *, then concatenation, then |. So AB|C = (AB)|C, A|BC = A|(BC), and AB* = A(B*), which is not (AB)*: the first is one A followed by any number of B’s, the second any number of AB pairs. When in doubt, parenthesize. This is the same operator-precedence discipline as arithmetic expressions, and the machine builder in §3 will use a stack to respect it, exactly as an expression evaluator does.
Everything else is sugar The rest of practical regex syntax is shorthand over the four operations. Here \(\varepsilon\) is the empty string: zero characters, the theory-book name for "", and the same \(\varepsilon\) that labels the free moves of §2’s automata:

(Inside brackets ^ negates; outside them, as the end of this aside explains, it anchors.) Because it is all sugar, machinery for the four core operations handles every regex. Two practical symbols are not sugar, because they change what “match” means rather than describing strings: ^ anchors the match to the start of the text, $ to the end. In the theory of this section a regex always describes whole strings; a practical engine instead searches for the pattern anywhere inside the text, and ^…$ turns that back into whole-string matching. A validator should anchor (or call a whole-string primitive such as Python’s re.fullmatch): without anchors, \d{3} happily “validates” abc123xyz by finding the 123 inside it.
Example (a real pattern, decoded and boundary-checked) The phone validator \(?\d{3}\)?[- ]?\d{3}-?\d{4} matches (206) 555-1234, 206-555-1234, and 2065551234. Piece by piece:
piecematches
\(?an optional literal (: \( is one token, and ? applies to it

The piece that trips readers is \(?: the backslash binds first, making \( a single ordinary-character token, and then ? makes that token optional. It desugars to ( ( | ε ), a choice between a literal parenthesis and nothing, and has nothing to do with grouping. Now boundary-check the pattern the way §1’s exercise taught. Does it match (206-555 1234? Walk it: \(? takes (, \d{3} takes 206, \)? matches nothing, [- ]? takes the dash, and \d{3} takes 555. Then -? cannot take a space, so \d{4} faces  1234 and fails. No match: the two separators are not symmetric, and only the first allows a space. Next try (206-5551234: it does match, unbalanced parenthesis and all, because \(? and \)? are independent choices. That case is worth pausing on. A simple regex can accept strings it was never meant to accept, and nothing warns you; the only defense is writing the pattern that says what you mean. Here that is a choice between the two paren forms at the top: (\(\d{3}\)|\d{3})[- ]?\d{3}-?\d{4}. Test a pattern against near-misses in both directions: strings that should fail, and strings that should not pass. One more step for a real validator: anchor it, ^…$, so the engine cannot “validate” a phone number it merely found inside a longer string. The example also shows the readability tax: regexes get cryptic fast, which is why understanding the underlying automaton matters.
DNA again: a genome marker One more application, from Sedgewick, over the DNA alphabet: the genome marker gcg(cgg|agg)*ctg, a gcg, then any number of cgg/agg codon blocks, then ctg. It matches gcgaggaggcggcggctg (blocks agg·agg·cgg·cgg) and, because * allows zero blocks, the bare gcgctg; it rejects gcgagctg, whose middle is no whole number of blocks. The substring-search handout’s DNA search looked for one fixed string; a regex describes a whole family of strings, which is what motif-finding tools actually match.

Regular languages, and what a regex cannot say

Definition (regular language) The languages describable by regular expressions are the regular languages, a fundamental class in the theory of computation. Regular: \(L(\texttt{A*B})\), \(L(\texttt{(AB)*})\), “an even number of A’s.” Not regular: balanced parentheses; \(\texttt{A}^n\texttt{B}^n\) (\(n\) A’s followed by exactly \(n\) B’s).

Why the ceiling? To match \(\texttt{A}^n\texttt{B}^n\) you must count \(n\), and (as §2 makes precise) a finite automaton has finite memory: no fixed number of states can count to arbitrary \(n\). The pumping lemma turns this intuition into a proof. Anything with unbounded counting or nesting (balanced brackets, HTML tags, arithmetic expressions) is inherently beyond regex and needs more machinery (a stack, a grammar; §5 places these on the ladder). The famous advice “don’t parse HTML with a regex” is this theorem in disguise. Knowing the limits of regex is as important as knowing its power.

2. Finite automata: machines that recognize languages

Definition (finite automaton) A finite automaton is a machine with a fixed set of states, a start state, one or more accept states, and transitions that say “in state \(s\), reading character \(c\), go to state \(t\).” It reads a string character by character, following transitions; if it ends in an accept state, it accepts the string, otherwise it rejects. The set of strings it accepts is the language it recognizes.

This is the simplest computer, and it is the machine counterpart to a regex: one describes a language, the other decides membership in it. A concrete example first, in the easy deterministic flavor.

Example (a DFA for (0|1)*0) A deterministic finite automaton (DFA) has exactly one transition per (state, character) pair. This two-state DFA recognizes binary strings ending in 0: the same “ends in…” language you wrote a regex for in §1, one alphabet over:

Run "110": \(A \xrightarrow{1} A \xrightarrow{1} A \xrightarrow{0} B\): accept. Run "0110": \(A \xrightarrow{0} B \xrightarrow{1} A \xrightarrow{1} A \xrightarrow{0} B\): accept. Run "111": \(A \to A \to A \to A\): reject. And the empty string never leaves \(A\): reject (it does not end in 0). Each step follows exactly one arrow, so a DFA processes an \(n\)-character string in \(O(n)\), and the invariant “state \(B\) \(\iff\) the input so far ends in 0” is the correctness argument, a loop invariant like every other one in these handouts. It is also the finite-memory point of §1 made concrete: two states can remember “ends in 0 or not,” but no fixed number of states can remember an unbounded count.

Nondeterminism and \(\varepsilon\)-transitions

Definition (NFA; \(\varepsilon\)-transition) A nondeterministic finite automaton (NFA) may have several transitions (or none) for a (state, character) pair, plus \(\varepsilon\)-transitions: moves between states that consume no input (“free” moves, after \(\varepsilon\), the empty string). An NFA accepts a string if some sequence of choices consumes the whole string and ends in an accept state.

“Nondeterministic” does not mean random. Picture the machine cloning itself to pursue every option in parallel: at any moment it occupies a set of states, not one, and it accepts if any clone ends accepting. That picture is not just intuition: §4 turns “track the set of states” into the actual, deterministic algorithm that runs an NFA on a real computer. The \(\varepsilon\)-transitions, meanwhile, are the construction’s superpower: they let you glue small machines together, offer a choice (|), loop back (*), without reading a character.

Why tolerate the extra complexity? Because each flavor is easy where the other is hard:

NFADFA
build from a length-\(m\) regexeasy, \(O(m)\) states (§3)can need \(2^m\) states
run on a length-\(n\) text\(O(mn)\) (track a set, §4)\(O(n)\) (follow one arrow)
\(\varepsilon\)-transitionsyesno

Build small or run fast: the classic space/time trade. Sedgewick’s route, and this handout’s, is to build the (small) NFA and simulate it. The other choice, paying the determinization cost up front to earn the \(O(n)\) scan, is weighed in §6. Either way, one bridge makes everything cohere: the automaton is a membership tester for the regex’s language:

\[ \begin{aligned} \text{the NFA accepts a string} &\iff \text{the string is in the regex's language}\\ \text{“does it match?”} &= \text{“does the NFA accept?”} \end{aligned} \]

3. Thompson’s construction: from regex to NFA

Thompson’s construction turns any regex into an NFA compositionally: each of the four operations has a fixed little machine (a gadget) with a single entry and a single exit, and gadgets plug together with \(\varepsilon\)-transitions, following the regex’s recursive structure. Because every piece has one way in and one way out, they compose without special cases: the same discipline as a recursive-descent parser or an expression-tree evaluation.

The atom: a single character

Concatenation AB: a series connection

Or A|B: a parallel connection

Closure A*: skip it, or loop it

Four operators, four wirings, each preserving the single-entry/single-exit invariant, so they nest freely, and building an NFA from a regex is just applying them along the parse. Note the skip edge in the closure gadget: it is the machine-level face of “(AB)* matches the empty string” from §1.

Sedgewick’s encoding: one state per character

The implementation insight that fits the whole construction in a page: don’t allocate gadget states: reuse the regex string itself.

Encoding invariant For a regex re of length \(m\), the NFA has states \(0, 1, \dots, m\), where state \(m\) is the accept state and state \(i\) “is” the character re[i]:
  • a letter state consumes its own character, stepping \(i \xrightarrow{\texttt{re}[i]} i+1\), and the only way to consume input is \(i \to i+1\);
  • a metacharacter state ((, ), |, *) never consumes input: it has only \(\varepsilon\)-edges.
The whole machine is the regex string plus an \(\varepsilon\)-digraph: nothing else.

Each state’s out-edges are listed in its row: this is the adjacency list that §4’s \(\varepsilon\)-closure will graph-search. The star wires two \(\varepsilon\)-edges around its operand: \(0 \to 1\) skips the A (zero copies; it leaves state \(0\), so it is listed there) and \(1 \to 0\) loops back for more copies (listed under state \(1\)), whose other edge falls through to the B. Three \(\varepsilon\)-edges, two match edges, four states: Thompson’s gadgets, compressed onto the string.

Where do the \(\varepsilon\)-edges go? A stack, and an outer wrap

Those five addEdge calls are the entire construction.

The outer wrap is a real implementation detail worth understanding: a top-level | or * needs an enclosing group to anchor its \(\varepsilon\)-edges: without it, A|B has no ( to pop when the ) logic fires. So the machine actually built for A*B is the machine for (A*B): six states instead of four, the letters shifted up by one, and structural \(\varepsilon\)-edges \(0\to1\) and \(4\to5\) at the ends. The demos (and the code below) build the wrapped machine; the worked figures above drop the wrap for clarity, and every state number simply shifts by one.

Concatenation is the operator that costs nothing: the two letters are adjacent in the string, so state \(2\) is already both the exit of A and the entry of B, and the \(\varepsilon\)-edge the gadget picture draws between them is absorbed by the numbering. That is the whole saving of the encoding. Union spends two edges, to fork and to join; closure spends two, to skip and to repeat, and its start closure reaching the accept state is the empty-string case falling out of the wiring rather than being special-cased. Running A|B on "B" reads the fork: from \(\{0,1,3\}\) the B advances state \(3\) to \(\{4\}\), the closure adds \(5\), and \(5\) is the accept state.

Proposition (the construction is linear) A regex of (wrapped) length \(m\) yields an NFA with \(m+1\) states and \(O(m)\) edges, built in \(\Theta(m)\) time.
Proof (count edges per character). Each letter contributes exactly one match edge. Each (, ), and * contributes one fall-through \(\varepsilon\)-edge; each * adds its skip/repeat pair; each | adds its branch-in/skip-out pair. So every character contributes at most one match edge and at most three \(\varepsilon\)-edges, and the single left-to-right scan does \(O(1)\) stack work per character. Check against the machine above, ((A*B|AC)D): \(9\) \(\varepsilon\)-edges \(= 5\) fall-throughs (from ( ( * ) )) \(+\ 2\) for the star \(+\ 2\) for the |, plus \(5\) match edges from the \(5\) letters: exactly the tally the demo reports. Contrast \(2^m\): that is what determinizing can cost (§5); the NFA itself never blows up. ∎

4. Simulating the NFA: track a set of states

An NFA is easy to build and awkward to run: it makes choices. The resolution is the idea from §2: instead of guessing which branch to take, follow all branches at once by maintaining the set of states the machine could possibly be in. That turns nondeterminism into bookkeeping:

Example (why not just guess?) Sedgewick calls these stalling sequences. Commit to single choices on ((A*B|AC)D) and watch them die: \[ \begin{array}{l} \text{input AAABD, guess the right branch:}\\ \qquad 0 \xrightarrow{\varepsilon} 1 \xrightarrow{\varepsilon} 6 \xrightarrow{\texttt{A}} 7 \qquad \text{stuck: state 7 wants C, the input has A}\\[8pt] \text{input AAAAC (the star loop is forced; nothing to guess):}\\ \qquad \cdots\ 2 \xrightarrow{\texttt{A}} 3 \xrightarrow{\varepsilon} 2 \xrightarrow{\texttt{A}} 3\ \cdots \xrightarrow{\varepsilon} 4 \qquad \text{stuck: state 4 wants B} \end{array} \] A wrong guess strands the machine in a state with no usable edge, and nothing tells you at guessing time which choice is wrong: the input decides, later. Backtracking (undo and try the other branch) restores correctness at a possibly exponential price (see the engines aside below). The algorithm here refuses to guess at all: it keeps every viable state alive at once and lets the input kill the wrong ones.
\[ \begin{array}{l} \mathit{states} \leftarrow \varepsilon\text{-closure}(\{\text{start}\})\\ \textbf{for each } \text{character } c \text{ of the text:}\\ \qquad \mathit{next} \leftarrow \{\, i+1 : i \in \mathit{states} \text{ and } \texttt{re}[i] = c \,\} \qquad \text{advance}\\ \qquad \mathit{states} \leftarrow \varepsilon\text{-closure}(\mathit{next}) \qquad \text{close}\\ \text{accept iff the accept state} \in \mathit{states} \end{array} \]

Two phases per character: advance every letter state whose character matches (its one \(i \to i+1\) edge; the encoding invariant doing its job), then \(\varepsilon\)-close to add the free moves. No backtracking, no exponential guessing.

Definition (\(\varepsilon\)-closure) The \(\varepsilon\)-closure of a set \(S\) of states is \(S\) together with every state reachable from \(S\) by following \(\varepsilon\)-edges, a graph-reachability computation: a depth-first or breadth-first search over the \(\varepsilon\)-digraph, seeded with \(S\). This is the graph search of the DFS handout, reused on the automaton.
Example (\(\varepsilon\)-closure, worked) On the A*B machine (\(\varepsilon\)-edges \(0\to1\), \(1\to0\), \(1\to2\)), compute \(\varepsilon\)-closure(\(\{0\}\)):
stepε-edgesresult

ε-closure({0}) = {0, 1, 2}
Read the result: before consuming anything, the machine is simultaneously ready to match an A (state 0) and to match the B directly (state 2): the skip edge has already opened both the zero-A’s and the some-A’s futures.

Here is the entire engine: construction, closure, and the set-of-states loop. It is a graph search per character, built from pieces you already own: 

// Regex -> NFA (Sedgewick's one-state-per-character encoding) + set-of-states
// simulation. Syntax: letters, concatenation, | (one per group), *, ( ).
struct NFA {
    string re;                    // wrapped regex: "(" + pattern + ")"
    int m;                        // re.length(); state m is the accept state
    vector<vector<int>> eps;      // eps[u] = the e-edge out-neighbors of u

    NFA(const string& pattern) {
        re = "(" + pattern + ")"; // implicit wrap anchors a top-level | or *
        m = re.size();
        eps.assign(m + 1, {});
        vector<int> ops;          // stack of '(' and '|' positions
        for (int i = 0; i < m; i++) {
            int lp = i;           // left end of the atom/group ending at i
            if (re[i] == '(' || re[i] == '|') ops.push_back(i);
            else if (re[i] == ')') {
                int orPos = ops.back(); ops.pop_back();
                if (re[orPos] == '|') {           // wire the alternation
                    lp = ops.back(); ops.pop_back();
                    eps[lp].push_back(orPos + 1); // '(' skips into branch 2
                    eps[orPos].push_back(i);      // '|' skips to the ')'
                } else lp = orPos;                // plain group: lp = the '('
            }
            if (i < m - 1 && re[i + 1] == '*') {  // closure around lp..i
                eps[lp].push_back(i + 1);         //   skip the operand
                eps[i + 1].push_back(lp);         //   repeat the operand
            }
            if (re[i] == '(' || re[i] == '*' || re[i] == ')')
                eps[i].push_back(i + 1);          // fall through the meta char
        }
    }

    // e-closure(S): DFS over the e-digraph -- all states reachable for free
    set<int> closure(const set<int>& s) const {
        set<int> seen = s;
        vector<int> stack(s.begin(), s.end());
        while (!stack.empty()) {
            int u = stack.back(); stack.pop_back();
            for (int v : eps[u])
                if (seen.insert(v).second) stack.push_back(v);
        }
        return seen;
    }

    // does the NFA accept text? -- track the reachable-state set: O(mn)
    bool matches(const string& text) const {
        set<int> pc = closure({0});               // states reachable on ""
        for (char c : text) {
            set<int> next;
            for (int u : pc)                      // advance every letter state
                if (u < m && re[u] == c) next.insert(u + 1);
            pc = closure(next);                   // then close over e-edges
            if (pc.empty()) return false;         // dead: nothing can revive
        }
        return pc.count(m) > 0;                   // accept state in final set?
    }
};

        Deque<Integer> ops = new ArrayDeque<>();  // '(' and '|' positions

            }
            if (i < m - 1 && re.charAt(i + 1) == '*') {  // closure lp..i
                eps.get(lp).add(i + 1);           //   skip the operand
                eps.get(i + 1).add(lp);           //   repeat the operand
            }
            if (c == '(' || c == '*' || c == ')')
                eps.get(i).add(i + 1);            // fall through the meta char
        }
    }

    // e-closure(S): DFS over the e-digraph -- all states reachable for free
    Set<Integer> closure(Set<Integer> s) {
        Set<Integer> seen = new TreeSet<>(s);
        Deque<Integer> stack = new ArrayDeque<>(s);
        while (!stack.isEmpty()) {
            int u = stack.pop();
            for (int v : eps.get(u))
                if (seen.add(v)) stack.push(v);
        }
        return seen;
    }

    // does the NFA accept text? -- track the reachable-state set: O(mn)
    boolean matches(String text) {
        Set<Integer> pc = closure(new TreeSet<>(Set.of(0)));
        for (char c : text.toCharArray()) {
            Set<Integer> next = new TreeSet<>();
            for (int u : pc)                      // advance every letter state
                if (u < m && re.charAt(u) == c) next.add(u + 1);
            pc = closure(next);                   // then close over e-edges
            if (pc.isEmpty()) return false;       // dead: nothing can revive
        }
        return pc.contains(m);                    // accept state in final set?
    }
}

# simulation. Syntax: letters, concatenation, | (one per group), *, ( ).
class NFA:
    def __init__(self, pattern):
        self.re = "(" + pattern + ")"   # implicit wrap anchors top-level | or *
        self.m = len(self.re)           # state m is the accept state
        self.eps = [[] for _ in range(self.m + 1)]
        ops = []                        # stack of '(' and '|' positions
        for i, c in enumerate(self.re):
            lp = i                      # left end of the atom/group ending at i
            if c in "(|":
                ops.append(i)
            elif c == ")":
                orpos = ops.pop()
                if self.re[orpos] == "|":          # wire the alternation
                    lp = ops.pop()
                    self.eps[lp].append(orpos + 1) # '(' skips into branch 2
                    self.eps[orpos].append(i)      # '|' skips to the ')'
                else:
                    lp = orpos                     # plain group: lp = the '('
            if i < self.m - 1 and self.re[i + 1] == "*":   # closure lp..i
                self.eps[lp].append(i + 1)         # skip the operand
                self.eps[i + 1].append(lp)         # repeat the operand
            if c in "(*)":
                self.eps[i].append(i + 1)          # fall through the meta char

    def closure(self, s):
        """e-closure(S): DFS over the e-digraph -- all states reachable free."""
        seen, stack = set(s), list(s)
        while stack:
            u = stack.pop()
            for v in self.eps[u]:
                if v not in seen:
                    seen.add(v)
                    stack.append(v)
        return seen

    def matches(self, text):
        """Does the NFA accept text? Track the reachable-state set: O(mn)."""
        pc = self.closure({0})                     # states reachable on ""
        for c in text:
            nxt = {u + 1 for u in pc               # advance every letter state
                   if u < self.m and self.re[u] == c}
            pc = self.closure(nxt)                 # then close over e-edges
            if not pc:
                return False                       # dead: nothing can revive
        return self.m in pc                        # accept state in final set?
// Regex -> NFA (Sedgewick's one-state-per-character encoding) + set-of-states
// simulation. Syntax: letters, concatenation, | (one per group), *, ( ).
struct Nfa {
    re: Vec<char>,           // wrapped regex: "(" + pattern + ")"
    m: usize,                // re.len(); state m is the accept state
    eps: Vec<Vec<usize>>,    // eps[u] = the e-edge out-neighbors of u
}

impl Nfa {
    fn new(pattern: &str) -> Nfa {
        let re: Vec<char> = format!("({})", pattern).chars().collect();
        let m = re.len();
        let mut eps = vec![Vec::new(); m + 1];
        let mut ops: Vec<usize> = Vec::new();   // '(' and '|' positions
        for i in 0..m {
            let mut lp = i;  // left end of the atom/group ending at i
            match re[i] {
                '(' | '|' => ops.push(i),
                ')' => {
                    let or = ops.pop().unwrap();
                    if re[or] == '|' {           // wire the alternation
                        lp = ops.pop().unwrap();
                        eps[lp].push(or + 1);    // '(' skips into branch 2
                        eps[or].push(i);         // '|' skips to the ')'
                    } else { lp = or; }          // plain group: lp = the '('
                }
                _ => {}
            }
            if i + 1 < m && re[i + 1] == '*' {   // closure around lp..i
                eps[lp].push(i + 1);             //   skip the operand
                eps[i + 1].push(lp);             //   repeat the operand
            }
            if matches!(re[i], '(' | '*' | ')') {
                eps[i].push(i + 1);              // fall through the meta char
            }
        }
        Nfa { re, m, eps }
    }

    // e-closure(S): DFS over the e-digraph -- all states reachable for free
    fn closure(&self, s: &BTreeSet<usize>) -> BTreeSet<usize> {
        let mut seen = s.clone();
        let mut stack: Vec<usize> = s.iter().copied().collect();
        while let Some(u) = stack.pop() {
            for &v in &self.eps[u] {
                if seen.insert(v) { stack.push(v); }
            }
        }
        seen
    }

    // does the NFA accept text? -- track the reachable-state set: O(mn)
    fn matches(&self, text: &str) -> bool {
        let mut pc = self.closure(&BTreeSet::from([0]));
        for c in text.chars() {
            let next: BTreeSet<usize> = pc.iter()
                .filter(|&&u| u < self.m && self.re[u] == c)  // letter states
                .map(|&u| u + 1)                             // ... advance
                .collect();
            pc = self.closure(&next);            // then close over e-edges
            if pc.is_empty() { return false; }   // dead: nothing can revive
        }
        pc.contains(&self.m)                     // accept state in final set?
    }
}

Example (the witness: one accepting path for "AAABD") Acceptance means at least one path through the machine consumes the whole string and lands on the accept state. The simulation never names that path, but it exists; unrolled: \[ \begin{aligned} &0 \xrightarrow{\varepsilon} 1 \xrightarrow{\varepsilon} 2 \xrightarrow{\texttt{A}} 3 \xrightarrow{\varepsilon} 2 \xrightarrow{\texttt{A}} 3 \xrightarrow{\varepsilon} 2 \xrightarrow{\texttt{A}} 3 \xrightarrow{\varepsilon} 4\\ &\quad \xrightarrow{\texttt{B}} 5 \xrightarrow{\varepsilon} 8 \xrightarrow{\varepsilon} 9 \xrightarrow{\texttt{D}} 10 \xrightarrow{\varepsilon} 11 \quad \text{accept} \end{aligned} \] Three trips through the star’s loop consume the A’s, the fall-through takes the B, the | skips to the join, and the D drives home. Every hop is an edge of the machine in §3. The set-of-states simulation is the device that establishes such a path exists without ever guessing which one it will be.
Proposition (simulation cost) Simulating a length-\(m\) regex’s NFA on a length-\(n\) text takes \(O(mn)\) time, worst case, guaranteed.
Proof. The NFA has \(m+1\) states and \(O(m)\) edges (§3). Each input character does at most \(m\) match checks (the set never exceeds \(m+1\) states) plus one graph search over the \(O(m)\)-edge \(\varepsilon\)-digraph (\(O(m)\) work) for \(n\) characters. There is no input that makes this engine blow up, because the set is bounded by the state count no matter how the branches multiply. Compare Knuth–Morris–Pratt (KMP): the same flavor of promise (linear, worst-case, never backs up over the text), one level more general. ∎
Theorem (the simulation is exact) After reading the prefix \(t[0..i)\), the tracked set equals exactly the set of states reachable from the start state by consuming \(t[0..i)\). Hence the final accept test decides NFA acceptance.
Proof (induction on \(i\): a loop invariant, like every other one in these handouts). Base: before any input the reachable states are those \(\varepsilon\)-reachable from the start: exactly the initial closure. Step: a path consuming one more character \(t[i]\) must take some matching edge out of a state reachable on the shorter prefix, then any number of \(\varepsilon\)-moves: exactly advance-then-close, no more and no less. So the set is never an approximation. At the end, “accept state \(\in\) set” is literally the definition of NFA acceptance: some path consumes the whole string and ends at the accept state. Nondeterminism handled by bookkeeping, proved by induction. ∎

Backtracking, ReDoS, and why this engine cannot blow up

Most production engines do not simulate an automaton at all. Perl, Java, Python, JavaScript, and C++’s <regex> match by backtracking: a recursive search over the pattern’s choices. At (a|aa) the engine tries a and continues with the rest of the pattern; if that fails somewhere later, it comes back, undoes the choice, tries aa, and continues again. Its working state is a single path through the pattern, held on the call stack, and failure means unwinding and trying the next path. That is “try all possibilities” taken literally, with all the cost that implies.

Example (how a pattern goes exponential) Match (a|aa)*b against \(n\) a’s followed by a c. Every way of cutting the run of a’s into pieces of size one and two is a different path through the pattern, and the engine tries them all. The number of such cuts obeys \(f(n) = f(n-1) + f(n-2)\) (the first piece is either one a or two), so it is a Fibonacci number: it grows like \(\varphi^{\,n} \approx 1.618^{\,n}\). The trailing c is the adversary’s trick, an input that almost matches: no path can short-circuit, so every one must be tried before the engine can answer “no”.

Definition (ReDoS) A regular-expression denial of service (ReDoS) attack supplies input, or a pattern, chosen so that matching takes superlinear time, so that one small request occupies a CPU core for seconds or minutes. Both halves are reachable in real systems: user input matched against a fixed pattern, and user-supplied patterns (search boxes, filters, alerting rules).

This is not hypothetical. Stack Overflow was down for 34 minutes in July 2016 when a post containing roughly 20,000 consecutive space characters met a pattern that trimmed trailing whitespace; Cloudflare served global HTTP 502s for 27 minutes in July 2019 when one regex in a new firewall rule exhausted CPU across the fleet. Sedgewick’s booksite records an earlier one: an address pattern in SpamAssassin that a hostile return address could stall.

Why the set simulation is immune: paths versus states A backtracking engine’s state is a path, and there are \(\varphi^{\,n}\) of them. This handout’s engine keeps a set of NFA states, and there are only \(m+1\) of those.

Two paths that arrive at the same NFA state after the same number of characters have identical futures: nothing about the rest of the match can distinguish them. The set stores that state once, so the work those two paths share is done once. A backtracker cannot notice the coincidence, because it only ever holds one path at a time. Collapsing exponentially many paths by indexing the work on the state they share is exactly memoization: the same move as dynamic programming, applied to path search instead of to a grid of subproblems. That is what takes \(1.618^{\,n}\) down to \(O(mn)\), and the \(O(mn)\) bound of the proposition above is unconditional: no pattern and no input can trigger a bad case, because the set is bounded by the state count no matter how the branches multiply. This is precisely why grep and Google’s RE2 are built this way, and why untrusted patterns must go through an engine of this kind (§6).

In fairness: what backtracking buys Backtracking supports features that are not regular, and so cannot be compiled into a finite automaton at all: back references such as (a+)\1 (“the same text again”, which requires remembering an arbitrary captured string) and lookaround. Matching with back references is NP-hard, so the exponential is not laziness that a better implementation could optimize away: it is the price of leaving the regular languages. The engineering rule follows. If your pattern needs only the four operations and their sugar, which is almost always, an automaton engine gives you the same answer with a guarantee.

5. Kleene’s theorem and the limits of regularity

Theorem (Kleene) Regular expressions and finite automata describe exactly the same class of languages: the regular languages. Every regex has an equivalent finite automaton, and every finite automaton has an equivalent regex.
Why, in both directions (sketch). Regex \(\to\) automaton is §3: Thompson’s construction is itself the proof, an explicit \(O(m)\) recipe. Automaton \(\to\) regex is state elimination: remove states one at a time, and whenever a state goes, merge the paths through it into a single edge labeled by a regex: concatenate what came in and out, star any self-loop, union parallel edges. When only one start\(\to\)accept edge remains, its label is a regex for the whole machine. Both directions constructive, so the two formalisms have exactly equal power. ∎

This is the deep result the handout has been building: a rare, beautiful equivalence between a syntax (patterns you write) and a machine model (automata you run). It is why “regular expression” and “finite automaton” are two views of one idea, and why we can answer “does it match?” by running a machine.

Determinizing: the subset construction The simulation’s “current set of states” can be made into an explicit DFA state: one DFA state per reachable subset of NFA states, with the advance-and-close step precomputed into its transitions. That is the subset construction, and it is where the \(2^m\) in §2’s table comes from: up to one DFA state per subset. Once built, the DFA matches in pure \(O(n)\), no closure per step.

Three closures worth checking by hand. \(\varepsilon\)-closure(\(\{0\}\)) walks \(0\to1\), then \(1\to2,4,6\), then \(6\to1\) (seen) and \(6\to7\): \(\{0,1,2,4,6,7\}\), the three letter states \(2, 4, 7\) all armed before any input, because the star may run zero times. \(\varepsilon\)-closure(\(\{3\}\)) walks \(3\to5\), \(5\to6\), \(6\to1\) and \(6\to7\), then \(1\to2,4,6\): \(\{1,2,3,4,5,6,7\}\), which is \(D_0\) plus the just-consumed \(3\) and \(5\), minus the unreachable start state \(0\). \(\varepsilon\)-closure(\(\{5,8\}\)) adds \(9\) from \(8\to9\), and state \(9\) is the accept state: that is why \(D_2\) is accepting, and it is reached exactly by the subsets whose last character was a B.

The worklist empties after three subsets: every row lands on a subset already named, so the reachable part of the \(2^{10}\) possible subsets is three states. Note what the table also proves: the DFA is total (a transition for every state and character) and deterministic, with no closure left to compute at match time. The \(2^m\) worst case of §2 is real but is a bound on the reachable subsets, not a promise; on ordinary patterns, as here, the count stays small.

The subset construction is honest but wasteful: it can hand back states that no input can tell apart. Minimization merges them. Say that the continuations of a state are the strings that drive it to an accept state, so a state’s continuations are the language it still has left to recognize. Two states with the same continuations cannot be distinguished by any input, so keeping them separate records history the language does not care about, and they can be merged.

Example (minimization, worked on (A|B)*B) Take §1’s ends-in-B pattern again. The worklist above finished with three states, each a set of NFA states: D0 (before any character) and D1 (after an A) are different sets of NFA states, but read the rows: the behavior is identical, and the continuations of both are “every string ending in B”. They differ only in history, so they merge, and what comes out is the two-state machine of §2 with the alphabet renamed: Three states down to two on a seven-character pattern; the same merging is what keeps the table of a real lexer, built from dozens of token patterns at once, small enough to ship.

Example (the canonical form decides equivalence) Minimization always yields the unique smallest DFA for a language, which makes it a canonical form: two patterns denote the same language exactly when their minimal DFAs coincide. Take A(BA)* and (AB)*A. They determinize to five and four states respectively, and both minimize to the same three: So the two patterns describe one language, the alternating strings that start and end with A: \(\{\texttt{A}, \texttt{ABA}, \texttt{ABABA}, \dots\}\). This is how tools decide regex equivalence, and it is the only reliable way: comparing the patterns themselves tells you nothing, since a language has infinitely many regexes but exactly one minimal DFA. Compilers minimize their lexer DFA for the other reason, space: that table is generated once and then ships inside every copy of the compiler.

Above the regular languages

Kleene’s theorem also sharpens §1’s ceiling: since regexes and finite automata are the same thing, whatever a finite-memory machine cannot do, no regex can say. \(\texttt{A}^n\texttt{B}^n\) needs an unbounded counter; balanced parentheses need unbounded nesting. Those sit on the next rungs of the Chomsky hierarchy, where each class adds power by adding memory:

Regex sits at the bottom rung, which explains both its speed (finite memory means one linear pass) and its limits (no counting, no nesting). Programming-language syntax lives one rung up, recognized with a stack: that is why a compiler’s lexer is a regex engine but its parser is not.

6. Choosing an engine in practice

Everything a real regex engine does is some point on the build-cost versus run-cost trade the NFA/DFA table of §2 set up:

you match…usewhy
a pattern oncesimulate the NFA\(O(mn)\), no build cost worth amortizing
one pattern, many texts (a lexer)compile to a DFApay the subset construction once, then \(O(n)\) per text

Precompute or pay per query: the same decision as indexes, hash tables, and dynamic programming. And the ideas land everywhere: grep and RE2 are the set-of-states simulator of §4; every compiler tokenizes source with a (minimized) DFA generated by tools like flex; protocol validators run automata over byte streams. One more callback: KMP’s precomputed failure-function table from the Knuth–Morris–Pratt handout is a DFA, specialized to a single fixed pattern: you were doing automata theory before the vocabulary arrived. Pattern \(\to\) machine threads through the whole strings unit.

(Check: "A" accepts: \(\{0\}\to\{1,2,3\}\); "B" rejects: the set dies immediately.)
  5. Simulate the worked A*B machine on "AB" and on the empty string "", giving every state set. What general fact does the second trace illustrate?
    solution "AB": start \(\{0,1,2\}\); read A: 0 advances to \(\{1\}\), closure \(\{0,1,2\}\); read B: 2 advances to \(\{3\}\), closure \(\{3\}\); \(3\) is the accept state → accept. "": no characters are read, so the final set is the start closure \(\{0,1,2\}\), which does not contain \(3\) → reject. The general fact: acceptance is evaluated only after the last character, on whatever set is active then: the machine being “near” the accept state, or passing through it mid-string, counts for nothing.
  6. Trace the wrapped 12-state (A*B|AC)D machine on "BD". Which branch of the alternation accepts it, and what does that reveal about the string?
    solution Start closure \(\{0,1,2,3,4,6\}\). Read B: only state 4 matches, advance \(\{5\}\), closure \(\{5,8,9\}\) (the | skips to the ), which falls through to the D). Read D: state 9 advances to \(\{10\}\), closure \(\{10,11\}\): contains the accept state \(11\) → accept. The left branch accepted, with the star contributing zero A’s: "BD" is \(\texttt{A*B}\) (as just B) followed by D. The right branch (AC) died on the first character: state 6 does not match B.
  7. Run the subset construction on the wrapped (A*B) machine (states \(0..5\), accept \(5\); \(\varepsilon\)-edges \(0\to1\), \(1\to2\), \(2\to1\), \(2\to3\), \(4\to5\); match edges \(1\,\xrightarrow{\texttt{A}}\,2\) and \(3\,\xrightarrow{\texttt{B}}\,4\)) over the alphabet \(\{\texttt{A}, \texttt{B}\}\). How many DFA states does it reach, and which of them could minimization merge?
    solution Four, one of them the empty set: The start closure is \(\{0,1,2,3\}\) (the wrap’s \(0\to1\), the star’s skip \(1\to2\), the fall-through \(2\to3\)), so the B is armed with zero A’s. An A advances \(\{2\}\) and closes to \(\{1,2,3\}\): the same set minus the unreachable start state, so the machine loops there for any run of A’s. A B advances \(\{4\}\) and closes to \(\{4,5\}\), which holds the accept state; from there nothing matches, so both characters land on the empty subset, a perfectly ordinary DFA state (the dead state) that the NFA simulation represents as an empty active set. \(D_0\) and \(D_1\) have identical rows and neither is accepting, so they are equivalent and merge: the minimal DFA has three states, one per honest fact about the input read so far (“only A’s so far”, “the B has been read”, “something is wrong”).
  8. A compiler’s lexer will match one fixed token pattern against millions of source lines; a web form will run patterns supplied by users against their own input. For each, choose NFA simulation or DFA compilation, with costs.
    solution Lexer: compile to a DFA. The subset construction’s build cost (potentially large, up to \(2^m\) states, though rarely near it) is paid once and amortized over millions of \(O(n)\) matches; per-text there is no set tracking and no closure. User-supplied patterns: NFA simulation. The build is \(\Theta(m)\) and matching is guaranteed \(O(mn)\), so no adversarial pattern can trigger exponential behavior; whereas handing untrusted patterns to a backtracking engine invites ReDoS, and determinizing an adversarial pattern could itself blow up in space. This is the build-cost/run-cost trade of §6: amortize when the pattern is reused, stay linear when it is not trusted or not reused.
  9. Classify each language over \(\{\texttt{A},\texttt{B}\}\) (or the bracket alphabet) as regular or not, with justification: (a) strings with an even number of A’s; (b) \(\texttt{A}^n\texttt{B}^n\); (c) balanced parentheses.
    solution (a) Regular: a two-state automaton whose state is the parity of A’s seen decides it: finite memory (one bit) suffices. A regex: (B|AB*A)*, reading left to right, each block is either a lone B or a pair of A’s with any B’s between, so A’s are consumed strictly in pairs. (b) Not regular: matching the B-count to the A-count requires remembering an unbounded integer \(n\), and a finite automaton’s only memory is which of its fixed states it occupies; the pumping lemma formalizes the contradiction. (c) Not regular, same reason: nesting depth is an unbounded count. Both (b) and (c) are context-free, one rung up the hierarchy, recognized with a stack.
