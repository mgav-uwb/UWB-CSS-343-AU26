The Floyd–Warshall Algorithm

Data Structures & Algorithms. Algorithm (dynamic programming).
All-pairs shortest paths by dynamic programming. The subproblem is derived rather than handed down: restricting which vertices a path may pass through turns a min over \(V\) choices into a min over two, and the whole algorithm into a triple loop. A matrix-by-matrix trace on a four-vertex digraph, path reconstruction from the next matrix, why negative edges are fine and how negative cycles announce themselves on the diagonal, the \(\Theta(V^3)\) time and \(\Theta(V^2)\) space accounting, and when \(V\) runs of Dijkstra beat it. With exercises.

The Dijkstra handout solves single-source shortest paths: one source, distances to everywhere. Route planners, network-routing tables, and any “distance oracle” ask a harder question: the distance between every pair of vertices at once. The obvious answer is to rerun a single-source algorithm from each source in turn. The Floyd–Warshall algorithm answers differently: a dynamic program whose entire body is three nested loops around one if, which computes all \(V^2\) distances in \(\Theta(V^3)\), tolerates negative edge weights that break Dijkstra outright, and detects negative cycles as a bonus. The interesting part is not the code, which is three lines; it is finding the subproblem, and this handout derives it instead of presenting it finished.

1. All-pairs shortest paths

Definition (all-pairs shortest paths) Given a weighted digraph with \(V\) vertices, the all-pairs shortest-paths (APSP) problem asks for the distance \(\delta(i,j)\), the minimum total weight of any \(i \to j\) path, for every ordered pair \((i,j)\), together with enough information to reconstruct an actual shortest path for each pair. If no \(i \to j\) path exists, \(\delta(i,j) = \infty\); always \(\delta(i,i) \le 0\) since the empty path costs \(0\).

The output is a \(V \times V\) distance matrix, which is why the natural input here is the adjacency matrix of the graph-representations handout: entry \((i,j)\) starts as the weight of the edge \(i \to j\) (or \(\infty\) if there is none), and the algorithm lowers entries until they are distances. This is the “dense” representation, and it fits: the answer alone occupies \(\Theta(V^2)\) space, so APSP is inherently a \(V^2\)-sized computation.

The baseline: one source at a time

APSP is \(V\) single-source problems, so the first solution is free: run a single-source algorithm from every vertex.

  • All weights nonnegative: \(V\) runs of Dijkstra with a binary heap, \(O(V \cdot E \log V)\).
  • Negative weights allowed (no negative cycles): Dijkstra’s greedy argument fails (its handout shows the exact line that breaks), so each source needs the slower relax-everything algorithm of Bellman and Ford at \(O(VE)\) per source: \(O(V^2 E)\) in all, which on a dense graph (\(E = \Theta(V^2)\)) is \(\Theta(V^4)\).

So the target is set: beat \(O(V \cdot E \log V)\) when the graph is dense, beat \(\Theta(V^4)\) whenever weights can be negative, and do it with less machinery than \(V\) coordinated heap runs. Floyd–Warshall achieves \(\Theta(V^3)\), unconditionally, with no heap, no adjacency list, and no per-source bookkeeping.

2. Finding the subproblem

The dynamic-programming method says: find a family of subproblems, ordered so that each is answerable from smaller ones, such that the original problem is the largest. The question is always what to shrink. For paths there are two natural knobs, and it pays to try the wrong one first.

Attempt 1: shrink the number of edges

Let \(d_m(i,j)\) be the cost of the cheapest \(i \to j\) path using at most \(m\) edges. Base case: \(d_0(i,j)\) is \(0\) if \(i = j\) and \(\infty\) otherwise. A path of at most \(m\) edges is a path of at most \(m-1\) edges to some predecessor \(x\), plus the final edge \(x \to j\) (or no final edge at all): \[ d_m(i,j) \;=\; \min\Big(\, d_{m-1}(i,j),\; \min_{x}\big( d_{m-1}(i,x) + w(x,j) \big) \Big). \] With no negative cycles a shortest path is simple, so \(m = V - 1\) suffices and \(d_{V-1} = \delta\). The recurrence is correct, but count its work: \(V - 1\) rounds, \(V^2\) entries per round, and each entry takes a minimum over all \(V\) candidate predecessors \(x\). That is \(\Theta(V^4)\): no better than Bellman–Ford run from every source, which is essentially what this is. The expensive part is the inner \(\min_x\) over \(V\) choices. To do better, the subproblem must change so that growing it by one step offers O(1) alternatives, not \(V\).

Attempt 2: shrink which vertices may appear inside

Here is the other knob. A path from \(i\) to \(j\) consists of its two endpoints and its interior: the vertices it passes through along the way. Instead of restricting how long the path is, restrict which vertices its interior may use. Number the vertices \(0, 1, \dots, V-1\) and admit them one at a time.

Definition (the Floyd–Warshall subproblem) For \(k = -1, 0, 1, \dots, V-1\), let \(d^{(k)}(i,j)\) be the cost of the cheapest \(i \to j\) path whose interior vertices all come from \(\{0, 1, \dots, k\}\) (the endpoints \(i, j\) themselves are exempt from the restriction). Read \(k = -1\) as the empty set: no intermediates at all, so \(d^{(-1)}(i,j)\) is \(0\) if \(i = j\), the weight \(w(i,j)\) if the edge \(i \to j\) exists, and \(\infty\) otherwise: exactly the adjacency matrix. At the other end, \(\{0,\dots,V-1\}\) is every vertex, so \(d^{(V-1)}(i,j) = \delta(i,j)\): the restriction has dissolved and the largest subproblem is the answer.

Why is this the right knob? Because admitting one new vertex \(k\) presents exactly one binary question per pair: does the best path use the newcomer or not?

Theorem (the recurrence) If the graph has no negative cycles, then for all \(i, j\) and all \(k \ge 0\): \[ d^{(k)}(i,j) \;=\; \min\Big( d^{(k-1)}(i,j),\;\; d^{(k-1)}(i,k) + d^{(k-1)}(k,j) \Big). \]
Proof. Consider a cheapest \(i \to j\) path \(P\) with interior in \(\{0,\dots,k\}\); with no negative cycles we may take \(P\) simple (deleting a cycle from a walk removes a subtour of nonnegative cost, never raising the total). Two cases, by whether \(k\) appears in \(P\)’s interior. Case 1: it does not. Then \(P\)’s interior already lies in \(\{0,\dots,k-1\}\), so \(P\) costs \(d^{(k-1)}(i,j)\), the first alternative. Case 2: it does. \(P\) is simple, so \(k\) appears exactly once; split \(P\) at that visit into \(i \rightsquigarrow k\) and \(k \rightsquigarrow j\). Neither piece contains \(k\) in its interior (\(k\) is now an endpoint of each), so each piece’s interior lies in \(\{0,\dots,k-1\}\), and by optimal substructure (each piece of a cheapest path must itself be cheapest for its endpoints and restriction, else splicing in a cheaper piece improves \(P\)) the two pieces cost \(d^{(k-1)}(i,k)\) and \(d^{(k-1)}(k,j)\): the second alternative. Conversely both alternatives are costs of genuine \(i \to j\) walks with interior in \(\{0,\dots,k\}\) (for the second, concatenate the two pieces; if the concatenation repeats a vertex, deleting the resulting cycle only cheapens it), so the minimum of the two is achieved and is exactly \(d^{(k)}(i,j)\). ∎

Compare the two attempts side by side. Both have \(\Theta(V)\) stages of \(\Theta(V^2)\) entries, but attempt 1 pays \(\Theta(V)\) per entry while the new recurrence pays \(\Theta(1)\): a two-way minimum. That single structural improvement is the whole algorithm: \(V \cdot V^2 \cdot O(1) = \Theta(V^3)\).

Where the DP recipe shows through This is the standard shape of a dynamic program: optimal substructure (proved inside the theorem above), a parameter that orders the subproblems (\(k\), the largest admitted intermediate), and massive overlap (all \(V^2\) pairs at stage \(k\) reuse the same stage-\((k-1)\) table). The catalog of such parameter choices is the DP patterns handout; “restrict the allowed resource set and admit one element per stage” is one of its recurring moves.

3. The algorithm: three loops

The recurrence wants \(V+1\) matrices \(d^{(-1)}, d^{(0)}, \dots\), but one matrix suffices, updated in place. That is safe because pass \(k\) never changes the entries it reads:

Proposition (row \(k\) and column \(k\) are fixed points of pass \(k\)) With no negative cycles, \(d^{(k)}(i,k) = d^{(k-1)}(i,k)\) and \(d^{(k)}(k,j) = d^{(k-1)}(k,j)\) for all \(i, j\).
Proof. Apply the recurrence to the pair \((i,k)\): the second alternative is \(d^{(k-1)}(i,k) + d^{(k-1)}(k,k)\), and \(d^{(k-1)}(k,k) = 0\) (the empty path costs \(0\), and with no negative cycles no closed walk beats it). So the two alternatives are equal and the entry does not move. Symmetrically for \((k,j)\). Hence during pass \(k\), the values \(d(i,k)\) and \(d(k,j)\) that the update reads are the same whether or not they have already been “overwritten” this pass, and one in-place matrix computes exactly the sequence \(d^{(0)}, d^{(1)}, \dots\) ∎

So the program is: load the adjacency matrix, then for each \(k\) sweep every pair once. Alongside dist we maintain nxt[i][j], the first hop of the best known \(i \to j\) path, for path reconstruction (§5): it starts as \(j\) where the edge \(i \to j\) exists, and whenever a route via \(k\) wins, the first hop toward \(j\) becomes the first hop toward \(k\). 

// Floyd-Warshall, in place. dist starts as the adjacency matrix:
// dist[i][i] = 0, dist[i][j] = w(i,j), INF where no edge. nxt[i][j] is the
// first hop of the best known i->j path (-1 = no path known).
const long INF = LONG_MAX / 4;   // headroom: INF + INF must not overflow

void floydWarshall(vector<vector<long>>& dist, vector<vector<int>>& nxt) {
    int V = dist.size();
    for (int k = 0; k < V; k++)               // pass k: admit k as an intermediate
        for (int i = 0; i < V; i++)
            for (int j = 0; j < V; j++)
                if (dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];  // route i -> k -> j wins
                    nxt[i][j]  = nxt[i][k];                // first hop: toward k now
                }
}

// dist[i][i] = 0, dist[i][j] = w(i,j), INF where no edge. nxt[i][j] is the

                }
            }
        }
    }
}

Two mechanical points. In languages with fixed-width integers, \(\infty\) is a large sentinel, and dist[i][k] + dist[k][j] can be sentinel + sentinel; dividing the maximum by \(4\) leaves headroom so the sum cannot overflow into a negative number and “win” the comparison. (Python’s float("inf") is a true infinity and needs no care.) Second:

The loop order is the algorithm \(k\) must be the outermost loop: the whole matrix must finish stage \(k-1\) before any entry consults it at stage \(k\). Swapping the loops to put \(k\) innermost computes, for each pair once, a minimum over intermediates using half-baked entries, and produces wrong answers (a concrete failure is exercise 7). The \(i\) and \(j\) loops may be exchanged freely; only \(k\)’s position is load-bearing.

5. Reconstructing paths: the next matrix

Distances say how far; the nxt matrix says which way. The invariant is: nxt[i][j] is the first hop of the cheapest known \(i \to j\) path. Initially, where an edge \(i \to j\) exists, the path is that edge and the first hop is \(j\) itself. When pass \(k\) reroutes pair \((i,j)\) via \(k\), the new best path starts with the best path from \(i\) to \(k\), so its first hop is nxt[i][k]: one assignment, already in the code of §3.

To print a path, hop until arrival: 

// The actual shortest i -> j path, from the nxt matrix; {} if none exists.
vector<int> path(vector<vector<int>>& nxt, int i, int j) {
    if (nxt[i][j] == -1) return {};       // dist[i][j] is INF: no path
    vector<int> p = {i};
    while (i != j) {
        i = nxt[i][j];                    // hop to the next vertex toward j
        p.push_back(i);
    }
    return p;
}

fn path(nxt: &Vec<Vec<usize>>, mut i: usize, j: usize) -> Vec<usize> {
    if nxt[i][j] == usize::MAX { return vec![]; } // no path
    let mut p = vec![i];
    while i != j {
        i = nxt[i][j];                    // hop to the next vertex toward j
        p.push(i);
    }
    p
}

Each hop re-reads the entry for the final destination \(j\), not for the next waypoint: \(\texttt{nxt}[1][3]\) is consulted, not \(\texttt{nxt}[1][2]\). The walk for a pair at distance \(d\) with \(h\) hops takes \(\Theta(h)\) time: reconstruction is free compared with the \(\Theta(V^3)\) already spent.

The alternative record is a predecessor matrix (pred[i][j] = the vertex just before \(j\) on the best \(i \to j\) path, updated as pred[i][j] = pred[k][j]), which walks paths backward, exactly like the parent[] array of the single-source algorithms. One matrix per convention; both are \(\Theta(V^2)\) space and both reconstruct any path in time proportional to its length.

6. Negative edges and negative cycles

Reread the correctness proof of §2: nowhere does it ask weights to be nonnegative. It asks only that the graph have no negative cycles, so that walks can be pruned to simple paths without raising cost. So Floyd–Warshall computes correct distances with negative edges present, no modifications, no extra passes: precisely the case where Dijkstra’s greedy settling fails (its handout exhibits the failing three-vertex graph). The DP does not greedily freeze anything; every entry stays revisable until all \(V\) passes are done.

Definition (negative cycle) A negative cycle is a directed cycle whose edge weights sum to less than \(0\). If some \(i \to j\) walk can reach such a cycle, loop it, and continue to \(j\), then no cheapest \(i \to j\) path exists: every trip around lowers the total, and the infimum is \(-\infty\). “Shortest path” stops being well defined for such pairs.

Floyd–Warshall cannot return correct distances in that case (there are none to return), but it detects the situation, and the detector is the diagonal it has been maintaining all along.

Theorem (negative-cycle detection) Run the triple loop to completion. Then \(\texttt{dist}[i][i] < 0\) for some \(i\) if and only if the graph contains a negative cycle. Moreover any such \(i\) lies on one.
Proof. (\(\Leftarrow\)) Let \(C\) be a negative cycle and let \(i\) be its highest-numbered vertex, say with cycle cost \(c < 0\). Split \(C\) at \(i\): it is an \(i \to i\) closed walk whose interior lies in \(\{0, \dots, i\}\), with the possible interior repetition of \(i\) itself absent since we split there. Trace the recurrence: after pass \(i\), \(\texttt{dist}[i][i]\) is at most the cost of the cheapest \(i \to i\) closed walk with interior in \(\{0,\dots,i\}\), hence \(\le c < 0\). Updates only decrease entries, so the final \(\texttt{dist}[i][i]\) is still negative. (\(\Rightarrow\)) Entries are only ever set to sums of edge weights along genuine walks (induction, exactly as for the honest-labels invariant of the single-source algorithms): \(\texttt{dist}[i][i] < 0\) exhibits a closed \(i \to i\) walk of negative total cost. A closed walk decomposes into simple cycles; if every one of them had nonnegative cost, the walk’s total would be nonnegative, so some simple cycle in it, through vertices of the walk, is negative. ∎

So the complete contract is: nonnegative edges, or negative edges with no negative cycle, give exact distances; a negative cycle is reported by a scan of the diagonal, \(\Theta(V)\) extra work after the run.

7. Cost, and when to use it

Proposition (time and space) Floyd–Warshall runs in exactly \(\Theta(V^3)\) time and \(\Theta(V^2)\) space, on every input.
Proof. The loop body (one addition, one comparison, at most two assignments) is \(\Theta(1)\), and it executes exactly \(V \cdot V \cdot V\) times: no early exit, no data-dependent pruning. Best case equals worst case, hence \(\Theta\), not merely \(O\). Space: the dist and nxt matrices are \(\Theta(V^2)\) each, updated in place (licensed by the fixed-point proposition of §3); no other state exists. Note \(\Theta(V^2)\) is optimal for APSP in any case: the output alone is \(V^2\) numbers. ∎

Two features of this accounting deserve notice. \(E\) does not appear: a sparse graph and a complete graph on the same \(V\) cost the same, because the matrix, not the edge list, drives the loops. And the constant factor is tiny: no heap, no visited sets, no pointer chasing; three loops over a contiguous array, which caches and vectorizes about as well as code can.

Floyd–Warshallany; detects neg. cycles\(\Theta(V^3)\)dense, or negative edges, or small \(V\)

The comparison is one substitution. Dense graph, \(E = \Theta(V^2)\): repeated Dijkstra costs \(\Theta(V^3 \log V)\), and Floyd–Warshall’s \(\Theta(V^3)\) wins by the \(\log\) factor and by its much smaller constant. Sparse graph, \(E = \Theta(V)\): repeated Dijkstra costs \(\Theta(V^2 \log V)\), which beats \(V^3\) by roughly \(V / \log V\), an enormous margin at scale (concrete numbers in exercise 6). Negative edges take repeated Dijkstra off the table entirely, at any density. And below a few hundred vertices the asymptotics hardly matter: the triple loop’s simplicity, predictability, and cache behavior make it the default APSP tool whenever \(V^3\) is affordable at all.

The sparse-and-negative corner: Johnson’s algorithm One cell of the decision table is left uncovered: sparse and negative-weighted. Johnson’s algorithm fills it by running the Bellman–Ford relaxation scheme once from an artificial source to compute a potential \(h(v)\) for every vertex, reweighting each edge as \(w'(u,v) = w(u,v) + h(u) - h(v) \ge 0\) (a transformation that, unlike adding a constant, preserves shortest paths, since the \(h\)-terms telescope along any path), and then running \(V\) Dijkstras on the now nonnegative graph: \(O(V E \log V)\) total. On dense graphs Floyd–Warshall still wins; on sparse ones Johnson does.

Where this sits

Floyd–Warshall is the graph catalog’s meeting point with dynamic programming: the subproblem-by-restriction derivation of §2 is the DP method practiced on a graph problem, and its stage-by-stage table is one more entry in the DP patterns family. Within shortest paths it completes a progression: unweighted single-source is BFS, weighted nonnegative single-source is Dijkstra, and all-pairs is this handout. It reads its input straight from the adjacency matrix of the graph-representations handout: the one algorithm in the catalog for which the matrix, not the list, is the natural home. The same triple loop with other operators computes transitive closure (exercise 8) and, with \((\min,+)\) swapped for other semirings, a family of path problems well beyond distances.

8. Exercises (with solutions)

  1. Run Floyd–Warshall by hand on the graph \(0\to1\,(2)\), \(1\to2\,(2)\), \(0\to2\,(5)\), \(2\to0\,(-1)\). Give the matrix after each pass, and state which entries each pass changed. (Note the negative edge; check first that no cycle is negative.)
    solution The two cycles are \(0\to1\to2\to0 = 2+2-1 = 3\) and \(0\to2\to0 = 5-1 = 4\), both positive, so distances exist. Initial rows: \((0, 2, 5)\), \((\infty, 0, 2)\), \((-1, \infty, 0)\). Pass \(k=0\): \(d(2,1) = d(2,0)+d(0,1) = -1+2 = 1\), one change. Pass \(k=1\): \(d(0,2) = d(0,1)+d(1,2) = 2+2 = 4 < 5\), one change (the candidate \(d(2,2) = 1+2 = 3\) loses to the diagonal’s \(0\)). Pass \(k=2\): \(d(1,0) = d(1,2)+d(2,0) = 2-1 = 1 < \infty\), one change (\(d(0,0) = 4-1 = 3\) loses to \(0\)). Final rows: \((0, 2, 4)\), \((1, 0, 2)\), \((-1, 1, 0)\). The negative edge caused no special handling anywhere; only a negative cycle would have.
  2. In the trace of §4, pass \(k=0\) changed nothing. State the structural property of vertex \(0\) that guarantees this in advance, and give the general condition under which pass \(k\) is vacuous no matter what the other passes did.
    solution Vertex \(0\) has no incoming edges, so \(d(i,0) = \infty\) for every \(i \ne 0\), and every candidate \(d(i,0) + d(0,j)\) with \(i \ne 0\) is \(\infty\); candidates with \(i = 0\) reduce to \(d(0,0) + d(0,j) = d(0,j)\), never an improvement. In general pass \(k\) is vacuous whenever no vertex reaches \(k\) or \(k\) reaches no vertex (row or column \(k\) is all \(\infty\) off the diagonal): a vertex nothing enters, or nothing leaves, can sit in no path’s interior.
  3. The in-place update reads \(\texttt{dist}[i][k]\) and \(\texttt{dist}[k][j]\) during the very pass that is overwriting the matrix. Prove this is safe, and point to the exact place where the argument uses the absence of negative cycles.
    solution Apply pass \(k\)’s own update to an entry in column \(k\): the candidate for \((i,k)\) is \(d(i,k) + d(k,k)\), and since \(d(k,k) = 0\) it ties the standing value and the strict < rejects it; symmetrically for row \(k\). So the entries the pass reads are never modified by it, and reading “partly updated” memory returns the same values as reading the previous stage’s matrix. The negative-cycle assumption is exactly what keeps \(d(k,k) = 0\): a negative closed walk through earlier intermediates would have driven \(d(k,k)\) below \(0\) in an earlier pass, and the pivot row and column would then shift mid-pass.
  4. Run Floyd–Warshall on \(0\to1\,(2)\), \(1\to2\,(-5)\), \(2\to1\,(2)\). Report the final diagonal, name the negative cycle, and classify every entry of the final matrix as meaningful or meaningless.
    solution The cycle \(1 \to 2 \to 1\) costs \(-5 + 2 = -3\). The final matrix has rows \((0, -1, -6)\), \((\infty, -3, -8)\), \((\infty, -1, -6)\): diagonal \((0, -3, -6)\), and the two negative diagonal entries flag vertices \(1\) and \(2\), exactly the vertices on the cycle. Meaningful entries: \(d(0,0) = 0\) (vertex \(0\) lies on no cycle) and \(d(1,0) = d(2,0) = \infty\) (nothing enters \(0\), a true no-path answer). Every other entry, \((0,1), (0,2), (1,1), (1,2), (2,1), (2,2)\), describes a pair whose walks can loop the cycle: the true infimum is \(-\infty\), and the printed finite numbers are merely where the \(V\)-pass recurrence stopped (running the triple loop a second time lowers them further, another usable symptom).
  5. Using only the final nxt matrix of §5, reconstruct the shortest paths \(3 \to 2\) and \(0 \to 2\), listing each hop and checking each cost against the distance matrix.
    solution \(3 \to 2\): at \(3\), \(\texttt{nxt}[3][2] = 1\), hop to \(1\); at \(1\), \(\texttt{nxt}[1][2] = 2\), hop to \(2\), arrived. Path \(3 \to 1 \to 2\), cost \(2 + 5 = 7 = \texttt{dist}[3][2]\). \(0 \to 2\): at \(0\), \(\texttt{nxt}[0][2] = 1\); at \(1\), \(\texttt{nxt}[1][2] = 2\), arrived. Path \(0 \to 1 \to 2\), cost \(3 + 5 = 8 = \texttt{dist}[0][2]\). Both agree with the trace (both were verified by machine as well).
  6. A graph has \(V = 1000\) vertices and nonnegative weights. Estimate the operation counts for all-pairs via \(V\) heap-Dijkstras versus Floyd–Warshall when (a) \(E = 5{,}000\) and (b) \(E = 499{,}500\) (nearly complete). Which wins where, and what single change of assumptions eliminates repeated Dijkstra at any density?
    solution Floyd–Warshall is \(V^3 = 10^9\) either way. (a) Repeated Dijkstra is roughly \(V \cdot E \log_2 V \approx 1000 \cdot 5000 \cdot 10 = 5 \times 10^7\): about \(20\times\) fewer operations; sparse Dijkstra wins comfortably. (b) Roughly \(1000 \cdot 499{,}500 \cdot 10 \approx 5 \times 10^9\): now Floyd–Warshall does about \(5\times\) fewer operations, each far cheaper (no heap traffic), so it wins decisively. One negative edge anywhere invalidates Dijkstra’s greedy proof and removes option one entirely, at any density; Floyd–Warshall’s count does not change.
  7. A classmate writes the three loops as for i, for j, for k (pairs outer, intermediates inner), reasoning that each pair should simply take its best intermediate in one shot. On the graph \(0\to3\,(1)\), \(3\to2\,(1)\), \(2\to1\,(1)\), what does one such sweep report for \(d(0,1)\) and for \(d(0,2)\) (loops ascending), and why does the correct loop order fix it?
    solution True distances: \(d(0,2) = 2\) (via \(3\)) and \(d(0,1) = 3\) (via \(3\) then \(2\)). The sweep computes \(d(0,1)\) first (with \(i=0, j=1\)): its candidates \(d(0,k) + d(k,1)\) use only direct-edge values, and no single intermediate connects \(0\) to \(1\) (\(d(0,2)\) is still \(\infty\) when read), so \(d(0,1)\) finishes as \(\infty\): wrong. \(d(0,2)\) happens to come out \(2\) via \(k=3\), because both halves are direct edges. The failure is structural: with \(k\) innermost each pair is finalized once, so a shortest path of \(h\) hops, which needs \(h-1\) levels of already-improved entries, can never assemble. With \(k\) outermost every pair is revisited at every stage, and the theorem of §2 guarantees stage \(k\) only ever needs stage \(k-1\) values. (Both sweeps verified by machine: the wrong order leaves \(d(0,1) = \infty\).)
  8. Transitive closure (Warshall’s algorithm). Adapt the triple loop to compute reachability instead of distance: \(\texttt{reach}[i][j]\) true iff some \(i \to j\) path exists. State the modified update and the resulting matrix for the running graph of §4.
    solution Booleans replace weights: initialize \(\texttt{reach}[i][j]\) true iff \(i = j\) or the edge \(i \to j\) exists, and update with reach[i][j] = reach[i][j] || (reach[i][k] && reach[k][j]): minimum becomes OR, addition becomes AND, the same derivation goes through word for word. On the running graph the result is the finiteness pattern of the final distance matrix: row \(0\) all true; rows \(1\), \(2\), \(3\) true everywhere except column \(0\), which is false (nothing enters vertex \(0\)). Packing rows as bitsets makes the inner loop a word-wide OR, cutting the cost to \(\Theta(V^3 / w)\) for word size \(w\): the standard trick for closures of large relations.
