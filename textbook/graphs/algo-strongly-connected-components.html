Strongly Connected Components

Data Structures & Algorithms. Algorithm.
Vertices that can reach each other in both directions. Strong connectivity defined, the component DAG (condensation) and its acyclicity, and Kosaraju’s two-pass algorithm: a depth-first search recording reverse post-order, the transpose graph, and a second search in that order. Proved correct and \(\Theta(V+E)\), with a fully unrolled two-pass trace on a three-component digraph, an aside on Tarjan’s one-pass alternative, applications (2-SAT, dependency clustering), and exercises.

Digraph vocabulary and the adjacency-list representation are in Graphs: Vocabulary & Representations. Depth-first search (DFS), its reachability theorem, and its cost accounting are in Depth-First Search; the reverse post-order construction reused here is developed on acyclic graphs in Topological Sort.

1. Strong connectivity

In an undirected graph, “connected” is symmetric: if you can walk from \(u\) to \(v\) you can walk back. A digraph breaks the symmetry: a one-way street from \(u\) to \(v\) says nothing about the return trip. The question this topic answers is what the right notion of “connected piece” is for a digraph, and how to compute the pieces fast. The answer is mutual reachability.

Definition (strongly connected, SCC) Vertices \(u\) and \(v\) of a digraph are strongly connected if there is a directed path \(u \rightsquigarrow v\) and a directed path \(v \rightsquigarrow u\). A strongly connected component (SCC) is a maximal set of vertices, every two of which are strongly connected: no further vertex can be added without breaking the property.
Proposition (SCCs partition the vertices) Strong connectivity is an equivalence relation, so the SCCs are its equivalence classes: every vertex lies in exactly one SCC.
Proof. Reflexive: the empty path connects \(v\) to itself both ways. Symmetric: the definition is symmetric in \(u\) and \(v\). Transitive: paths \(u \rightsquigarrow v\) and \(v \rightsquigarrow w\) concatenate into \(u \rightsquigarrow w\), and likewise in the other direction. An equivalence relation partitions its ground set into classes, and each class is maximal by construction. ∎

The running digraph for this handout has \(V = 8\) vertices and \(E = 10\) edges, adjacency lists (sorted ascending) \(0\to\{1\}\), \(1\to\{0,2\}\), \(2\to\{3\}\), \(3\to\{4\}\), \(4\to\{2\}\), \(5\to\{6\}\), \(6\to\{3,7\}\), \(7\to\{5\}\). Its SCCs are \(A=\{0,1\}\) (the two-cycle \(0 \to 1 \to 0\)), \(B=\{2,3,4\}\) (the cycle \(2 \to 3 \to 4 \to 2\)), and \(C=\{5,6,7\}\) (the cycle \(5 \to 6 \to 7 \to 5\)). The cross edges \(1 \to 2\) and \(6 \to 3\) are one-way: nothing in \(B\) can get back to \(A\) or to \(C\), so the three sets stay separate.

2. The component DAG (condensation)

Definition (condensation) The condensation (component graph) of a digraph \(G\) contracts each SCC to a single vertex, with an edge \(C \to D\) between distinct components exactly when \(G\) has some edge from a vertex of \(C\) to a vertex of \(D\).
Theorem (the condensation is acyclic) The condensation of any digraph is a directed acyclic graph (DAG).
Proof. Suppose the condensation had a directed cycle \(C_1 \to C_2 \to \cdots \to C_k \to C_1\) through distinct components. Pick any vertices \(u \in C_1\) and \(v \in C_2\). Following the cycle, \(u\) reaches \(v\): walk inside \(C_1\) to the tail of the \(C_1 \to C_2\) edge (possible because \(C_1\) is strongly connected), cross it, then walk inside \(C_2\) to \(v\). Continuing around the cycle the same way, \(v\) also reaches \(u\). So \(u\) and \(v\) are strongly connected, and \(C_1 \cup C_2\) sits inside one equivalence class, contradicting the maximality of \(C_1\) and \(C_2\) as distinct SCCs. ∎

This theorem is why SCCs matter beyond taxonomy: every digraph is a DAG of clusters. Whatever cyclic tangle a digraph contains is confined inside the components; between components, order reigns, and the whole DAG toolkit applies, starting with topological sort of the condensation. The algorithmic problem is therefore to compute the SCCs, and the standard answers run in linear time.

3. Kosaraju’s algorithm

A single DFS almost works: it finds everything reachable, but reachable is not mutual. From vertex \(0\) of the running digraph a DFS reaches all eight vertices, three components indiscriminately. Kosaraju’s algorithm repairs this with a second search that runs against the edges, in a carefully chosen order: 

1. run DFS on G (restarting at every unvisited vertex);
   record the REVERSE POST-ORDER: list vertices by finish time, latest first
2. build the TRANSPOSE Gᵀ: same vertices, every edge reversed
3. run DFS on Gᵀ, picking start vertices in the order from step 1;
   each restart of this second search marks exactly one SCC

The transpose \(G^{\mathsf T}\) (also called the reverse graph) has an edge \(v \to u\) for each edge \(u \to v\) of \(G\). Reversing edges does not change the SCCs: a pair of opposite paths stays a pair of opposite paths (exercise 4). What changes is what a DFS can leak into, and the order from step 1 turns that leak off, as §5 proves. The code is two copies of the DFS from Depth-First Search plus one edge-reversing scan: 

// pass 1: plain DFS on G, recording post-order
void dfs1(Graph& g, int u, vector<bool>& seen, vector<int>& order) {
    seen[u] = true;
    for (int v : g.adj[u])
        if (!seen[v]) dfs1(g, v, seen, order);
    order.push_back(u);                     // on FINISHING u
}
// pass 2: plain DFS on the transpose, labeling one component
void dfs2(vector<vector<int>>& radj, int u, int c, vector<int>& comp) {
    comp[u] = c;
    for (int v : radj[u])
        if (comp[v] == -1) dfs2(radj, v, c, comp);
}
vector<int> kosaraju(Graph& g) {
    vector<bool> seen(g.V, false);
    vector<int> order;                      // pass-1 finish order
    for (int s = 0; s < g.V; s++)
        if (!seen[s]) dfs1(g, s, seen, order);
    vector<vector<int>> radj(g.V);          // transpose: reverse every edge
    for (int u = 0; u < g.V; u++)
        for (int v : g.adj[u]) radj[v].push_back(u);
    vector<int> comp(g.V, -1);
    int c = 0;
    for (int i = g.V - 1; i >= 0; i--)      // reverse post-order
        if (comp[order[i]] == -1) dfs2(radj, order[i], c++, comp);
    return comp;                            // comp[v] = component id of v
}
boolean[] seen; List<Integer> order;        // pass-1 state
List<List<Integer>> radj; int[] comp;       // pass-2 state

void dfs1(Graph g, int u) {                 // plain DFS on G
    seen[u] = true;
    for (int v : g.adj.get(u))
        if (!seen[v]) dfs1(g, v);
    order.add(u);                           // on FINISHING u
}
void dfs2(int u, int c) {                   // plain DFS on the transpose
    comp[u] = c;
    for (int v : radj.get(u))
        if (comp[v] == -1) dfs2(v, c);
}
int[] kosaraju(Graph g) {
    seen = new boolean[g.V];
    order = new ArrayList<>();
    for (int s = 0; s < g.V; s++)
        if (!seen[s]) dfs1(g, s);
    radj = new ArrayList<>();               // transpose: reverse every edge
    for (int u = 0; u < g.V; u++) radj.add(new ArrayList<>());
    for (int u = 0; u < g.V; u++)
        for (int v : g.adj.get(u)) radj.get(v).add(u);
    comp = new int[g.V];
    Arrays.fill(comp, -1);
    int c = 0;
    for (int i = g.V - 1; i >= 0; i--)      // reverse post-order
        if (comp[order.get(i)] == -1) dfs2(order.get(i), c++);
    return comp;                            // comp[v] = component id of v
}
def kosaraju(g):
    seen = [False] * g.V
    order = []                              # pass-1 finish order

    def dfs1(u):                            # plain DFS on G
        seen[u] = True
        for v in g.adj[u]:
            if not seen[v]:
                dfs1(v)
        order.append(u)                     # on FINISHING u

    for s in range(g.V):
        if not seen[s]:
            dfs1(s)

    radj = [[] for _ in range(g.V)]         # transpose: reverse every edge
    for u in range(g.V):
        for v in g.adj[u]:
            radj[v].append(u)

    comp = [-1] * g.V

    def dfs2(u, c):                         # plain DFS on the transpose
        comp[u] = c
        for v in radj[u]:
            if comp[v] == -1:
                dfs2(v, c)

    c = 0
    for r in reversed(order):               # reverse post-order
        if comp[r] == -1:
            dfs2(r, c)
            c += 1
    return comp                             # comp[v] = component id of v
fn kosaraju(g: &Graph) -> Vec<i32> {
    fn dfs1(adj: &[Vec<usize>], u: usize,
            seen: &mut [bool], order: &mut Vec<usize>) {
        seen[u] = true;
        for &v in &adj[u] {
            if !seen[v] { dfs1(adj, v, seen, order); }
        }
        order.push(u);                      // on FINISHING u
    }
    fn dfs2(radj: &[Vec<usize>], u: usize, c: i32, comp: &mut [i32]) {
        comp[u] = c;
        for &v in &radj[u] {
            if comp[v] == -1 { dfs2(radj, v, c, comp); }
        }
    }
    let n = g.adj.len();
    let (mut seen, mut order) = (vec![false; n], Vec::new());
    for s in 0..n {
        if !seen[s] { dfs1(&g.adj, s, &mut seen, &mut order); }
    }
    let mut radj = vec![Vec::new(); n];     // transpose: reverse every edge
    for u in 0..n {
        for &v in &g.adj[u] { radj[v].push(u); }
    }
    let mut comp = vec![-1; n];
    let mut c = 0;
    for &r in order.iter().rev() {          // reverse post-order
        if comp[r] == -1 { dfs2(&radj, r, c, &mut comp); c += 1; }
    }
    comp                                    // comp[v] = component id of v
}

5. Why it works, and the cost

Write \(f(v)\) for the position of \(v\) in pass 1’s finish (post-) order, so pass 2 scans vertices in decreasing \(f\), and for a component \(C\) write \(f(C) = \max_{v \in C} f(v)\). One lemma carries the whole proof.

Lemma (edges between components order the finishes) If \(C\) and \(D\) are distinct SCCs and \(G\) has an edge from \(C\) to \(D\), then \(f(C) > f(D)\): the last-finished vertex of \(C\) finishes after all of \(D\).
Proof. Consider the first vertex of \(C \cup D\) that pass 1 discovers; call it \(x\). Two cases. (1) \(x \in C\): every vertex of \(C \cup D\) is reachable from \(x\) (within \(C\) by strong connectivity, then across the \(C \to D\) edge, then within \(D\)) and none is yet visited, so by the DFS reachability theorem of Depth-First Search all of \(C \cup D\) is visited inside the call \(\texttt{dfs}(x)\), and \(x\) finishes after all of it: \(f(C) \ge f(x) > f(v)\) for every \(v \in D\). (2) \(x \in D\): no path leads from \(D\) back to \(C\) (such a path, with the \(C \to D\) edge, would merge the two components into one strongly connected set), so \(\texttt{dfs}(x)\) visits and finishes all of \(D\) while no vertex of \(C\) has even been discovered; every \(C\)-vertex finishes later. In both cases \(f(C) > f(D)\). ∎

In the trace: \(A \to B\) and \(C \to B\) are the condensation edges, and indeed \(f(A) = f(0) = 5 > f(B) = f(2) = 3\) and \(f(C) = f(5) = 8 > f(B)\). Note what the lemma does not say: individual vertices of \(B\) may finish before or after individual vertices of \(A\) (here \(4, 3, 2\) all finish before \(1, 0\)); only the maxima are ordered. That is exactly enough.

Theorem (Kosaraju is correct) Each restart of pass 2 labels exactly one SCC of \(G\).
Proof. By induction on the restarts. Assume every earlier restart labeled exactly one whole SCC (vacuously true at the first), and let \(r\) be the current root: the unlabeled vertex with the largest \(f\), by the scan order. Let \(C_r\) be \(r\)’s SCC; since components are labeled whole, \(C_r\) is entirely unlabeled. The dive reaches all of \(C_r\): every vertex of \(C_r\) has a path from \(r\) in \(G^{\mathsf T}\) (the reversal of its path to \(r\) in \(G\)), through unlabeled vertices of \(C_r\), so DFS reachability marks it. The dive never leaves \(C_r\): suppose it crosses an edge \(u \to v\) of \(G^{\mathsf T}\) with \(u \in C_r\), \(v\) in a different component \(D\). That edge is \(v \to u\) in \(G\), an edge \(D \to C_r\), so the lemma gives \(f(D) > f(C_r) \ge f(r)\). The vertex of \(D\) achieving the max thus has larger \(f\) than \(r\); it cannot be unlabeled (that would contradict the choice of \(r\)), so \(D\) is already fully labeled, and \(v\)’s label stops the dive: exactly the cut-short events of the trace. The restart therefore labels all of \(C_r\) and nothing else. ∎
Proposition (cost) Kosaraju’s algorithm runs in \(\Theta(V+E)\) time on adjacency lists, plus \(\Theta(V+E)\) space for the transpose.
Proof. Pass 1 is a DFS with restarts: each vertex is visited once and each edge examined once, \(\Theta(V+E)\) by the degree-sum accounting of the Depth-First Search cost proof (the restart loop adds \(\Theta(V)\)). Building the transpose scans every adjacency list once and appends each edge exactly once: \(\Theta(V+E)\). Pass 2 is again a DFS with restarts on \(G^{\mathsf T}\), which has the same \(V\) and \(E\): \(\Theta(V+E)\). Three linear phases sum to \(\Theta(V+E)\), and any SCC algorithm must read every vertex and edge, so this is optimal up to constants. ∎
Aside: Tarjan’s one-pass algorithm (optional, not examined) Tarjan’s algorithm finds the SCCs in a single DFS of \(G\), no transpose. It keeps the two per-vertex numbers of the articulation-point aside in Depth-First Search (\(\texttt{disc}[v]\), discovery time, and \(\texttt{low}[v]\), the earliest discovery time reachable from \(v\)’s subtree using at most one back edge) plus an explicit stack of vertices whose component is not yet decided. When a vertex finishes with \(\texttt{low}[v] = \texttt{disc}[v]\), it is the root of an SCC, and popping the stack down to \(v\) yields exactly that component. Same \(\Theta(V+E)\) bound, roughly half the constant (one pass, no transpose), a subtler invariant; production libraries usually ship Tarjan, while Kosaraju’s two transparent passes are the version to reconstruct from memory.

6. Applications, and where this sits

Dependency clustering. Wherever a dependency digraph is supposed to be acyclic but is not (module imports, build targets, package requirements, spreadsheet formulas, microservice calls), the SCCs are the offending clusters: each component of size \(\ge 2\) (or with a self-loop) is a set of items that can only be processed together, and the condensation is the DAG that remains once each cluster is treated as a unit. Compute SCCs, contract, then topologically sort the condensation: that pipeline turns any digraph problem into a DAG problem, and it is the standard first move in interprocedural compiler analysis (cycles in the call graph are mutual recursion) and in resolving circular package dependencies.

2-SAT. 2-satisfiability asks whether Boolean variables can be assigned to satisfy a conjunction of two-literal clauses. Each clause \((a \lor b)\) is two implications, \(\lnot a \Rightarrow b\) and \(\lnot b \Rightarrow a\); drawing all of them as edges on the \(2n\) literal vertices \(x_1, \lnot x_1, \dots\) gives the implication graph. The formula is satisfiable if and only if no variable \(x\) has \(x\) and \(\lnot x\) in the same SCC (mutual implication of a literal and its negation is a contradiction), so one Kosaraju run decides 2-SAT in linear time, and processing the components in condensation order even reads off a satisfying assignment. Exercise 6 runs one instance end to end.

Where this sits in the catalog: the machinery is two runs of Depth-First Search, and the reverse post-order of pass 1 is the same construction that Topological Sort proves correct on DAGs; this handout is what that construction still buys on a digraph with cycles (on a DAG every SCC is a single vertex and Kosaraju’s output degenerates to a topological order of \(G\) itself). The undirected analogue, plain connected components via one search with restarts, appears in Depth-First Search; digraph vocabulary and representations are in Graphs: Vocabulary & Representations.

7. Exercises (with solutions)

  1. Run Kosaraju’s algorithm by hand on the digraph with \(V=6\) and edges \(0\to1,\ 1\to0,\ 2\to1,\ 2\to4,\ 3\to2,\ 4\to3,\ 5\to4\) (adjacency lists sorted ascending). Give pass 1’s post-order, the reverse post-order, and the components in the order pass 2 discovers them.
    solution Pass 1: \(\texttt{dfs}(0)\) visits \(0, 1\) (edge \(1\to0\) skipped), finishing \(1, 0\); restart at \(2\): \(2\)’s edge to \(1\) is skipped, then \(2\to4\to3\) (edge \(3\to2\) skipped), finishing \(3, 4, 2\); restart at \(5\): edge \(5\to4\) skipped, finish \(5\). Post-order \(1\,0\,3\,4\,2\,5\); reverse post-order \(5\,2\,4\,3\,0\,1\). Transpose lists: \(0\to\{1\}\), \(1\to\{0,2\}\), \(2\to\{3\}\), \(3\to\{4\}\), \(4\to\{2,5\}\), \(5\to\varnothing\). Pass 2: root \(5\) has no transpose edges, so \(C_0=\{5\}\); root \(2\) dives \(2\to3\to4\) (\(4\)’s edges to \(2\) and \(5\) both labeled), so \(C_1=\{2,3,4\}\); root \(0\) dives \(0\to1\) (\(1\)’s edges to \(0\) and \(2\) labeled), so \(C_2=\{0,1\}\). Discovery order \(\{5\}, \{2,3,4\}, \{0,1\}\); note it is a topological order of the condensation \(\{5\}\to\{2,3,4\}\to\{0,1\}\).
  2. A classmate implements Kosaraju but scans pass 2’s roots in plain post-order instead of reverse post-order. Exhibit a two-vertex digraph on which this returns the wrong answer, and trace the failure.
    solution Take the single edge \(0 \to 1\): two singleton SCCs. Pass 1 from \(0\) finishes \(1\) then \(0\), post-order \(1\,0\). The transpose has the edge \(1 \to 0\). Scanning in un-reversed order \(1, 0\): the first root is \(1\), and its transpose edge \(1 \to 0\) reaches the unlabeled \(0\), so \(\{0, 1\}\) comes out as one component, wrong. Reversed order \(0, 1\) labels \(\{0\}\) first, and \(1\)’s dive is then cut by \(0\)’s label: two components, correct. The reversal is what makes the second search start in a component that the lemma of §5 protects.
  3. The same classmate next runs pass 2 on \(G\) itself (correct reverse post-order, but no transpose). Show this fails on the same two-vertex digraph, and say in one sentence what the transpose is for.
    solution On \(0 \to 1\), reverse post-order is \(0\,1\); a second DFS on \(G\) from root \(0\) crosses \(0 \to 1\) and labels both vertices as one component, wrong. The transpose turns every edge that leaves the root’s component into an edge arriving from an already-labeled component, so the search can reach exactly the vertices that could reach the root: pass 1 certifies “root reaches \(v\),” pass 2 on \(G^{\mathsf T}\) certifies “\(v\) reaches root,” and the intersection is mutual reachability.
  4. Prove that \(G\) and its transpose \(G^{\mathsf T}\) have exactly the same SCCs.
    solution A directed path \(u \rightsquigarrow v\) in \(G\), traversed edge-by-edge backward, is a directed path \(v \rightsquigarrow u\) in \(G^{\mathsf T}\), and vice versa. So “\(u \rightsquigarrow v\) and \(v \rightsquigarrow u\) in \(G\)” holds if and only if “\(v \rightsquigarrow u\) and \(u \rightsquigarrow v\) in \(G^{\mathsf T}\)” holds: the two relations are literally the same relation, hence have the same equivalence classes. (This is why pass 2 is allowed to search \(G^{\mathsf T}\) and still claim components of \(G\).)
  5. Add the edge \(4 \to 7\) to the running digraph. What are the SCCs now? Argue from cycles, and check your answer by reasoning about the condensation.
    solution \(B\) and \(C\) merge: the new edge gives the cycle \(3 \to 4 \to 7 \to 5 \to 6 \to 3\) (using the old cross edge \(6 \to 3\)), so \(3, 4, 7, 5, 6\) are mutually reachable, and \(2\) joins because \(2 \to 3\) and \(4 \to 2\) already made \(2, 3, 4\) mutual. The SCCs are \(\{0,1\}\) and \(\{2,3,4,5,6,7\}\) (machine-checked). In condensation terms: the old component DAG had \(A \to B\) and \(C \to B\); the new edge adds \(B \to C\), closing the 2-cycle \(B \leftrightarrows C\) in the contracted graph, and components joined by a cycle of components collapse into one (the acyclicity theorem of §2 read backward). \(A\) is untouched: still nothing enters it.
  6. Decide by the SCC method whether the 2-SAT formula \((x \lor y) \land (x \lor \lnot y) \land (\lnot x \lor y) \land (\lnot x \lor \lnot y)\) is satisfiable: build the implication graph on vertices \(x, \lnot x, y, \lnot y\) and find its SCCs.
    solution Each clause \((a \lor b)\) contributes \(\lnot a \to b\) and \(\lnot b \to a\). The four clauses give, in order: \(\lnot x \to y,\ \lnot y \to x\); \(\lnot x \to \lnot y,\ y \to x\); \(x \to y,\ \lnot y \to \lnot x\); \(x \to \lnot y,\ y \to \lnot x\). Then \(x \to y \to x\) and \(x \to \lnot y \to \lnot x \to y\) with \(y \to x\) chain everything together: all four literals are mutually reachable, one SCC (machine-checked with Kosaraju). Since \(x\) and \(\lnot x\) share an SCC, \(x \Leftrightarrow \lnot x\) is forced and the formula is unsatisfiable, as expected: its four clauses rule out all four assignments of \((x, y)\).
