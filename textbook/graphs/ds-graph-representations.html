Graphs: Vocabulary & Representations

Leonhard Euler’s 1736 proof that no walk crosses each of the seven bridges of Königsberg exactly once is usually counted as the first theorem of graph theory. L. Euler, “Solutio problematis ad geometriam situs pertinentis,” 1736

Trees were graphs with a restriction: connected and acyclic, exactly one path between any two nodes. This handout removes the restriction. A graph is any set of vertices connected by edges (cycles allowed, multiple paths allowed, disconnected pieces allowed), and that generality is why graphs model road maps, social networks, the web, task dependencies, and circuits alike. The price of the generality is that a search can go in circles, so every graph search carries a visited set; the searches themselves are the subject of the Depth-First Search, Breadth-First Search, and Topological Sort handouts. This handout supplies what they all share: the vocabulary, two counting facts, and the representation.

1. Vertices, edges, and vocabulary

Definition (graph) A graph \(G = (V, E)\) is a set \(V\) of vertices and a set \(E\) of edges, each edge joining a pair of vertices. In an undirected graph an edge \(\{u,v\}\) connects \(u\) and \(v\) symmetrically; in a directed graph (a digraph) an edge \((u,v)\), written \(u \to v\), goes one way only, and \(u\to v\) does not imply \(v\to u\).

Undirected edges model symmetric relations: friendship, two-way roads. Directed edges model one-way relations: web links, one-way streets, “must happen before.” The distinction matters for every algorithm, and topological sort (the Topological Sort handout) only makes sense on a digraph. Here is a small undirected graph used throughout this section: 

  0 —— 1       V = { 0, 1, 2, 3 }
  |  / |       E = { 0–1, 0–2, 1–2, 1–3 }
  | /  |
  2    3       4 vertices, 4 edges, a cycle 0–1–2–0

The shared vocabulary for the rest of the unit:

  • adjacent: two vertices joined by an edge;
  • degree of a vertex: the number of edges at it (for a digraph, in-degree and out-degree separately);
  • path: a sequence of edges leading from one vertex to another; its length is the number of edges;
  • cycle: a path that returns to its start;
  • connected (undirected): a path exists between every pair of vertices.

2. Counting edges: the handshake lemma and trees

Two counting facts about edges anchor the cost analyses of the graph algorithms, and place trees within the family of graphs.

Lemma (handshake) In an undirected graph, \(\displaystyle\sum_{v \in V} \deg(v) = 2\,|E|\). In a digraph, \(\displaystyle\sum_{v} \text{in-deg}(v) = \sum_{v} \text{out-deg}(v) = |E|\).
Proof. Count the pairs (vertex, edge incident to it) two ways. Grouping by vertex, vertex \(v\) contributes \(\deg(v)\) pairs, for a total of \(\sum_v \deg(v)\). Grouping by edge, each undirected edge has exactly two endpoints and so contributes exactly \(2\) pairs, for a total of \(2|E|\). The two counts are equal. For a digraph, count (vertex, out-edge) pairs: each edge has one tail, so the out-degree sum is \(|E|\); symmetrically for heads and the in-degree sum. ∎

On the running graph (§3) the total degrees are \(3, 3, 2, 5, 3, 3, 1, 2\), summing to \(22 = 2\cdot 11\). The lemma looks like trivia but it is precisely why “scan every vertex’s entire neighbor list” costs \(V + 2E\), i.e. \(\Theta(V+E)\); it is cashed in for the cost of DFS and BFS. (The average degree \(2E/V\) also measures how sparse a graph is.)

How many edges can a graph have?

In a simple undirected graph (no self-loops, no repeated edges), the edge count ranges from \(0\) to one edge per pair of vertices:

\[ 0 \;\le\; |E| \;\le\; \binom{V}{2} = \frac{V(V-1)}{2} = \Theta(V^2). \]

A graph is sparse when \(|E| = O(V)\) and dense when \(|E| = \Theta(V^2)\). Real graphs are almost always sparse: a road intersection meets a handful of streets, a person has hundreds of friends and not billions. This single fact will choose our representation in §3.

Trees are the sparsest connected graphs

Proposition (trees) A tree is a connected acyclic undirected graph. Every tree on \(V\) vertices has exactly \(V - 1\) edges. Moreover, any two of the three properties {connected, acyclic, \(|E| = V-1\)} imply the third.
Why “undirected” is load-bearing The directed diamond \(1\to2,\ 1\to3,\ 2\to4,\ 3\to4\) is connected and has no directed cycle, yet it is not a tree: two distinct paths reach vertex \(4\) (it has two “parents”), it has \(E = V\) edges, and its undirected shadow contains the cycle \(1\)-\(2\)-\(4\)-\(3\)-\(1\). “Connected + acyclic \(\Rightarrow\) tree” is an undirected theorem. The directed analogue of “acyclic” is the DAG (the Topological Sort handout): a strictly bigger family, and the home of topological sort.
Proof that a tree has \(V-1\) edges (induction on \(V\)). A tree with \(V \ge 2\) vertices has a leaf, a vertex of degree \(1\): otherwise every vertex has degree \(\ge 2\), and following unused edges out of vertices can never get stuck, so by the pigeonhole argument behind the source lemma of the Topological Sort handout a walk must repeat a vertex and expose a cycle, contradicting acyclicity. Remove a leaf and its one edge: the result is still connected and acyclic, a tree on \(V-1\) vertices, which by induction has \(V-2\) edges. Adding the removed edge back gives \(V-1\). The base case \(V=1\) has \(0\) edges. The “two-of-three” claims follow similarly: adding one edge to a tree creates a cycle, and removing one disconnects it. ∎

So a tree is the minimum connected graph: drop any edge and it falls apart, add any edge and it gains a cycle. All the tree structures we studied earlier were graphs with these restrictions; this handout works without them. (The fact previews the minimum spanning tree, the subject of Minimum Spanning Trees: the cheapest set of edges that keeps a graph connected is necessarily a tree.)

3. Representing a graph

Two representations, chosen by whether the graph is dense or sparse.

Adjacency matrix

A \(V \times V\) matrix with \(a[u][v] = 1\) when \(u\)–\(v\) is an edge and \(0\) otherwise: 

       0 1 2 3
    0 [0 1 1 0]      edge 0–1?  → a[0][1] = 1   (O(1) lookup)
    1 [1 0 1 1]
    2 [1 1 0 0]
    3 [0 1 0 0]      space: Theta(V^2)

“Is there an edge \(u\)–\(v\)?” is a single array access. The fatal flaw is space: \(\Theta(V^2)\) regardless of how few edges exist. For a social network of a billion people with a few hundred friends each, the matrix is \(10^{18}\) cells, almost all zero: impossible. Matrices suit only small or dense graphs.

Adjacency list

One list of neighbors per vertex:

  0 → [1, 2]        space: Theta(V + E)
  1 → [0, 2, 3]     iterate 1's neighbors: O(deg 1)
  2 → [0, 1]        edge query 0–2: scan 0's list
  3 → [1]

The list stores only the edges that exist, so its space is \(\Theta(V+E)\), proportional to the actual graph. Iterating a vertex’s neighbors, the inner loop of every search, is \(O(\deg u)\), which is optimal. Its one weakness is the edge query “is \(u\)–\(v\) an edge?” (scan a list), but graph algorithms rarely ask that: they iterate neighbors. Hence the adjacency list is the default.

Insertion is \(O(1)\) either way: two symmetric cell writes, or two appends at the ends of two lists. The representations part company on the three read operations. Run each on the finished structure:

operationadjacency matrixadjacency list

The middle row is the one that decides the representation, because iterating neighbors is the inner loop of every graph search. Sweeping every vertex’s neighbors costs the matrix \(V\) cell reads per vertex, so \(V^2\) reads no matter how few edges exist; it costs the list \(\deg(u)\) reads per vertex, and by the handshake lemma (§2) those sum to \(2|E|\), here \(2 \cdot 4 = 8\) reads against the matrix’s \(16\). That \(V + 2E\) against \(V^2\) is exactly the \(\Theta(V+E)\) cost of DFS and BFS.

Dense or sparse: the numbers

Fix \(V = 1000\) and vary the edge count. A matrix always holds \(V^2 = 1{,}000{,}000\) cells; a list holds \(V + 2E\) slots, one per vertex plus one per edge endpoint.

complete graph499,500 1,000,0001,000,000 1,000,000 vs 999,000 reads

The break-even is exact: \(V + 2E = V^2\) precisely when \(E = V(V-1)/2\), the complete graph. So the matrix never uses less space than the list on a simple graph, and it matches only when every pair of vertices is joined. On the sparse road network the list is smaller by a factor of \(200\) and its search sweep is faster by a factor of \(250\). What the matrix buys with that space is the \(O(1)\) membership test, which is the trade worth making when \(V\) is small enough that \(V^2\) cells fit comfortably, or when a single bit per cell makes the matrix physically smaller than a list of 32-bit vertex numbers.

Since real graphs are sparse and algorithms iterate neighbors, we use the adjacency list throughout. In C++ it is a vector of vectors: 

struct Graph {
    int V;                        // number of vertices
    vector<vector<int>> adj;      // adj[u] = u's neighbors
    Graph(int n) : V(n), adj(n) {}
    void addEdge(int u, int v) {
        adj[u].push_back(v);
        adj[v].push_back(u);      // omit this line for a digraph
    }
};
class Graph {
    int V;                                  // number of vertices
    List<List<Integer>> adj;                // adj.get(u) = u's neighbors
    Graph(int n) {
        V = n;
        adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    }
    void addEdge(int u, int v) {
        adj.get(u).add(v);
        adj.get(v).add(u);                  // omit this line for a digraph
    }
}
class Graph:
    def __init__(self, n):
        self.V = n
        self.adj = [[] for _ in range(n)]   # adj[u] = u's neighbors

    def add_edge(self, u, v):
        self.adj[u].append(v)
        self.adj[v].append(u)               # omit this line for a digraph
struct Graph {
    adj: Vec<Vec<usize>>,               // adj[u] = u's neighbors
}
impl Graph {
    fn new(n: usize) -> Self {
        Graph { adj: vec![Vec::new(); n] }
    }
    fn add_edge(&mut self, u: usize, v: usize) {
        self.adj[u].push(v);
        self.adj[v].push(u);            // omit this line for a digraph
    }
}

4. Exercises (with solutions)

  1. An undirected graph has degree sequence \(4, 3, 3, 2, 2\). How many edges does it have? Could a simple undirected graph have degree sequence \(4, 4, 1, 1\)?
    solution By the handshake lemma \(\sum \deg = 2E\), so \(E = (4+3+3+2+2)/2 = 14/2 = 7\). For \(4,4,1,1\): the sum is \(10\), an even number, so the lemma is satisfied, but a vertex of degree \(4\) needs \(4\) distinct neighbors and there are only \(3\) other vertices: impossible in a simple graph. (The handshake parity test is necessary, not sufficient.)
  2. A digraph has \(V\) vertices and \(E\) edges. You must answer many “is \(u \to v\) an edge?” queries and no neighbor-iteration queries. Which representation do you choose, and how does the answer change if the graph is sparse and you instead iterate neighbors constantly?
    solution For pure edge-existence queries the adjacency matrix answers each in \(O(1)\); if you can afford \(\Theta(V^2)\) space (small or dense graph), it wins. For a sparse graph where the operations iterate neighbors (as DFS, BFS, and topological sort do), the adjacency list wins on both counts: \(\Theta(V+E)\) space and \(O(\deg u)\) neighbor iteration, which is optimal. Representation follows the algorithm’s access pattern.
  3. A graph has \(V = 10{,}000\) vertices and average degree \(6\). Give the edge count, the matrix cell count, and the list slot count. How many reads does one sweep of every vertex’s neighbors cost in each representation? At what edge count do the two space costs meet?
    solution Average degree \(6\) means \(\sum_v \deg(v) = 60{,}000\), so by the handshake lemma \(E = 30{,}000\). The matrix holds \(V^2 = 100{,}000{,}000\) cells; the list holds \(V + 2E = 10{,}000 + 60{,}000 = 70{,}000\) slots, smaller by a factor of about \(1{,}429\). A full sweep reads \(V^2 = 100{,}000{,}000\) matrix cells against \(2E = 60{,}000\) list entries, a factor of about \(1{,}667\). The space costs meet when \(V + 2E = V^2\), i.e. \(E = V(V-1)/2 = 49{,}995{,}000\): the complete graph, and roughly \(1{,}667\) times as many edges as this graph has.
  4. On the four-vertex graph \(E = \{0\text{-}1, 0\text{-}2, 1\text{-}2, 1\text{-}3\}\), count the comparisons an adjacency list needs to answer “is \(2\)–\(3\) an edge?” and “is \(3\)–\(2\) an edge?” Why do the two counts differ when the answer is the same, and what does that say about which endpoint to scan from?
    solution Scanning from \(2\): its list is [0,1], so \(0\) no, \(1\) no, exhausted: \(2\) comparisons, answer no. Scanning from \(3\): its list is [1], so \(1\) no, exhausted: \(1\) comparison, answer no. The cost is \(O(\deg u)\) in whichever endpoint you scan, so on an undirected graph the query should start at the endpoint of smaller degree; that costs \(O(\min(\deg u, \deg v))\) rather than \(O(\deg u)\). The matrix reads a[2][3] or a[3][2] in one access either way, which is the whole of its advantage.
