Bellman-Ford

Lester Ford described the algorithm in 1956 and Richard Bellman published it in 1958. It became the basis of distance-vector routing on the early ARPANET and in RIP. R. Bellman, “On a Routing Problem,” Quarterly of Applied Mathematics 16, 1958

The Dijkstra handout solves single-source shortest paths by a greedy rule (settle the nearest unsettled vertex) and proves the rule safe under one precondition: every edge weight is \(\ge 0\). It also exhibits the failure when the precondition is dropped: a negative edge lets a cheaper route arrive after its destination has been settled, and Dijkstra never reconsiders a settled vertex. Bellman-Ford is the algorithm for that harder problem. It gives up the greedy shortcut entirely: no vertex is ever declared final early; instead every edge is relaxed, over and over, until no label can move. Organized properly, “over and over” means exactly \(V-1\) rounds, because round \(i\) is a dynamic-programming step over the number of edges a path may use. The same rounds also answer a question Dijkstra never faces: whether the graph contains a negative cycle, which makes “shortest path” meaningless. Negative edge weights are not exotic; they appear whenever a step can pay instead of cost (a rebate, a gain, a currency conversion modeled by log-exchange rates) and in constraint systems where an edge encodes an inequality.

1. The problem: negative weights break greed

The setup is the single-source shortest-paths (SSSP) problem of the Dijkstra handout, on the weighted digraph representation of the graph-representations handout: given a weighted digraph and a source \(s\), compute the distance \(\delta(v)\) (the minimum total edge weight of any \(s \to v\) path) for every vertex \(v\), with parent pointers to reconstruct the paths. The one change: edge weights may now be negative.

Definition (edge relaxation, recap) Keep a tentative distance \(\texttt{dist}[v]\) for every vertex, initialized to \(\texttt{dist}[s] = 0\) and \(\infty\) elsewhere. To relax an edge \(u \to v\) of weight \(w\): 
  if (dist[u] + w < dist[v]) {
      dist[v] = dist[u] + w;   // found a cheaper route to v
      parent[v] = u;           // remember the edge, for the path
  }
Relaxation never raises a label, and a finite label is always the cost of some real route from \(s\) (append the relaxed edge to the route that set \(\texttt{dist}[u]\)). When no edge in the graph can be relaxed, every label equals the true distance; the proof is in the Dijkstra handout and does not use any sign assumption on the weights.

Every shortest-path algorithm is a schedule for relaxations. Dijkstra schedules them greedily and, the moment a vertex is settled, promises never to touch its label again. One negative edge voids the promise:

Example (the counterexample, recapped) On \(s \to a\,(1)\), \(s \to b\,(2)\), \(b \to a\,(-4)\), Dijkstra settles \(s\) at \(0\), then \(a\) at \(1\) (the nearest), declaring \(\texttt{dist}[a] = 1\) final. Only then does \(b\) settle at \(2\) and relax \(b \to a\): \(2 + (-4) = -2 < 1\), but \(a\) is frozen. The true distance is \(\delta(a) = -2\); Dijkstra reports \(1\), silently. The Dijkstra handout pins the failure to the one proof step that needs \(w \ge 0\).

So with negative weights no label may be trusted early. But there is a second, deeper problem: with negative weights the answer itself can stop existing.

Definition (negative cycle) A negative cycle is a directed cycle whose edge weights sum to a negative number. If some \(s \to v\) route can reach a negative cycle and continue on to \(v\), then no shortest \(s \to v\) path exists: each extra lap around the cycle lowers the total, so the costs descend toward \(-\infty\).

The honest problem statement is therefore two-sided, and Bellman-Ford answers both sides: if no negative cycle is reachable from \(s\), report every \(\delta(v)\); otherwise, report that a reachable negative cycle exists (§6).

2. Rounds of relaxation as a dynamic program

If no single relaxation schedule can be trusted, schedule all of them: relax every edge in the graph, one full pass; then do it again; and again. Each pass is a round. The question is how many rounds are enough, and the answer comes from parameterizing the problem the way dynamic programming (DP) always does: by a size measure of the solution. Here the measure is how many edges a path may use.

Definition (the DP subproblem) For \(i \ge 0\), let \[ D_i(v) \;=\; \text{the minimum cost of an } s \to v \text{ path using at most } i \text{ edges} \] (\(\infty\) if no such path exists). Base case: \(D_0(s) = 0\) and \(D_0(v) = \infty\) for \(v \ne s\). Recurrence: \[ D_i(v) \;=\; \min\Bigl(\, D_{i-1}(v),\; \min_{\,u \to v \text{ of weight } w} \bigl(D_{i-1}(u) + w\bigr) \Bigr). \] A best path of at most \(i\) edges either uses at most \(i-1\) edges (first term) or arrives by some final edge \(u \to v\), preceded by a best path to \(u\) of at most \(i-1\) edges (second term, one candidate per incoming edge). The optimal-substructure argument that the prefix may be assumed optimal is the exchange argument of the Dijkstra handout, and it does not care about signs.

Computing row \(D_i\) from row \(D_{i-1}\) means, for every edge \(u \to v\), testing \(D_{i-1}(u) + w\) against the entry for \(v\): that is exactly one relaxation pass over all \(E\) edges. And the rows stop changing quickly: a shortest path never needs \(V\) or more edges (it would repeat a vertex, and the enclosed cycle could be cut out; with no negative cycles, cutting never makes it worse, as proved in §7). So \(D_{V-1}(v) = \delta(v)\) for every \(v\): \(V-1\) rounds suffice.

One practical wrinkle. The code below does not keep two rows; it relaxes in place, into the single array \(\texttt{dist}\). In-place rounds can only be ahead of the table: if an edge scanned early in a round improves \(\texttt{dist}[u]\), an edge scanned later in the same round already sees the improvement, chaining several hops into one round. Since labels are monotone and always honest (real path costs), running ahead never produces a wrong value; after round \(i\), \(\texttt{dist}[v] \le D_i(v)\), and the \(V-1\)-round guarantee holds a fortiori. The trace in §4 shows the chaining happen, and one exercise shows when the distinction matters.

3. The algorithm

\(V-1\) rounds; each round relaxes every edge once, scanning vertices in index order and each vertex’s out-edges in adjacency-list order. Two refinements: a round that changes nothing ends the run early (nothing can change later, §5), and one extra detection pass reports reachable negative cycles (§6). The WGraph type is the weighted adjacency list of the graph-representations handout. 

// Bellman-Ford: V-1 rounds of relax-every-edge, then one detection pass.
// Handles negative weights; reports whether a negative cycle is reachable.
struct BFResult { vector<long> dist; bool negCycle; };

BFResult bellmanFord(WGraph& g, int s) {
    vector<long> dist(g.V, LONG_MAX);        // LONG_MAX plays infinity
    dist[s] = 0;
    for (int round = 1; round <= g.V - 1; round++) {
        bool changed = false;
        for (int u = 0; u < g.V; u++) {
            if (dist[u] == LONG_MAX) continue;   // no route to u yet: skip
            for (Edge e : g.adj[u])
                if (dist[u] + e.w < dist[e.to]) {
                    dist[e.to] = dist[u] + e.w;  // relax: cheaper route
                    changed = true;
                }
        }
        if (!changed) return {dist, false};  // nothing moved: all final
    }
    for (int u = 0; u < g.V; u++)            // detection pass (round V)
        if (dist[u] != LONG_MAX)
            for (Edge e : g.adj[u])
                if (dist[u] + e.w < dist[e.to])
                    return {dist, true};     // still relaxes: negative cycle
    return {dist, false};
}
// Bellman-Ford: V-1 rounds of relax-every-edge, then one detection pass.
// Handles negative weights; reports whether a negative cycle is reachable.
// Returns null if a negative cycle is reachable from s, else the distances.
long[] bellmanFord(WGraph g, int s) {
    long[] dist = new long[g.V];
    Arrays.fill(dist, Long.MAX_VALUE);       // MAX_VALUE plays infinity
    dist[s] = 0;
    for (int round = 1; round <= g.V - 1; round++) {
        boolean changed = false;
        for (int u = 0; u < g.V; u++) {
            if (dist[u] == Long.MAX_VALUE) continue;  // no route yet: skip
            for (Edge e : g.adj.get(u))
                if (dist[u] + e.w < dist[e.to]) {
                    dist[e.to] = dist[u] + e.w;   // relax: cheaper route
                    changed = true;
                }
        }
        if (!changed) return dist;           // nothing moved: all final
    }
    for (int u = 0; u < g.V; u++)            // detection pass (round V)
        if (dist[u] != Long.MAX_VALUE)
            for (Edge e : g.adj.get(u))
                if (dist[u] + e.w < dist[e.to])
                    return null;             // still relaxes: negative cycle
    return dist;
}

# Handles negative weights; reports whether a negative cycle is reachable.
def bellman_ford(g, s):
    dist = [float("inf")] * g.V
    dist[s] = 0
    for _round in range(g.V - 1):
        changed = False
        for u in range(g.V):
            for v, w in g.adj[u]:            # inf + w is inf: no guard needed
                if dist[u] + w < dist[v]:
                    dist[v] = dist[u] + w    # relax: cheaper route
                    changed = True
        if not changed:
            return dist, False               # nothing moved: all final
    for u in range(g.V):                     # detection pass (round V)
        for v, w in g.adj[u]:
            if dist[u] + w < dist[v]:
                return dist, True            # still relaxes: negative cycle
    return dist, False
// Bellman-Ford: V-1 rounds of relax-every-edge, then one detection pass.
// Handles negative weights; Err(()) means a negative cycle is reachable.
fn bellman_ford(g: &WGraph, s: usize) -> Result<Vec<i64>, ()> {
    let n = g.adj.len();
    let mut dist = vec![i64::MAX; n];        // i64::MAX plays infinity
    dist[s] = 0;
    for _round in 1..n {
        let mut changed = false;
        for u in 0..n {
            if dist[u] == i64::MAX { continue; }  // no route to u yet: skip
            for &(v, w) in &g.adj[u] {
                if dist[u] + w < dist[v] {
                    dist[v] = dist[u] + w;   // relax: cheaper route
                    changed = true;
                }
            }
        }
        if !changed { return Ok(dist); }     // nothing moved: all final
    }
    for u in 0..n {                          // detection pass (round V)
        if dist[u] == i64::MAX { continue; }
        for &(v, w) in &g.adj[u] {
            if dist[u] + w < dist[v] { return Err(()); }  // negative cycle
        }
    }
    Ok(dist)
}

Three implementation notes. The dist[u] == ∞ skip is not an optimization but a correctness guard in the fixed-width languages: LONG_MAX + w overflows (and for negative \(w\) would compare as a genuine improvement); Python’s float("inf") absorbs addition, so its pane needs no guard. Second, unlike Dijkstra there is no priority queue and no settled array: the only state is \(\texttt{dist}\) itself (plus parent pointers if paths are wanted; set parent[v] = u inside the improving branch exactly as in the relaxation definition). Third, the algorithm never decides anything about the graph; it just relaxes on a fixed schedule, which is why negative weights cost it nothing.

5. Early termination, and edge order

Proposition (early termination is sound) If some round relaxes no edge, then no later round would relax an edge, and every label already equals its final value. Stopping is safe.
Proof. Whether an edge relaxes depends only on the current \(\texttt{dist}\) array. A round that changes nothing ends with the same array it began with, so the next round faces the identical array and makes the identical (empty) set of changes, and so on by induction. Moreover “no edge relaxes” is exactly the terminal condition of the relaxation invariant (§1): at that point \(\texttt{dist}[v] = \delta(v)\) for every \(v\). ∎

The running trace used it: round 3 was the confirming, all-fail round, and round 4 never ran. How many rounds a run actually needs depends on the edge scan order, which affects speed but never the answer. The extreme case is a path:

Example (best and worst scan order) Take the path \(0 \to 1 \to 2 \to 3\), each edge of weight \(1\), source \(0\). Scanned against the path direction, order \(2\to3,\ 1\to2,\ 0\to1\): 
  round 1:  2→3: dist[2]=∞, skip     1→2: dist[1]=∞, skip     0→1: 0+1=1<∞ ⇒ dist[1]=1
  round 2:  2→3: dist[2]=∞, skip     1→2: 1+1=2<∞ ⇒ dist[2]=2   0→1: 1 ≥ 1, no change
  round 3:  2→3: 2+1=3<∞ ⇒ dist[3]=3   1→2: 2 ≥ 2   0→1: 1 ≥ 1
  final:    dist = [0, 1, 2, 3]  after the full V-1 = 3 rounds
Each round the news travels exactly one edge, so all \(V-1\) rounds are needed; the skipped tests (source label still \(\infty\), so \(\infty + 1\) offers nothing and the guard skips) are the remaining branch of the loop. Scanned with the path direction, order \(0\to1,\ 1\to2,\ 2\to3\), round 1 chains all three improvements (\(\texttt{dist} = [\,0,1,2,3\,]\) immediately) and round 2 is the all-fail confirming round: two rounds total, the best case.

Both runs end with the same distances; the guarantee of §7 is scan-order-free because it only ever argues “by the end of round \(i\), paths of \(\le i\) edges are accounted for,” which any complete pass delivers regardless of order.

6. Detecting negative cycles

After \(V-1\) full rounds, every label must be final, if the distances exist at all. So run the loop body one more time as a detection pass (round \(V\)): if any edge still relaxes, the labels have not converged after they provably should have, and §7 shows this happens exactly when a negative cycle is reachable from \(s\).

Example (a detection pass that fires) Vertices \(0,1,2,3\), source \(0\), edges in scan order \(0\to1\,(1)\), \(1\to2\,(1)\), \(2\to3\,(-1)\), \(3\to1\,(-1)\). The cycle \(1\to2\to3\to1\) has weight \(1-1-1 = -1\): negative, and reachable. The \(V-1 = 3\) rounds:

after round 2 0−110
after round 3 0−20−1
Round 1 already laps the cycle once within the round (the scan order follows the cycle): \(0\to1\) sets \(\texttt{dist}[1] = 1\), the lap returns via \(3\to1\) with \(1 - 1 - 1 = 0 < 1\) and lowers it to \(0\). Every following round subtracts another lap: the three labels on the cycle slide down by \(1\) per round, forever, and no round is ever the all-fail round (early termination never triggers). Detection pass, round 4: the first test is \(0\to1\): \(0 + 1 = 1 \ge -2\), no change; but \(1\to2\): \(-2 + 1 = -1 < 0\) still relaxes, and the pass reports a negative cycle. (Verify the claim honestly: had the labels been true distances, nothing could relax after \(V-1\) rounds.)

Two boundary cases sharpen the statement. First, the detection pass fires only for cycles reachable from \(s\): an unreachable negative cycle sits at \(\texttt{dist} = \infty\), its edges are skipped by the \(\infty\) guard, and the reachable part of the graph still gets correct distances (one exercise works this). Second, when the pass fires, every vertex reachable from the cycle has \(\delta = -\infty\), while vertices the cycle cannot reach still have honest finite labels; the boolean answer “a negative cycle exists” is what the basic algorithm returns.

Recovering the cycle itself The pass tells you a negative cycle exists; to exhibit one, take the edge \(u \to v\) that still relaxed and walk the \(\texttt{parent}\) pointers back from \(u\) for \(V\) steps. After \(V\) steps the walk must have repeated a vertex, and any repeated vertex lies on a cycle of parent edges; that cycle is a negative one (its labels strictly dropped on the last lap that rewired the parents). Currency arbitrage detectors are exactly this: vertices are currencies, the weight of \(u \to v\) is \(-\log(\text{rate}_{u\to v})\), and a negative cycle is a sequence of conversions that ends with more money than it started with.

7. Correctness and cost

Three facts do all the work. Throughout, “path” allows repeated vertices (a walk) unless it says simple; \(\delta(v)\) is the infimum over all \(s \to v\) walks.

Lemma (round guarantee) After round \(i\), for every vertex \(v\), \(\texttt{dist}[v] \le\) the cost of every \(s \to v\) path that uses at most \(i\) edges.
Proof (induction on \(i\)). Base \(i = 0\): the only 0-edge path is the empty path at \(s\), and \(\texttt{dist}[s] = 0\) from the start. Step: assume the claim after round \(i-1\), and take any \(s \to v\) path \(P\) with at most \(i\) edges. If \(P\) has at most \(i-1\) edges, the claim already held after round \(i-1\), and labels never rise. Otherwise write \(P = P' \cdot (u \to v)\), where the prefix \(P'\) has at most \(i-1\) edges, so at the start of round \(i\), \(\texttt{dist}[u] \le \operatorname{cost}(P')\). During round \(i\) the edge \(u \to v\) is tested; at that moment \(\texttt{dist}[u]\) can only be smaller still, so afterwards \[ \texttt{dist}[v] \;\le\; \texttt{dist}[u] + w(u,v) \;\le\; \operatorname{cost}(P') + w(u,v) \;=\; \operatorname{cost}(P), \] and later relaxations only lower it further. ∎
Theorem (Bellman-Ford is correct) If no negative cycle is reachable from \(s\), then after \(V-1\) rounds \(\texttt{dist}[v] = \delta(v)\) for every vertex \(v\), and the detection pass relaxes nothing. If a negative cycle is reachable from \(s\), the detection pass relaxes some edge.
Proof. No reachable negative cycle. First, some shortest walk to each reachable \(v\) is simple: if a walk repeats a vertex it contains a cycle; splicing the cycle out leaves an \(s \to v\) walk and changes the cost by \(-w(\text{cycle}) \le 0\) under the hypothesis, so removal never increases cost, and repeating removals must terminate in a simple walk at least as cheap. A simple path has at most \(V-1\) edges, so by the round-guarantee lemma, after \(V-1\) rounds \(\texttt{dist}[v] \le \delta(v)\). The relaxation invariant (§1) gives the other direction, \(\texttt{dist}[v] \ge \delta(v)\), since every finite label is a real walk’s cost. Hence equality; and with every label equal to \(\delta\), no edge can relax (\(\delta(v) \le \delta(u) + w(u,v)\) for every edge, else appending \(u \to v\) to a shortest walk to \(u\) would beat \(\delta(v)\)), so the detection pass is silent.
A reachable negative cycle exists. Let its vertices in order be \(v_1 \to v_2 \to \cdots \to v_k \to v_1\) with edge weights \(w_1, \dots, w_k\), \(\sum_j w_j < 0\). All its labels are finite after at most \(V-1\) rounds (the cycle is reachable, and the lemma discovers every reachable vertex within \(V-1\) rounds). Suppose, for contradiction, the detection pass relaxes nothing; then for every cycle edge, \(\texttt{dist}[v_{j+1}] \le \texttt{dist}[v_j] + w_j\) (indices mod \(k\)). Summing all \(k\) inequalities, each \(\texttt{dist}[v_j]\) appears once on each side and cancels, leaving \(0 \le \sum_j w_j\), contradicting \(\sum_j w_j < 0\). So some edge still relaxes, and the pass fires. ∎

The summation step is worth savoring: it converts “no edge relaxes” (a local, per-edge fact) into a statement about the whole cycle’s weight, with the labels themselves canceling out. Whatever values the labels hold, a negative cycle always leaves at least one of its edges relaxable.

Cost

Proposition (Bellman-Ford cost) Bellman-Ford runs in \(\Theta(VE)\) time in the worst case and \(\Theta(V + E)\) extra space; with the early-termination test, a run that stabilizes after \(r\) improving rounds costs \(\Theta((r+1)\,E)\).
Proof. One round scans every adjacency list once, doing an \(O(1)\) test-and-maybe-write per edge: \(\Theta(E)\) per round, or \(\Theta(V+E)\) counting the vertex loop on graphs with isolated vertices. There are at most \(V-1\) rounds plus one detection pass, so \(O(VE)\) overall; and the bound is tight, since the against-the-path example of §5 generalizes to a \(V\)-vertex path whose reversed scan order improves exactly one label per round, forcing all \(V-1\) rounds of \(\Theta(E)\) work. With early termination, the run does \(r\) improving rounds plus the one all-fail confirming round: \((r+1)\,\Theta(E)\); the best case \(r = 1\) is \(\Theta(E)\). Space: the \(\texttt{dist}\) and \(\texttt{parent}\) arrays, \(\Theta(V)\), beside the \(\Theta(V+E)\) graph itself. No heap, no queue, no recursion. ∎

8. Bellman-Ford or Dijkstra?

The two algorithms relax the same edges toward the same fixed point and differ only in schedule, which is exactly what the price tags measure:

paradigmgreedy (Greedy Method)DP (Dynamic Programming)

The decision rule: if every weight is nonnegative, use Dijkstra; the greedy license is paid for and \(O(E\log V)\) beats \(\Theta(VE)\) by roughly a factor of \(V/\log V\). Reach for Bellman-Ford when weights can be negative, when the question is the negative cycle (arbitrage detection), or when the setting cannot support a global priority queue: distance-vector routing protocols such as RIP (Routing Information Protocol) run Bellman-Ford distributively, each router repeatedly relaxing using only its neighbors’ latest tables, which is one round from that router’s point of view. On a directed acyclic graph there is a third option that beats both: relax each vertex’s out-edges once, in topological order (the topological-sort handout), for \(\Theta(V+E)\) even with negative weights. And with unit weights, plain breadth-first search already returns shortest paths in \(\Theta(V+E)\).

Where this sits in the catalog: the relaxation primitive, its invariant, and the greedy schedule are the Dijkstra handout; the parameterize-and- recur pattern used in §2 is the Dynamic Programming handout, of which Bellman-Ford is the classic graph instance; the weighted adjacency list is the graph-representations handout; and the priority queue Bellman-Ford pointedly does without is the Heaps & Priority Queues handout.

9. Exercises (with solutions)

  1. Run Bellman-Ford from \(0\) on \(0\to1\,(5)\), \(0\to2\,(4)\), \(1\to3\,(3)\), \(2\to1\,(-2)\), \(2\to3\,(4)\), edges scanned in that order. Give \(\texttt{dist}\) after each round and state when the run stops.
    solution Round 1: \(0\to1\) sets \(\texttt{dist}[1]=5\); \(0\to2\) sets \(\texttt{dist}[2]=4\); \(1\to3\) sets \(\texttt{dist}[3]=8\); \(2\to1\): \(4-2=2 < 5\) improves \(\texttt{dist}[1]=2\); \(2\to3\): \(4+4=8 \ge 8\), a tie, no change. After round 1: \([\,0,2,4,8\,]\). Round 2: only \(1\to3\) fires (\(2+3=5 < 8\)), giving \([\,0,2,4,5\,]\); note the negative edge improved \(1\) after \(1\to3\) was scanned in round 1, so \(3\) needed the second round. Round 3: all five tests fail (\(5\ge2\), \(4\ge4\), \(5\ge5\), \(2\ge2\), \(8\ge5\)), so changed is false and the run stops early, before the nominal \(V-1 = 3\)rd improving round would even matter. Final: \(\delta = 0, 2, 4, 5\).
  2. For the path \(0\to1\to2\to\cdots\to n\) (each weight \(1\), source \(0\)): which edge scan orders make Bellman-Ford do the most rounds, which the fewest, and how many in each case (counting the final all-fail round)?
    solution Worst: scan the edges in reverse path order (\((n{-}1)\to n\) first, \(0\to1\) last). Each round, every edge whose source is still \(\infty\) is skipped, and exactly one new label is set (the next one along the path), so \(n = V-1\) improving rounds are needed, plus the all-fail round: \(V\) rounds, the \(\Theta(VE)\) worst case realized. Best: scan in path order; round 1 chains all \(n\) improvements in one pass (each edge sees the label its predecessor just wrote), and round 2 is the all-fail confirmation: \(2\) rounds total, \(\Theta(E)\). Same answers either way; only the round count moves.
  3. Add the edge \(3\to1\,(1)\) to the running graph of §4 (scanned last). Identify the negative cycle this creates, give \(\texttt{dist}\) after each of the \(V-1 = 4\) rounds from source \(0\), and show the detection pass firing.
    solution The cycle is \(1\to4\to3\to1\) with weight \(3 - 5 + 1 = -1\). Rounds (verified by running the algorithm): after round 1, \([\,0,3,2,2,7\,]\) (the new edge tests \(2+1=3 \ge 3\), a tie); after round 2, \([\,0,2,2,1,6\,]\) (now \(3\to1\): \(1+1=2<3\)); after round 3, \([\,0,1,2,0,5\,]\); after round 4, \([\,0,0,2,-1,4\,]\). Each round the cycle’s three labels drop by \(1\): one more lap. No round is change-free, so early termination never triggers. Detection pass: \(1\to4\) tests \(0+3 = 3 < 4\) and still relaxes; the pass reports a reachable negative cycle. (Vertex \(2\) is untouched by the cycle: no route from the cycle back to \(2\) exists, and its label \(2\) is genuinely final.)
  4. Suppose a negative cycle exists but is not reachable from the source: \(0\to1\,(1)\) plus the two-vertex cycle \(2\to3\,(-1)\), \(3\to2\,(-1)\), source \(0\). What do the rounds compute, and what does the detection pass report? Point to the line of the code that decides it.
    solution \(\texttt{dist}[2]\) and \(\texttt{dist}[3]\) stay \(\infty\) forever: every scan of \(2\to3\) and \(3\to2\) hits the dist[u] == ∞ guard and is skipped, so the cycle never enters the computation. Round 1 sets \(\texttt{dist}[1] = 1\); round 2 changes nothing and the run stops with \([\,0, 1, \infty, \infty\,]\), which is correct (\(2\) and \(3\) are unreachable, so their distance is \(\infty\)). The detection pass, guarded the same way, is silent: correctly so, because the theorem of §7 concerns cycles reachable from \(s\); an unreachable cycle cannot lower any \(s\)-distance. Without the \(\infty\) guard (in the fixed-width languages) the arithmetic itself breaks: LONG_MAX + (-1) compares as an improvement and the pass would misfire.
  5. Prove or refute: on an undirected graph, a single negative edge already makes single-source shortest paths undefined for every vertex that can reach that edge.
    solution True. An undirected edge \(\{u, v\}\) of weight \(w\) is the two directed edges \(u \to v\) and \(v \to u\), both of weight \(w\) (this is how the weighted adjacency list stores it). For \(w < 0\) those two arcs form the cycle \(u \to v \to u\) of weight \(2w < 0\): a negative cycle. Any vertex that can reach \(u\) can lap it forever, driving costs to \(-\infty\). So “Bellman-Ford handles negative weights” must be read on digraphs; on undirected graphs a negative edge is instantly a negative cycle (and Bellman-Ford, run on the two-arc encoding, correctly reports it).
  6. Your airline problem: cheapest route from \(s\) using at most \(k\) flights, \(k < V-1\). A classmate proposes: run Bellman-Ford but stop after \(k\) rounds, and read off \(\texttt{dist}\). Using the running trace of §4, show the proposal is wrong, and fix it.
    solution The in-place code can run ahead of the DP: after round 1 on the running graph, \(\texttt{dist} = [\,0,3,2,2,7\,]\), but \(\texttt{dist}[1] = 3\) is the cost of the two-edge path \(0\to2\to1\) and \(\texttt{dist}[3] = 2\) of the three-edge path \(0\to1\to4\to3\); the true one-edge row is \(D_1 = [\,0,4,2,\infty,\infty\,]\). With \(k = 1\) the proposal reports routes that use too many flights. The fix is the snapshot recurrence of §2: keep the previous round’s array \(D_{i-1}\) frozen, relax every edge reading from \(D_{i-1}\) and writing into a fresh copy \(D_i\), and repeat \(k\) times; then \(D_k(v)\) is exactly the cheapest cost using at most \(k\) edges. Cost \(\Theta(kE)\) time and \(\Theta(V)\) extra space for the second row. (For plain shortest paths the in-place shortcut is harmless, which is why the standard code uses it.)
  7. In the correctness theorem’s cycle-summation step, the labels \(\texttt{dist}[v_j]\) cancel. Explain why the argument needs every label on the cycle to be finite, and where the proof guarantees that.
    solution The summation adds the \(k\) inequalities \(\texttt{dist}[v_{j+1}] \le \texttt{dist}[v_j] + w_j\) and cancels each label across the two sides, which is only legitimate arithmetic if every \(\texttt{dist}[v_j]\) is a real number: \(\infty\) on both sides of an inequality cancels to the vacuous \(0 \le 0 + w\) only if one pretends \(\infty - \infty = 0\), which is not a step at all (and with an \(\infty\) label the edge test itself is skipped by the guard, so the per-edge inequality is not even asserted). The proof guarantees finiteness from reachability: the cycle is reachable from \(s\), so each of its vertices has some \(s\)-path, a simple version of which has at most \(V-1\) edges; by the round-guarantee lemma, after \(V-1\) rounds every such label is finite. This is also exactly why an unreachable negative cycle (previous exercise) escapes detection: its labels stay \(\infty\) and the summation never gets off the ground.
