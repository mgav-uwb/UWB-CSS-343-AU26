P, NP & Reductions

Stephen Cook proved in 1971 that satisfiability is NP-complete. A year later Richard Karp showed that 21 other problems, among them the knapsack problem and the traveling salesman problem, are NP-complete too. S. A. Cook, “The Complexity of Theorem-Proving Procedures,” STOC 1971; R. M. Karp, “Reducibility Among Combinatorial Problems,” 1972

Most of this catalog answers the question “how fast is this algorithm?” For some problems the honest answer is that nobody knows a fast algorithm, and has not for over fifty years. That is a statement about the state of knowledge, not a proof; but there is a way to make it precise and transferable. If you can show that a fast algorithm for your problem would immediately give a fast algorithm for thousands of others that many people have failed to solve, you have said something definite about your problem. The machinery for saying it is the classes P and NP and the polynomial-time reduction.

1. Decision problems and input size

The theory is built on yes/no questions. That is a restriction, and the first job is to show it costs nothing.

Definition (decision problem) A decision problem is a question about an input that has the answer yes or no. Fixing an alphabet \(\Sigma\) and an encoding of inputs as strings over \(\Sigma\), a decision problem is the set \(L \subseteq \Sigma^{*}\) of strings whose answer is yes. Such a set is called a language, and “solving the problem” means deciding membership in \(L\).
Definition (input size) The size \(|x|\) of an input is the number of symbols in its encoding. Running times are measured against \(|x|\). Numbers are written in binary, so an integer \(W\) contributes \(\lfloor \log_2 W\rfloor + 1\) symbols, not \(W\) symbols. A graph with \(n\) vertices and \(m\) edges contributes \(\Theta(n^2)\) symbols as an adjacency matrix or \(\Theta((n+m)\log n)\) as adjacency lists (see Graph Representations); the two are within a polynomial of each other, which is all that will matter.

The binary encoding of numbers is not a technicality. It is the single point on which the knapsack discussion in section 7 turns.

Optimization, evaluation, decision

Every optimization problem comes in three forms. Take Vertex Cover, using the definitions of section 5:

  • Optimization: given \(G\), output a smallest set of vertices touching every edge.
  • Evaluation: given \(G\), output the size \(\tau(G)\) of a smallest such set.
  • Decision: given \(G\) and an integer \(k\), is \(\tau(G) \le k\)?

The decision form looks weakest. It is not, because the three are interchangeable at polynomial cost.

Proposition (self-reducibility of Vertex Cover) Given a subroutine \(D(G,k)\) that answers the decision form, one can produce a minimum vertex cover of an \(n\)-vertex graph using at most \(2n+1\) calls to \(D\) plus polynomial extra work.
Proof. First find \(\tau(G)\): ask \(D(G,0), D(G,1), \ldots\) until the answer is yes. The answer is yes at \(k=n\) at the latest, so this costs at most \(n+1\) calls and returns \(k^{*} = \tau(G)\). Now build the set. For a vertex \(v\), let \(G-v\) be \(G\) with \(v\) and all its incident edges deleted. Claim: \(v\) belongs to some vertex cover of \(G\) of size \(k\) if and only if \(D(G-v, k-1)\) is yes. If \(C\) is a cover of \(G\) of size \(k\) containing \(v\), then \(C \setminus \{v\}\) has size \(k-1\) and covers every edge of \(G-v\), since those edges are exactly the edges of \(G\) not touching \(v\). Conversely if \(C'\) covers \(G-v\) and \(|C'| = k-1\), then \(C' \cup \{v\}\) has size at most \(k\) and covers every edge of \(G\): an edge either touches \(v\) or survives in \(G-v\). So: walk the vertices once, and whenever \(D(G-v, k-1)\) is yes, put \(v\) into the answer and replace \(G \leftarrow G-v\), \(k \leftarrow k-1\). That is \(n\) further calls. The invariant “the remaining graph has a cover of size \(k\)” holds throughout, and \(k\) reaches \(0\) exactly when the remaining graph has no edges. ∎

The same trick works for the other problems here. So nothing is lost by studying only decision problems, and a great deal of formal convenience is gained: a decision problem is just a set of strings, and sets can be compared, mapped into one another and collected into classes.

2. The class P

Definition (P) P is the class of decision problems \(L\) for which some algorithm decides membership in \(L\) in time \(O(|x|^{c})\) for a constant \(c\) fixed in advance, on every input \(x\). Equivalently: problems solvable in polynomial time. The name abbreviates polynomial time.

Two properties make the polynomial the natural boundary to draw, rather than, say, \(O(n^3)\).

Closure under composition. If an algorithm runs in \(O(n^{a})\) steps and each step may call a subroutine costing \(O(n^{b})\), the total is \(O(n^{a+b})\), still a polynomial. Feeding the output of one polynomial-time algorithm into another is therefore safe, and a polynomial-time algorithm may call a polynomial-time subroutine polynomially many times on polynomially larger inputs and remain polynomial-time. No smaller class of growth rates is as well behaved: \(O(n^3)\) algorithms composed \(n\) times are \(O(n^4)\).

Robustness across machine models. A problem in P on a random-access machine is in P on a single-tape Turing machine and on every other reasonable sequential model; the models simulate each other with polynomial overhead, so membership in P does not depend on which one is chosen. The models themselves and the simulations between them are treated in Turing Machines and Computability.

P is an idealization An algorithm running in \(n^{100}\) steps is in P and is useless; an algorithm running in \(2^{n/1000}\) steps is not in P and is fine for \(n\) up to a few thousand. P is defined the way it is because it is closed under composition and stable across machine models, not because every polynomial is practical. In practice the polynomial-time algorithms people actually find have small exponents.

Almost every algorithm in this catalog witnesses membership in P: sorting (mergesort, \(\Theta(n\log n)\)), single-source shortest paths (Dijkstra, Bellman–Ford), minimum spanning trees (Kruskal, Prim), substring search (Knuth–Morris–Pratt), connectivity and bipartiteness (breadth-first search). Deciding whether an integer written in binary is prime is also in P, though that took until 2002 and the algorithm is nothing like trial division.

3. The class NP: verifiers and certificates

Some problems have a feature that is weaker than a fast algorithm but still sharp: a yes answer can be justified briefly. If someone hands you the justification, you can check it quickly, even though finding it seems to require search.

Definition (verifier, certificate, NP) A verifier for a decision problem \(L\) is an algorithm \(V(x, c)\) taking an input \(x\) and a second string \(c\), the certificate (or witness). \(L\) is in NP if there is a verifier \(V\) and a polynomial \(p\) such that:
  • Completeness. If \(x \in L\), then some \(c\) with \(|c| \le p(|x|)\) makes \(V(x,c)\) accept.
  • Soundness. If \(x \notin L\), then no \(c\) whatsoever makes \(V(x,c)\) accept.
  • Efficiency. \(V\) runs in time polynomial in \(|x|\).
The name abbreviates nondeterministic polynomial time.

Three features of the definition are load-bearing and are the usual places a proposed proof of membership goes wrong. The certificate must be short (polynomial in \(|x|\), so the verifier can afford to read it). The verifier must be fast. And the guarantee is one-sided: yes-instances have certificates, no-instances have none, and nothing is claimed about certifying a no.

A certificate checked step by step

Definition (Hamiltonian Cycle) A Hamiltonian cycle in an undirected graph \(G = (V,E)\) is a cycle that visits every vertex exactly once and returns to its start. HAM-CYCLE is the decision problem: given \(G\), does it contain a Hamiltonian cycle? (After William Rowan Hamilton, who in 1857 sold a puzzle based on finding such a cycle on the dodecahedron.)

The graph \(H\) has exactly two Hamiltonian cycles up to rotation and reflection, \(\langle 1,2,3,4,5,6\rangle\) and \(\langle 1,4,3,2,5,6\rangle\), out of \(5!/2 = 60\) cyclic orders to consider. A verifier is handed one of the two. A solver has to find one.

The verifier in code, and its cost

// Verifier for HAM-CYCLE. adj is an n x n adjacency matrix; cert is a
// claimed Hamiltonian cycle as a vertex sequence. Returns accept/reject.
bool verify(const vector<vector<bool>>& adj, const vector<int>& cert) {
    int n = adj.size();
    if ((int)cert.size() != n) return false;      // wrong length
    vector<bool> seen(n, false);
    for (int v : cert) {                          // permutation test
        if (v < 0 || v >= n || seen[v]) return false;
        seen[v] = true;
    }
    for (int i = 0; i < n; i++) {                 // adjacency test, incl. wrap
        int u = cert[i], w = cert[(i + 1) % n];
        if (!adj[u][w]) return false;
    }
    return true;
}

Cost, argued rather than asserted. The permutation loop performs \(n\) iterations, each doing a constant number of array operations: \(\Theta(n)\). The adjacency loop performs \(n\) iterations, each one matrix lookup: \(\Theta(n)\). So the body of the verifier is \(\Theta(n)\) once the matrix is in memory, and reading the input itself dominates at \(\Theta(n^2)\). The certificate holds \(n\) labels of \(O(\log n)\) bits each, so \(|c| = O(n\log n)\), polynomial in \(|x| = \Theta(n^2)\). All three clauses of the definition hold, so HAM-CYCLE \(\in\) NP.

Guess and check

The equivalent phrasing that gives the class its name: imagine a machine allowed to guess. On input \(x\) it writes down a string \(c\) of length at most \(p(|x|)\) with no cost and no justification, then runs the verifier. The machine accepts \(x\) if some sequence of guesses leads to acceptance. Such a machine is called nondeterministic, and NP is the class of problems it decides in polynomial time. The two definitions describe the same class: the guessed string is the certificate, and the deterministic part of the machine is the verifier. Guessing is not a physical operation; it is a way of naming the search that a real algorithm has to perform.

NP does not mean “not polynomial” The N stands for nondeterministic. It is not a negation, and NP is not the complement of P. Every problem in P is in NP; sorting, shortest paths and minimum spanning trees are all NP problems. Saying “this problem is NP” therefore says almost nothing, and saying “NP means no polynomial algorithm exists” is false in two separate ways. The claim people usually intend is NP-complete, defined in section 6, and even that does not prove no polynomial algorithm exists: it proves that if one does, then one exists for every problem in NP.
Theorem \(\mathrm{P} \subseteq \mathrm{NP} \subseteq \mathrm{EXP}\), where EXP is the class of problems decidable in time \(2^{q(n)}\) for some polynomial \(q\).
Proof. For the first containment, let \(L \in \mathrm{P}\) with decider \(A\) running in polynomial time. Define \(V(x,c)\) to ignore \(c\) entirely and return \(A(x)\), and take the certificate bound \(p(n) = 0\). If \(x \in L\) the empty certificate is accepted; if \(x \notin L\) no certificate is accepted, since \(V\) does not consult \(c\); and \(V\) runs in polynomial time because \(A\) does. So \(L \in \mathrm{NP}\).
For the second, let \(L \in \mathrm{NP}\) with verifier \(V\) running in time \(q(n)\) and certificate bound \(p(n)\). Decide \(L\) by brute force: enumerate every string \(c\) over \(\Sigma\) of length at most \(p(n)\) and run \(V(x,c)\); accept if any run accepts, reject after all of them fail. Completeness and soundness make this correct. The number of strings enumerated is \(\sum_{i=0}^{p(n)} |\Sigma|^{i} < |\Sigma|^{p(n)+1}\), and each costs \(q(n)\), so the total is \(O(|\Sigma|^{p(n)+1} q(n)) = 2^{O(p(n))}\), which is \(2^{q'(n)}\) for a polynomial \(q'\). ∎

A separate result, the time hierarchy theorem, shows \(\mathrm{P} \ne \mathrm{EXP}\). So at least one of the two containments above is strict. Which one is unknown. Whether \(\mathrm{P} = \mathrm{NP}\) is the open question of the field, posed by Stephen Cook in 1971 and carrying one of the seven Clay Mathematics Institute Millennium Prizes.

The missing half: co-NP HAM-CYCLE has short certificates for yes. What certifies a no, that a graph has no Hamiltonian cycle? Listing all \((n-1)!/2\) failed cyclic orders is not a short certificate, and no short one is known. The class of problems whose no-instances have short certificates is called co-NP. Whether \(\mathrm{NP} = \mathrm{co\text{-}NP}\) is also open. The asymmetry is built into the definition of NP, and it is why the definition insists on the one-sided guarantee.

4. Polynomial-time reductions

A reduction is a translation of one problem into another that preserves the answer. It is the tool for transferring hardness.

Definition (polynomial-time reduction) Problem \(A\) reduces to problem \(B\), written \(A \le_{p} B\), if there is a function \(f\) computable in polynomial time such that for every input \(x\), \[ x \in A \quad\Longleftrightarrow\quad f(x) \in B. \] \(f\) maps instances of \(A\) to instances of \(B\); yes-instances must map to yes-instances and no-instances to no-instances. (This is a many-one or Karp reduction, the kind used throughout here.)

One consequence is worth stating because it is often assumed silently: an algorithm running in time \(t(n)\) cannot write more than \(t(n)\) symbols of output, so if \(f\) is computable in time \(O(n^{a})\) then \(|f(x)| = O(|x|^{a})\). The translated instance is automatically only polynomially larger.

Theorem (closure) If \(A \le_{p} B\) and \(B \in \mathrm{P}\), then \(A \in \mathrm{P}\).
Proof. Let \(f\) be the reduction, computable in time \(O(n^{a})\), and let \(B\) have a decider running in time \(O(n^{b})\). To decide \(A\) on input \(x\) with \(|x| = n\): compute \(y = f(x)\), then run the \(B\)-decider on \(y\) and return its answer. Correctness is the definition of \(f\). Cost: computing \(y\) takes \(O(n^{a})\), and \(|y| = O(n^{a})\) by the remark above, so deciding \(B\) on \(y\) takes \(O((n^{a})^{b}) = O(n^{ab})\). The total is \(O(n^{a} + n^{ab}) = O(n^{ab})\) for \(a, b \ge 1\), a polynomial. ∎
Corollary (the contrapositive, which is the useful form) If \(A \le_{p} B\) and \(A \notin \mathrm{P}\), then \(B \notin \mathrm{P}\). Informally: \(B\) is at least as hard as \(A\).
Theorem (transitivity) If \(A \le_{p} B\) and \(B \le_{p} C\) then \(A \le_{p} C\).
Proof. Let \(f\) reduce \(A\) to \(B\) in time \(O(n^{a})\) and \(g\) reduce \(B\) to \(C\) in time \(O(n^{b})\). Take \(h = g \circ f\). Correctness chains the two equivalences: \(x \in A \Leftrightarrow f(x) \in B \Leftrightarrow g(f(x)) \in C\). Cost: \(f(x)\) costs \(O(n^{a})\) and has length \(O(n^{a})\), so applying \(g\) to it costs \(O((n^{a})^{b}) = O(n^{ab})\). The composition of two polynomials is a polynomial, so \(h\) is polynomial-time computable. ∎
The direction, which is where reductions go wrong Read \(A \le_{p} B\) as “\(A\) is no harder than \(B\)”, in the same spirit as \(\le\) on numbers. The mechanical reading: a reduction converts any solver for \(B\) into a solver for \(A\), so \(B\) must be at least as hard.

To prove that \(B\) is hard, reduce a known-hard \(A\) into \(B\): show \(A \le_{p} B\). Building an instance of \(B\) is the work; the known-hard problem is the source.

The failure mode is doing it backwards. “I encoded Vertex Cover as a satisfiability instance, and satisfiability is NP-complete, therefore Vertex Cover is NP-hard” is not an argument. It establishes \(\text{VC} \le_{p} \text{SAT}\), which says Vertex Cover is no harder than satisfiability. That is true of every problem in NP and proves nothing about Vertex Cover. Whenever a reduction argument feels like it worked too easily, check which problem is the source and which is the target.

5. A reduction worked in full: Independent Set and Vertex Cover

Definitions Let \(G = (V,E)\) be an undirected graph, \(n = |V|\).
  • \(S \subseteq V\) is an independent set if no edge of \(G\) has both endpoints in \(S\). INDEPENDENT SET: given \(\langle G, k\rangle\), does \(G\) have an independent set of size at least \(k\)? Write \(\alpha(G)\) for the largest size.
  • \(C \subseteq V\) is a vertex cover if every edge of \(G\) has at least one endpoint in \(C\). VERTEX COVER: given \(\langle G, k\rangle\), does \(G\) have a vertex cover of size at most \(k\)? Write \(\tau(G)\) for the smallest size.

The two problems are the same problem seen from opposite sides, and the following theorem is the whole content of the reduction.

Theorem (complementation) For every graph \(G=(V,E)\) and every \(S \subseteq V\): \(S\) is an independent set of \(G\) if and only if \(V \setminus S\) is a vertex cover of \(G\). Consequently \(\alpha(G) + \tau(G) = n\).
Proof. (\(\Rightarrow\)) Suppose \(S\) is independent and take any edge \(\{u,v\} \in E\). If both \(u\) and \(v\) were in \(S\), that edge would have both endpoints in \(S\), contradicting independence. So at least one of \(u, v\) lies outside \(S\), that is, in \(V \setminus S\). Since the edge was arbitrary, \(V \setminus S\) is a vertex cover.
(\(\Leftarrow\)) Suppose \(V \setminus S\) is a vertex cover and take any edge \(\{u,v\} \in E\). It has an endpoint in \(V \setminus S\), so not both \(u\) and \(v\) lie in \(S\). Since the edge was arbitrary, no edge has both endpoints in \(S\), so \(S\) is independent.
For the size identity, apply the equivalence twice. If \(S\) is a largest independent set then \(V \setminus S\) is a vertex cover of size \(n - \alpha(G)\), so \(\tau(G) \le n - \alpha(G)\), that is \(\alpha(G) + \tau(G) \le n\). If \(C\) is a smallest vertex cover then \(V \setminus C\) is independent of size \(n - \tau(G)\), so \(\alpha(G) \ge n - \tau(G)\), that is \(\alpha(G) + \tau(G) \ge n\). Hence \(\alpha(G) + \tau(G) = n\). ∎
The reduction \(f(\langle G, k\rangle) = \langle G, \,n - k\rangle\), where \(n\) is the number of vertices of \(G\). Reading it as INDEPENDENT SET \(\le_{p}\) VERTEX COVER: the source instance asks for an independent set of size at least \(k\); the target instance asks for a vertex cover of size at most \(n-k\) in the same graph.

The reduction is polynomial-time. It copies the graph and performs one subtraction: \(\Theta(|x|)\) work, well inside polynomial. The graph is not modified at all, which makes this reduction unusually transparent; most are gadget constructions that build a structurally different instance.

The reduction is correct. \(G\) has an independent set of size \(\ge k\) iff \(\alpha(G) \ge k\) iff \(n - \tau(G) \ge k\) (by the theorem) iff \(\tau(G) \le n-k\) iff \(G\) has a vertex cover of size \(\le n-k\). Each step is an equivalence, so \(\langle G,k\rangle\) is a yes-instance of INDEPENDENT SET exactly when \(f(\langle G,k\rangle)\) is a yes-instance of VERTEX COVER.

Worked on a concrete graph

Take \(G\) with \(V = \{a,b,c,d,e,f,g\}\), \(n = 7\), and the seven edges \(E = \{ab,\, bc,\, ca,\, ad,\, be,\, cf,\, dg\}\): a triangle \(a\,b\,c\), a pendant edge at \(b\) and at \(c\), and a path \(a\!-\!d\!-\!g\) hanging off \(a\).

Direction one: an INDEPENDENT SET yes-instance

Source instance: \(\langle G, 4\rangle\). Is there an independent set of size at least \(4\)? Apply \(f\): the target instance is \(\langle G, 7-4\rangle = \langle G, 3\rangle\), asking for a vertex cover of size at most \(3\).

The target is a yes: \(C = \{b, c, d\}\) covers every edge. Checking all seven edges, one row per edge:

It has size \(7 - 3 = 4\), which answers the source instance yes. Checking it directly means testing all \(\binom{4}{2} = 6\) pairs against \(E\):

Direction two: reading the answer back

The reduction as defined only has to preserve yes and no. In this case it also transports solutions, which is what makes it usable for the optimization form. Suppose a VERTEX COVER solver is given \(\langle G, 3\rangle\) and returns the cover \(\{b,c,d\}\). To answer the original INDEPENDENT SET question, take the complement: \(V \setminus \{b,c,d\} = \{a,e,f,g\}\), of size \(7-3 = 4 \ge 4\). The table above is the proof that this works, and the theorem is the proof that it always works.

Note that \(\{b,c,d\}\) is not independent: \(b\!-\!c\) is an edge. A vertex cover and an independent set are different objects; they are related by complementation, not by being the same set.

Direction three: a no-instance

Source instance \(\langle G, 5\rangle\): is there an independent set of size at least \(5\)? Apply \(f\): the target is \(\langle G, 7-5\rangle = \langle G, 2\rangle\), a vertex cover of size at most \(2\). Both are no, and the reason is easiest to see on the cover side.

Claim: \(\tau(G) = 3\). Upper bound: \(\{b,c,d\}\) is a cover, verified row by row above, so \(\tau(G) \le 3\). Lower bound: any cover \(C\) must contain at least two of \(\{a,b,c\}\), because if it omitted two of them, the edge between those two (all three pairs \(ab, bc, ca\) are edges) would be uncovered. \(C\) must also contain at least one of \(\{d,g\}\), to cover the edge \(d\!-\!g\). The vertex sets \(\{a,b,c\}\) and \(\{d,g\}\) are disjoint, so these two requirements count different vertices and \(|C| \ge 2 + 1 = 3\). Hence \(\tau(G) = 3\), and by the complementation theorem \(\alpha(G) = 7 - 3 = 4\). ∎

So there is no cover of size \(2\) and no independent set of size \(5\): both instances are no, as the reduction requires. Exhaustive search confirms the counts: the only vertex cover of size \(3\) is \(\{b,c,d\}\), and the only independent set of size \(4\) is \(\{a,e,f,g\}\).

A caution about this particular pair The map \(k \mapsto n-k\) is its own inverse, so the same construction also proves VERTEX COVER \(\le_{p}\) INDEPENDENT SET. That symmetry is unusual and makes this a poor example for internalizing the direction rule: here both directions happen to be available. A one-way construction is given next.

A construction that runs one way: 3-SAT into INDEPENDENT SET

In a Boolean formula in conjunctive normal form (a conjunction of clauses, each clause a disjunction of literals, a literal being a variable or its negation), 3-SAT asks whether a formula with exactly three literals per clause has a satisfying assignment. The reduction 3-SAT \(\le_{p}\) INDEPENDENT SET builds a graph from a formula: one vertex per literal-occurrence, the three vertices of each clause joined into a triangle, and an edge between any two vertices carrying complementary literals (\(x\) and \(\bar x\)). Ask for an independent set of size \(k = \) the number of clauses.

Example \(\varphi = (x \vee y \vee \bar z) \wedge (\bar x \vee y \vee z)\), two clauses, so \(k = 2\). The graph has six vertices \(x_1, y_1, \bar z_1\) (first clause) and \(\bar x_2, y_2, z_2\) (second). Edges: the two triangles \(\{x_1y_1, x_1\bar z_1, y_1\bar z_1\}\) and \(\{\bar x_2 y_2, \bar x_2 z_2, y_2 z_2\}\), plus the conflict edges \(x_1\!-\!\bar x_2\) and \(\bar z_1\!-\!z_2\). Eight edges in all; \(y_1\) and \(y_2\) carry the same literal \(y\), not complementary ones, so they are not joined.

A triangle contains no independent pair, so any independent set has at most one vertex per clause, hence size at most \(2\); the size-\(2\) sets are exactly the ways of choosing one literal per clause without choosing a variable and its negation. \(\{y_1, y_2\}\) is one, giving the assignment \(y = \text{true}\), and indeed \(\varphi\) is satisfied. \(\{x_1, z_2\}\) is another, giving \(x = \text{true}, z = \text{true}\), which also satisfies \(\varphi\). Exhaustive check: \(\alpha = 2\), and the independent pairs are \(x_1y_2,\; x_1z_2,\; y_1\bar x_2,\; y_1y_2,\; y_1z_2,\; \bar z_1\bar x_2,\; \bar z_1y_2\), seven of them, each a satisfying assignment of \(\varphi\).

In general: a size-\(k\) independent set picks one literal per clause, never a variable together with its negation, so setting those literals true is consistent and satisfies every clause; conversely a satisfying assignment makes at least one literal true per clause, and picking one such vertex per clause gives an independent set of size \(k\). Nothing about this construction reverses. Formulas go in, graphs come out.

6. NP-hardness, NP-completeness, Cook–Levin

Definition (NP-hard, NP-complete) A problem \(B\) is NP-hard if \(A \le_{p} B\) for every \(A \in \mathrm{NP}\). \(B\) is NP-complete if it is NP-hard and also \(B \in \mathrm{NP}\).

NP-hard says “at least as hard as everything in NP”, and does not require \(B\) to be in NP or even to be a decision problem. NP-complete says “exactly as hard as the hardest problems in NP”: these are the problems on which the whole class stands or falls.
Theorem If any NP-complete problem is in P, then \(\mathrm{P} = \mathrm{NP}\).
Proof. Let \(B\) be NP-complete with \(B \in \mathrm{P}\), and let \(A\) be any problem in NP. Since \(B\) is NP-hard, \(A \le_{p} B\). By the closure theorem of section 4, \(A \in \mathrm{P}\). So \(\mathrm{NP} \subseteq \mathrm{P}\), and \(\mathrm{P} \subseteq \mathrm{NP}\) always holds. ∎

The definition of NP-hard quantifies over every problem in NP, infinitely many of them, which looks impossible to establish directly. One theorem does it once, and afterwards a single reduction suffices.

Theorem (Cook 1971, Levin 1973), stated without proof SAT, the problem of deciding whether a Boolean formula in conjunctive normal form has a satisfying assignment, is NP-complete.

The proof is not given here, but its idea is short to state and is not magic. Let \(L \in \mathrm{NP}\) with verifier \(V\) running in time \(p(n)\). On input \(x\), the entire computation of \(V\) on \((x, c)\) can be laid out as a table with \(p(n)\) rows, one per step, each row recording the machine's memory and state at that step. Cook and Levin build, in time polynomial in \(p(n)\), a formula \(\varphi_x\) whose variables are the certificate bits and the table entries, with clauses asserting that row \(0\) is the correct starting configuration, that each row follows from the previous one by the machine's transition rules, and that the last row is accepting. A satisfying assignment of \(\varphi_x\) is exactly an accepting run of \(V\) on \((x,c)\) for some \(c\), so \(\varphi_x\) is satisfiable iff \(x \in L\). Boolean logic is expressive enough to describe a step of computation, and that is the entire content of the theorem.

Theorem (the working method) If \(B\) is NP-complete, \(C \in \mathrm{NP}\), and \(B \le_{p} C\), then \(C\) is NP-complete.
Proof. Take any \(A \in \mathrm{NP}\). Since \(B\) is NP-hard, \(A \le_{p} B\); combined with \(B \le_{p} C\), transitivity gives \(A \le_{p} C\). As \(A\) was arbitrary, \(C\) is NP-hard, and \(C \in \mathrm{NP}\) by assumption, so \(C\) is NP-complete. ∎

This turns an NP-completeness proof into two obligations, both concrete: exhibit a short certificate and a fast verifier for \(C\), and exhibit one reduction from one already-known NP-complete problem into \(C\). 7. What an NP-completeness proof licenses

Establishing that a problem is NP-complete does not end the engineering work; it changes what the engineering work should be. Three moves are standard, and a fourth observation about numeric inputs is where the knapsack fits.

Approximate: give up optimality, keep a guarantee

Minimum Vertex Cover is NP-hard, but a cover within a factor of two of optimal can be built in linear time.

Theorem (2-approximation for Vertex Cover) Let \(M \subseteq E\) be a maximal matching of \(G\): a set of pairwise vertex-disjoint edges to which no further edge can be added. Then the set \(C_M\) of all endpoints of edges in \(M\) is a vertex cover, and \(|C_M| = 2|M| \le 2\,\tau(G)\).
Proof. \(C_M\) is a cover: if some edge \(\{u,v\}\) had neither endpoint in \(C_M\), then \(\{u,v\}\) is disjoint from every edge of \(M\), so \(M \cup \{\{u,v\}\}\) is still a matching, contradicting maximality. The size bound: the edges of \(M\) are pairwise disjoint, so a vertex cover must contain at least one endpoint of each, and no vertex serves two of them; hence \(\tau(G) \ge |M|\). And \(|C_M| = 2|M|\) because the edges are disjoint. Combining, \(|C_M| = 2|M| \le 2\tau(G)\). ∎
Worked on \(G\) Sweep the edges in the order \(ab, bc, ca, ad, be, cf, dg\), taking each edge whose endpoints are both still free. Take \(ab\) (free), skip \(bc, ca, ad\) and \(be\) (each touches \(a\) or \(b\)), take \(cf\) (both free), take \(dg\) (both free). \(M = \{ab, cf, dg\}\), which is maximal: the four skipped edges each touch a matched vertex. So \(C_M = \{a,b,c,d,f,g\}\), size \(6\). It is a cover: the only vertex outside it is \(e\), whose single edge \(b\!-\!e\) is covered by \(b\). And \(\tau(G) = 3\), so the guarantee \(6 \le 2 \cdot 3\) holds with equality: this instance realizes the worst case of the bound. The algorithm never learns that \(\{b,c,d\}\) is available; it buys a factor of two, in linear time, without search.

Parameterize: confine the exponential to a small quantity

A cover of size at most \(k\) can be found in \(O(2^{k}\cdot(n+m))\) time. The exponential is in \(k\) alone, so for a small target the algorithm is fast no matter how large the graph is. The idea: pick any uncovered edge \(\{u,v\}\); every cover contains \(u\) or \(v\), so branch on those two choices and recurse with the budget reduced by one. 

// Bounded-search-tree vertex cover: is there a cover of size <= k?
// Branches on the two endpoints of one uncovered edge.  O(2^k * (n+m)).
bool cover(vector<pair<int,int>> edges, int k, vector<int>& out) {
    if (edges.empty()) return true;              // nothing left to cover
    if (k == 0) return false;                    // budget spent, edges remain
    auto [u, v] = edges[0];                      // any uncovered edge
    for (int w : {u, v}) {                       // it must contribute an endpoint
        vector<pair<int,int>> rest;
        for (auto& e : edges)
            if (e.first != w && e.second != w) rest.push_back(e);
        out.push_back(w);
        if (cover(rest, k - 1, out)) return true;
        out.pop_back();                          // undo, try the other endpoint
    }
    return false;
}

static boolean cover(List<int[]> edges, int k, Deque<Integer> out) {
    if (edges.isEmpty()) return true;            // nothing left to cover
    if (k == 0) return false;                    // budget spent, edges remain
    int u = edges.get(0)[0], v = edges.get(0)[1];  // any uncovered edge
    for (int w : new int[]{u, v}) {              // it must contribute an endpoint
        List<int[]> rest = new ArrayList<>();
        for (int[] e : edges)
            if (e[0] != w && e[1] != w) rest.add(e);
        out.addLast(w);
        if (cover(rest, k - 1, out)) return true;
        out.removeLast();                        // undo, try the other endpoint
    }
    return false;
}

# Branches on the two endpoints of one uncovered edge.  O(2^k * (n+m)).
def cover(edges, k, out):
    if not edges:                                # nothing left to cover
        return True
    if k == 0:                                   # budget spent, edges remain
        return False
    u, v = edges[0]                              # any uncovered edge
    for w in (u, v):                             # it must contribute an endpoint
        rest = [e for e in edges if w not in e]
        out.append(w)
        if cover(rest, k - 1, out):
            return True
        out.pop()                                # undo, try the other endpoint
    return False
// Bounded-search-tree vertex cover: is there a cover of size <= k?
// Branches on the two endpoints of one uncovered edge.  O(2^k * (n+m)).
fn cover(edges: &[(usize, usize)], k: usize, out: &mut Vec<usize>) -> bool {
    if edges.is_empty() { return true; }          // nothing left to cover
    if k == 0 { return false; }                   // budget spent, edges remain
    let (u, v) = edges[0];                        // any uncovered edge
    for w in [u, v] {                             // it must contribute an endpoint
        let rest: Vec<_> =
            edges.iter().copied().filter(|e| e.0 != w && e.1 != w).collect();
        out.push(w);
        if cover(&rest, k - 1, out) { return true; }
        out.pop();                                // undo, try the other endpoint
    }
    false
}

Cost, argued. Let \(T(k)\) be the number of recursive calls with budget \(k\). Each call makes at most two children with budget \(k-1\), so \(T(k) \le 2T(k-1) + 1\) with \(T(0) = 1\), giving \(T(k) \le 2^{k+1}-1\). Each call does \(O(n+m)\) work filtering the edge list, so the total is \(O(2^{k}(n+m))\). Correctness: the branch is exhaustive, since any cover of the remaining edges must contain \(u\) or \(v\); and the recursion is sound, since after committing \(w\) the edges still needing coverage are exactly those not touching \(w\).

Twelve recursive calls in all, against the bound \(T(3) \le 2^{4}-1 = 15\); six of them are leaves, five failing and one succeeding, and the cover found is the unique minimum one. All five failures die the same way: the budget reaches \(0\) while the edge \(d\!-\!g\) is still uncovered. That is the lower-bound argument for \(\tau(G) \ge 3\) reappearing as a dead branch: each failing leaf spent all three vertices without buying either \(d\) or \(g\), and at least two of the three had to go to the triangle.

For comparison, testing all \(\binom{7}{3} = 35\) vertex triples would also work here, but that approach is \(\Theta(n^{k})\), which grows with the graph; the branching bound does not.

Heuristics: give up the guarantee, keep the speed

Branch-and-bound solvers, local search, and general-purpose satisfiability and integer-programming solvers routinely settle NP-complete instances with thousands of variables. They have exponential worst cases and no guarantee on any particular input. NP-completeness is a statement about worst-case behaviour over all instances; the instances arising in an application are not adversarial, and this is why the practical situation is better than the classification suggests.

The numeric loophole: pseudo-polynomial algorithms

0/1 Knapsack asks, given \(n\) items with weights \(w_i\) and values \(v_i\) and a capacity \(W\), for the maximum total value of a subset of weight at most \(W\). It is NP-hard: Subset-Sum reduces to it by taking \(v_i = w_i\) and asking whether value \(W\) is attainable. Yet the dynamic-programming solution fills a table of \(n \times (W{+}1)\) cells in \(\Theta(nW)\) time, and \(nW\) is a product of two input quantities, not an exponential. There is no contradiction, and the resolution is the encoding rule of section 1.

Definition (pseudo-polynomial) An algorithm is pseudo-polynomial if its running time is polynomial in the numeric values appearing in the input, but not in the length of the input. Since a number \(W\) occupies about \(\log_2 W\) bits, a running time of \(\Theta(W)\) is \(\Theta(2^{\log_2 W})\): exponential in the number of bits used to write \(W\).
The numbers Take \(n = 100\) items with weights, values and capacity all below \(2^{60}\), and \(W = 2^{60} = 1{,}152{,}921{,}504{,}606{,}846{,}976\). The instance is written in \(100 \times (60 + 60) + 60 = 12{,}060\) bits, about \(1.5\) kilobytes. The knapsack table has \(nW \approx 1.15 \times 10^{20}\) cells. A \(1.5\)-kilobyte input demands \(10^{20}\) table cells: the table is exponential in the input length, which is exactly what “not polynomial-time” means. The \(\Theta(nW)\) algorithm is genuinely useful whenever \(W\) is small (capacities in the thousands, say), and that is the case the knapsack handout works through; it is not an algorithm for the general problem.

Two consequences worth carrying. First, when a running time contains an input value rather than an input count, check whether that value is bounded by a polynomial in the input length before calling the algorithm efficient. Counting sort is \(\Theta(n+k)\) for keys below \(k\) and is subject to the same reading (see Counting and Radix Sort), though there the assumption \(k = O(n)\) is usually stated outright. Second, some problems admit no pseudo-polynomial algorithm at all unless \(\mathrm{P} = \mathrm{NP}\): the Travelling Salesman problem is hard even when all numbers in the input are tiny, a property called strong NP-hardness, and the numeric loophole is closed for it.

Knapsack has a further escape that Travelling Salesman does not: scaling the item values down to \(O(n/\varepsilon)\) distinct levels and running the same table on the scaled values yields a solution within a factor \((1+\varepsilon)\) of optimal in time polynomial in \(n\) and \(1/\varepsilon\). A family of algorithms of that shape is called a fully polynomial-time approximation scheme, and it is the strongest kind of approximation an NP-hard problem can have.

8. Where this sits

The cost vocabulary used throughout, and the counting arguments the proofs above rely on, are set up in Asymptotic Notation and Time Analysis; the encoding and input-length discussion of section 1 is the same accounting used in Space Complexity. The branching recurrence \(T(k) \le 2T(k-1)+1\) solved in section 7 is one of the standard forms handled in Recursion & Induction.

The Sorting Lower Bound is the other lower-bound argument in this catalog, and the contrast is worth holding in view. That bound is unconditional but restricted: within the comparison model, \(\Omega(n\log n)\) is proved outright, and the escape is to leave the model. NP-completeness is unrestricted but conditional: it proves nothing outright, only that a fast algorithm for one problem is a fast algorithm for all of them.

The problems named here are the hard neighbours of algorithms elsewhere in the catalog. Minimum spanning tree (Kruskal) is in P, while Travelling Salesman on the same weighted graph is NP-hard; Dijkstra finds a shortest path in polynomial time, while finding a longest simple path is NP-hard; breadth-first search decides 2-colourability in linear time, while 3-colourability is NP-complete. The greedy method and dynamic programming are the two paradigms that turn out to solve many of the polynomial-time neighbours, and the 0/1 knapsack table is the pseudo-polynomial case dissected in section 7. Verifying the Hamiltonian-cycle certificate uses the adjacency matrix of Graph Representations.

Everything above takes for granted that “an algorithm” can be made precise, that machine models simulate each other with polynomial overhead, and that some problems have no algorithm at all. Those are the subject of Turing Machines and Computability, which supplies the machine model relied on here; the finite automata of Regular Expressions and Automata are the weakest machine in that hierarchy, at the opposite end from the Turing machines implicit in the Cook–Levin construction.

9. Exercises (with solutions)

  1. COMPOSITE asks, given an integer \(N\) written in binary, whether \(N\) has a divisor strictly between \(1\) and \(N\). Show COMPOSITE \(\in\) NP by naming a certificate, a verifier, and the two size bounds. Why is trial division not a proof that COMPOSITE \(\in\) P?
    solution Certificate: a divisor \(d\) with \(1 < d < N\), written in binary. Verifier: check \(1 < d < N\) and that \(N \bmod d = 0\). Sizes: the input has \(|x| = \Theta(\log N)\) bits; the certificate has at most \(\log_2 N\) bits, so \(|c| \le |x|\), polynomial. Long division of two \(\log N\)-bit numbers is \(O(\log^{2} N)\) bit operations, polynomial in \(|x|\). Completeness: a composite \(N\) has such a divisor. Soundness: if \(N\) is prime no \(d\) passes.
    Trial division tries up to \(\sqrt{N}\) candidates, which is \(2^{|x|/2}\): exponential in the input length, the same pseudo-polynomial reading as the knapsack table. (COMPOSITE is in fact in P, but by a much more intricate algorithm.)
  2. A classmate writes: “I built a polynomial-time map turning any instance of 3-COLOURING into an instance of SAT, preserving the answer. SAT is NP-complete, therefore 3-COLOURING is NP-hard.” Identify the error precisely, say what the construction does establish, and state what would have to be built instead.
    solution The construction establishes 3-COLOURING \(\le_{p}\) SAT, which says 3-COLOURING is no harder than SAT. That is true of every problem in NP and carries no information about 3-COLOURING: it follows already from 3-COLOURING \(\in\) NP together with SAT being NP-complete. Hardness flows from source to target, so a reduction out of a problem never makes that problem hard.
    What is needed is a reduction in the other direction, from a known-hard problem into 3-COLOURING: for instance 3-SAT \(\le_{p}\) 3-COLOURING, a map taking a formula and producing a graph that is 3-colourable exactly when the formula is satisfiable. Together with 3-COLOURING \(\in\) NP (certificate: the colouring; verifier: check every edge has differently coloured endpoints), that proves NP-completeness.
  3. Using the graph \(G\) of section 5, work the reduction on the source instance \(\langle G, 3\rangle\) of INDEPENDENT SET. What target instance does \(f\) produce, what is the answer, and exhibit the two witnesses.
    solution \(f(\langle G,3\rangle) = \langle G, 7-3\rangle = \langle G,4\rangle\): does \(G\) have a vertex cover of size at most \(4\)? Yes. \(\{b,c,d\}\) is one of size \(3 \le 4\), and adding any fourth vertex, say \(\{b,c,d,e\}\), also works, since supersets of covers are covers. The source instance is also yes: \(\{a,e,f,g\}\) is independent and has size \(4 \ge 3\), and any \(3\)-subset of it, such as \(\{a,e,f\}\), is independent too, since subsets of independent sets are independent.
    Note the asymmetry of the two thresholds: INDEPENDENT SET asks for at least \(k\) and VERTEX COVER for at most \(k\), which is what makes \(k \mapsto n-k\) flip the inequality correctly.
  4. A student proposes this certificate for HAM-CYCLE: “the certificate is the list of all \((n-1)!/2\) cyclic orders together with a mark on one that is a cycle.” The verifier reads the mark and checks that one order. Is this a valid proof that HAM-CYCLE \(\in\) NP?
    solution No. The verifier is fine and the completeness and soundness clauses hold, but the certificate violates the length bound: it has \(\Theta((n-1)!)\) entries, and \((n-1)!\) is not bounded by any polynomial in \(|x| = \Theta(n^{2})\). A verifier cannot even read it in polynomial time. The certificate must be short; the correct one is the single cycle, of length \(O(n \log n)\) bits. This is the most common way a proposed NP-membership argument fails: the verification step is cheap, but what is being verified is enormous.
  5. Suppose someone exhibits a polynomial-time algorithm for VERTEX COVER. What follows for INDEPENDENT SET, for HAM-CYCLE, and for the general 0/1 knapsack problem? Justify each, naming the results used.
    solution VERTEX COVER is NP-complete, so by the theorem of section 6, \(\mathrm{P} = \mathrm{NP}\), and every problem in NP acquires a polynomial-time algorithm.
    INDEPENDENT SET: directly, without invoking \(\mathrm{P} = \mathrm{NP}\). Apply the reduction of section 5: answer \(\langle G,k\rangle\) by running the VERTEX COVER algorithm on \(\langle G, n-k\rangle\), one call plus \(\Theta(|x|)\) work, by the closure theorem.
    HAM-CYCLE: it is in NP (verifier given in section 3), so it inherits a polynomial-time algorithm from \(\mathrm{P} = \mathrm{NP}\). Concretely, one composes the chain HAM-CYCLE \(\le_{p}\) SAT (from Cook–Levin applied to its verifier) \(\le_{p}\) 3-SAT \(\le_{p}\) INDEPENDENT SET \(\le_{p}\) VERTEX COVER; transitivity makes the composition a single polynomial-time reduction.
    0/1 knapsack: the decision form is in NP (certificate: the chosen subset; verifier: sum the weights and values), so it too gets a polynomial-time algorithm, and by self-reducibility the optimization form does as well. In particular a genuinely polynomial algorithm would replace the \(\Theta(nW)\) table, whose cost is exponential in the bit length of \(W\).
  6. Run the maximal-matching 2-approximation on the graph \(H\) of section 3, scanning edges in the order \(12, 14, 16, 23, 34, 25, 45, 56\). What cover does it return? Compare with \(\tau(H)\), which you should determine, and check the guarantee.
    solution Take \(12\) (both free). Skip \(14, 16\) (touch \(1\)), skip \(23\) (touches \(2\)). Take \(34\) (both free). Skip \(25, 45\). Take \(56\) (both free). \(M = \{12, 34, 56\}\), maximal, so the cover is \(C_M = \{1,2,3,4,5,6\}\), all six vertices.
    \(\tau(H)\): \(H\) is bipartite with parts \(\{1,3,5\}\) and \(\{2,4,6\}\), so each part is a vertex cover, giving \(\tau(H) \le 3\). And \(M\) is a matching of size \(3\) with pairwise disjoint edges, so \(\tau(H) \ge 3\) by the argument in the 2-approximation proof. Hence \(\tau(H) = 3\), for example \(C = \{1,3,5\}\). The guarantee: \(|C_M| = 6 = 2 \cdot 3 = 2\tau(H)\), tight again. Any graph that is a disjoint union of edges, or that the sweep happens to match perfectly, realizes the factor of two.
  7. Let \(A \le_{p} B\) with reduction \(f\) computable in \(O(n^{2})\), and suppose \(B\) has an algorithm running in \(O(n^{3})\). Bound the resulting running time for \(A\), being explicit about where the instance size enters. Then explain why the same argument fails if \(B\)'s algorithm runs in \(O(2^{n})\).
    solution On an input \(x\) of size \(n\), computing \(y = f(x)\) costs \(O(n^{2})\), and because an \(O(n^{2})\)-time algorithm writes at most \(O(n^{2})\) output symbols, \(|y| = O(n^{2})\). Running the \(B\)-algorithm on \(y\) costs \(O(|y|^{3}) = O((n^{2})^{3}) = O(n^{6})\). Total: \(O(n^{2} + n^{6}) = O(n^{6})\). The instance size enters twice: once as the cost of building \(y\), once as the size of \(y\) fed into the exponent of the second algorithm.
    With an \(O(2^{n})\) algorithm for \(B\) the composition gives \(O(2^{|y|}) = O(2^{cn^{2}})\), worse than \(2^{n}\). Polynomial blow-up in instance size is harmless inside a polynomial, because polynomials compose to polynomials, and harmful inside an exponential. This is precisely why the reduction framework is built on P: the closure theorem depends on the composition property, and \(\mathrm{EXP}\) does not have it in the same way.
  8. Someone claims: “My problem is NP, so it has no efficient solution.” List every distinct error in that sentence.
    solution Three errors.
    (i) NP abbreviates nondeterministic polynomial time, not “not polynomial”. It is a class of problems whose yes answers have short certificates.
    (ii) Membership in NP is not evidence of hardness. \(\mathrm{P} \subseteq \mathrm{NP}\), so sorting, shortest paths and minimum spanning trees are all in NP. The intended claim is presumably NP-complete or NP-hard, which requires proving a reduction from a known-hard problem.
    (iii) Even NP-completeness does not establish that no efficient algorithm exists. It establishes that a polynomial-time algorithm for this problem would give one for every problem in NP. Whether \(\mathrm{P} = \mathrm{NP}\) is open, so no such non-existence has been proved for any problem in NP.
    A fourth point, not an error but a common omission: even a correct NP-completeness proof is a worst-case statement, and it leaves the approximation, parameterization and heuristic routes of section 7 entirely open.
