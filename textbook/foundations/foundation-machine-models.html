Algorithms on Real Machines

Data Structures & Algorithms. Foundation.
What the machine does to an asymptotic bound: every bound is a statement about a cost model; costs that stay within constant limits leave the order of growth unchanged however large the constants are; a memory hierarchy makes the cost of one access a step function of the working set, which a doubling experiment sees as a knee; the exponent changes only when the cost of a basic step grows with the input; pipelines, superscalar execution and branch prediction change constant factors; and what it means for a programmer to optimize a program. Builds on the Computer Systems Primer and Asymptotic Notation.

An analysis that says an algorithm runs in \(\Theta(N^2)\) time counts operations in an idealized machine where every operation costs the same. Real machines are not like that: one memory read can take 1.4 ns or 5 ms, a factor of more than three million, depending on where the data is. This chapter answers three questions that follow. Does a slow memory, or a program that runs out of memory and swaps to disk, change the order of growth? When does the order of growth really change? And if the order of growth is fixed by the algorithm, what is left for a programmer to optimize?

1. Every bound is relative to a cost model

A statement such as “brute-force 3-sum runs in \(\Theta(N^3)\) time” is a statement about a function \(T(N)\), and \(T(N)\) is defined by a cost model: a choice of which operations count and what each one costs.

Definition (RAM model) The random-access machine (RAM) has an unbounded memory of words, addressed by integers. Reading or writing any word, an arithmetic operation or comparison on words, and a branch each cost one step. The cost of an algorithm on an input is the number of steps it takes.

Every bound in the analysis chapters of this book is a bound in the RAM model, or in a coarser model that counts one kind of operation (a comparison, an array access) as a stand-in for all of them. The model leaves out the property that dominates real running times: in a real machine a memory read costs more or less depending on where the data currently is (Computer Systems Primer, section 2). The question for this chapter is when that omission changes the order of growth and when it only changes the constant.

Real running time is a sum over the operations the program executes:

\[ R(N) \;=\; \sum_{\text{operations } o} \operatorname{cost}(o), \]

where \(\operatorname{cost}(o)\) is the time that operation actually took. The RAM model replaces every \(\operatorname{cost}(o)\) by 1. The next section shows that this replacement cannot change a \(\Theta\) bound as long as every cost stays between two fixed constants.

2. Bounded costs preserve the order of growth

Theorem (bounded costs) Suppose every operation of a program costs at least \(a\) and at most \(b\), for constants \(0 < a \le b\) that do not depend on \(N\). If the program executes \(T(N)\) operations, its running time \(R(N)\) satisfies \[ a\,T(N) \;\le\; R(N) \;\le\; b\,T(N), \] so \(R(N) \in \Theta(T(N))\).
Each of the \(T(N)\) terms of the sum \(R(N) = \sum_o \operatorname{cost}(o)\) lies between \(a\) and \(b\), so the sum lies between \(a\,T(N)\) and \(b\,T(N)\). These are exactly the witnesses of Asymptotic Notation: \(R \in O(T)\) with \(c = b\), and \(R \in \Omega(T)\) with \(c = a\), for every \(N \ge 1\). □

The constants may be enormous. Consider a machine whose instructions take one cycle but whose every memory read takes \(10^6\) cycles, and an all-pairs loop that executes three instructions and one memory read for each of its \(N^2\) pairs:

\[ R(N) = N^2\,(3 + 10^6) \text{ cycles}, \qquad R(1000) = 1{,}000{,}003{,}000{,}000 \text{ cycles}, \qquad \frac{R(2000)}{R(1000)} = 4. \]

The doubling ratio is exactly 4, as on any other machine: the program is \(\Theta(N^2)\), slower than on an ordinary computer by a factor of about \(10^6\). A slow memory, however slow, does not change an order of growth if every read costs the same.

What the constant does change is which of two algorithms is faster at a given \(N\). On the same machine, compare that \(\Theta(N^2)\) loop, at \(10^6\) cycles per pair, with a \(\Theta(N^3)\) algorithm whose data stays in registers, at one cycle per step. The cubic algorithm is faster while \(N^3 < 10^6 N^2\), that is, for every \(N\) below \(10^6\). On an ordinary machine, where a read costs about as much as an instruction, the quadratic algorithm wins for every \(N\) above 4. Asymptotics say which algorithm wins eventually; the cost model decides where “eventually” begins.

3. The memory hierarchy: cost per access as a step function

On a real machine the cost of a memory read is not one constant but one of several, depending on which level of the hierarchy holds the data. Which level that is depends on how much memory the program is using.

Definition (working set) The working set of a program over a stretch of its execution is the set of memory locations it accesses repeatedly during that stretch. Its size \(W\), in bytes, decides which level of the hierarchy the accesses are served from.

A simple model gives the expected cost of one access as a function of \(W\). It describes a machine by its levels, fastest first, each with a capacity \(C_k\), a time \(L_k\) to serve one read, and the size of the block it hands to the level above on a miss (64-byte cache lines; 4096-byte pages from a disk).

  • Sequential scan of \(W\) bytes held at level \(k\), the first level with \(C_k \ge W\): each block is fetched once, then its items are read from the top level. One access to an \(e\)-byte item costs \(L_1 + L_k \cdot e / \text{block}_k\).
  • Random order over \(W\) bytes: in the steady state a level of capacity \(C\) holds a fraction \(\min(1, C/W)\) of the working set, so an access is first found at level \(k\) with probability \(F_k - F_{k-1}\), where \(F_k = \min(1, C_k/W)\). The expected cost is \(\sum_k (F_k - F_{k-1})\,L_k\).

With the latencies measured in the Computer Systems Primer (1.4 ns for the level-1 cache, L1; about 4 ns for L2; about 15 ns for L3; about 100 ns for main memory) and a typical 50 µs for a solid-state drive (SSD), the model gives this picture:

Two facts follow. First, the cost per access is bounded: it never exceeds the latency of the slowest level, 50 µs here. So on this fixed machine the theorem of section 2 applies, with \(a = 1.4\) ns and \(b = 50\) µs: no program’s order of growth is changed by the hierarchy. Second, the ratio \(b/a\) is about 35,700. A bound that hides a constant of that size is still a correct bound, and it is a poor predictor of running time across that range. The next section shows what this looks like in a doubling experiment.

4. Crossing a boundary: swap, the knee, and the doubling ratio

Take a machine with only 64 MiB of main memory, backed by swap space on a hard disk with a 5 ms access time, and a \(\Theta(N)\) program: \(N\) lookups at random positions in a table of \(N\) eight-byte entries, which is what a hash table does. If the time per operation changes from \(c(N)\) to \(c(2N)\) while the operation count of a \(\Theta(N^b)\) algorithm grows by \(2^b\), the doubling ratio is \(2^b \cdot c(2N)/c(N)\), so the measured exponent is

\[ b_{\text{local}} \;=\; b \;+\; \lg \frac{c(2N)}{c(N)} . \]

Inside a level \(c(2N) = c(N)\) and the experiment reads off the true \(b\). In the doubling where the working set crosses from memory to a disk whose access time is 50,000 times that of memory, the term \(\lg 50{,}000 \approx 15.6\) is added: the \(\Theta(N)\) lookups show \(b \approx 15.7\). After the crossing the ratio returns to 2, and the exponent to 1, because every lookup now costs about the same 5 ms.

Swapping and the exponent On a fixed machine, swapping does not change an order of growth: once the working set is on the disk, every access costs at most the disk’s access time, a constant, and section 2 applies. An \(N^2\) algorithm stays \(\Theta(N^2)\). What swapping changes is the constant, by a factor of up to \(50{,}000\) for random access to a hard disk (500 for an SSD), and that change is concentrated in the one doubling where the working set crosses the size of memory.

A doubling experiment that spans the crossing can still mislead. Over \(k\) doublings that include it, the apparent exponent is \(b + \lg(c_{\text{after}}/c_{\text{before}})/k\). Measuring the lookups from 64 MiB to 16 GiB, eight doublings, gives an apparent exponent of 2.96: a \(\Theta(N)\) program that looks cubic. A quadratic program measured over the same range would look like \(N^4\). This is a statement about the experiment, not about the algorithm, and it is the reason the Computer Systems Primer says to watch for a change of level in any doubling table.

The access pattern decides the size of the knee

A disk transfers a whole 4096-byte page per access. A sequential scan uses every byte of it: 1024 four-byte items per disk read. The same model, applied to an \(N^2\) all-pairs loop that scans an array of \(N\) integers once per element, gives a per-access cost of 7.65 ns while the array fits in the 64 MiB of memory and 4,884 ns once it does not: a factor of 638, a local exponent of \(2 + 9.3 = 11.3\), and then \(b = 2\) again. Random access over the same array pays a full disk access almost every time, a factor of about 50,000.

Definition (thrashing) A program is thrashing when its working set exceeds physical memory and it spends most of its time waiting for pages to be read back from swap. Thrashing multiplies running time by a large constant; it does not change the order of growth.

One more limit lies outside every cost model in this chapter. When the data no longer fits in memory and swap together, the program does not run slowly; it fails. Asymptotic statements assume the input fits in the machine.

5. When the exponent does change

The theorem of section 2 has one hypothesis: a constant upper bound \(b\) on the cost of an operation. The exponent can change only if that hypothesis fails, that is, if the cost of a basic step grows with \(N\).

Costs that grow with the size of memory

A memory that holds \(S\) bits occupies an area proportional to \(S\). On a chip, which is flat, the farthest bit is at a distance proportional to \(\sqrt{S}\), and no signal travels faster than light, so the time to fetch an arbitrary bit grows at least like \(\sqrt{S}\) (like \(\sqrt[3]{S}\) for memory packed in three dimensions). A fixed computer hides this behind a fixed hierarchy. A model in which the input grows without bound and the machine grows with it must charge for it. In the simplest such model, accessing address \(x\) costs \(\sqrt{x}\):

\[ \text{scan of } N \text{ items: } \sum_{x=1}^{N} \sqrt{x} \;\approx\; \int_0^N \sqrt{x}\,dx \;=\; \tfrac{2}{3} N^{3/2} . \]

A scan, \(\Theta(N)\) in the RAM model, is \(\Theta(N^{3/2})\) in this one. An all-pairs algorithm that makes \(N^2\) accesses spread over \(N\) items pays about \(\tfrac{2}{3}\sqrt{N}\) per access on average and becomes \(\Theta(N^{5/2})\). Here the exponent really changes, because the cost of one step is no longer bounded. Aggarwal, Alpern, Chandra and Snir (1987) studied algorithms in this kind of model, the hierarchical memory model, in which accessing location \(x\) costs \(f(x)\) for a growing function \(f\) such as \(\log x\) or \(x^{\alpha}\). The measured staircase of section 3 is a coarse version of the same curve: from 32 KiB to 16 GiB, a factor of \(2^{19}\) in size, the cost of a random access grows from 1.4 ns to about 100 ns, a factor of 71, between the cube root (80) and the square root (724) of the size ratio.

Counting transfers: the external-memory model

A different way to make the hierarchy visible in a bound is to count only what is expensive. The external-memory model (Computer Systems Primer, section 4) charges one unit per block transfer between a fast memory of \(M\) items and a slow memory, with \(B\) items per block, and nothing for computation.

Multiplying two \(N \times N\) matrices stored row by row takes \(N^3\) multiply-adds however the loops are arranged, and the transfers depend on the arrangement:

The external-memory model predicts the order of these three times, and it does not predict their ratios: the processor prefetches the sequential reads of i-k-j, so its cost per multiply-add is already close to the cost of the arithmetic, and blocking gains a further 1.7× rather than the 100-fold reduction in transfers. A model is chosen to capture the dominant cost; when that cost stops dominating, the model stops predicting.

6. Pipelines, parallel execution and branch prediction

The time a program takes is

\[ R \;=\; (\text{instructions executed}) \times (\text{cycles per instruction}) \times (\text{seconds per cycle}). \]

The RAM model counts the first factor. The processor features of the Computer Systems Primer, section 1 act on the second. Pipelining overlaps the stages of consecutive instructions, and superscalar execution starts several independent instructions in the same cycle, so a stretch of independent arithmetic can average well under one cycle per instruction. An instruction that waits for main memory stalls everything that depends on it for hundreds of cycles. Branch prediction lets the pipeline run ahead past a branch along the direction it guesses; a wrong guess discards the work done since the branch, typically 15 to 20 cycles on current processors.

branch.cpp runs the same loop over the same 16,777,216 random values from 0 to 255, first in random order and then sorted. The work is identical; only the predictability of the test differs.

loop bodyrandom ordersortedratio
if (a[i] >= 128) s += a[i];0.31 ns0.30 ns1.0×
if (a[i] >= 128) s += weight(a[i]);4.22 ns1.15 ns3.7×

Measured per value, g++ -std=c++17 -O2; weight is a function the compiler does not inline. The second ratio varied from 3.2× to 4.7× across runs.

In the first loop the optimizer replaced the branch by branch-free instructions that compute both outcomes and keep one, so there is nothing to predict and the order of the values does not matter. In the second, the branch guards a function call and stays a branch. On random data the processor guesses wrongly about half the time; on sorted data the outcome changes once in sixteen million values and the guess is almost always right.

These effects, the locality ratios of 41× and 52× measured in the Computer Systems Primer, and the 9.1× of the loop order above, all change the cycles per instruction. None changes an order of growth: each is bounded by a constant on a given processor. They are nonetheless larger than the difference between many algorithms that differ in order. At \(N = 10^6\), \(\lg N \approx 20\), so a \(\Theta(N \lg N)\) algorithm with a 50× better constant is faster than a \(\Theta(N)\) one up to astronomically large \(N\) (until \(\lg N > 50\), past \(10^{15}\)).

7. What it means to optimize a program

The compiler’s optimizer rewrites code without changing what it computes (Computer Systems Primer, section 7). A programmer optimizing a program does something the compiler cannot: changes the computation itself, choosing a different algorithm, a different representation of the data, or a different order of work, and decides where that effort is worth spending. The choices fall into levels, ordered by what each can achieve.

1. The algorithm: the only lever on the exponent

The 3-sum ladder of the lecture is the example. At \(N = 8000\):

algorithmorderinner operations at \(N = 8000\)
brute force, three loops\(\Theta(N^3)\)85,301,336,000
sort, then binary search for each pair\(\Theta(N^2 \lg N)\)about 415,948,000
sort, then two pointers for each \(i\)\(\Theta(N^2)\)about 32,000,000

Brute force: \(N(N-1)(N-2)/6\) triples; binary search: \(\binom{N}{2}\) pairs times \(\lceil \lg N \rceil = 13\) probes; two pointers: about \(N^2/2\) steps.

The factors are 205 and 2,666, and they grow without bound as \(N\) grows. No constant-factor technique in this chapter reaches them at large \(N\).

2. The data structure

Replacing a list searched linearly by a hash table turns each lookup from \(\Theta(N)\) into expected \(\Theta(1)\), and a program that performs \(N\) lookups from \(\Theta(N^2)\) into expected \(\Theta(N)\). Choosing the structure is choosing which operations are cheap, and it can change the exponent of the whole program.

3. Constants under the real cost model

Once the algorithm and the structure are right, the remaining work is on the constant, and the cost model that matters is the real machine’s:

  • Locality. Traverse memory in the order it is laid out (9.1× for the matrix loop order); block computations so that what is reused stays in cache (a further 1.7× here, more when memory is the bottleneck).
  • Contiguous layout. An array instead of linked nodes (52× for a scattered list walk); a structure of arrays when a loop reads one field of many records.
  • Smaller data. A 4-byte int instead of an 8-byte long where the range allows halves the bytes moved and doubles what fits in each cache level.
  • Fewer allocations. Each new costs time and places the object wherever the allocator finds room; reserving a vector’s capacity or reusing nodes avoids both.
  • Less work in the inner loop. Move computations that do not change inside the loop out of it, and avoid recomputing values that can be carried from one iteration to the next.
  • Predictable branches. Process data in an order that makes tests predictable, or write the test so that the compiler can make it branch-free (3.7× above).

4. Choosing for the actual \(N\)

An asymptotic comparison is about large \(N\); a program runs at the \(N\) it is given. Insertion sort makes about \(N^2/4\) comparisons on random input and mergesort about \(N \lg N\):

5. Measure first

Every technique above costs programming time and usually clarity. The first step is to find where the time goes, with a profiler (a tool that samples which function the program is executing, such as perf on Linux or Instruments on macOS), and the second is to estimate what an improvement can be worth.

Amdahl’s law If a fraction \(p\) of the running time is spent in a part that is made \(s\) times faster, the whole program becomes \[ \text{speedup} \;=\; \frac{1}{(1 - p) + p/s} \] times faster, and never more than \(1/(1-p)\) times faster however large \(s\) is.
Normalize the old running time to 1. The part that is not changed still takes \(1 - p\); the optimized part took \(p\) and now takes \(p/s\). The speedup is the old time divided by the new. As \(s \to \infty\) the new time tends to \(1 - p\). □
Example A function takes 60% of the running time and is made 10 times faster. The program becomes \(1/(0.4 + 0.06) \approx 2.17\) times faster, and no improvement to that function can make it more than \(1/0.4 = 2.5\) times faster. Had the function taken 90% of the time, the same change would give \(1/(0.1 + 0.09) \approx 5.26\). Making a part that takes 5% of the time 100 times faster gives \(1/(0.95 + 0.0005) \approx 1.05\).

Knuth’s remark about optimization is often quoted only in its middle. In full (Knuth, “Structured Programming with go to Statements,” Computing Surveys, 1974):

“Programmers waste enormous amounts of time thinking about, or worrying about, the speed of noncritical parts of their programs, and these attempts at efficiency actually have a strong negative impact when debugging and maintenance are considered. We should forget about small efficiencies, say about 97% of the time: premature optimization is the root of all evil. Yet we should not pass up our opportunities in that critical 3%.”

Amdahl’s law is the arithmetic behind the passage: effort spent on the 97% has a small \(p\) and returns little; the critical 3% of the code, found by measuring, often holds most of the running time. The choice of algorithm and data structure is not a small efficiency and is not premature: it decides the exponent, and it is cheapest to make before the program is written.

8. Exercises (with solutions)

  1. On a machine where instructions take one cycle and every memory read takes \(10^6\) cycles, algorithm \(X\) performs \(N^2\) steps of two memory reads each, and algorithm \(Y\) performs \(N^3\) steps entirely in registers. For which \(N\) is \(Y\) faster? What are the orders of growth on this machine?
    solution \(X\) costs about \(2 \times 10^6 N^2\) cycles and \(Y\) costs \(N^3\). \(Y\) is faster while \(N^3 < 2 \times 10^6 N^2\), that is, for \(N < 2{,}000{,}000\). The orders are unchanged: \(X \in \Theta(N^2)\) and \(Y \in \Theta(N^3)\), because each read costs a constant.
  2. A doubling experiment on a quadratic program gives the ratios 4.0, 4.1, 3.9, 2,600, 4.0. Explain the fourth ratio and estimate by what factor the cost of one access changed.
    solution The operation count still quadrupled, so the cost per access rose by \(2600/4 = 650\) in that doubling: the working set crossed a level boundary. A factor of about 650 matches a sequential scan moving from main memory to a disk with 4096-byte pages (the model of section 4 gives 638). The last ratio, 4.0, shows the order is still \(N^2\).
  3. A \(\Theta(N \lg N)\) program accesses its data in random order. In the doubling where its working set outgrows main memory (about 100 ns per access) and moves to an SSD (about 50 µs), roughly what local exponent does a doubling experiment report?
    solution \(b_{\text{local}} \approx 1 + \lg(50{,}000/100) = 1 + \lg 500 \approx 1 + 9.0 = 10\), plus a few hundredths from the \(\lg N\) factor. The next doublings return to about 1.
  4. A \(\Theta(N)\) program is measured over four doublings that include a crossing at which the cost per access grows by a factor of 50,000. What exponent does a fit over the four doublings suggest?
    solution \(1 + \lg(50{,}000)/4 \approx 1 + 15.6/4 \approx 4.9\). A program that is linear looks like \(N^5\) over that range.
  5. Explain why the theorem of section 2 does not apply to the model in which accessing address \(x\) costs \(\sqrt{x}\), and show that an algorithm making \(N^2\) accesses spread evenly over \(N\) items is \(\Theta(N^{5/2})\) in that model.
    solution The theorem needs a constant upper bound on the cost of one operation; here the cost \(\sqrt{x}\) grows without bound as \(N\) grows. Each item is accessed \(N\) times, so the total is \(N \sum_{x=1}^{N} \sqrt{x} \approx N \cdot \tfrac{2}{3}N^{3/2} = \tfrac{2}{3}N^{5/2}\).
  6. In the external-memory model with \(B = 16\) four-byte integers per block, how many transfers does a scan of \(2^{30}\) integers cost? How many do \(2^{30}\) reads at random positions of an array much larger than the fast memory cost?
    solution Scan: \(2^{30}/16 = 2^{26} = 67{,}108{,}864\) transfers. Random reads: almost every read lands in a block that is not in fast memory, so about \(2^{30} = 1{,}073{,}741{,}824\) transfers, 16 times as many.
  7. For \(N = 2048\), \(B = 8\) and tiles of \(T = 64\), how many transfers does blocked matrix multiplication make, compared with the i-k-j loop? The measured speedup of blocking over i-k-j was only 1.7×. Why?
    solution Blocked: \(2N^3/(BT) = 2 \cdot 2^{33}/(8 \cdot 64) = 2^{25} = 33{,}554{,}432\). i-k-j: \(2N^3/B = 2^{31} = 2{,}147{,}483{,}648\), 64 times as many. The i-k-j loop reads memory sequentially, the processor prefetches those reads, and the time per multiply-add (0.53 ns) is already close to the cost of the arithmetic, so the transfers it saves were not the dominant cost.
  8. A profile shows 70% of a program’s time in one function. How much faster must that function become for the program to run twice as fast? Can any change to that function make the program 3.5 times faster?
    solution \(1/(0.3 + 0.7/s) = 2\) gives \(0.7/s = 0.2\), so \(s = 3.5\). The largest possible speedup is \(1/0.3 \approx 3.33\), so 3.5 is out of reach however fast the function becomes.
  9. A program looks up each of \(N\) names in a linked list of the same \(N\) names. Of these changes, which change the order of growth: compiling with -O3; unrolling the search loop four times; storing the list in an array; replacing the list by a hash table?
    solution Only the hash table: it makes each lookup expected \(\Theta(1)\) and the program expected \(\Theta(N)\) instead of \(\Theta(N^2)\). The other three change the constant (the array substantially, through locality).
  10. In branch.cpp, sorting the values made the second loop 3.7 times faster. Sorting costs \(\Theta(N \lg N)\) and the loop costs \(\Theta(N)\). When is sorting first worth it?
    solution Only when the loop runs over the same data many times: one pass saves about \(3.07\) ns per value, while sorting costs \(\Theta(\lg N)\) comparisons per value, each of them a few nanoseconds. For a single pass sorting costs more than it saves; over many passes the one-time sort is repaid. It is the preprocessing trade of the faster 3-sum: pay once to make every later operation cheaper.
