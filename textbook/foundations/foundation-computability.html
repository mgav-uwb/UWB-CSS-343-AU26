Turing Machines & Computability

Data Structures & Algorithms. Foundation.
What a computer can do at all, before any question of how fast. The Turing machine defined as a 7-tuple (tape, head, states, transition function), with configurations and the yields relation; a machine \(M_{ab}\) built for \(\{a^n b^n\}\) and traced configuration by configuration to acceptance on aabb and to rejection on aab, aabbb, aba and ba, with its exact step count \(2n^2+2n+1\) proved; the Church–Turing thesis stated as a thesis and its evidence listed; encodings and the universal machine; decidable versus recognizable languages, with the theorem that a language is decidable exactly when it and its complement are both recognizable; the halting problem proved undecidable by diagonalization, twice (counting and self-reference); reachability of a line of code proved undecidable by reduction; Rice’s theorem and what compilers do instead; the gap between computable and tractable. With exercises.

Every other reading in this catalog compares algorithms: this one is faster, that one uses less memory, this bound is tight. All of it presumes an algorithm exists. This handout asks the prior question. Fix a problem, allow any amount of time and any amount of memory, and ask whether some program solves it at all. The answer is not always yes, and the problems that answer no are not exotic: does this program terminate? is one of them, and so is is this line of code ever reached? To prove such a statement you need a definition of “program” precise enough to reason about, which is what the Turing machine is for.

1. Why a machine model is needed

“No algorithm solves this problem” is a claim about every algorithm, including the ones nobody has thought of yet. You cannot check them one at a time. The only way to prove such a statement is to make “algorithm” a mathematical object, so that the set of all algorithms is something you can quantify over, count, and diagonalize against.

The requirements pull in two directions. The model must be simple, or proofs about all of its programs will be unmanageable. It must also be strong, or a negative result about it says nothing about C++. Alan Turing’s 1936 model meets both by copying what a person does with pencil and paper: read one symbol at a time, write one symbol at a time, remember a bounded amount in your head, move your attention one place left or right, and follow a fixed finite rulebook.

The model sits at the top of a ladder whose lower rungs appear in Regular Expressions and Automata. A finite automaton has states and nothing else; it cannot count, because counting to an unbounded \(n\) needs unbounded memory. A pushdown automaton adds a stack, which buys nesting and \(\{a^n b^n\}\) but not \(\{a^n b^n c^n\}\). A Turing machine adds a read/write tape with free movement in both directions, and with that one change the ladder stops: nobody has found a physically realizable model that computes more.

2. The Turing machine

The machine has three parts: an infinite tape divided into cells, a head positioned over one cell that can read and write it and then move one cell left or right, and a finite control holding one of finitely many states. All of the machine’s behaviour is one function from (state, symbol read) to (state, symbol written, direction).

Definition (Turing machine) A Turing machine (TM) is a 7-tuple \(M = (Q, \Sigma, \Gamma, \delta, q_0, q_{\mathrm{acc}}, q_{\mathrm{rej}})\) where
  • \(Q\) is a finite set of states;
  • \(\Sigma\) is the finite input alphabet, not containing the blank symbol _;
  • \(\Gamma \supseteq \Sigma\) is the finite tape alphabet, with _ \(\in \Gamma\);
  • \(\delta : (Q \setminus \{q_{\mathrm{acc}}, q_{\mathrm{rej}}\}) \times \Gamma \to Q \times \Gamma \times \{L, R\}\) is the transition function;
  • \(q_0 \in Q\) is the start state, and \(q_{\mathrm{acc}} \neq q_{\mathrm{rej}}\) are the two halting states.
The tape is infinite to the right. Initially it holds the input string in cells \(0, 1, \dots, |w|-1\) and blanks thereafter, the head is on cell \(0\), and the state is \(q_0\).

Read \(\delta(q, x) = (r, y, D)\) as one instruction: in state \(q\), seeing \(x\), enter state \(r\), overwrite the cell with \(y\), and move one cell in direction \(D\). The whole machine is that table. There is no separate program: the program is \(\delta\), and \(\delta\) is finite, which is exactly what will make it possible to count machines in section 7.

Two conventions keep the definition small. Moving left from cell \(0\) leaves the head on cell \(0\) (the tape does not extend to the left). And the machine stops the instant it enters \(q_{\mathrm{acc}}\) or \(q_{\mathrm{rej}}\); \(\delta\) is undefined on those states, which is why they are excluded from its domain.

Configurations

To reason about a run you need a name for “everything that is true at one instant.” A finite automaton’s instant is just its state. A Turing machine’s instant is its state plus the tape contents plus the head position.

Definition (configuration; yields) A configuration of \(M\) is written \(u\,q\,v\), where \(q \in Q\) is the current state, \(uv \in \Gamma^{*}\) is the tape content up to the last non-blank cell, and the head is on the first symbol of \(v\). The start configuration on input \(w\) is \(q_0 w\). Configuration \(C_1\) yields \(C_2\), written \(C_1 \vdash C_2\), if one application of \(\delta\) turns \(C_1\) into \(C_2\). A configuration is accepting if its state is \(q_{\mathrm{acc}}\), rejecting if its state is \(q_{\mathrm{rej}}\), and halting if it is either.

So XXYYq3b, the configuration drawn above, means: the tape reads XXYYb then blanks, the head is on the b in cell 4, and the state is \(q_3\). Writing the state inside the tape string, just left of the scanned cell, is the standard trick: one line of text captures the whole machine, so a run is a list of lines and a proof about a run is an induction over that list.

Definition (accepts, halts, decides, recognizes) \(M\) accepts \(w\) if the sequence of configurations starting from \(q_0 w\) reaches an accepting configuration. It halts on \(w\) if that sequence reaches a halting configuration; otherwise it loops on \(w\). The language of \(M\) is \(L(M) = \{w : M \text{ accepts } w\}\). \(M\) recognizes \(L(M)\); if in addition \(M\) halts on every input, \(M\) decides \(L(M)\).

The gap between recognizing and deciding is one word, every, and it is the whole subject of section 6. A recognizer is allowed to run forever on strings that are not in the language; a decider is not.

3. A machine built and traced: deciding \(a^n b^n\)

\(\{a^n b^n : n \ge 0\}\) is the standard example of a language no finite automaton recognizes: matching the counts needs unbounded memory, and a finite automaton has none. A Turing machine has a tape, so it can keep the count on the tape. It does not even need to count: it can pair off one \(a\) with one \(b\), crossing off both, and check that nothing is left over. That idea, made into a transition table, is the machine below.

The machine \(M_{ab}\) \(Q = \{q_0, q_1, q_2, q_3, q_{\mathrm{acc}}, q_{\mathrm{rej}}\}\), \(\Sigma = \{\texttt{a}, \texttt{b}\}\), \(\Gamma = \{\texttt{a}, \texttt{b}, \texttt{X}, \texttt{Y}, \texttt{\_}\}\), start state \(q_0\). The marks mean: X is “an a already paired off,” Y is “a b already paired off.” The four working states mean:
  • \(q_0\): the head is on the leftmost unmarked cell; start a new round.
  • \(q_1\): walk right looking for the leftmost unmarked b.
  • \(q_2\): walk back left to the X just written.
  • \(q_3\): every a is marked; verify that only Ys remain.
\(\delta\)ab XY_
\(q_0\) new round \(q_1\), X, R \(q_{\mathrm{rej}}\) – \(q_3\), Y, R \(q_{\mathrm{acc}}\)
\(q_1\) seek a b \(q_1\), a, R \(q_2\), Y, L – \(q_1\), Y, R \(q_{\mathrm{rej}}\)
\(q_2\) rewind \(q_2\), a, L – \(q_0\), X, R \(q_2\), Y, L –
\(q_3\) verify tail \(q_{\mathrm{rej}}\) \(q_{\mathrm{rej}}\) – \(q_3\), Y, R \(q_{\mathrm{acc}}\)

Cells marked “–” are unreachable, proved below; a formally total \(\delta\) sends them to \(q_{\mathrm{rej}}\). Entries that halt do not need a written symbol or direction, since the machine stops. Fifteen entries; every one of them is exercised by the traces in this section.

The control never holds a number.

With the two tables, that is all fifteen entries of \(\delta\) fired at least once: \(q_0\) on a, b, Y, _; \(q_1\) on a, b, Y, _; \(q_2\) on a, X, Y; \(q_3\) on a, b, Y, _.

Why the “–” cells never fire One fact settles all five: the Xs always occupy a prefix of the tape, cells \(0\) through \(k-1\), because the only rule that writes an X is \(q_0\) on a, and \(q_0\) is only ever reached with the head on cell \(k\) (initially \(k=0\), and thereafter from \(q_2\) reading the X in cell \(k-1\) and moving right). So \(q_0\) and \(q_3\), whose head is at or right of cell \(k\), never read X, and neither does \(q_1\), which only moves right from there. \(q_2\) walks left from a cell it has just written Y into, and every b left of that point is already a Y, so it never reads b; it is stopped by the X in cell \(k-1\), which exists because \(q_2\) is only entered after \(q_0\) wrote one, so it never falls off the left end onto a blank either.

Correctness

Claim \(M_{ab}\) decides \(\{a^n b^n : n \ge 0\}\).
Invariant. Whenever the machine is in \(q_0\) with the head on cell \(k\): the input’s first \(k\) symbols are all a (since \(k\) only ever grows by \(q_0\) reading an a), cells \(0 \dots k-1\) hold X, and the rest of the tape is the input suffix \(w[k\,{\dots}]\) with its \(k\) leftmost bs turned into Y. It holds vacuously at the start with \(k=0\), and one round preserves it: \(q_0\) marks \(w[k]\) as X, \(q_1\) moves right over as and Ys to the leftmost remaining b and marks it Y, and \(q_2\) returns to that new X and steps right, re-entering \(q_0\) at cell \(k+1\). On \(w = a^p b^q\) the invariant reads concretely as \(\texttt{X}^{k}\,\texttt{a}^{p-k}\,\texttt{Y}^{k}\,\texttt{b}^{q-k}\), which is what the trace of aabb shows at steps 0, 5 and 10.
Termination. Each completed round turns one a into X, and no rule ever writes an a, so the number of unmarked as strictly decreases and is bounded below by \(0\). After at most \(|w|\) rounds \(q_0\) reads something other than a and the loop is left. Every cycle in the state diagram passes through \(q_0\), and within a round \(q_1\), \(q_2\) and \(q_3\) each move in one direction only, across at most \(|w|+1\) cells. So the machine halts on every input.
Acceptance. There are exactly two rules into \(q_{\mathrm{acc}}\). One is \(q_0\) on a blank: by the invariant the tape from cell \(k\) on is \(w[k\,{\dots}]\) with \(k\) of its bs marked, so a blank there means both \(k = |w|\) and \(k = 0\), that is \(w = \varepsilon = a^0 b^0\). The other is \(q_3\) on a blank. \(q_3\) is entered from \(q_0\) reading Y, so \(w[k]\) is one of the marked bs and \(w = \texttt{a}^{k}\,\texttt{b}\cdots\); \(q_3\) then walks right and reaches the blank only if every cell from \(k\) on holds Y, that is only if \(w[k\,{\dots}]\) consists of exactly those \(k\) marked bs. Hence \(|w| = 2k\) and \(w = a^k b^k\). So \(M_{ab}\) accepts \(w\) if and only if \(w \in \{a^n b^n\}\), and since it halts on every input it decides the language. The four rejecting rules label the four ways to fail: \(q_0\) on b (a b before any a), \(q_1\) on a blank (an unpaired a), \(q_3\) on b (an unpaired b), \(q_3\) on a (an a after a b). ∎

Cost

Count the steps on the worst input, \(w = a^n b^n\) of length \(N = 2n\). Round \(i\) starts in \(q_0\) on cell \(i-1\) and does: one step to write the X; then \(q_1\) walks right across the \(n-i\) unmarked \(a\)s and the \(i-1\) existing Ys, which is \(n-1\) steps, plus one more step to mark the b; then \(q_2\) walks left across those same \(n-1\) cells, plus one step on the X to return to \(q_0\). That is \(1 + (n-1) + 1 + (n-1) + 1 = 2n+1\) steps per round, and there are \(n\) rounds. The audit then costs \(1\) step to enter \(q_3\), \(n-1\) steps across the remaining Ys, and \(1\) step to accept on the blank, so \(n+1\) more. Total \[ T(n) \;=\; n(2n+1) + (n+1) \;=\; 2n^2 + 2n + 1 . \] In terms of the input length \(N = 2n\) this is \(N^2/2 + N + 1 = \Theta(N^2)\).

The quadratic comes from the pairing strategy, not from the language. The head moves one cell per step, so shuttling from the mark to the far end and back once per pair costs \(\Theta(n)\) per round however the rules are written; but a cleverer one-tape machine crosses out every other a and every other b on each pass and compares the two parities, halving both blocks per pass, which decides the same language in \(\Theta(N \log N)\). That is optimal for one tape: a one-tape machine deciding any non-regular language provably needs \(\Omega(N \log N)\) steps (Hennie, 1965), so linear time is out of reach here. Add a second tape and it is not: copy the \(a\)s to tape 2, then run the \(b\)s down against them, \(\Theta(N)\). One language, three running times, all on legitimate Turing machines. That is exactly why P, NP & Reductions is careful to say “polynomial time” and not “linear time”: polynomials are what survive a change of machine model, individual exponents are not.

4. The Church–Turing thesis

A one-tape machine that shuffles marks looks far too weak to stand in for a programming language. It is not. Everything a modern computer does can be done by one of these, with a polynomial slowdown, and nothing a modern computer does escapes them.

The Church–Turing thesis A function on strings is computable by an effective procedure, in the informal sense of a finite mechanical recipe that a clerk could follow without insight, exactly when it is computable by a Turing machine.

This is a thesis, not a theorem, and the distinction matters. One side of the claim (“effective procedure”) is not a mathematical object: it is an informal notion about what counts as a mechanical process. There is nothing to induct on and no axioms to derive it from, so it cannot be proved. It could, however, be refuted, by exhibiting a procedure that everyone agrees is mechanical and that computes something no Turing machine computes. In ninety years nobody has.

What supports it is convergence. Several people, working from unrelated intuitions, defined “computable” in ways that turned out to describe exactly the same set of functions:

The last row is not a figure of speech. A Python interpreter is a (large) Turing machine, and a Turing machine simulator is a short Python program; each direction is a construction, and together they show the two define the same computable functions. The next section writes the simulator down.

The thesis is what lets the rest of this handout be useful. Proofs are carried out about Turing machines because they are simple enough to reason about; the conclusions are then stated about programs, because the thesis says the two are the same. When section 7 proves that no Turing machine decides halting, the intended reading is that no program in any language does.

What the thesis does not say It says nothing about speed: a Turing machine may be polynomially or worse slower than a real CPU, and it does not claim those overheads are small. It says nothing about physical machines that are not finite and discrete (an idealized analog device with infinite precision is not covered, and is not buildable). And it says nothing about randomness or quantum mechanics changing what is computable: randomized and quantum machines compute exactly the same functions as Turing machines. They may compute some of them faster, which is a question about complexity, not computability.

5. Encodings and the universal machine

\(M_{ab}\) is a finite object: six states, five tape symbols, fifteen rules. Nothing stops us from writing it out as a string, and once machines are strings they can be the input to other machines.

Definition (encoding) For any finite object \(O\) (a machine, a graph, a pair of machines), \(\langle O \rangle\) denotes a fixed string over \(\{0,1\}\) that describes it: number the states and symbols, then list the tuples of \(\delta\) in some canonical order with a fixed separator. The exact scheme is irrelevant as long as it is unambiguous and both directions are computable, so we speak of “the” encoding.

This is the same move that a compiler makes when it reads your source file: a program is data. It also has a consequence that will do the work in section 7: a machine can be given its own description as input, since \(\langle M \rangle\) is just a string and any string is a legal input.

Theorem (universal machine) There is a single Turing machine \(U\) such that for every machine \(M\) and input \(w\), \(U\) on input \(\langle M, w\rangle\) simulates \(M\) on \(w\): \(U\) accepts if \(M\) accepts, rejects if \(M\) rejects, and loops if \(M\) loops.
Construction. \(U\) keeps three things on its tape: the description \(\langle M \rangle\) (never modified), \(M\)’s current state, and \(M\)’s current tape with a mark for \(M\)’s head position. One step of \(M\) is simulated by: read the symbol under the mark, scan \(\langle M \rangle\) for the unique tuple matching (state, symbol), overwrite the marked cell with the written symbol, move the mark left or right, and overwrite the stored state. Each of those is a bounded number of passes over a finite region, so each is a finite number of \(U\)’s steps. \(U\) halts exactly when the stored state becomes \(M\)’s accept or reject state, which happens exactly when \(M\) halts. ∎

\(U\) is the stored-program computer, described more than a decade before one was built: one fixed piece of hardware that behaves like whatever machine is written on its input. The construction below is the same simulator in four languages, and its structure is exactly the proof: a loop whose body is one table lookup. 

// Universal simulator: run the machine described by delta on input w.
// delta maps (state, symbol) to (state, write, move). Returns the halting
// state. Does not terminate if the simulated machine does not.
struct Act { string next; char write; int move; };   // move = +1 (R) or -1 (L)

string simulate(const map<pair<string,char>, Act>& delta, string w) {
    string tape = w.empty() ? string("_") : w;
    size_t head = 0;
    string q = "q0";
    while (q != "qacc" && q != "qrej") {
        while (head >= tape.size()) tape.push_back('_');   // tape is infinite
        auto it = delta.find({q, tape[head]});
        if (it == delta.end()) return "qrej";              // undefined = reject
        const Act& a = it->second;
        tape[head] = a.write;
        head = (a.move > 0) ? head + 1 : (head == 0 ? 0 : head - 1);
        q = a.next;                                        // one step of M
    }
    return q;
}

    int head = 0;
    String q = "q0";
    while (!q.equals("qacc") && !q.equals("qrej")) {
        while (head >= tape.length()) tape.append('_');    // tape is infinite
        Act a = delta.get(q + "," + tape.charAt(head));
        if (a == null) return "qrej";                      // undefined = reject
        tape.setCharAt(head, a.write());

    }
    return q;
}

def simulate(delta, w):

        tape[head] = write
        head = head + 1 if move == 'R' else max(0, head - 1)
        q = q_next                              # one step of M
    return q

    let mut tape: Vec<char> = if w.is_empty() { vec!['_'] } else { w.chars().collect() };
    let (mut head, mut q) = (0usize, String::from("q0"));
    while q != "qacc" && q != "qrej" {

            Some(a) => a.clone(),
            None => return String::from("qrej"),        // undefined = reject

        head = if act.2 > 0 { head + 1 } else { head.saturating_sub(1) };
        q = act.0;                                      // one step of M
    }

}

6. Decidable and recognizable

The one-word gap in the definitions of section 2 splits the languages into three tiers, and knowing which tier a problem lives in is the whole content of a computability result.

Definition (decidable, recognizable) A language \(L\) is Turing-recognizable (equivalently recursively enumerable) if some TM \(M\) has \(L(M) = L\): on \(w \in L\), \(M\) accepts; on \(w \notin L\), \(M\) rejects or loops. \(L\) is decidable (equivalently recursive) if some TM has \(L(M) = L\) and halts on every input: on \(w \notin L\), \(M\) must reject in finite time. \(L\) is co-recognizable if its complement \(\overline{L}\) is recognizable.

Decidable means “there is a program that always answers, yes or no.” Recognizable means “there is a program that says yes to every yes-instance, eventually, and never lies”: a search that is guaranteed to find a witness if one exists, but that has no way of knowing when to give up. Every decidable language is recognizable (a decider is a recognizer that happens to halt). The converse is what fails.

Theorem (the two halves) \(L\) is decidable if and only if \(L\) and \(\overline{L}\) are both Turing-recognizable.
(\(\Rightarrow\)) If \(D\) decides \(L\), then \(D\) recognizes \(L\), and the machine that runs \(D\) and swaps its two answers is a decider, hence a recognizer, for \(\overline{L}\).
(\(\Leftarrow\)) Let \(M_1\) recognize \(L\) and \(M_2\) recognize \(\overline{L}\). Build \(D\) on input \(w\): for \(t = 1, 2, 3, \dots\), run \(M_1\) on \(w\) for \(t\) steps, then \(M_2\) on \(w\) for \(t\) steps. (This interleaving is called dovetailing; it is needed because running \(M_1\) to completion first could loop forever.) If \(M_1\) accepts within its budget, accept; if \(M_2\) accepts within its budget, reject. Every \(w\) lies in exactly one of \(L\) and \(\overline{L}\), so exactly one of the two machines accepts \(w\), say after \(t_0\) steps; the loop reaches \(t = t_0\) after simulating at most \(2\sum_{t \le t_0} t = t_0(t_0+1)\) steps, which is finite. So \(D\) halts on every input and agrees with \(L\). ∎

The contrapositive is the tool used constantly: if \(L\) is recognizable but not decidable, then \(\overline{L}\) is not even recognizable. Undecidability of one language therefore hands you a language on the third tier for free.

languagetierwhy
\(A_{\mathrm{DFA}} = \{\langle D, w\rangle : D\) is a finite automaton accepting \(w\}\) decidable simulate \(D\) for exactly \(|w|\) steps and look at the state
\(\{\langle M, w, 1^k\rangle : M\) accepts \(w\) within \(k\) steps\(\}\) decidable the step budget is part of the input: simulate \(k\) steps and stop
\(A_{\mathrm{TM}} = \{\langle M, w\rangle : M\) accepts \(w\}\) recognizable, not decidable \(U\) recognizes it (§5); undecidable by §7
\(\mathrm{HALT} = \{\langle M, w\rangle : M\) halts on \(w\}\) recognizable, not decidable simulate and accept on halt; undecidable by §7
\(\overline{\mathrm{HALT}}\), “\(M\) loops on \(w\)” not recognizable the theorem above, contrapositive

Note how ordinary the two decidable rows are. Bounding the resource turns an undecidable question into a decidable one: “does it halt?” is undecidable, “does it halt within a million steps?” is decidable by the obvious method. Every practical tool in section 9 is a variation on that trade.

7. The halting problem

The question is the one every programmer has wanted answered: given a program and its input, will it finish? Formally, is \[ \mathrm{HALT} \;=\; \{\langle M, w\rangle : M \text{ is a TM and } M \text{ halts on input } w\} \] decidable? The answer is no, and there are two proofs worth having. The first counts and shows that something must be undecidable without saying what; the second names the problem.

7.1 Counting: most languages have no machine at all

Theorem There are countably many Turing machines and uncountably many languages over \(\{0,1\}\). Hence some languages are not recognized by any Turing machine.
Machines are countable. Each machine is completely described by the finite string \(\langle M \rangle\) over \(\{0,1\}\) (§5). The set of finite binary strings is countable: list them in shortlex order \(\varepsilon, 0, 1, 00, 01, 10, 11, 000, \dots\), which reaches every string in finite position. Discard the strings that are not valid encodings and the remainder is still a list \(M_1, M_2, M_3, \dots\) containing every machine.
Languages are uncountable. A language \(L \subseteq \{0,1\}^{*}\) is determined by its characteristic sequence: fix the shortlex list \(s_1, s_2, \dots\) of all strings and write the infinite bit sequence whose \(i\)-th bit is \(1\) iff \(s_i \in L\). Suppose the languages could be listed as \(L_1, L_2, \dots\). Define \(B\) by making its \(i\)-th bit the opposite of the \(i\)-th bit of \(L_i\). Then \(B\) differs from \(L_i\) on \(s_i\) for every \(i\), so \(B\) is on no list: contradiction (this is Cantor’s diagonal argument).
A countable list cannot cover an uncountable set, so some language has no machine. ∎

This is decisive but unsatisfying: it proves undecidable problems exist by a census, without exhibiting one anybody cares about. The next argument runs the same diagonal against a specific table.

7.2 Diagonalization against the halting table

Suppose, for contradiction, that HALT is decidable: some machine \(H\) exists with \[ H(\langle M, w\rangle) = \begin{cases} \text{accept} & \text{if } M \text{ halts on } w, \\ \text{reject} & \text{if } M \text{ loops on } w, \end{cases} \] and \(H\) itself always halts. Lay out the infinite table whose rows are the machines \(M_1, M_2, \dots\) from §7.1 and whose columns are those same machines’ encodings. Entry \((i, j)\) records what \(M_i\) does on input \(\langle M_j \rangle\), which by assumption is a fact \(H\) can compute. An arbitrary filling of the top-left corner:

\(\langle M_1\rangle\)\(\langle M_2\rangle\) \(\langle M_3\rangle\)\(\langle M_4\rangle\)…
\(M_1\)haltsloopshaltshalts…
\(M_2\)loopsloopshaltsloops…
\(M_3\)haltshaltsloopshalts…
\(M_4\)loopshaltshaltshalts…
………………
\(D\) loopshalts haltsloops…

The last row is built to disagree with the shaded diagonal in every column: \(D\) loops on \(\langle M_i \rangle\) exactly when \(M_i\) halts on \(\langle M_i \rangle\). Such a \(D\) is a legitimate program if \(H\) exists, because \(H\) computes the diagonal entry: 

  D takes one input x, which it treats as the encoding of a machine.
  D(x):
      if H(x, x) says "halts":      ask the oracle about x running on itself
          loop forever                e.g. while(true) {}
      else:
          halt                        return immediately
Theorem (Turing, 1936) HALT is undecidable: no Turing machine decides it.
Suppose \(H\) decides HALT and let \(D\) be the machine above. \(D\) is a Turing machine: it calls \(H\) (which halts on every input, so the call returns), then either enters a trivial infinite loop or halts. So \(D\) appears in the list of §7.1 as \(M_d\) for some index \(d\). Now run \(D\) on its own encoding \(\langle D \rangle\) and read the definition:
  • If \(D\) halts on \(\langle D \rangle\), then \(H(\langle D, D\rangle)\) says “halts,” so \(D\) takes the first branch and loops forever. So \(D\) does not halt on \(\langle D \rangle\).
  • If \(D\) loops on \(\langle D \rangle\), then \(H(\langle D, D\rangle)\) says “loops,” so \(D\) takes the second branch and halts immediately. So \(D\) does halt on \(\langle D \rangle\).
Each case implies its own negation, so \(D\) both halts and does not halt on \(\langle D \rangle\). Every step in the construction of \(D\) from \(H\) is elementary and constructive; the only unsupported assumption is that \(H\) exists, so that assumption is false. ∎

In table terms: row \(D\) differs from row \(M_i\) at column \(i\) for every \(i\), so \(D\) is not any row. But every machine is a row. The contradiction is not that \(D\) is a strange program; \(D\) is a perfectly ordinary five-line program. It is that \(H\) cannot exist.

Where the self-reference is legitimate Two steps in the proof look like sleight of hand and are not. Feeding \(D\) its own description is allowed because \(\langle D \rangle\) is just a string, and a program that takes strings takes that one; a compiler compiling itself is the same move. And \(D\) can be written without knowing \(\langle D \rangle\) in advance, since the argument only needs \(D\) to exist as a machine, and the code above defines it from \(H\) alone. Formally this is the recursion theorem: every machine can obtain its own description.

HALT is recognizable: run \(U\) on \(\langle M, w\rangle\) and accept if the simulation ever halts. If \(M\) loops, so does the recognizer, which is permitted. By the theorem of section 6, since HALT is recognizable and undecidable, its complement is not recognizable: there is not even a semi-procedure that confirms “this program loops forever.”

8. Reduction: one undecidable problem breeds many

Nobody diagonalizes twice. Every other undecidability proof imports the halting problem into the new problem, using the same technique that P, NP & Reductions uses for hardness, minus the polynomial-time budget.

Definition (mapping reduction) \(A\) reduces to \(B\), written \(A \le_m B\), if there is a computable total function \(f\) with \(w \in A \iff f(w) \in B\) for every \(w\). The function \(f\) turns questions about \(A\) into equivalent questions about \(B\).
Lemma (transfer) If \(A \le_m B\) and \(B\) is decidable, then \(A\) is decidable. Contrapositive: if \(A \le_m B\) and \(A\) is undecidable, then \(B\) is undecidable.
Let \(R\) decide \(B\) and let \(f\) be the reduction. Decide \(A\) on input \(w\) by computing \(f(w)\) (which halts, since \(f\) is total and computable) and running \(R\) on it (which halts, since \(R\) is a decider), answering as \(R\) answers. The result is correct because \(w \in A \iff f(w) \in B\), and it halts on every input, so it decides \(A\). ∎

The direction is the part people get backwards. To prove \(B\) undecidable you reduce the known-undecidable problem to it, \(A \le_m B\), so that a decider for \(B\) would give one for \(A\). Reducing \(B\) to HALT proves nothing about \(B\).

A worked reduction: is this line of code ever reached?

Compilers ask this constantly. If a statement can never execute, its code can be deleted, its variables need no registers, and a warning is worth printing. Formally, over programs in any language rich enough to simulate a Turing machine: \[ \mathrm{REACH} = \{\langle P, \ell, x\rangle : \text{program } P \text{ on input } x \text{ eventually executes line } \ell\}. \]

Theorem REACH is undecidable.
We show \(\mathrm{HALT} \le_m \mathrm{REACH}\). Define \(f\) on input \(\langle M, w\rangle\) to output \(\langle P, \ell, w\rangle\) where \(P\) is this program and \(\ell\) is the line marked below: 
  P(x):
      simulate M on x            the universal machine of §5, inlined
      print("reached")           line L
\(f\) is computable and total. Building \(P\) is textual: paste \(\langle M \rangle\) into a fixed simulator template and append one line. No simulation is performed while computing \(f\); it only writes source code, so it always halts.
\(f\) is correct in both directions. If \(M\) halts on \(w\), the simulation inside \(P\) terminates and control falls through to line \(\ell\), so \(\langle P, \ell, w\rangle \in \mathrm{REACH}\). If \(M\) loops on \(w\), the simulation inside \(P\) never terminates, no statement after it ever executes, so \(\langle P, \ell, w\rangle \notin \mathrm{REACH}\). Hence \(\langle M, w\rangle \in \mathrm{HALT} \iff f(\langle M, w\rangle) \in \mathrm{REACH}\).
By the transfer lemma, a decider for REACH would decide HALT, which §7 forbids. ∎

The shape generalizes immediately. Prefixing an arbitrary computation to the behaviour you want to ask about makes almost any behavioural question at least as hard as halting: does this program ever divide by zero (put the division after the simulation), does it ever write to this file, can this assertion fail, are these two functions equivalent (compare “simulate \(M\), then return 0” with “return 0”). Rice’s theorem is the statement that this is not an accident.

Theorem (Rice, 1953) Let \(\mathcal{P}\) be any property of the language a program recognizes (equivalently, of its input/output behaviour) that is nontrivial: some program has it and some program lacks it. Then deciding whether a given program has \(\mathcal{P}\) is undecidable.

The two conditions are exactly the fine print. Nontrivial rules out the two properties that are decidable for the silly reason that the answer is constant (“computes some function,” always yes; “is both total and non-total,” always no). Property of the language rules out questions about the text of the program rather than its behaviour. Two programs with the same behaviour must get the same answer, or Rice does not apply:

question about a programkindstatus
Does the source contain the token goto?syntacticdecidable (scan the text)
Does it type-check?syntacticdecidable (run the type rules)
Does it execute more than \(10^6\) instructions on input 17?boundeddecidable (simulate \(10^6\) steps)
Does it halt on every input?semantic, nontrivialundecidable (Rice)
Does it compute the constant-zero function?semantic, nontrivialundecidable (Rice)

9. Living with undecidability

None of this stops anyone from shipping a compiler. It constrains what the compiler is allowed to promise. Three honest options exist, and every real tool picks one.

strategypromisepriceexample
Approximate, soundly never wrong when it answers, but may answer “don’t know” false alarms; missed optimizations type checkers, escape and alias analysis, abstract interpretation
Bound the resource correct answer within a fixed budget says nothing beyond the bound bounded model checking, fuzzing, test suites, timeouts
Restrict the language every accepted program provably terminates rejects some perfectly good programs structural recursion in Coq and Agda, loop bounds in real-time subsets

A compiler’s dead-code elimination is the first strategy applied to §8’s REACH: it deletes a block only when it can prove the block unreachable, and leaves it otherwise. That is why if (false) { ... } is removed but a block guarded by a condition the compiler cannot evaluate is not, even when a human can see it never fires. The same asymmetry explains why the “variable may be used uninitialized” warning sometimes fires on correct code: the analysis approximates the set of reachable states from above, and an over-approximation costs a false warning, while an under-approximation would cost a missed bug. Compiler writers choose the direction that fails safe.

Termination is the sharpest case. There is no universal termination checker, and Rice says there is not even one for the special case “computes the constant-zero function.” What exists instead are termination provers that search for a ranking function: a quantity that is bounded below and strictly decreases every iteration, exactly the argument used in §3 to show \(M_{ab}\) halts (the number of unmarked \(a\)s). When the prover finds one, termination is established for that program; when it does not, the answer is “don’t know,” never “loops forever.” The same technique proves the loop bounds in Recursion & Induction and underlies the well-founded recursion that proof assistants demand.

Real computers are finite, and it does not help A machine with \(m\) bits of memory has at most \(2^m\) configurations, so it is a finite automaton, and halting is decidable for it: run it for \(2^m\) steps, and if it has not halted it must have repeated a configuration and will loop forever. This is a correct algorithm and a useless one. For a machine with 8 GiB of RAM, \(m = 2^{36}\) bits and the bound is \(2^{2^{36}}\) configurations, a number with roughly twenty billion decimal digits. Undecidability is the mathematically clean statement; the practical statement, that no analysis can settle termination in any feasible amount of work, survives the finiteness of real hardware unchanged.

10. Computable but intractable

Decidability is a coarse line. It divides the problems a program can settle at all from the ones it cannot, and it says nothing at all about cost: a problem is decidable if some machine always halts, even if that machine would outlast the universe on a ten-character input. Most problems that matter in practice are on the decidable side and still out of reach.

problemdecidable?cost
Sorting \(n\) items by comparisonyes\(\Theta(n \log n)\)
Boolean satisfiability, travelling salesman, graph colouringyesNP-complete; no known polynomial algorithm
Optimal play in generalized chess or Go on an \(n \times n\) boardyesEXPTIME-complete; provably not polynomial
Truth of a sentence of Presburger arithmetic (integers with \(+\) and \(<\))yesat least doubly exponential in the sentence length
Truth of a sentence of full arithmetic (with \(\times\))nonot decidable at any cost (Gödel, Church)
HALTnono algorithm at any cost

The fourth row is the instructive one. Presburger arithmetic has a decision procedure, published, implemented, and used inside SMT solvers, and it also has a proved doubly exponential lower bound: a sentence of a few dozen symbols can exhaust any machine. “Decidable” and “usable” are different claims, and the vocabulary for the second is the subject of P, NP & Reductions: the classes P, NP and EXP, polynomial-time reductions, and NP-completeness. That handout sits one level of refinement below this one. Computability asks whether a machine halts at all; complexity asks how many steps it takes, with the answer measured by Asymptotic Notation.

The two also differ in what a negative result is worth. Undecidability is a theorem: no algorithm exists, proved, permanently. NP-completeness is conditional: no efficient algorithm is known, and finding one for any NP-complete problem would give one for all of them. When a problem turns out to be undecidable, the only response is to change the question (bound it, approximate it, restrict the inputs). When it turns out to be NP-complete, the same responses apply, but nobody has proved they are necessary.

11. Where this sits

This handout is the top of a ladder of machines, each rung adding memory and with it the ability to recognize more languages. The bottom rung is the finite automaton of Regular Expressions and Automata: finitely many states and no writable storage, so it decides exactly the regular languages, in one linear pass, and cannot recognize \(\{a^n b^n\}\) at all. The middle rung adds a stack, giving the pushdown automaton and the context-free languages of Context-Free Grammars & Parsing, which is where programming language syntax lives and where \(\{a^n b^n\}\) first becomes recognizable. The top rung is this one: a read/write tape with free movement, which decides \(\{a^n b^n\}\) (the machine of §3), \(\{a^n b^n c^n\}\), and everything else computable.

The cost side of the same story is in Time Analysis and Space Complexity, whose step counting is exactly what §3 did by hand for \(M_{ab}\), and in P, NP & Reductions, which reuses this handout’s reduction machinery with a polynomial-time budget attached. The termination argument of §3 is a well-founded induction of the kind set up in Recursion & Induction, and the amortized reasoning of Amortized Analysis is the same style of potential-function argument used to prove termination in §9.

12. Exercises (with solutions)

  1. Give the full configuration sequence of \(M_{ab}\) on input abb, and say which rule causes the halt.
    solution q0abb ⊢ Xq1bb ⊢ q2XYb ⊢ Xq0Yb ⊢ XYq3b ⊢ XYb qrej. Five steps. Round 1 pairs the single a with the first b; \(q_0\) then reads Y, so there is no unmarked a left and the machine enters the audit state \(q_3\); \(q_3\) reads the unmarked b in cell 2 and the rule \(q_3, \texttt{b} \to q_{\mathrm{rej}}\) fires. The reject reason is “more bs than as,” the same branch that rejects aabbb.
  2. What language does \(M_{ab}\) decide if the single rule \(q_0, \texttt{\_} \to q_{\mathrm{acc}}\) is changed to \(q_0, \texttt{\_} \to q_{\mathrm{rej}}\)? Justify using the correctness proof, not by re-tracing.
    solution \(\{a^n b^n : n \ge 1\}\). The acceptance paragraph of the proof identifies exactly two ways to reach \(q_{\mathrm{acc}}\): from \(q_0\) on a blank, which the invariant shows happens only with \(k = 0\) on an empty tape, that is on input \(\varepsilon\); and via \(q_3\), which requires at least one completed round and so \(n \ge 1\). Changing the first rule removes the \(n = 0\) case and leaves the other untouched. Every other input still halts, so the machine is still a decider.
  3. Verify the step-count formula \(T(n) = 2n^2 + 2n + 1\) against the traces in §3, then give \(T\) for \(n = 10\) and say why a two-tape machine changes the exponent but the Church–Turing thesis is untouched.
    solution \(n = 0\) is the empty input: \(T(0) = 1\), matching the one-step run q0 ⊢ qacc. \(n = 2\) is aabb: \(T(2) = 8 + 4 + 1 = 13\), matching the thirteen steps of the accepting trace (fourteen configurations). \(T(10) = 200 + 20 + 1 = 221\). A two-tape machine copies the \(a\)s to tape 2 in \(n\) steps and then consumes one \(b\) per \(a\) in \(n\) more, so it decides the same language in \(\Theta(N)\). The thesis is about which functions are computable, not how fast; both machines decide the same language, so both are consistent with it. The exponent is a complexity fact, which is why complexity theory fixes a model and computability theory does not have to.
  4. HALT is recognizable. Explain why the obvious “recognizer” for \(\overline{\mathrm{HALT}}\), namely “simulate \(M\) on \(w\); if it has not halted, accept,” is not a recognizer, and state what §6 concludes about \(\overline{\mathrm{HALT}}\).
    solution “If it has not halted” is not a decidable test at any point in time: after any finite number of simulated steps the machine may still halt later, so accepting at that moment can be wrong, and waiting forever never accepts. A recognizer must accept every string in the language after finitely many steps, and no finite prefix of a non-halting run certifies that the run is infinite. By §6, HALT is recognizable and undecidable, so if \(\overline{\mathrm{HALT}}\) were recognizable then both halves would be recognizable and HALT would be decidable, contradiction. Hence \(\overline{\mathrm{HALT}}\) is not recognizable: it sits on the third tier.
  5. Prove that \(\mathrm{EQ} = \{\langle P_1, P_2\rangle : P_1\) and \(P_2\) halt on exactly the same inputs\(\}\) is undecidable, by reduction. State your reduction’s direction explicitly and check both directions of the equivalence.
    solution Reduce \(\mathrm{HALT} \le_m \mathrm{EQ}\) (the known-undecidable problem into the new one; the other direction would prove nothing). Given \(\langle M, w\rangle\), let \(f\) output \(\langle P_1, P_2\rangle\) where \(P_1(x)\) = “simulate \(M\) on \(w\), then halt” (it ignores \(x\)) and \(P_2(x)\) = “halt immediately.” Writing these two programs is textual, so \(f\) is total and computable. (\(\Rightarrow\)) If \(M\) halts on \(w\), then \(P_1\) halts on every \(x\), as does \(P_2\), so they halt on the same set (all inputs) and \(\langle P_1, P_2\rangle \in \mathrm{EQ}\). (\(\Leftarrow\)) If \(M\) loops on \(w\), then \(P_1\) halts on no input while \(P_2\) halts on all of them, and since there is at least one input the sets differ, so \(\langle P_1, P_2\rangle \notin \mathrm{EQ}\). Both directions hold, so by the transfer lemma EQ is undecidable. (Rice gives the same conclusion in one line, but the reduction is what Rice’s own proof does.)
  6. Classify each as decidable or undecidable, and for each undecidable one say whether Rice’s theorem applies directly: (a) does program \(P\) contain a while loop in its source? (b) does \(P\) halt within \(10^9\) steps on input 17? (c) does \(P\) halt on input 17? (d) does \(P\) print the same output as echo hello on every input? (e) is \(P\) longer than 500 bytes?
    solution (a) Decidable, syntactic: parse the source. Rice does not apply, and this is exactly the escape hatch in Rice’s statement, since two programs with identical behaviour can differ on this question. (b) Decidable: simulate for \(10^9\) steps and report. The bound is a constant of the problem, so the procedure always halts. Bounding the resource is the second strategy of §9. (c) Undecidable. Rice applies to the language property “accepts 17”; it is nontrivial, since some program halts on 17 and some does not. (It also follows from HALT by a one-line reduction that hard-codes the input.) (d) Undecidable, and Rice applies directly: it is a nontrivial property of the program’s input/output behaviour. (e) Decidable, syntactic: measure the file. Rice does not apply for the same reason as (a).
  7. The diagonal argument of §7.2 builds \(D\) from a hypothetical \(H\). Run the same construction against the decidable problem \(\mathrm{HALT}_{10^6} = \{\langle M, w\rangle : M\) halts on \(w\) within \(10^6\) steps\(\}\), whose decider \(H_{10^6}\) really does exist. Where exactly does the contradiction fail to appear?
    solution Define \(D'(x)\): if \(H_{10^6}(x,x)\) says yes, loop forever; else halt. \(D'\) is a real program and the table row is real. Now ask what happens on \(\langle D'\rangle\). If \(D'\) halts on \(\langle D'\rangle\) within \(10^6\) steps, then \(H_{10^6}\) says yes and \(D'\) loops: contradiction, so that case is impossible. But the other case is not a contradiction. \(H_{10^6}\) says no, so \(D'\) halts, and it halts after more than \(10^6\) steps, since running \(H_{10^6}\) itself takes longer than that. “Halts, but not within the budget” is entirely consistent, and no contradiction arises. The diagonal argument needs the oracle to answer the same question its caller is being judged by; a resource bound breaks that identity, which is precisely why \(\mathrm{HALT}_{10^6}\) is decidable while HALT is not.
  8. The Church–Turing thesis cannot be proved. Describe what a refutation would have to look like, and explain why “a quantum computer factors integers faster than any known classical algorithm” is not one.
    solution A refutation would exhibit a procedure that (i) everyone accepts as an effective mechanical procedure, requiring no insight, finitely describable, each step determined by a fixed finite rulebook, and (ii) computes a function that provably no Turing machine computes. Producing a machine that decides HALT would do it. Quantum speedup fails clause (ii): a quantum computer computes exactly the same set of functions as a Turing machine (a TM can simulate the quantum state vector, exponentially slowly), so it changes the complexity of factoring, not its computability. Factoring was always decidable, by trial division. The thesis is silent about speed, which is why a complexity result can never refute it.
