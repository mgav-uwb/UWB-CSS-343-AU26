Counting Loop Iterations

Data Structures & Algorithms. Foundation.
How to find, exactly, how many times a statement inside loops runs, as a function of the input size: the trip count of a single loop and its off-by-one traps, loops in sequence and loops nested, inner loops whose bounds depend on the outer index, loops that halve or double, and loops whose count depends on the data. It ends with a five-step method and exercises with solutions. What to do with a count once you have it (which terms matter, and how counts compare) is the subject of Analysis of Algorithms: Time; counting the calls of a recursive function is in Recursion & Induction, section 6.

Every cost in this book starts as a count: how many comparisons a search makes, how many times a sort swaps, how many pairs an algorithm examines. Most of those counts come from loops, and a loop’s count is a precise question with a precise answer. The answer is an expression in \(n\) that is exactly right for every \(n\), and it can be checked by putting a counter in the loop and running it. This chapter teaches the few patterns that cover nearly every loop in the course.

1. What we count

Pick one statement, usually the innermost one, and ask how many times it executes. Call that statement the basic operation; in the examples below it is ops++, a counter that does nothing else, so that the code you read is the code being counted. 

long ops = 0;
for (int i = 0; i < n; i++)
    ops++;                     // runs n times
Definition (count, trip count) The count of a statement is the number of times it executes, as a function of the input size \(n\). The trip count of a loop is the number of times its body runs, which is the number of values its loop variable takes for which the condition is true.

The second sentence is the key to every example that follows: to count a loop, list the values the loop variable takes, then count the list. A count is exact (499,500, not “about half a million”), and it is a property of the code, not of the machine: the same loop has the same count on every computer.

2. One loop: the trip count

A loop that starts at \(a\), runs while \(i \lt b\), and adds a step \(s \ge 1\) visits \(a, a+s, a+2s, \ldots\) up to the last value below \(b\), so for (i = a; i < b; i += s) runs

\[ \max\!\left(0, \left\lceil \frac{b - a}{s} \right\rceil\right) \text{ times.} \]

Off by one The difference between < and <=, or between starting at 0 and starting at 1, changes the count by one. That is irrelevant to how the count grows, but it is the difference between a right and a wrong answer to “how many times exactly”, and between a correct loop and one that reads past the end of an array. When in doubt, write out the values for \(n = 3\).

3. Loops in sequence and loops nested

Two loops one after the other run their bodies one set after the other, so their counts add. A loop inside another runs completely once for every iteration of the outer loop, so when the inner count does not depend on the outer variable, the counts multiply. 

for (int i = 0; i < n; i++) ops++;          // n
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++) ops++;      // n * m
                                            // total: n + n*m
Rule (sequence and nesting) Code in sequence: add the counts. A loop of trip count \(t\) around a body of count \(c\) that does not depend on the loop variable: \(t \cdot c\). Three nested loops of \(n\) iterations each give \(n^3\); a loop over all \(n^2\) cells of a matrix around a body of count \(c\) gives \(n^2 c\).

The rule applies to whatever the inner body is, including another loop of a different shape. A loop of \(n^2\) iterations around a halving loop (section 6) counts \(n^2(\lfloor \log_2 n \rfloor + 1)\): at \(n = 16\), \(256 \times 5 = 1280\).

4. Dependent inner loops: counts become sums

When the inner loop’s bounds involve the outer variable, the inner count is different on each outer iteration, and the total is a sum of those counts. 

for (int i = 0; i < n; i++)
    for (int j = 0; j <= i; j++)
        ops++;

Follow the method of section 1 one level at a time. For a fixed \(i\), the inner variable takes the values \(0, 1, \ldots, i\): that is \(i + 1\) values. The outer variable takes \(i = 0, 1, \ldots, n - 1\). So

\[ \text{count} \;=\; \sum_{i=0}^{n-1} (i + 1) \;=\; 1 + 2 + \cdots + n \;=\; \frac{n(n+1)}{2}. \]

At \(n = 10\) that is 55, which is easy to confirm: the inner loop runs 1, 2, 3, …, 10 times. Changing j <= i to j < i makes the inner count \(i\) instead of \(i + 1\), and the total \(0 + 1 + \cdots + (n-1) = n(n-1)/2\), which is 45 at \(n = 10\).

Pairs and triples

The loop for (i = 0; i < n; i++) for (j = i + 1; j < n; j++) visits every pair of indices \(i \lt j\) exactly once. Its count can be found as a sum (the inner loop runs \(n - 1, n - 2, \ldots, 0\) times) or by counting what it visits: the number of ways to choose 2 of \(n\) indices,

\[ \binom{n}{2} = \frac{n(n-1)}{2}, \qquad \binom{n}{3} = \frac{n(n-1)(n-2)}{6}. \]

The second is the count of three nested loops with j = i + 1 and k = j + 1, which visit every triple \(i \lt j \lt k\) once: 120 at \(n = 10\). Recognizing what a set of nested loops enumerates is often the fastest way to count it.

Steps that skip

A dependent inner loop with a step uses section 2 inside the sum. In 

for (int i = 0; i < n; i++)
    for (int j = i; j < n; j += 2)
        ops++;

the inner loop runs \(\lceil (n - i)/2 \rceil\) times, so the count is \(\sum_{i=0}^{n-1} \lceil (n-i)/2 \rceil\): 30 at \(n = 10\) (\(5 + 5 + 4 + 4 + 3 + 3 + 2 + 2 + 1 + 1\)), and about \(n^2/4\) in general.

6. Loops that halve or double

A loop whose variable is multiplied or divided by 2 each time takes logarithmically many steps, because the base-2 logarithm counts exactly how many times a number can be halved.

loop headervalues of i (n = 16)trip count\(n = 16\)\(n = 17\)\(n = 1000\)
for (i = n; i >= 1; i /= 2)16, 8, 4, 2, 1\(\lfloor \log_2 n \rfloor + 1\)5510
for (i = 1; i <= n; i *= 2)1, 2, 4, 8, 16\(\lfloor \log_2 n \rfloor + 1\)5510
for (i = 1; i < n; i *= 2)1, 2, 4, 8\(\lceil \log_2 n \rceil\)4510

Integer division matters in the first row: with \(n = 17\) the values are 17, 8, 4, 2, 1, because 17 / 2 is 8 in C++. The count is again the number of halvings, rounded down, plus one for the first iteration.

Nested around a halving loop

By the nesting rule, \(n\) iterations around a halving loop count \(n(\lfloor \log_2 n \rfloor + 1)\): 10,000 at \(n = 1000\). This is the shape of the costs written \(n \log n\) later in the course.

A dependent inner loop that adds up to linear

The nesting rule fails when the inner bound depends on the outer variable, and the result can be surprising: 

for (int i = n; i > 0; i /= 2)
    for (int j = 0; j < i; j++)
        ops++;

The outer loop runs about \(\log_2 n\) times, and the inner loop up to \(n\) times, but the count is not \(n \log_2 n\). The inner loop runs \(n\), then \(n/2\), then \(n/4\) times, and so on: a sum of halvings, which by section 5 is less than \(2n\). At \(n = 16\) the count is \(16 + 8 + 4 + 2 + 1 = 31\); at \(n = 1000\) it is 1994. Multiplying the largest inner count by the outer trip count gives an upper bound, not the count; the sum gives the count.

7. Loops whose count depends on the data

A while loop, or a for loop with a break, may stop at a point that depends on the values in the input, not only on \(n\). Its count is then not one function of \(n\) but a range, and we report the cases. 

int find(const vector<int>& a, int key) {
    for (int i = 0; i < (int)a.size(); i++)
        if (a[i] == key) return i;        // one comparison per iteration
    return -1;
}
  • Best case: the key is first: 1 comparison.
  • Worst case: the key is last or absent: \(n\) comparisons.
  • Average case, for a key equally likely to be at each of the \(n\) positions: \((n+1)/2\) comparisons.

When a loop has no simple formula, bound it by finding something that shrinks every iteration and cannot go below zero. A binary search loop halves the size of the range it still has to search, so it runs at most \(\lfloor \log_2 n \rfloor + 1\) times. Two indices that move toward each other, one of them by one step each iteration, start \(n - 1\) apart and stop when they meet, so the loop runs at most \(n - 1\) times, whatever the data. 

int lo = 0, hi = n - 1;
while (lo < hi) {
    if (/* some test on a[lo], a[hi] */) lo++;
    else hi--;                            // hi - lo shrinks by 1 every iteration
}

8. The method, in five steps

  1. Choose the statement to count, usually the innermost one.
  2. Work from the inside out. For the innermost loop, list the values of its variable for fixed outer variables, and count them (section 2). The result may involve the outer variables.
  3. Combine: add for code in sequence; multiply when the inner count does not depend on the outer variable; otherwise write a sum over the outer variable.
  4. Close the sum with the table of section 5, or by recognizing what the loops enumerate (pairs, triples).
  5. Check the formula at a small \(n\), such as 3 or 4, by listing every iteration by hand, or by putting a counter in the code and printing it for several \(n\).

The last step catches almost every error. A formula that gives 6 where the hand count gives 5 has an off-by-one in it, and \(n = 3\) is small enough to find where.

9. Exercises (with solutions)

  1. How many times does the body run? for (i = 2; i < n; i += 2), for \(n = 10\) and in general (\(n \ge 2\)).
    solution The values are 2, 4, 6, 8: 4 times at \(n = 10\). In general \(\lceil (n - 2)/2 \rceil\), which is \(n/2 - 1\) for even \(n\).
  2. Count ops++: 
    for (i = 0; i < n; i++) ops++;
for (j = 0; j < 2 * n; j++) ops++;
for (k = 0; k < n; k++) for (m = 0; m < 3; m++) ops++;
    solution \(n + 2n + 3n = 6n\). The loops are in sequence, so their counts add; the last is \(n\) iterations around a body of 3.
  3. Count ops++ in for (i = 1; i <= n; i++) for (j = 1; j <= i; j++) ops++; for \(n = 6\), then in general.
    solution The inner loop runs \(i\) times: \(1 + 2 + \cdots + 6 = 21\). In general \(n(n+1)/2\).
  4. Count ops++ in for (i = 0; i < n; i++) for (j = 0; j < n; j++) for (k = 0; k < j; k++) ops++;
    solution The innermost loop runs \(j\) times, so the two inner loops count \(0 + 1 + \cdots + (n-1) = n(n-1)/2\), and the outer loop repeats that \(n\) times: \(n \cdot n(n-1)/2\). At \(n = 10\): 450.
  5. Count ops++ in for (i = 0; i < n; i++) for (j = 0; j < i * i; j++) ops++;
    solution The inner loop runs \(i^2\) times, for \(i = 0, \ldots, n-1\): \(\sum_{i=0}^{n-1} i^2 = \frac{(n-1)n(2n-1)}{6}\). At \(n = 10\): 285.
  6. How many times does for (i = 1; i < n; i *= 3) run, for \(n = 100\)?
    solution The values are 1, 3, 9, 27, 81: 5 times. In general \(\lceil \log_3 n \rceil\) for \(n \ge 2\).
  7. Count ops++ in for (i = 1; i < n; i *= 2) for (j = 0; j < i; j++) ops++; for \(n = 100\).
    solution The outer values are 1, 2, 4, 8, 16, 32, 64, and the inner loop runs that many times: \(1 + 2 + \cdots + 64 = 127\). A sum of doublings, less than twice the last term, so less than \(2n\) in general.
  8. A loop runs while (n > 1) { n = n / 2; ops++; }. Starting from \(n = 100\), what is ops at the end?
    solution \(n\) goes 100, 50, 25, 12, 6, 3, 1, so the body runs 6 times: \(\lfloor \log_2 100 \rfloor = 6\). (Compare the halving loop of section 6, which also runs once for \(i = 1\).)
  9. A function scans an array for the first negative number and stops there. Give its best-case and worst-case number of comparisons for an array of \(n\) elements.
    solution Best case 1 (the first element is negative); worst case \(n\) (the only negative is last, or there is none).
  10. Someone claims that for (i = n; i > 0; i /= 2) for (j = 0; j < i; j++) ops++; counts \(n \log_2 n\). Find the actual count for \(n = 64\) and explain the error.
    solution \(64 + 32 + 16 + 8 + 4 + 2 + 1 = 127\), less than \(2n = 128\), while \(64 \log_2 64 = 384\). Multiplying the outer trip count by the largest inner count gives an upper bound, but the inner count shrinks each time, so the count is a sum of halvings, not a product.
