Skip Lists

“Skip lists use probabilistic balancing rather than strictly enforced balancing and as a result the algorithms for insertion and deletion in skip lists are much simpler and significantly faster than equivalent algorithms for balanced trees.” William Pugh, “Skip Lists: A Probabilistic Alternative to Balanced Trees,” CACM 33(6), 1990

A sorted array gives binary search but \(O(n)\) insertion; a sorted linked list gives \(O(1)\) splicing but \(O(n)\) search, because a list has no random access to jump to the middle. The binary search tree is one resolution of that tension. The skip list (Pugh, 1990) is another, and it never leaves the linked list: it adds express lanes above the list and a coin to decide who is in them.

1. Express lanes over a sorted list

Start with a sorted singly linked list. Now build a second list above it containing every other node, a third containing every fourth node, and so on, each node keeping a pointer down to its copy below. To search, run along the top (sparsest) list until the next key is too big, drop down one level, and repeat. Each level roughly halves the candidates, just as binary search does, so with \(\log_2 n\) levels a search costs \(O(\log n)\) steps.

That perfect every-other-node layout is a fine static structure, but one insertion at the front shifts the parity of every node after it: keeping the layout exact costs \(O(n)\) per update, the same trap as keeping an array sorted. The skip list keeps the layered shape and gives up the exact spacing: each node’s height is chosen randomly, by coin flips, when the node is created, and never changes afterward. On average the levels still thin out by half each step up, which is all the search argument needs, and an update now touches only the one tower it inserts or removes.

2. The structure, and the fixed example

Definition (skip list) A collection of sorted singly linked lists, level \(0\) up to level \(L\). Level \(0\) contains every key. A node’s tower height \(h \ge 1\) is fixed at insertion time: flip a fair coin, and the tower grows one level per heads, stopping at the first tails, so \(\Pr[h \ge k] = (1/2)^{k-1}\). A node of height \(h\) appears in levels \(0\) through \(h-1\); one node object simply carries an array next[0..h-1] of forward pointers, one per level. A head sentinel (no key) is as tall as the tallest tower and starts every level.

The whole structure is one node type: key plus an array of forward pointers. There are no parent pointers, no rotations, no colors, no balance factors. The level-\(0\) list alone is a plain sorted linked list; everything above it is an index into that list.

In text form, with dashes standing for the forward links:

L3  head ------------------------------- 34 -------------------------> nil
L2  head ------- 9 --------------------- 34 -------------- 50 -------> nil
L1  head ------- 9 --------- 22 -------- 34 -------- 42 -- 50 -------> nil
L0  head - 4 --- 9 --- 13 -- 22 -- 27 -- 34 -- 38 -- 42 -- 50 -- 55 -> nil
A note on the example In real use the heights come out of the random number generator; here they are fixed by fiat so that every trace below is deterministic and checkable. Nothing in the algorithms depends on which heights occurred, only the cost analysis does, and it is deferred to the expected-cost section. The list level (index of the top level) is \(3\); it always equals the tallest tower’s height minus one.

3. Search, traced

Search keeps one finger x, starting at the head on the top level, and repeats one two-way decision until it reaches the bottom:

  • Move right if the next key on this level is \(<\) the target: x = x.next[i].
  • Drop down one level otherwise (next key \(\ge\) target, or no next node).

After the bottom level is processed, x is the last node with key \(<\) target, so x.next[0] either is the target or proves it absent. The invariant that makes this correct: x.key \(<\) target at all times, so the answer can never be to the left of the finger, and dropping never skips it.

4. Insert: build a tower, splice it in

Insert has three phases, two of them already familiar:

  1. Search for the key, recording in an array pred[i] the last node visited on each level \(i\) (the level-\(i\) predecessor of the key). If the key is already present, stop.
  2. Flip the coin for the new tower’s height \(h\): start at \(1\), add one per heads, stop at the first tails. If \(h\) exceeds the current number of levels, add new empty levels to the head (the level increase case) with pred[i] = head for each new level.
  3. Splice: create one node with \(h\) forward pointers and link it after pred[i] on each level \(i < h\), exactly the two-assignment splice of a singly linked list, done \(h\) times.

No other node moves, ever: an insertion writes the new tower’s \(h\) pointers and rewrites \(h\) predecessor pointers, and nothing else in the structure changes. Compare the AVL rebalance, which may rotate on the whole path back to the root.

5. Delete: unlink a tower

Delete is insert’s mirror: search, recording the same pred array; if pred[0].next[0] is not the key, it is absent and nothing happens (the no-op case). Otherwise unlink the target from every level its tower reaches: pred[i].next[i] = target.next[i] for each \(i\) below the tower height. If the top level ends up empty, drop it (and repeat; the shrink can cascade).

Trace: delete 34 (from the list with 30 and 47) Search for \(34\): L4 drops at head (next \(47\)); L3 drops at head (next \(34\), not \(< 34\)); L2 moves right to \(9\), drops (next \(34\)); L1 moves right to \(22\), then to \(30\), drops (next \(34\)); L0 at \(30\) stops (next \(34\)). So pred = [30, 30, 9, head, head] for levels \(0\ldots4\), and pred[0].next[0] is \(34\): present, height \(4\). Unlink at levels \(0\ldots3\):

For contrast, deleting \(47\) next would unlink at all five levels and leave both L4 and L3 empty (\(34\), the only other occupant of L3, is already gone), so the list level would drop by two, back to L2 on top: the cascading-shrink case.

No borrow, no fuse, no rebalance: compare deletion in a red-black tree or a B-tree, where the delete cases outnumber the insert cases. A skip-list delete is exactly \(h\) pointer rewrites.

6. The code

All three operations share the predecessor-collecting descent; the entire structure is under sixty lines. next[i] is the successor on level \(i\); the head sentinel’s array length is the list height. 

// Skip list over int keys, p = 1/2. A node's height is fixed at birth by
// coin flips; search moves right while next->key < key, else drops a level.
struct Node {
    int key;
    std::vector<Node*> next;                 // next[i] = successor on level i
    Node(int k, int h) : key(k), next(h, nullptr) {}
};

struct SkipList {
    Node head{0, 1};                          // sentinel; its height = list height
    std::mt19937 rng{343};

    int height() const { return (int)head.next.size(); }
    int flipHeight() {                        // 1 + number of leading heads
        int h = 1;
        while (rng() & 1) ++h;                // heads: grow the tower
        return h;
    }
    // fills pred[i] = last node with key < k on level i; returns the finger
    Node* descend(int k, std::vector<Node*>& pred) {
        Node* x = &head;
        for (int i = height() - 1; i >= 0; --i) {
            while (x->next[i] && x->next[i]->key < k)
                x = x->next[i];               // move right; else drop down
            pred[i] = x;
        }
        return x;
    }
    bool contains(int k) {
        std::vector<Node*> pred(height());
        Node* y = descend(k, pred)->next[0];
        return y && y->key == k;
    }
    void insert(int k) {
        std::vector<Node*> pred(height());
        Node* x = descend(k, pred);
        if (x->next[0] && x->next[0]->key == k) return;   // already present
        int h = flipHeight();
        while (height() < h) {                // level increase: new empty levels
            head.next.push_back(nullptr);
            pred.push_back(&head);
        }
        Node* n = new Node(k, h);
        for (int i = 0; i < h; ++i) {         // splice on each level the tower reaches
            n->next[i] = pred[i]->next[i];
            pred[i]->next[i] = n;
        }
    }
    void erase(int k) {
        std::vector<Node*> pred(height());
        Node* t = descend(k, pred)->next[0];
        if (!t || t->key != k) return;        // absent: no-op
        for (int i = 0; i < (int)t->next.size(); ++i)
            pred[i]->next[i] = t->next[i];    // unlink every level of the tower
        delete t;
        while (height() > 1 && !head.next.back())
            head.next.pop_back();             // top level empty: shrink (may cascade)
    }
};
// Skip list over int keys, p = 1/2. A node's height is fixed at birth by
// coin flips; search moves right while next.key < key, else drops a level.
class SkipList {
    static class Node {
        int key; Node[] next;                 // next[i] = successor on level i
        Node(int k, int h) { key = k; next = new Node[h]; }
    }
    Node head = new Node(0, 1);               // sentinel; its height = list height
    java.util.Random rng = new java.util.Random(343);

    int height() { return head.next.length; }
    int flipHeight() {                        // 1 + number of leading heads
        int h = 1;
        while (rng.nextBoolean()) h++;        // heads: grow the tower
        return h;
    }
    // fills pred[i] = last node with key < k on level i; returns the finger
    Node descend(int k, Node[] pred) {
        Node x = head;
        for (int i = height() - 1; i >= 0; i--) {
            while (x.next[i] != null && x.next[i].key < k)
                x = x.next[i];                // move right; else drop down
            pred[i] = x;
        }
        return x;
    }
    boolean contains(int k) {
        Node y = descend(k, new Node[height()]).next[0];
        return y != null && y.key == k;
    }
    void insert(int k) {
        Node[] pred = new Node[height()];
        Node x = descend(k, pred);
        if (x.next[0] != null && x.next[0].key == k) return;  // present
        int h = flipHeight(), old = height();
        if (h > old) {                        // level increase: new empty levels
            head.next = java.util.Arrays.copyOf(head.next, h);
            pred = java.util.Arrays.copyOf(pred, h);
            for (int i = old; i < h; i++) pred[i] = head;
        }
        Node n = new Node(k, h);
        for (int i = 0; i < h; i++) {         // splice on each level the tower reaches
            n.next[i] = pred[i].next[i];
            pred[i].next[i] = n;
        }
    }
    void erase(int k) {
        Node[] pred = new Node[height()];
        Node t = descend(k, pred).next[0];
        if (t == null || t.key != k) return;  // absent: no-op
        for (int i = 0; i < t.next.length; i++)
            pred[i].next[i] = t.next[i];      // unlink every level of the tower
        int h = height();
        while (h > 1 && head.next[h - 1] == null) h--;  // shrink (may cascade)
        if (h < height()) head.next = java.util.Arrays.copyOf(head.next, h);
    }
}

# search moves right while next.key < key, else drops a level.
import random

class Node:
    def __init__(self, key, height):
        self.key = key
        self.next = [None] * height   # next[i] = successor on level i

class SkipList:
    def __init__(self):
        self.head = Node(None, 1)     # sentinel; its height = list height

    def height(self):
        return len(self.head.next)

    def _flip_height(self):           # 1 + number of leading heads
        h = 1
        while random.random() < 0.5:  # heads: grow the tower
            h += 1
        return h

    def _descend(self, key):
        """pred[i] = last node with key < key on level i."""
        pred = [None] * self.height()
        x = self.head
        for i in reversed(range(self.height())):
            while x.next[i] and x.next[i].key < key:
                x = x.next[i]         # move right; else drop down
            pred[i] = x
        return pred

    def contains(self, key):
        y = self._descend(key)[0].next[0]
        return y is not None and y.key == key

    def insert(self, key):
        pred = self._descend(key)
        y = pred[0].next[0]
        if y and y.key == key:        # already present
            return
        h = self._flip_height()
        while self.height() < h:      # level increase: new empty levels
            self.head.next.append(None)
            pred.append(self.head)
        node = Node(key, h)
        for i in range(h):            # splice on each level the tower reaches
            node.next[i] = pred[i].next[i]
            pred[i].next[i] = node

    def delete(self, key):
        pred = self._descend(key)
        t = pred[0].next[0]
        if not t or t.key != key:     # absent: no-op
            return
        for i in range(len(t.next)):
            pred[i].next[i] = t.next[i]   # unlink every level of the tower
        while self.height() > 1 and self.head.next[-1] is None:
            self.head.next.pop()      # top level empty: shrink (may cascade)
// Skip list, p = 1/2, in an index arena: usize indices stand in for pointers,
// which sidesteps shared-ownership issues (many levels point at one node).
// nodes[0] is the head sentinel; NIL marks the end of a level.
const NIL: usize = usize::MAX;

struct Node { key: i32, next: Vec<usize> }    // next[i] = successor on level i

struct SkipList { nodes: Vec<Node>, rng: u64 }

impl SkipList {
    fn new() -> Self {
        SkipList { nodes: vec![Node { key: i32::MIN, next: vec![NIL] }], rng: 343 }
    }
    fn height(&self) -> usize { self.nodes[0].next.len() }

    fn flip(&mut self) -> bool {              // xorshift64 coin
        self.rng ^= self.rng << 13; self.rng ^= self.rng >> 7;
        self.rng ^= self.rng << 17; self.rng & 1 == 1
    }
    fn flip_height(&mut self) -> usize {      // 1 + number of leading heads
        let mut h = 1;
        while self.flip() { h += 1 }          // heads: grow the tower
        h
    }
    // pred[i] = index of the last node with key < k on level i
    fn descend(&self, k: i32) -> Vec<usize> {
        let mut pred = vec![0; self.height()];
        let mut x = 0;
        for i in (0..self.height()).rev() {
            while self.nodes[x].next[i] != NIL
                && self.nodes[self.nodes[x].next[i]].key < k {
                x = self.nodes[x].next[i];    // move right; else drop down
            }
            pred[i] = x;
        }
        pred
    }
    fn contains(&self, k: i32) -> bool {
        let y = self.nodes[self.descend(k)[0]].next[0];
        y != NIL && self.nodes[y].key == k
    }
    fn insert(&mut self, k: i32) {
        let mut pred = self.descend(k);
        let y = self.nodes[pred[0]].next[0];
        if y != NIL && self.nodes[y].key == k { return; }   // present
        let h = self.flip_height();
        while self.height() < h {             // level increase: new empty levels
            self.nodes[0].next.push(NIL);
            pred.push(0);
        }
        let id = self.nodes.len();
        let next = (0..h).map(|i| self.nodes[pred[i]].next[i]).collect();
        self.nodes.push(Node { key: k, next });
        for i in 0..h { self.nodes[pred[i]].next[i] = id; }  // splice each level
    }
    fn remove(&mut self, k: i32) {
        let pred = self.descend(k);
        let t = self.nodes[pred[0]].next[0];
        if t == NIL || self.nodes[t].key != k { return; }    // absent: no-op
        for i in 0..self.nodes[t].next.len() {
            let after = self.nodes[t].next[i];
            self.nodes[pred[i]].next[i] = after;  // unlink every level
        }
        while self.height() > 1 && *self.nodes[0].next.last().unwrap() == NIL {
            self.nodes[0].next.pop();         // top level empty: shrink
        }
    }
}

Two details worth pausing on. The splice loop runs bottom to top, so even mid-insert the list is never broken below the current level. And the equality test happens once, at the bottom: on the way down the comparison is always strict (\(<\)), which is what makes the recorded pred array the strict-predecessor array that insert and delete both need.

7. Why expected \(O(\log n)\)

Every cost here is an expectation over the coin flips (see the asymptotic notation handout for the notation itself). Three facts do all the work: towers are short on average, the list is low on average, and the search path spends little time on each level on average.

Proposition (space) The expected height of a tower is \(2\), so a skip list on \(n\) keys holds \(2n\) forward pointers in expectation: expected space \(O(n)\).
Proof. For a height \(H \ge 1\), \(\mathbb{E}[H] = \sum_{k \ge 1} \Pr[H \ge k]\), and a tower reaches height \(k\) exactly when the first \(k-1\) flips are heads: \(\Pr[H \ge k] = 2^{-(k-1)}\). So \(\mathbb{E}[H] = 1 + \tfrac12 + \tfrac14 + \cdots = 2\). Summing over the \(n\) towers gives \(2n\) expected pointers. ∎
Proposition (height of the list) The expected number of levels is at most \(\log_2 n + 2\), and the probability of exceeding \(2\log_2 n\) levels is at most \(2/n\).
Proof. Let \(M = \max\) tower height over \(n\) independent towers. By the union bound, \(\Pr[M \ge k] \le n \cdot 2^{-(k-1)}\). For the tail: at \(k = 2\log_2 n + 1\) this is \(n \cdot 2 \cdot n^{-2} = 2/n\). For the expectation, split the sum \(\mathbb{E}[M] = \sum_{k\ge 1} \Pr[M \ge k]\) at \(\log_2 n\): the first \(\log_2 n\) terms are each at most \(1\), and the rest form a geometric series, \(\sum_{j \ge 1} n\, 2^{-(\log_2 n + j - 1)} = \sum_{j\ge 1} 2^{1-j} = 2\). So \(\mathbb{E}[M] \le \log_2 n + 2\). ∎

Intuitively: each level up keeps a node with probability \(1/2\), so level \(k\) holds \(n/2^k\) nodes in expectation, and around level \(\log_2 n\) the population dwindles to about one. That matches the fixed example: \(10\) keys, \(5, 3, 1\) nodes on levels \(1, 2, 3\), each within a whisker of \(10/2^k = 5, 2.5, 1.25\).

Proposition (search cost) The expected number of steps on any one level of a search path is at most \(2\), so the expected total search cost is \(O(\log n)\) comparisons.
Proof (sketch, the idea made precise). Walk the search path backwards, from where it stopped back up to the head. Read in reverse, every step is either up (the forward path dropped down through this node’s tower) or left (the forward path moved right into this node). Stand at any node on the path at level \(i\). The path is at this node because the node’s tower reaches level \(i\); whether the tower also continues to level \(i+1\) was decided by one more independent coin flip. If heads (probability \(1/2\)), the backward walk goes up here; if tails, the forward path could not have come from above at this node, so the backward walk goes left. The number of left-steps taken on one level before an up-step is therefore dominated by a geometric random variable with mean \(1\): at most \(2\) expected steps per level, counting the up-step. By the previous proposition there are \(O(\log n)\) levels in expectation, and (with a little care in combining the two expectations, which we omit) the expected total is \(\le 2\log_2 n + O(1) = O(\log n)\). ∎

Insert and delete each run one search and then do \(O(1)\) expected extra work (the new or removed tower has expected height \(2\)), so all three operations are expected \(O(\log n)\). The \(2\log_2 n\) constant is real, not an artifact of the proof: a search in a skip list makes about twice the comparisons of a perfectly balanced BST, the price of levels that only tend to halve. Measured on the model that verified this handout’s traces: random skip lists at \(n = 1000\) averaged \(20.1\) steps per search against \(2\log_2 1000 = 19.9\).

8. No bad inputs, only bad flips

A plain BST has a bad input: insert \(1, 2, \ldots, n\) in order and the tree is a path, deterministically, every time. Its \(O(\log n)\) claim needs luck in the data. The balanced trees (AVL, red-black, 2-3) remove the luck by enforcing an invariant with rebalancing work. The skip list removes it differently: it moves the randomness out of the input and into the structure.

A skip list’s shape is determined by the set of (key, height) pairs alone, not by the order of insertion; the towers are decided by the generator, and the keys have no say in them. So there is no sequence of keys an adversary can choose that makes the expected cost bad: the expected \(O(\log n)\) bound of the previous section holds for every input, with the expectation over the flips only. The only way to get a bad skip list is bad flips, for instance every tower coming up height \(1\), which flattens the list back to a plain linked list; that event has probability \(2^{-n}\), and the milder degradations are likewise exponentially unlikely (the \(2/n\) tail bound above). An adversary who knows the algorithm but not the random bits is helpless.

The same trick elsewhere This is the same move randomized quicksort makes (see Quicksort): sorted input ruins first-element pivots, but a random pivot has no bad input, only bad coin flips. And it is the same reason hashing quotes expected \(O(1)\): the hash function plays the role of the coin. Randomization buys immunity from the input at the price of a guarantee that is expected rather than worst-case.

9. Skip lists among the ordered symbol tables

This handout sits in the trees folder of the catalog with no tree in it, and that placement is the point: the skip list is a drop-in alternative to the balanced search trees as an ordered symbol table. It supports the same operations at the same expected cost: search, insert, delete in \(O(\log n)\), plus the ordered ones (min, max, floor, ceiling, range search) that hashing gives up. An ordered scan is just a walk along level \(0\), the same one-descent-plus-walk pattern as the leaf chain of a B+ tree.

Where the skip list wins, and why it is not merely a curiosity:

  • Simplicity. Delete, the operation with the heaviest case analysis in every balanced tree, is \(h\) pointer rewrites. There are no rotation cases to get wrong; the code in this handout is complete.
  • Concurrency. This is the industrial reason. An insertion changes \(h\) pointers near one spot; a tree rotation restructures an entire subtree and, under locking, must hold every node it moves. Skip lists admit fine-grained and even lock-free concurrent versions built on compare-and-swap of single pointers, which is why java.util.concurrent provides ConcurrentSkipListMap (there is no concurrent red-black map beside it), why Redis implements sorted sets with a skip list, and why LevelDB and RocksDB use one for the in-memory write buffer.

Where the trees win: the guarantee. An AVL or red-black tree bounds the worst case, with no probability in the statement, which matters under real-time constraints and against the (unlikely but possible) bad flips. On disk the contest goes to the B-tree either way, since neither a binary tree nor a skip list matches its node size to the block.

  5. Coin-flip probabilities, with the tower rule of this handout (height \(1\) plus one per leading heads): (a) what is the probability that a given tower has height exactly \(3\)? (b) In a \(10\)-key skip list, what is the expected number of nodes on level \(2\) or higher? (c) What is the probability that all \(10\) towers have height \(1\), collapsing the structure to a plain sorted linked list?
    solution (a) Height exactly \(3\) means heads, heads, tails: \((1/2)^3 = 1/8\). (b) A node reaches level \(2\) iff its height is \(\ge 3\), probability \((1/2)^2 = 1/4\); by linearity of expectation, \(10 \cdot 1/4 = 2.5\) nodes. (The fixed example has \(3\): the keys \(9\), \(34\), \(50\).) (c) Each tower stops at height \(1\) with probability \(1/2\), independently: \((1/2)^{10} = 1/1024\). For \(n\) keys, \(2^{-n}\): the all-flat catastrophe is exponentially unlikely, and note that no choice of keys changes this number.
  6. Pugh’s original design promotes with probability \(p = 1/4\) instead of \(1/2\) (grow the tower while a four-sided die shows \(1\)). What happens to (a) the expected number of pointers per node, and (b) the expected number of levels? (c) Why might one accept the slower level thinning?
    solution (a) \(\Pr[H \ge k] = p^{\,k-1}\), so \(\mathbb{E}[H] = \sum_{k\ge1} p^{\,k-1} = 1/(1-p) = 4/3\) pointers per node, versus \(2\) at \(p = 1/2\): a third of the index overhead. (b) Level \(k\) keeps \(n p^k\) nodes in expectation, which reaches \(1\) at \(k = \log_{1/p} n = \log_4 n = \tfrac12 \log_2 n\): half as many levels. (c) The per-level cost grows to about \(1/p = 4\) expected steps (the geometric mean-\(1/p\) run of the backward-walk argument), so the total expected comparisons come to \(4 \cdot \tfrac12\log_2 n = 2\log_2 n\): the same leading term as \(p = 1/2\), but with \(2/3\) fewer index pointers. Slightly more comparisons per level, traded for less space and fewer levels; \(p = 1/4\) is a standard production choice.
  7. True or false: “There is a sequence of insertions and searches that forces a skip list to \(\Theta(n)\) expected time per search.” Contrast with the corresponding statement for a plain BST.
    solution False. The expected-cost analysis conditions on nothing about the input: for every fixed set of keys and every operation sequence, the expectation over the coin flips of the search cost is \(O(\log n)\), because the tower heights are independent of the keys (the shape is determined by the (key, height) pairs, and the heights come from the generator alone). \(\Theta(n)\) behavior requires improbable flips, probability vanishing exponentially, not a clever input. For a plain BST the corresponding statement is true and easy: insert \(1, 2, \ldots, n\) in order and every subsequent search for a large key walks a path of length \(\Theta(n)\), with probability \(1\). That difference, guaranteed-in-expectation against every input versus hoping the input is kind, is the entire case for randomizing the structure.
