Homework 3: Recursion on Trees

“Recursion is the root of computation since it trades description for time.” Alan Perlis, “Epigrams on Programming,” SIGPLAN Notices 17(9), 1982
At a glance
Covers: Lecture 4 (Trees and BSTs) and Lecture 5 (AVL Trees) Format: individual Language: C++17 Starter: hw03.cpp Submit: a .zip with your hw03.cpp Due: Sun Oct 18, 11:59 PM

Five short recursive functions on binary trees. Each follows the shape of the tree, and each asks you to use what a tree promises: the BST ordering, the AVL balance condition, or the structure of an expression. The starter has the node type and a self-running test battery; you fill in five TODOs. Quiz 3 (Monday Oct 19) asks about the same material. None of these functions is part of Programming Assignment 1, so they can be practiced first.

Tasks

TODOFunctionWhat it must do
1isBSTWhether a tree satisfies the BST ordering at every node. Checking each node against its two children is not enough.
2lowestCommonAncestorThe deepest node whose subtree holds two given keys, found on one path from the root by using the ordering.
3isAVLWhether every node's subtrees differ in height by at most 1, in time proportional to the number of nodes.
4toInfixAn expression tree as a fully parenthesized infix string, such as (2+(3*4)).
5countInRangeHow many keys of a BST lie in [lo, hi], skipping every subtree that cannot hold one.

The full contract of each function, with examples, is in the comment above it in the starter.

The tests run themselves

g++ -std=c++17 -g hw03.cpp -o hw03 && ./hw03

Each check prints [PASS] or [FAIL]. The unmodified starter compiles and fails most of them. The last test of T5 counts the nodes your countInRange visits, so it fails if the function looks at every node.

Build on the lab Code is graded on the CSS Linux lab with g++ -std=c++17. Build and run there at least once before you submit; the Computing Environment guide has the login and file-transfer commands. Code that does not compile on the lab receives no points.
