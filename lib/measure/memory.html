Memory Hierarchy, Measured

Three experiments that run in your browser, on your machine. Each one does a fixed amount of work and times how long it takes, so the numbers describe your processor’s caches and memory. The dashed curve and the reference lines are the C++ versions of the same programs on the textbook’s 2019 laptop.

About 15 seconds in all (longer with the largest sizes). Close other heavy tabs for steadier numbers. The page stays usable while it runs.

1. How long does one memory read take?

An array of indices forms one random cycle through every slot, and the program follows it, p = next[p], ten million times. Each read needs the previous result and the next address is unpredictable, so the time per read is the time to fetch one value from wherever the array fits. As the array grows past each cache, the time jumps.

How to read it: each flat stretch is one level of the hierarchy, and the array size where the curve rises is about that level’s capacity. On the textbook laptop the steps are at 32 KiB (L1), 256 KiB (L2) and a few MiB (L3), and main memory costs about 100 ns per read.

2. Same additions, different order: a matrix

Sum every element of an n × n matrix stored row by row, first along the rows, then down the columns, three times each, keeping the fastest. Both loops perform exactly n² additions on the same values. Along a row, neighbours share a 64-byte cache line; down a column, every read is in a different line.

Textbook laptop (C++, n = 8192): by rows 0.3 ns per element, by columns 12.6 ns: 41× slower. The C++ row loop is faster than a browser’s because the compiler uses vector instructions that add several elements at once; down a column, both pay about 10 ns or more per read.

3. Same additions, different order: a linked list

Walk a linked list and add up its values, first with the nodes laid out in memory in list order, then with the same nodes linked in a shuffled order, three times each, keeping the fastest. Every walk visits every node once. The scattered walk is pointer chasing: each node’s address is known only after the previous node arrives.

Textbook laptop (C++, 16,777,216 nodes): in order 2.1 ns per node, scattered 111 ns: 52× slower.

The experiments use JavaScript typed arrays (source) and match the C++ programs latency.cpp and locality.cpp. Browsers round their clocks to protect privacy; every measurement here times enough work for the rounding not to matter. Results vary with the browser, battery state and other running programs; the shape is what to compare.
